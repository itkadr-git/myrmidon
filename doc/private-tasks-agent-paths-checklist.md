# 1.7 PRIVATE-TASKS: чек-лист ручной дым-проверки приватности агентских путей

Задача: OPE-12198 (часть D эпика OPE-12157). Дата базовой линии: 2026-11-07 (стенд 1.6.6-rc.46, commit f3885b2).
Назначение: после сдачи частей A–C (isPrivate в схеме, фильтры чтений, фильтры heartbeat/checkout) прогнать этот
чек-лист на живом стенде с агентским ключом и board-ключом, приложить выводы к OPE-12198.

Как пользоваться:

1. На стенде завести две тестовые задачи от владельца (user-ключ/доска):
   - «приватная» — признак приватности включён (isPrivate=true после части A);
   - «публичная» — обычная задача (isPrivate=false).
2. Все запросы ниже делать дважды: с агентским API-ключом (Bearer, X-Paperclip-Run-Id) и с board-ключом.
3. В выводе НЕ цитировать заголовки реальных личных задач владельца — только идентификаторы и длины полей.
4. Критерий провала выпуска: хотя бы один агентский путь, где приватная видна хоть заголовком,
   или board потерял доступ к приватной.

Пути агента (маршруты сняты с main 42c79c5da4):

Board-регресс (обязателен): после части A убедиться, что board (user) по-прежнему видит и редактирует
обе тестовые задачи, и что ранее существовавшие приватные задачи владельца (например, OPE-9224, OPE-4444)
не потеряли ни доступ, ни данные — статус и заголовок читаются board-ключом.

Красные флаги при проверке:

- приватная задача возвращается с любым непустым подмножеством полей (даже только id или заголовок) — провал;
- search находит приватную по номеру или тексту заголовка — провал;
- board-ключ ловит 403/404 на свою приватную — регресс, провал;
- heartbeat-кандидаты включают приватную (например, по dueAt/watchdog без фильтра приватности) — провал.
