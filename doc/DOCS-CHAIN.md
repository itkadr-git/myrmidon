# Контракт и рунбук цепочки документации (DOCS-CHAIN)

Рунбук и контракт цепочки сопровождения документации для предотвращения дрейфа и неконтролируемых правок:
«влит PR, меняющий поведение или доки → задача на EN-доки и навык (дубль-проверка) → после влития EN-изменений задача на RU только изменённых разделов со ссылкой на исходный PR; ревью обязательно, лимит запусков, автослияния нет».

## 1. Триггеры (Triggers)

Цепочка запускается при соблюдении следующих условий:
- **Триггер**: Влит PR (merged PR), изменяющий пользовательское поведение, интерфейсы, API, контракты или существующую документацию.
- **Исключения**: Чисто внутренние рефакторинги без изменения публичного API, тесты, bump зависимостей и правки CI не требуют запуска цепочки (см. правила классификации в `.agents/skills/doc-maintenance/SKILL.md`).

## 2. Архитектура цепочки (Chain Stages)

1. **Этап 1 (EN-документация и навыки)**:
   - Создаётся **EN docs task** («задача на EN-доки и навык»).
   - Агент сверяет внесённые изменения с английской документацией (`README.md`, `doc/SPEC.md`, `doc/PRODUCT.md` и др.) и выполняет дубль-проверку навыков в `.agents/skills/`.
   - Подготавливается минимальный PR с правками EN-документации.
   - PR проходит обязательное ревью. **Автослияния нет (no auto-merge)**.

2. **Этап 2 (RU-перевод изменённых разделов)**:
   - Только после того, как PR с EN-изменениями влит в `main`, создаётся **RU task** («задача на RU только изменённых разделов»).
   - Переводятся строго изменённые разделы (**RU changed sections**). Полный пересказ или рерайт стабильных документов запрещён.
   - В описании задачи и PR обязательно указывается ссылка на исходный функциональный PR.
   - PR проходит обязательное ревью. **Автослияния нет (no auto-merge)**.

## 3. Ограничения безопасности (Safety Constraints)

- **Запрет автослияния (no auto-merge)**: Все PR в рамках цепочки документации требуют явного подтверждения и проверки ревьюером доски или оператором. Автослияние запрещено (автослияния нет).
- **Лимит запусков на PR (run limit)**: На каждый PR устанавливается лимит запусков (не более 3–5 прогонов агента), чтобы предотвратить зацикливание при автоматических правках.
- **Обязательное ревью (review required)**: Ревью обязательно для каждого этапа цепочки перед вливанием в `main`.
- **Локализация по дельте**: Переводятся только затронутые блоки, чтобы исключить рассинхронизацию с основной английской версией.
- **Идемпотентность (idempotency)**: Автозавод задач цепочки использует ключ `docs-chain:<repo>:<pr>:<en|ru>`. Скрипт `scripts/docs-chain/create-chain-tasks.mjs` хранит ключи только в памяти процесса (DedupStore) и опционально передаёт их через `apiClient.createIssue` (ответ `deduplicated`). Повторная доставка того же merged PR в новом процессе без подключённого apiClient создаст задачу повторно — постоянную идемпотентность обеспечивает сторона завода задач (apiClient/доска), которая обязана проверять ключ `docs-chain:<repo>:<pr>:<en|ru>` перед созданием задачи. Для проверки без создания используйте режим `--dry-run` (печатает задачи, не создаёт).

## 4. Шаблоны задач (Task Templates)

### Шаблон EN-задачи (EN Docs Task Template)

```markdown
**Название**: [DOCS-EN] Актуализация EN-документации и навыков по PR #{SOURCE_PR_NUMBER}

**Обязательные поля**:
- Ссылка на исходный PR / Source PR: #{SOURCE_PR_NUMBER} (URL: https://github.com/itkadr-git/myrmidon/pull/{SOURCE_PR_NUMBER})
- Список изменённых разделов / Changed sections:
  - {Список файлов/разделов doc/ и README.md, затронутых изменением}
  - {Список навыков в .agents/skills/, требующих дубль-проверки}

**Критерии приёмки**:
1. Актуализирована EN-документация под изменения из исходного PR.
2. Проведена дубль-проверка и синхронизация связанных навыков в `.agents/skills/`.
3. Правки минимальны: факт, а не рерайт стиля.
4. Открыт PR с описанием изменений и ссылкой на исходный PR.
5. Соблюдён лимит запусков на PR (run limit).
6. Ревью обязательно, автослияния нет (no auto-merge).
```

### Шаблон RU-задачи (RU Changed Sections Task Template)

```markdown
**Название**: [DOCS-RU] Локализация изменённых разделов по PR #{SOURCE_PR_NUMBER}

**Обязательные поля**:
- Ссылка на исходный PR / Source PR: #{SOURCE_PR_NUMBER} (URL: https://github.com/itkadr-git/myrmidon/pull/{SOURCE_PR_NUMBER})
- Ссылка на EN PR / EN docs PR: #{EN_PR_NUMBER} (URL: https://github.com/itkadr-git/myrmidon/pull/{EN_PR_NUMBER})
- Список изменённых разделов / Changed sections:
  - {Точный перечень изменённых разделов / файлов для локализации}

**Критерий приёмки**:
- переведены только изменённые разделы, ссылка на PR есть
- Ревью обязательно, автослияния нет (no auto-merge).
- Соблюдён лимит запусков на PR (run limit).
```
