---
title: PARA memory files
summary: Durable workspace files that complement the Hindsight memory bank
---

PARA files are the durable, inspectable layer around an agent's working context. They complement Hindsight's searchable bank and the approved knowledge delivered through [[wiki]]. They are files in the agent workspace, not another hidden database.

## Four buckets

- **Projects** contain active, outcome-oriented work: the issue brief, current decisions, acceptance evidence, and next action.
- **Areas** contain continuing responsibilities such as a role's operating rules, runbooks, and service ownership notes.
- **Resources** contain reusable reference material: architecture notes, source maps, and domain explanations.
- **Archive** contains inactive project or area material retained for provenance rather than active prompting.

The buckets are a filing convention, not a claim that every file is generated by the server. A run should preserve source links and dates when it moves information between buckets.

## Relationship to memory

Use Hindsight for compact facts and retrieval across runs. Use PARA files when a human or another agent must inspect, edit, diff, or carry the context in a repository. Use the knowledge module for governed company knowledge with revisions, approval, publication, and `[[slug]]` backlinks.

A useful flow is: capture a durable decision in the active Project file; distill reusable guidance into Resources or an Area; retain a concise searchable fact in Hindsight; archive the project when its work is complete. Do not treat a Hindsight digest as the canonical project record.

## File contract

A PARA file should state its scope, owner or role, status, last-updated time, and source references. Keep generated or delivered files separate from agent-authored files, and never overwrite an existing instruction bundle silently. Links should use repository paths or knowledge slugs that can be followed by a reviewer.

## Operational safeguards

PARA writes must be append-or-review operations when they affect policy or a published decision. Avoid copying secrets into files, and keep transient run output out of Resources. When a file is delivered into a bot profile, its bytes participate in the profile hash; unchanged content should not cause a restart.
