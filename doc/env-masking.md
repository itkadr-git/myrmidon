# Маскировка env при диагностике (класс OPE-434)

Любой вывод переменных окружения — своего процесса или контейнера — перед попаданием
в транскрипт прогона проходит маску: имя переменной остаётся, значение скрывается `***`.

## Команда

    <диагностика env> | sed -E 's/(_URL=|PASSWORD=|SECRET=|TOKEN=|_KEY=).*/\1***/'

- Одна маска закрывает секретные поля: `*_URL`, `*PASSWORD*`, `*SECRET*`, `*TOKEN*`, `*_KEY*`;
  не-секретные (`PGUSER`, `PGHOST`, `POSTGRES_PORT`) проходят как есть.
- `sed -E` обязателен: та же запись без `-E` (BRE) падает `invalid reference \1` и маски
  не даёт. Команду прогоняй до вывода, не доверяй «похоже на прошлую рабочую».
- Диагностика контейнеров доски:

      docker exec paperclip-server-1 env | grep -iE 'DATABASE|PG|POSTGRES' \
        | sed -E 's/(_URL=|PASSWORD=|SECRET=|TOKEN=|_KEY=).*/\1***/'

- В транскрипт не выходит ни значение, ни его длина, ни отпечаток, ни префикс. Сырой вывод —
  сначала в переменную или файл в `$PAPERCLIP_SCRATCH_DIR`, наружу — только после маски.
- Сверить значение с эталоном (ротация, аудит) — отпечатком sha256[:12], не печатью значения.
- Значение уже вышло в транскрипт — считай скомпрометированным (класс OPE-434): потребителей
  ищи по sha256 значения, живой вызов каждого, потом ротация (навык `secret-rotation`).
  «Стёр строку из чата» утечку не закрывает: значение в транскрипте = остаточное.
