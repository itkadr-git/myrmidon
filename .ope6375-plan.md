# OPE-6375 — 1.6.5 F-09 ч.A: зависшие queued-прогоны

## Цель (по постановке)
1. Прогон, чья задача в backlog/терминальном статусе, отменяется с errorCode.
2. queued > 60 мин без waitReason → waitReason + сигнал внимания (queue_stall).
3. idle-агент со свободным слотом и задачей в todo → прогон стартует.
4. Тесты на embedded PG (по baseline.db.myrmidon.test.ts) + unit exhaustive таблица sweep→waitReason.
5. Зелёный CI до ревью, PR в rel/1.6.5-rc.7.

## Разведка кода (факты)
- `resumeQueuedRuns` (heartbeat.ts:19460) — sweep по компаниям; на каждую компанию:
  `sweepRuns` → `reconcileStrandedAssignedIssues` → `sweepPendingInteractionAddresseeWake` →
  `sweepExecutionHoldStaleReviewCarryover` → `sweepIssueDependencyReadinessWake` →
  `startQueuedRunsForCompany(20)` → `resumeQueuedTimerRunsForCompany` → `sweepStaleQueueWakeReserveLeases`.
  Именно из `resumeQueuedRuns` сигналов внимания НЕТ: единственные записи — warn-логи.
- `claimQueuedRun` (heartbeat.ts:17208): считает `staleness` ДО claim; stale-проверки
  (backlog/terminal/cancelled) проходят в `decideQueuedRunStaleness`
  (run-dispatch/domain/policy.ts:501) и в dispatch-потоке (heartbeat.ts:20062–20150).
- Молчаливые выходы sweep: запись осталась queued после `decideQueuedRunStaleness`
  → policy вернула {stale:false}, но старт не состоялся — причина не объясняется.
- Пауза агента: `enqueueWakeup` на paused НЕ логирует явно; suspended/paused агент
  с queued-записями пропускается бесшумно (idle-pickup.ts:707 note).
- OPE-4099 (parent comment context): прогон завис в queued на 112 ч на фоне
  idle-агента со свободным слотом.

## Архитектура изменений

### A. Отмена нестартуемых (errorCode)
В `claimQueuedRun` (heartbeat.ts:17208) staleness уже вычисляется до claim —
оставляем как есть. Усиливаем точку, где статус issue = backlog:
`decideQueuedRunStaleness` в run-dispatch/domain/policy.ts уже различает
`issue_terminal_status` (done/cancelled) и `issue_not_in_progress` (todo/in_review
и т.п.). Backlog сейчас молча приводит к `skipped` с "Waiting for issue to become
startable" без errorCode в heartbeat_runs.errorCode. Добавляем: запись
queued → cancelled с `errorCode = "issue_backlog_not_startable"` (новый код в
QueuedRunStalenessErrorCode), если issue.status === "backlog". Это лечит и
«0 runs with backlog/terminal task» критерий.

### B. waitReason для queued > 60 мин + сигнал queue_stall
Новый модуль `server/src/myrmidon/queue-explain/`:
- `policy.ts` — чистые решения (queued age > threshold, outcome → waitReason).
- `attention.ts` — in-memory реестр `queue_stall` сигналов (replace-per-company,
  как review-routing), с `readQueueStallSignals`/`replaceQueueStallSignals`,
  `dedupKey`, `whyNow`, `severity`.
- `sweep.ts` — `sweepStuckQueuedRuns(db, companyId, now)`: находит queued > 60 мин
  без waitReason, вычисляет waitReason по facts (admission / paused / backlog /
  stale-skip), проставляет `heartbeat_runs.waitReason`, пишет queue_stall
  сигнал, логирует.

Подключаем в `resumeQueuedRuns` после всех под-sweep: собираем карту
outcome-by-run-id, для queued > 60 мин без reason — вызываем `sweepStuckQueuedRuns`.
Также публикуем сигнал в `services/attention.ts` (новый `sourceKind: "queue_stall"`).

### C. idle-агент + todo → старт
Существует `myrmidon/idle-pickup.ts` (sweep). Он должен запускать прогон, когда
агент idle + слот свободен + есть todo-задача. Проверяем, что на ветке он работает
и покрыт тестом; если есть баг — чиним. Из описания OPE-4099: агент был idle,
слот был свободен, но прогон не стартовал. Причина скорее всего в gating
внутри enqueueWakeup или в sweep-условии. Тест embedded PG на
`idle-pickup.myrmidon.test.ts`-подобном шаблоне: idle agent + todo issue →
queued запись создаётся и startNextQueuedRunForAgent её запускает.
