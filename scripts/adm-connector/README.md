# ADM connector cache (OPE-9261)

This Node-only library is imported by the connector hooks; importing it does not install hooks, call MCP, publish knowledge, or modify an ADM profile. Contract dependency: #1793 (already merged).

`AdmCache({ profileDir, company, space, integrityKey, metric })` requires an absolute profile path outside shared /tmp and a separately provisioned integrity key of at least 32 bytes. The caller must keep that key outside knowledge, cache, logs and prompts; changing it invalidates old cache. HMAC-SHA256 authenticates the envelope, while SHA256 checks each item and the complete envelope. Only validated, published, internal items and owner-approved policies may be stored. This is an additional integrity gate, not a substitute for REST authentication or upstream JSON Schema validation.

`read({ fetchItems, hazardous })` calls the injected REST adapter with an AbortSignal. The adapter must throw on non-success HTTP statuses, authenticate separately, and return a complete validated snapshot with item IDs. Timeout defaults to 2 seconds. Bounded exponential backoff and a circuit breaker are persisted per company/space across hook invocations. The default hazardous cache age limit is 5 minutes; operators should choose stricter policy-specific values where needed. Results explicitly distinguish fresh, stale-read and fail-closed. Failed fetches never overwrite the previous valid snapshot. Invalid or expired hazardous cache returns no items. The library makes no authorization/execution decisions itself: consumers must honor hazardousAllowed and fail-closed.

The profile contains `adm-connector/<company-space-hash>/cache.json`, private health/session files and deferred proposals. Complete snapshots are written to an exclusive 0600 temporary file, synced, and atomically renamed; the leaf directory is 0700. Existing symlink directory components are rejected. Concurrent readers see complete old or new snapshots; callers should use a single writer per company/space to preserve fetch ordering.

`defer(proposal, { ttlMs })` persists an unpublishable proposal containing base_revision and idempotency_key, expiration and requires_owner_review. It does not replay, publish or provide a transport. Recovery must enforce expiry, compare the current board base revision, obtain renewed owner review and verify the published API result by readback. Secret-like proposal or snapshot content is rejected without echoing it.

`ContextDelivery(cache, sessionId).deliver({ items, phase, triggers, compacted })` is the shared budget gate for hooks. Input must come from a successful cache result; fail-closed items must not be delivered. SessionStart emits only policy title/summary (combined 300 Unicode characters) and a trigger index, maximum 12 KiB. UserPromptSubmit emits at most 2 KiB, with no output on no match; slug+revision dedup persists in the session file. Compaction emits policies only. Mandatory policies never silently disappear on overflow: ADM_BUDGET_EXCEEDED must block delivery. Full bodies never enter output. Trigger matching is deterministic code, not model/MCP selection. The hook REST adapter and trigger classifier are task C, not installed by this library.

The injected metric callback receives knowledge_fetch, cache_hit, cache_stale, write_deferred, fail_closed and context_bytes (messageBytes/sessionBytes). The hook adapter must append these structured events to its connector journal. Events contain no bodies, upstream exception text or credentials. Byte caps are deterministic; real token-cost comparisons against the existing ADM brief require the task C/F hook rollout baseline.

Verification: `node --test scripts/adm-connector/cache.test.mjs`; the existing CLI Vitest CI shard executes the same Node suite through `cli/src/adm-connector-cache.test.ts`, without dependencies or database skips. No workflow permission is required. No production rollout is performed by this change.
