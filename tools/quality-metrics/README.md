# Harness quality metrics

Run `python3 tools/quality-metrics/metrics.py --from 2026-10-19T00:00:00Z --to 2026-10-21T00:00:00Z`. Configure `PAPERCLIP_API_URL`, `PAPERCLIP_API_KEY`, `PAPERCLIP_COMPANY_ID`, and `LITELLM_API_BASE`/`LITELLM_API_KEY` in the environment; credentials are never printed. Dates are an inclusive `from`, exclusive `to` UTC interval. Output reports counts and rates against runs; spend is USD and shown as a period total (not a run rate).

The script reads the board's `GET /api/companies/{companyId}/heartbeat-runs`, `/activity`, `/issues`, each issue's `/comments`, plus LiteLLM's `/spend/logs` endpoint. It uses run IDs, timestamps, agent IDs, activity `action`/`entityType`/`entityId`/`details`/`runId`, issue `status`/`blockedByIssueIds`/`blockerMetadata`/`reviewPolicy`/`monitorNextCheckAt`, comment `body`/`createdAt`, and LiteLLM spend `spend`/`startTime`/`endTime`/`metadata`/`key_alias`. These existing APIs may paginate or cap results; use a period small enough to fit API limits. The script fails rather than silently accepting an unrecognized collection shape.

Metric definitions: idle means no mutating activity attributable to a run (runId match, or comment/document/issue mutation explicitly tied to the run); blocked-without-reason counts blocked transitions lacking issue blocker IDs/metadata and a comment naming a blocker; gate bypass counts transitions into in_review whose issue policy is `human_only`; wait-without-monitor counts CI/deploy waiting comments where the issue has no monitor check timestamp. A single run may have multiple flagged behaviors, so reported counts need not sum to runs. Denominator for rates is all runs in the selected interval. Missing monitor timestamp is evaluated at query time. Gate bypass is a proxy based on issue policy and transition activity; review outcomes requiring richer audit data are not inferred.

To add a metric, implement a counter over the normalized `runs`, `activities`, `issues`, and `comments` collections in `metrics.py`, then add a row to `METRICS` with its count and description. API credentials must only be sent in authorization headers; never add them to command-line arguments or output.
