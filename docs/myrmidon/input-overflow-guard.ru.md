# Предохранитель переполнения входа и свежая сессия на повторах (OPE-6168)

> English version: [input-overflow-guard.md](input-overflow-guard.md)

Инцидент: агент `hermes_gateway` раз за разом падал с ответом провайдера
`Range of input length should be [1, 1048576]`. Каждый упавший ход заново клал свой
промпт (~220 КБ) в ту же сессию, сессия выросла до ~9,6 МБ, а доска каждые 3–5
минут запускала задачу снова с тем же исходом и без карточки внимания.

## Что изменено

1. **Автоматический транзиентный повтор начинает свежую сессию задачи** (апстрим
   paperclipai/paperclip #15487). `shouldResetTaskSessionForWake` возвращает true
   для `transient_failure_retry`. Исключение — явный первый шаг `same_session`
   лестницы codex.
2. **Переполнение входа — отдельное семейство ошибок `input_overflow`** (не
   транзиентная ошибка и не квота). Таблица формулировок —
   `packages/adapter-utils/src/input-overflow.ts` (DashScope «Range of input length
   should be», OpenAI `context_length_exceeded` / «maximum context length»,
   Anthropic «prompt is too long», Gemini «input token count exceeds the
   maximum», общие формулировки про окно контекста). Адаптер `hermes_gateway`
   ставит семейство сам; сервер распознаёт его и по тексту у любого адаптера.
3. **Следующая попытка — со свежей сессией.** После такого отказа сервер
   сбрасывает сохранённую сессию задачи и передаёт `sessionGeneration`
   в конфиге адаптера (1 + число отказов переполнения по задаче). `hermes_gateway` добавляет `:g<N>` (N ≥ 2) к
   ключу сессии шлюза, и новый прогон не использует раздутую историю.
4. **Остановка и карточка внимания.** После N подряд отказов переполнения одного
   агента по одной задаче (по умолчанию 3, env
   `MYRMIDON_INPUT_OVERFLOW_MAX_FAILURES`) доска эскалирует задачу через
   существующее восстановление «застрявшей» задачи (действие восстановления на
   доске блокирует общее автовосстановление) с комментарием: формулировка
   провайдера, id прогона, фрагмент ошибки. Что делать: сбросить или сжать сессию
   (карточка прогона → сброс сессии задачи), сократить контекст или сменить
   модель, затем разбудить агента.

Лимит входа из каталога моделей с проверкой до отправки описан в
[input-limit-precheck.ru.md](input-limit-precheck.ru.md); идемпотентная запись
хода внутри шлюза Hermes — патч среды ботов `11-stranded-run-turn-replace.patch`.

(бэкпорт в P3 вместе с ограничением истории продолжения).
