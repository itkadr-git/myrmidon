## changelog-en

### The queue starts reviews, releases and current-release work first (1.6.5 RUN-PRIORITY, part A)

- While run admission is closed, a freed slot no longer goes to whoever queued
  first: every queued run now carries an effective weight — the larger of its
  agent's role weight and its issue's priority weight, plus a bonus when the
  issue is labeled (or its workspace branch named) with the instance's current
  release, plus an aging step that grows with the time the run has waited in
  `queued`. Default role weights put `review` and `release` on top, `lead`
  next, then `engineer` and `docs`, everything else at the floor; default
  issue weights follow the familiar critical > high > medium > low order.
- Both queue paths apply it: the global sweep visits agents by their
  best-weighted queued run (weight, then the age of that run, then id) before
  starting anything, and the per-agent comparator sorts each agent's own queue
  by the same weight inside each readiness rank, with a `createdAt`
  tie-break. The admission gates themselves (load, memory, starts per
  minute, per-agent slots, the fair share) are unchanged — priority only
  reorders the choice inside the slots admission admits.
- Against starvation: the effective weight grows by a configurable step per
  configurable waiting minutes (capped by a maximum bonus), and a run that
  waits past the starvation limit gets the top weight outright, so no queued
  run can stay behind the queue forever.
- The weights are live settings, the run-limits pattern: the sweeps read them
  fresh every pass, so a change through `PATCH /api/myrmidon/run-priority`
  (or the environment at boot) reorders the very next sweep without a server
  restart. Turning the feature off falls back to the pre-feature ordering
  (fair-share oldest-first globally, priority-rank + `createdAt` per agent).

## changelog-ru

### Очередь первым делом запускает ревью, релизы и задачи текущего релиза (1.6.5 RUN-PRIORITY, часть A)

- Пока допуск прогонов закрыт, освободившееся место больше не достаётся тому,
  кто встал в очередь первым: каждый queued-прогон получает эффективный вес —
  большее из веса роли агента и веса приоритета задачи, плюс надбавка, когда
  задача помечена текущим релизом инстанса (меткой или именем ветки воркспейса),
  плюс aging-шаг, растущий с временем ожидания в `queued`. Дефолтные веса
  ролей ставят наверх `review` и `release`, затем `lead`, потом `engineer` и
  `docs`, остальных — на пол; веса приоритетов задач идут привычным порядком
  critical > high > medium > low.
- Применяется в обоих проходах: глобальный sweep обходит агентов по их
  лучшему по весу queued-прогону (вес, затем возраст этого прогона, затем id)
  перед стартом, а компаратор внутри агента сортирует его очередь по тому же
  весу внутри ранга готовности зависимостей, с tie-break по `createdAt`.
  Гейты допуска сами (нагрузка, память, старты в минуту, слоты агента,
  справедливая доля) не меняются — приоритет лишь упорядочивает выбор внутри
  допущенных слотов.
- Против голодания: эффективный вес растёт на настраиваемый шаг за каждые
  настраиваемые минуты ожидания (с потолком), а прогон, простоявший дольше
  предела голодания, получает топ-вес целиком — ни одна очередь не может
  ждать вечно.
- Веса — живые настройки, паттерн run-limits: проходы читают их каждый раз
  заново, поэтому изменение через `PATCH /api/myrmidon/run-priority` (или из
  окружения при старте) переставляет следующий же sweep без перезапуска
  сервера. Выключение возвращает дословно довоенный порядок (глобально —
  oldest-first по справедливой доле, внутри агента — ранг готовности, вес
  приоритета задачи, createdAt).

## settings-en

Stored as `instance_settings.general.runPriority.enabled` and flipped live on `PATCH /api/myrmidon/run-priority` | unset — on. The sweeps re-read the in-force settings every pass, so the next sweep after a settings change uses the new value without a restart |
| `MYRMIDON_RUN_PRIORITY_ROLE_WEIGHTS` | 1.6.5 RUN-PRIORITY | `review=90,release=90,lead=80,engineer=50,docs=50` | Weight per agent role (`agents.role`, compared case-insensitively). The run of a review agent at a closed admission starts ahead of an engineer's older run. Pairs `role=weight` separated by commas; a role with no entry falls back to the default role weight. Stored in `general.runPriority.roleWeights`; a settings write merges over the environment, then over the defaults | malformed pair — skipped with a log; negative/NaN — the whole map falls back to defaults.
