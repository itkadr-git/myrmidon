## changelog-en

### The run-admission CPU check reads /proc/loadavg through the exec gate (1.6.5 RUN-ADMISSION-CPU-BUSY)

- The host CPU sample (1-minute load ÷ core count) is now read by the bot's
  driver over the exec gate, the same path as the disk checks, instead of the
  board shell. A bot whose container blocks `/proc/loadavg` still reports a
  conservative value rather than failing admission.

## changelog-ru

### Допуск ходов решает загрузка процессора, а не load average (1.6.5 RUN-ADMISSION, rc.3)

- Решение о допуске новых ходов переехало с load average хоста на измеренную
  загрузку процессора: долю не-idle времени всех ядер из `/proc/stat` за
  короткое окно (дельта двух чтений, которые admission хранит у себя; окно не
  короче 250 мс) и, по желанию оператора, PSI cpu — поле `some avg10` из
  `/proc/pressure/cpu`. Load average остался в отчёте гейта только
  вспомогательной величиной. Причина: 06.10 хост нёс load1 65.7 на 16 ядрах
  (203 % сверх фона) и держал 11 ходов, хотя CPU был занят лишь 60–75 % и
  простаивал 15–25 % — load average считает и ожидающих на диске или блокировке,
  поэтому нехватка CPU подмена перегрузкой.
- Два новых лимита прогонов: `maxHostCpuBusyPercent`
  (`MYRMIDON_MAX_HOST_CPU_BUSY_PERCENT`, по умолчанию 90, default-on) —
  абсолютный процент всего процессора (не «на ядро сверх фона»: занятость уже
  измеряет реальную работу), и `maxHostCpuPsiSomeAvg10`
  (`MYRMIDON_MAX_HOST_CPU_PSI_SOME_AVG10`, выключен, пока оператор не задал).
  Потолок закрывается, когда процент занятости достигает первого порога, а
  если задан PSI-порог — когда `some avg10` достигает второго.
- Строка настроек, сохранённая до rc.3, не содержит ни одного нового ключа, а
  отсутствующий ключ означает «выключен»: такая строка продолжает решать по
  load average ровно как в 1.6.5 (устарело, но работает). Как только хоть один
  CPU-потолок задан, решает он, а load average только отчитывается. Нечитаемый
  `/proc/stat` (или `/proc/pressure/cpu` при заданном его пороге) оставляет
  гейт в состоянии `unknown`, потолок не действует, причина пишется в журнал
  один раз — как раньше для loadavg. Пути переопределяются
  `MYRMIDON_HOST_PROCSTAT_PATH` и `MYRMIDON_HOST_PRESSURE_CPU_PATH`.
- Отчёт гейта (`GET /api/myrmidon/runtime-limits`, карточка внимания) получил
  `cpuBusyPercent`, `busyThresholdPercent`, `psiSomeAvg10`,
  `psiThresholdPercent` и `source` (`cpu-busy` / `load-average`); старые поля
  сохранены без смены смысла.

## divergence

| 1.6.5-RUN-ADMISSION (rc.3) | Решение о допуске принимает доля не-idle CPU из `/proc/stat` (суммарная строка `cpu `, тики idle+iowait против суммы всех полей; процент считается по дельте между двумя чтениями, которые admission хранит у себя, окно не короче 250 мс — `CPU_BUSY_SAMPLE_WINDOW_MS`) и, когда оператор задал, PSI cpu `some avg10` из `/proc/pressure/cpu`. Пороги абсолютные проценты всего CPU: `maxHostCpuBusyPercent` (`MYRMIDON_MAX_HOST_CPU_BUSY_PERCENT`, умолчание 90, default-on по общему правилу: `0`/`off`/`false`/`no`/`none` выключает, мусор оставляет умолчание) и `maxHostCpuPsiSomeAvg10` (`MYRMIDON_MAX_HOST_CPU_PSI_SOME_AVG10`, умолчание off — закрытие по давлению только по выбору оператора). Гейт закрыт, если busy >= порога ИЛИ (PSI задан и someAvg10 >= его порога); фон как у load average не вычитается (`createHostLoadFloor` в busy-решении не участвует). Приоритет: если активны и busy/PSI, и старый `maxHostLoadPercentPerCore`, решает busy/PSI, load average только заполняет поля отчёта; строка `runLimits` без новых ключей (сохранённая до rc.3) продолжает решать по load average — обратная совместимость, порог помечен устаревшим. Нечитаемый `/proc/stat` (или pressure при заданном PSI-пороге) — состояние `unknown`, потолок не действует, причина в журнал один раз (`onHostCpuUnavailable`); базовая проба и последний процент живут в admission, `updateLimits` при выключении всех CPU-потолков сбрасывает холд (`cpuHold.reset()`). Первая проба после старта не имеет базы и потому не измеряет — гейт открыт (допуск не держится на ничем не подтверждённое число), поведение зафиксировано тестом. `HostCpuGate` дополнен полями `cpuBusyPercent`, `busyThresholdPercent`, `psiSomeAvg10`, `psiThresholdPercent`, `source` ('cpu-busy' \| 'load-average'); старые поля не удалены (UI читает их; панель — отдельная задача). Пути файлов: `MYRMIDON_HOST_PROCSTAT_PATH` (по умолчанию `/proc/stat`), `MYRMIDON_HOST_PRESSURE_CPU_PATH` (по умолчанию `/proc/pressure/cpu`) — в контейнере без lxcfs ядро не разграничивает их, это значения хоста. Машинно-зависимые потолки по умолчанию выключены в тестах (`server/src/__tests__/setup-supertest.ts`) | `server/src/myrmidon/run-admission.ts`, `packages/shared/src/myrmidon-runtime-limits.ts`, `server/src/myrmidon/runtime-limits/service.ts`, тесты `run-admission.myrmidon.test.ts`, `myrmidon-runtime-limits.test.ts`, `runtime-limits.myrmidon.test.ts` |

## settings-en

| `MYRMIDON_MAX_HOST_CPU_BUSY_PERCENT` | 1.6.5 RUN-ADMISSION | `90` | Host CPU utilisation ceiling of run admission, an ABSOLUTE percent of all cores: a new run starts only while the non-idle share of the CPU over a short recent window stays under this value. The window is the delta of two aggregate `cpu ` readings from `/proc/stat` kept by the admission (at least 250 ms apart); idle counts as the `idle + iowait` fields. Unlike the deprecated load-average ceiling this subtracts no background floor — utilisation already measures real work. When set (default), it decides ahead of `maxHostLoadPercentPerCore`: the load average then only fills the report fields. `0`/`off`/`false`/`no`/`none` switches it off; unset or garbage keeps the default. Readable paths: the file is the host's inside a plain Docker container (the kernel does not namespace `/proc/stat`); override the path with `MYRMIDON_HOST_PROCSTAT_PATH`. Unreadable counters leave the gate `unknown`, the ceiling inactive, and log the reason once. Stored in `instance_settings.general.runLimits.maxHostCpuBusyPercent` and changed on the fly without a restart (Settings → Runs & queue, `PATCH /api/myrmidon/runtime-limits`); a row saved before rc.3 lacks the key, which means off — that row keeps the old load-average rule. |
| `MYRMIDON_MAX_HOST_CPU_PSI_SOME_AVG10` | 1.6.5 RUN-ADMISSION | off | PSI cpu ceiling of run admission: the gate closes when the `some avg10` field of `/proc/pressure/cpu` — the percent of the last ten minutes in which at least one task stalled on the CPU — reaches this value. Default off: only an explicitly set value makes pressure close the gate (pressure rises on oversubscribed CPU, not on slow disk, so it guards a different failure than the busy ceiling). An unreadable pressure file while this ceiling is set makes the gate `unknown` rather than pretending zero. Override the path with `MYRMIDON_HOST_PRESSURE_CPU_PATH`. Stored in `instance_settings.general.runLimits.maxHostCpuPsiSomeAvg10`, changed on the fly like the other run limits. |

## settings-ru

| `MYRMIDON_MAX_HOST_CPU_BUSY_PERCENT` | 1.6.5 RUN-ADMISSION | `90` | Потолок загрузки CPU хоста для допуска прогонов, АБСОЛЮТНЫЙ процент всех ядер: новый ход стартует, пока доля не-idle времени CPU на коротком свежем окне держится ниже этого значения. Окно — дельта двух суммарных чтений строки `cpu ` из `/proc/stat`, которые admission хранит у себя (не короче 250 мс); idle — поля `idle + iowait`. В отличие от устаревшего потолка load average фон не вычитается: занятость уже измеряет реальную работу. Заданный (по умолчанию) решает вприоритет над `maxHostLoadPercentPerCore`: load average тогда только заполняет поля отчёта. `0`/`off`/`false`/`no`/`none` выключает; не задано или мусор — умолчание. В обычном Docker-контейнере файл хостовый (ядро не разграничивает `/proc/stat`), путь переопределяется `MYRMIDON_HOST_PROCSTAT_PATH`. Нечитаемые счётчики оставляют гейт `unknown`, потолок не действует, причина пишется один раз. Хранится в `instance_settings.general.runLimits.maxHostCpuBusyPercent`, меняется на лету без перезапуска (Settings → «Прогоны и очередь», `PATCH /api/myrmidon/runtime-limits`); строка до rc.3 ключа не имеет, что значит «выключен» — такая строка остаётся на старом правиле load average. |
| `MYRMIDON_MAX_HOST_CPU_PSI_SOME_AVG10` | 1.6.5 RUN-ADMISSION | выключен | PSI-потолок допуска: гейт закрывается, когда поле `some avg10` из `/proc/pressure/cpu` — процент последних десяти минут, в течение которых хотя бы одна задача ждала CPU — достигает этого значения. По умолчанию выключен: давление закрывает гейт только по явному выбору оператора (растёт оно от пересыщения CPU, а не от медленного диска, — это страж другого отказа, чем порог занятости). Нечитаемый файл при заданном пороге делает гейт `unknown`, а не притворяется нулём. Путь переопределяется `MYRMIDON_HOST_PRESSURE_CPU_PATH`. Хранится в `instance_settings.general.runLimits.maxHostCpuPsiSomeAvg10`, меняется на лету, как остальные лимиты прогонов. |
