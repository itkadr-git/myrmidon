## changelog-en

### 1.6.6 SETTINGS-UI B: the bot-disk lifecycle screen, the agent daily caps (OPE-6258)

- Settings → instance now edits the whole `general.botDisk` object: alongside the
  cache/runtime fields the panel gained the lifecycle section — the sweep switch,
  the draft TTL, the mirror refresh interval, the shared-cache roles and the five
  workspace-lifecycle numbers (closing grace, scratch TTL, the three partition
  percents). Before this part a PATCH of any key silently dropped those five from
  the stored object; they now validate, merge and audit like the rest, and GET
  reports the value in force per key. New read routes power the screen:
  `GET /api/myrmidon/bot-disk/physical` (relays the dockergate C5 disk answer —
  partition, per-bot quota/used, no gate configured is a 200 with "no data",
  never an error) and `GET /api/myrmidon/bot-disk/reports` (the stored C4 per-bot
  reports with the board's receive time); `POST /api/myrmidon/bots/me/disk-report`
  (contract C4, implemented in 1.6.5 but never mounted) is mounted now.
- The agent card's Run Policy section gained the fields the heartbeat engine has
  always read: Max runs per day (`runtimeConfig.heartbeat.maxDailyRuns`), Max
  daily cost in cents (`maxDailyCostCents`) and the Skip-timer-when-no-actionable-work
  switch (`skipTimerWhenNoActionableWork`). 0 or empty in the cap fields means
  "no limit" — stored as `null`, never as `0` (a stored 0 blocks every run).
- Input limits: verified covered, no new UI — the prompt input budget is the
  model's `maxInputTokens` window with the warn/crit percents already editable
  in PromptBudgetSettingsPanel (1.6.3 PROMPT-BUDGET B); no env-only input-limit
  knob exists in `server/src/myrmidon/prompt-budget`.

## changelog-ru

### 1.6.6 SETTINGS-UI B: экран жизненного цикла bot-disk, дневные лимиты агента (OPE-6258)

- В настройках экземпляра теперь редактируется весь объект `general.botDisk`:
  рядом с полями кэса/рантайма панель получила секцию жизненного цикла —
  переключатель sweep, TTL черновиков, интервал обновления зеркал, роли
  общего кэса и пять чисел жизненного цикла рабочих пространств (грант на
  закрытие, TTL scratch, три порога раздела). До этой части PATCH любого
  ключа молча терял эти пять ключей из хранимого объекта; теперь они
  проходят валидацию, слияние и аудит наравне с остальными, а GET
  показывает действующее значение по каждому ключу. Экран питают новые
  маршруты чтения: `GET /api/myrmidon/bot-disk/physical` (ретрансляция
  ответа dockergate C5 — раздел, квота/занято по ботам; отсутствие шлюза
  — 200 с «нет данных», а не ошибка) и `GET /api/myrmidon/bot-disk/reports`
  (хранёные отчёты C4 по ботам с временем приёма доской); `POST
  /api/myrmidon/bots/me/disk-report` (контракт C4, реализован в 1.6.5, но
  не был подключён) теперь подключён.
- В секции Run Policy карточки агента появились поля, которые движок
  побуждений читал всегда: максимум прогонов в сутки
  (`runtimeConfig.heartbeat.maxDailyRuns`), дневной лимит стоимости в
  центах (`maxDailyCostCents`) и переключатель пропуска побудки без
  задачи (`skipTimerWhenNoActionableWork`). 0 или пустое поле лимита
  означает «без лимита» — хранится как `null`, а не `0` (ноль заблокировал
  бы все прогоны).
- Лимиты входа: проверено покрытие, новый UI не нужен — бюджет входа
  промпта это окно `maxInputTokens` модели с порогами warn/crit, уже
  редактируемыми в PromptBudgetSettingsPanel (1.6.3 PROMPT-BUDGET B);
  env-only переключателя лимита входа в `server/src/myrmidon/prompt-budget`
  нет.

## settings-en-new

### 1.6.6 — SETTINGS-UI B: the bot-disk lifecycle screen (`general.botDisk`, stored)

Not environment variables: instance settings under `instance_settings.general.botDisk`,
edited by the "Shared package cache for bots" panel in Settings → instance
(`GET/PATCH /api/myrmidon/bot-disk`, PATCH instance-admin only, audited as
`instance.bot_disk.updated`). These five keys had no patch-schema entry before this
part and were dropped by a PATCH of another key; they now validate, merge and audit
like the rest. None has an environment variable: stored value or the default below.
The values apply live without a restart (the workspace view and the sweep re-read the
row every pass).

| Key | Function | Default | What it does | How to disable / special |
|---|---|---|---|---|
| `general.botDisk.graceClosingMinutes` | 1.6.6-SETTINGS-UI-B | `30` | Grace, in minutes, a task in `in_review`/`done` still gets before its workspace is reaped by the workspace-lifecycle view (5–1440) | `null` — back to the default |
| `general.botDisk.scratchTtlHours` | 1.6.6-SETTINGS-UI-B | `24` | Idle scratch entries older than this many hours are listed for reclamation (1–720) | `null` — back to the default |
| `general.botDisk.partitionThresholdPercent` | 1.6.6-SETTINGS-UI-B | `85` | Partition fill percent at which the disk pressure is attention-level (50–100) | `null` — back to the default |
| `general.botDisk.partitionRefuseOpenPercent` | 1.6.6-SETTINGS-UI-B | `90` | Partition fill percent at which pressure is refuse-new-work level (50–100) | `null` — back to the default |
| `general.botDisk.partitionCriticalPercent` | 1.6.6-SETTINGS-UI-B | `95` | Partition fill percent at which pressure is critical (50–100) | `null` — back to the default |

Read side of the screen: `GET /api/myrmidon/bot-disk/physical` relays the dockergate
C5 answer (`MYRMIDON_DOCKERGATE_BASE_URL` + `MYRMIDON_DOCKERGATE_TOKEN`; without
them, or with an unreachable gate, it answers 200 with `gateReached: false` and a
`note` — the screen shows "no data", never an error) and rides along the stored
lifecycle settings; `GET /api/myrmidon/bot-disk/reports` returns the stored C4
per-bot reports with `receivedAt` and the 30-minute staleness window. The bot-side
`POST /api/myrmidon/bots/me/disk-report` (contract C4, 1.6.5-BOT-DISK-H4b) is now
mounted on the board; botd sends it unchanged.

### 1.6.6 — SETTINGS-UI B: экран жизненного цикла bot-disk (`general.botDisk`, хранимые)

Не переменные окружения: настройки экземпляра в `instance_settings.general.botDisk`,
редактируются панелью «Shared package cache for bots» в Settings → instance
(`GET/PATCH /api/myrmidon/bot-disk`, PATCH только для instance-admin, аудит
`instance.bot_disk.updated`). У этих пяти ключей до этой части не было записи в
схеме патча, и PATCH любого другого ключа терял их; теперь они валидируются,
сливаются и пишутся в аудит как остальные. Переменных окружения у них нет:
хранимое значение или умолчание ниже. Значения применяются без перезапуска
(view рабочих пространств и sweep перечитывают строку каждый проход).

| Ключ | Функция | Умолчание | Что делает | Как выключить / особенности |
|---|---|---|---|---|
| `general.botDisk.graceClosingMinutes` | 1.6.6-SETTINGS-UI-B | `30` | Грант в минутах задаче в `in_review`/`done` перед изъятием рабочего пространства (5–1440) | `null` — вернуть умолчание |
| `general.botDisk.scratchTtlHours` | 1.6.6-SETTINGS-UI-B | `24` | Простаивающие scratch-записи старше этого числа часов помечаются к изъятию (1–720) | `null` — вернуть умолчание |
| `general.botDisk.partitionThresholdPercent` | 1.6.6-SETTINGS-UI-B | `85` | Заполненность раздела (процент), с которой давление уровня attention (50–100) | `null` — вернуть умолчание |
| `general.botDisk.partitionRefuseOpenPercent` | 1.6.6-SETTINGS-UI-B | `90` | Заполненность, с которой давление уровня refuse-new-work (50–100) | `null` — вернуть умолчание |
| `general.botDisk.partitionCriticalPercent` | 1.6.6-SETTINGS-UI-B | `95` | Заполненность, с которой давление критическое (50–100) | `null` — вернуть умолчание |

Читающая сторона экрана: `GET /api/myrmidon/bot-disk/physical` ретранслирует ответ
dockergate C5 (`MYRMIDON_DOCKERGATE_BASE_URL` + `MYRMIDON_DOCKERGATE_TOKEN`; без них
или при недоступном шлюзе отвечает 200 с `gateReached: false` и `note` — экран
показывает «нет данных», а не ошибку) и несёт хранимые настройки жизненного цикла;
`GET /api/myrmidon/bot-disk/reports` отдаёт хранёные отчёты C4 по ботам с
`receivedAt` и 30-минутным окном устаревания. Бот-сторона
`POST /api/myrmidon/bots/me/disk-report` (контракт C4, 1.6.5-BOT-DISK-H4b) теперь
подключена на доске; botd отправляет её без изменений.
