## changelog-en

### CONNECTORS S1: the channel connector contract, registry and hub (1.6.6)

- New `server/src/myrmidon/channel-connectors/` module. `contract.ts` fixes what
  one channel connector is — lifecycle (`start`/`stop`/`status`), links
  (`conversationKey`/`conversationUrl`/`route`/`bind`), inbound
  (`normalize`/`admit`/`intakeMedia`), outbound (`plan`/`send`), the media
  limits and settings (`keys`/`resolve`) — and it reaches the data only through
  one seam (`ChannelConnectorStore`), so no connector writes SQL of its own and
  every method takes an explicit context instead of module state.
- `registry.ts` — `registerChannelConnector(provider, factory)` and
  `getChannelConnector(provider, deps)`. A provider with no connector answers
  `null` and stays on the vendor path.
- `hub.ts` — `myrmidonChannelConnectorHub(db, deps)` routes inbound, outbound,
  lifecycle and settings by `endpoint.provider`. An unregistered provider, an
  unreadable endpoint and a connector that throws all pass through without
  decisions (fail-open, journaled).
- Default behaviour is unchanged: no connector is registered and no vendor file
  is touched, so the running board sends and receives exactly as before. The
  watchdog tests cover the contract structure, the registry and the hub
  routing.

## changelog-ru

### CONNECTORS S1: контракт, реестр и хаб коннекторов канала (1.6.6)

- Новый модуль `server/src/myrmidon/channel-connectors/`. `contract.ts` задаёт,
  чем является коннектор канала — жизненный цикл (`start`/`stop`/`status`),
  ссылки (`conversationKey`/`conversationUrl`/`route`/`bind`), входящие
  (`normalize`/`admit`/`intakeMedia`), исходящие (`plan`/`send`), лимиты медиа
  и настройки (`keys`/`resolve`) — и ходит за данными только через один слой
  (`ChannelConnectorStore`): SQL вразнос не пишет ни один коннектор, а каждый
  метод получает явный контекст вместо состояния модуля.
- `registry.ts` — `registerChannelConnector(provider, factory)` и
  `getChannelConnector(provider, deps)`. Провайдер без коннектора отвечает
  `null` и остаётся на вендорском пути.
- `hub.ts` — `myrmidonChannelConnectorHub(db, deps)` маршрутизирует входящие,
  исходящие, жизненный цикл и настройки по `endpoint.provider`.
  Незарегистрированный провайдер, нечитаемый эндпоинт и упавший коннектор идут
  сквозным проходом без решений (fail-open, с записью в журнал).
- Поведение по умолчанию не меняется: ни один коннектор не зарегистрирован и ни
  один вендорский файл не тронут, поэтому боевая доска шлёт и принимает ровно
  как раньше. Сторожевые тесты покрывают структуру контракта, реестр и
  маршрутизацию хаба.
