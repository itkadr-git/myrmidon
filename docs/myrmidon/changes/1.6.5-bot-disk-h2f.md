## changelog-en

### `myr-ws migrate`: the old object mirror becomes the class-D base (1.6.5 BOT-DISK-H2f)

- New `docker/bot-runtime/myr-ws/lib/migrate.js`: a one-shot, idempotent
  migration of `.myrmidon/git-objects/<owner>/<repo>.git` (refspec
  `+refs/heads/*:refs/heads/*`) into `.myrmidon/git-base/<owner>/<repo>.git` with
  the standard refspec. Objects are hardlinked (copied across devices), the
  mirror's heads become `refs/remotes/origin/*`, the origin URL is rebuilt
  without the mirror's credentials, and the base is built beside its final path
  and renamed only after `git fsck --connectivity-only` passes.
- The mirror is only read, never changed or deleted, so existing clones that
  borrow its objects through `objects/info/alternates` keep working. After a
  successful check it gets a `.migrated` marker; on a failed check it stays
  unmarked, no base is left behind and the command exits non-zero. A second run
  is a no-op. The ninth base is refused with exit code 4.
- The result is the contract shape `{ ok, repo, basePath, refs }`. The verb is
  not wired into `cli.js` or the entrypoint yet (`command` in `migrate.js` is
  the handler), so bot behaviour is unchanged.

## changelog-ru

### `myr-ws migrate`: старое зеркало объектов становится базой класса D (1.6.5 BOT-DISK-H2f)

- Новый `docker/bot-runtime/myr-ws/lib/migrate.js`: одноразовая идемпотентная
  миграция `.myrmidon/git-objects/<owner>/<repo>.git` (refspec
  `+refs/heads/*:refs/heads/*`) в `.myrmidon/git-base/<owner>/<repo>.git` со
  стандартным refspec. Объекты переносятся жёсткими ссылками (между устройствами
  копируются), ветки зеркала становятся `refs/remotes/origin/*`, URL origin
  собирается заново без учётных данных зеркала, а база строится рядом с
  итоговым путём и переименовывается только после успешного
  `git fsck --connectivity-only`.
- Зеркало только читается, не меняется и не удаляется, поэтому существующие
  клоны, берущие объекты через `objects/info/alternates`, продолжают работать.
  После успешной проверки зеркало получает метку `.migrated`; при неудачной
  остаётся без метки, база не остаётся на диске, команда завершается с ненулевым
  кодом. Повторный запуск ничего не делает. Девятая база отклоняется с кодом 4.
- Результат — форма контракта `{ ok, repo, basePath, refs }`. Глагол пока не
  подключён в `cli.js` и entrypoint (обработчик — `command` в `migrate.js`),
  поведение ботов не меняется.
