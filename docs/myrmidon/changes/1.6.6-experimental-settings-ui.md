## changelog-en

### Pipelines in instance experimental settings (1.6.6 SETTINGS-UI)

- Instance admins can switch Pipelines in Settings > Instance > Experimental. The existing GET/PATCH endpoint stores the flag; the sidebar and pipeline route gate read it. A cloud-managed key stays visible but locked.
- No control is added for workspace recovery or sandbox transport kill switches; these remain operator decisions described below.

## changelog-ru

### Конвейеры в экспериментальных настройках экземпляра (1.6.6 SETTINGS-UI)

- Администратор экземпляра включает «Конвейеры» в Настройки > Экземпляр > Экспериментальные. Существующие GET/PATCH сохраняют флаг; меню и защита маршрута читают его. Управляемый облаком ключ виден, но заблокирован.
- Переключатели восстановления рабочих копий и транспорта sandbox оставлены оператору по причинам ниже.

### Решения по строкам аудита 08.10

| Строка / ключ | Решение и операторский сценарий |
|---|---|
| 218 `enablePipelines` | UI: сохранённый флаг уже управляет Sidebar и PipelinesExperimentalGate; существующий PATCH требует instance admin, GET доступен участнику. Карточка использует общий контракт managedKeys и hidden settings. Не меняет production значение. |
| 239 `enableWorkspaceBranchReconcileForward` | No UI: при расхождении записанной ветки с checkout heartbeat может передвинуть ветку вперёд до запуска; отключение требует диагностики branch containment и выбора стратегии для текущих задач. Оператор фиксирует состояние workspace и меняет ключ через instance settings PATCH только в координации с исполнителями, затем проверяет следующий запуск. Переключатель «пользовательского предпочтения» скрыл бы влияние на живые рабочие копии. |
| 240 `enableWorkspaceDirtyQuarantineRepair` | No UI: при грязном execution workspace runtime карантинирует и чинит его до запуска; отключение при инциденте требует сохранения артефактов/диагностики причины грязного дерева и плана ручного восстановления. Оператор меняет ключ через instance settings PATCH после фиксации инцидента и проверяет следующий запуск; обычное нажатие в UI может оставить задачи без восстановления. |
| 242 `enableSandboxDuplexBridge` | No UI: это транспортный kill switch, а не opt-in пользователя. Оператор при сбое duplex транспорта выключает ключ через instance settings PATCH (false), чтобы новые запуски использовали file bridge; уже запущенные не переключаются. Включение требует проверки capability провайдера и пробного запуска, поэтому общий UI не должен предлагать небезопасное включение. |
| 214 `enableStreamlinedLeftNavigation` | No UI: sidebar стал стандартным; экспериментальный opt-out удалён из страницы, совместимый ключ в схеме не имеет живого потребителя. Включать обратный переключатель без альтернативной навигации нельзя. |
| 216 `enableApps` | No UI: normalizer принудительно включает Apps, compatibility key не меняет поведение; UI создавал бы ложное обещание отключения. |
| 241 `enableOwnerInstanceAdmin` | No UI: только cloud-managed доверенная auth-граница на выделенном экземпляре владельца; на self-hosted инертен. Делегировать переключение владельцу в том же UI означало бы самоназначение доступа; изменение — облачный оператор. |
| 243 `enableRunnerPreviewIngress` | No UI: устаревший compatibility key; ingress следует `enableNativeRunner`, который уже имеет карточку. Второй переключатель вводил бы в заблуждение. |
