## changelog-en

### Bot Runtime: `skill_view` resolves the qualified board-skill alias instead of failing every run skill load (OPE-12719)

- Board-managed skills materialize inside the bot profile as `paperclip-managed/<slug>--<hash>/SKILL.md` (hashed directory names from the run-scoped skills materialization), but the agent-facing skills index renders each entry as `paperclip-managed:<slug>` (category = first path segment, name = frontmatter `name:`). The hermes `skill_view` resolver matched exact directory names and bare frontmatter names only, so every agent call with the index name returned "Skill '...' not found", failed three times, and the run guard stopped the run — the failure signature `skill_view failed 3 times consecutively` seen on live runs (OPE-12719).
- `docker/bot-runtime/patches/34-skill-view-managed-name.patch` adds a zero-candidate fallback in `_collect_skill_candidates` (`tools/skills_tool.py`): when the exact-name passes found nothing, a qualified `namespace:bare` name resolves by matching a skill whose parent-of-parent directory equals the namespace and whose frontmatter `name:` equals the bare part. The fallback never runs when any candidate exists, so exact matches, project precedence, and the quarantine gate are untouched; two same-slug skills from different board keys still refuse as "Ambiguous skill name".
- Build-time regression `docker/bot-runtime/tests/skill_view_managed_name.py` pins: the qualified alias resolves to the hashed directory, the direct hashed path resolves, bare names keep resolving, an unknown namespace still fails with not found, same-slug collisions refuse as ambiguous, and `skills_list` output shape is unchanged. Wired as a Dockerfile RUN step; the full patch stack 02–34 applies cleanly in sequence on a fresh upstream checkout.
- Replaced dead references to the renamed operational skill across agent-facing instructions and docs (`paperclip` → `myrmidon`, `paperclip-create-agent` → `myrmidon-create-agent`, `paperclip-converting-plans-to-tasks` → `myrmidon-converting-plans-to-tasks`, `skills/paperclip/scripts/paperclip-upload-artifact.sh` → `skills/myrmidon/scripts/paperclip-upload-artifact.sh`) in `AGENTS.md`, onboarding bundles (`server/src/onboarding-assets/`), the accepted-plan heartbeat directive (`server/src/services/heartbeat.ts`), the agent-configuration LLMs endpoint (`server/src/routes/llms.ts`), `skills/myrmidon/references/`, developer skills under `.agents/skills/`, and `doc/AGENT-ARTIFACTS.md` / `doc/DEVELOPING.md`. The onboarding brand guard's allowed-token list shrinks to `X-Paperclip-Run-Id` plus the helper filename. Untouched: the `/api/skills/paperclip` invite route contract, `LEGACY_BUNDLED_SKILL_*` alias tables, the `PAPERCLIP_*`/`MYRMIDON_*` dual-write environment variables (`packages/shared/src/env-alias.ts`), and the artifact work-product wire value `provider: "paperclip"` — all are live contracts, not skill names.
- Requires a bot-runtime image rebuild; running containers keep the old resolver until the next deploy. Post-deploy proof: zero runs with `skill_view failed` caused by "Skill 'paperclip-managed:...' not found" (operator acceptance after the release).

## changelog-ru

### Bot Runtime: `skill_view` разрешает квалифицированный алиас навыка с доски вместо падения загрузки каждого скилла в прогоне (OPE-12719)

- Досочные навыки материализуются в профиле бота как `paperclip-managed/<slug>--<hash>/SKILL.md` (хэшированные имена каталогов из run-scoped материализации), но агентский индекс навыков показывает каждую запись как `paperclip-managed:<slug>` (категория = первый сегмент пути, имя = frontmatter `name:`). Резолвер `skill_view` в hermes матчит только точные имена каталогов и bare-имя из frontmatter, поэтому каждый вызов агента с именем из индекса возвращал "Skill '...' not found", падал трижды, и run guard останавливал прогон — сигнатура отказа `skill_view failed 3 times consecutively` на боевых прогонах (OPE-12719).
- `docker/bot-runtime/patches/34-skill-view-managed-name.patch` добавляет fallback при нуле кандидатов в `_collect_skill_candidates` (`tools/skills_tool.py`): если точные проходы ничего не нашли, квалифицированное имя `namespace:bare` резолвится по совпадению «каталог-дедушка == namespace» и «frontmatter `name:` == bare-часть». Fallback не запускается, когда есть хоть один кандидат, поэтому точные совпадения, приоритет проекта и карантин не тронуты; два скилла с одинаковым slug из разных досочных ключей по-прежнему отказывают как "Ambiguous skill name".
- Регрессия времени сборки `docker/bot-runtime/tests/skill_view_managed_name.py` фиксирует: алиас резолвится в хэшированный каталог, прямой хэшированный путь резолвится, bare-имена продолжают резолвиться, неизвестный namespace отвечает not found, коллизия slug отказывает как ambiguous, форма вывода `skills_list` не меняется. Подключено RUN-шагом в Dockerfile; полный стек патчей 02–34 применяется последовательно без конфликтов на свежем upstream-чекайте.
- Заменены мёртвые ссылки на переименованный операционный навык в агентских инструкциях и доках (`paperclip` → `myrmidon`, `paperclip-create-agent` → `myrmidon-create-agent`, `paperclip-converting-plans-to-tasks` → `myrmidon-converting-plans-to-tasks`, `skills/paperclip/scripts/paperclip-upload-artifact.sh` → `skills/myrmidon/scripts/paperclip-upload-artifact.sh`): `AGENTS.md`, онбординг-бандлы (`server/src/onboarding-assets/`), директива принятого плана в heartbeat (`server/src/services/heartbeat.ts`), endpoint конфигурации агента (`server/src/routes/llms.ts`), `skills/myrmidon/references/`, навыки разработчика в `.agents/skills/`, `doc/AGENT-ARTIFACTS.md` / `doc/DEVELOPING.md`. Список разрешённых токенов guard-теста онбординг-бренда сокращён до `X-Paperclip-Run-Id` и имени файла хелпера. Не тронуты: контракт инвайт-роутов `/api/skills/paperclip`, таблицы алиасов `LEGACY_BUNDLED_SKILL_*`, dual-write переменные окружения `PAPERCLIP_*`/`MYRMIDON_*` (`packages/shared/src/env-alias.ts`) и wire-значение `provider: "paperclip"` у artifact work product — всё это живые контракты, а не имена навыков.
- Требуется пересборка образа bot-runtime; запущенные контейнеры сохраняют старый резолвер до следующего выката. Приёмка после выката: ноль прогонов с отказом `skill_view failed` по причине "Skill 'paperclip-managed:...' not found" (проверяет оператор после релиза).
