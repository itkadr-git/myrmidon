## changelog-en

### The settings panel shows the signal the admission decides on (1.6.5 RUN-ADMISSION, rc.3, part B)

- The «Runs & queue» settings (both panels: Settings → Runtime limits and
  ui2 → Settings → Runs & queue) now lead the live host line with the signal
  the gate decides on: the CPU busy percent (the non-idle share of all cores
  from `/proc/stat`) with its threshold and verdict, and — when the operator
  set the PSI ceiling — the PSI cpu `some avg10` pressure next to it. The
  load average follows as an explicitly auxiliary reading («Auxiliary: load
  average …»). A gate that still decides on load average (a settings row
  saved before rc.3) keeps the old load-average line.
- Two new editable limits: `maxHostCpuBusyPercent` (default 90, absolute
  percent of all cores) and `maxHostCpuPsiSomeAvg10` (off unless set); the
  legacy `maxHostLoadPercentPerCore` stays editable and is marked deprecated
  in the label and hint. The host state line moved from the legacy field to
  the busy-ceiling field, next to the ceiling it describes. An unmeasured
  first sample window and an unreadable counter render honestly («busy % not
  measured yet», «the host load cannot be read, so the ceiling is inactive:
  …») instead of invented numbers.
- Both CPU keys are typed members of `RunLimits`/`RunLimitsPatch` since part
  A, but are not `RunLimitKey`s yet (their source map arrives with the shared
  key promotion): the panels carry them as string literals and fall back to
  the «Default» source label for them.

## changelog-ru

### Панель настроек показывает тот сигнал, по которому решается допуск (1.6.5 RUN-ADMISSION, rc.3, часть B)

- Настройки «Прогоны и очередь» (обе панели: Settings → Runtime limits и
  ui2 → Настройки → Прогоны и очередь) ведут живую строку о хосте от сигнала,
  по которому гейт решает: занятость процессора (доля не-idle времени всех
  ядер из `/proc/stat`) с её порогом и вердиктом и — когда оператор задал
  PSI-потолок — давление PSI cpu `some avg10` рядом. Load average уходит в
  конец как явно вспомогательный показатель («Дополнительно: load average
  …»). Гейт, который ещё решает по load average (строка настроек, сохранённая
  до rc.3), показывает прежнюю строку.
- Два новых редактируемых лимита: `maxHostCpuBusyPercent` (умолчание 90,
  абсолютный процент всех ядер) и `maxHostCpuPsiSomeAvg10` (выключен, пока
  не задан); старый `maxHostLoadPercentPerCore` остаётся редактируемым и
  помечен устаревшим в метке и подсказке. Строка состояния хоста переехала от
  старого поля к полю потолка занятости — рядом с потолком, который она
  описывает. Неизмеренное первое окно и нечитаемый счётчик показываются
  честно («занятость ещё не измерена», «нагрузка хоста не читается, потолок
  не действует: …») вместо придуманных чисел.

## settings-en-append

<!-- section: Track 2 — wake and run core -->
The «Runs & queue» settings panels (Settings → Runtime limits and ui2 →
Settings → Runs & queue) show the signal the admission decides on: the CPU
busy percent (the non-idle share of all cores from `/proc/stat`) with the
`maxHostCpuBusyPercent` threshold (default 90) and the verdict leads the live
host line; when the operator set `maxHostCpuPsiSomeAvg10` (off unless set),
the PSI cpu `some avg10` pressure joins the line. The load average follows as
an explicitly auxiliary reading. The legacy `maxHostLoadPercentPerCore`
ceiling stays editable, marked deprecated, and decides only for a settings row
saved before rc.3. Both new ceilings are editable in both panels; until the
keys are promoted to `RunLimitKey`s, their source shows as «Default».

## settings-ru-append

<!-- section: Трек 2 — ядро побудок и прогонов -->
Панели настроек «Прогоны и очередь» (Settings → Runtime limits и ui2 →
Настройки → Прогоны и очередь) показывают сигнал, по которому решается
допуск: живую строку ведёт занятость CPU (доля не-idle времени всех ядер из
`/proc/stat`) с порогом `maxHostCpuBusyPercent` (умолчание 90) и вердиктом;
при заданном `maxHostCpuPsiSomeAvg10` (по умолчанию выключен) рядом — давление
PSI cpu `some avg10`. Load average уходит в конец как явно вспомогательный
показатель. Старый потолок `maxHostLoadPercentPerCore` остаётся
редактируемым, помечен устаревшим и решает только для строки настроек,
сохранённой до rc.3. Оба новых потолка редактируются в обеих панелях; пока
ключи не стали `RunLimitKey`, источник показывается как «Умолчание».
