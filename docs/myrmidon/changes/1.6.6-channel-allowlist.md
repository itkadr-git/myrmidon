## changelog-en

### Channel allowlist — who may write to the bots (CA-A, OPE-4949)

- New general-channel-layer mechanism, not Telegram code: the board keeps a
  list of admitted channel writers. Admission is by the channel identity
  (numeric Telegram id, matched case-insensitively by @username too) — a
  board account is NOT required (owner clarification 06.10); when a person
  does have one, the row may store the link. One row covers all bots of the company
  or one specific bot endpoint; revoked rows never admit and stay for audit.
- New instance channel setting `channelAccessMode`
  (`MYRMIDON_CHANNEL_ACCESS_MODE`, default `sponsor`): `sponsor` keeps the
  vendor guest-sponsorship path byte-for-byte, `allowlist` makes the board
  list the sole decider for unlinked writers (linked members are untouched).
  Read live per message — a toggle applies without a restart.
- A writer whom neither mechanism admits is not served: their message does
  not execute, they get one refusal line without details, and the owner (or
  the admin tier, then operator — Part C adds a designated admin) receives a
  board access-request card with the channel identity needed to admit. One
  card and one notice per sender per UTC day; every refusal is journalled
  (`channel_allowlist.access_requested`).
- Board screen «Who may write to the bots» (Settings → Channel allowlist,
  `/company/settings/channel-allowlist`, EN+RU): mode select, admitted list
  with scope and revoke/restore, add-a-person form. API
  `/api/myrmidon/channel-allowlist` (GET/POST/PATCH, board-only, audited).
- Rights on the writer, the approve/deny buttons on the card, and the
  per-message audit marking arrive in the follow-up parts of OPE-4949 (B–D).

## changelog-ru

### Список допущенных каналов — кто может писать ботам (CA-A, OPE-4949)

- Новый механизм общего слоя каналов, не код Telegram: на доске ведётся
  список допущенных пишущих. Допуск — по идентичности канала (числовой
 Telegram id, дополнительно совпадение по @username без учёта регистра);
 учётка доски НЕ требуется (уточнение владельца 06.10); если она у человека
 есть, строка может хранить привязку. Одна строка покрывает все боты
  компании или один конкретный бот-эндпоинт; отозанные строки не допускают и
  остаются для аудита.
- Новая настройка каналов `channelAccessMode`
  (`MYRMIDON_CHANNEL_ACCESS_MODE`, по умолчанию `sponsor`): `sponsor` —
  вендорский путь поручительства гостей байт в байт; `allowlist` — список на
  доске единственный решающий для непривязанных (привязанные участники идут
  прежним путём). Читается на каждое сообщение — переключение без
  перезапуска.
- Пишущего, кого не допускает ни один механизм, не обслуживают: сообщение не
  выполняется, ему отвечают одной строкой отказа без подробностей, а
  владельцу (или администратору, затем оператору — назначенного админа
  добавит часть C) уходит карточка «запрос доступа» с идентичностью
  канала, нужной для допуска. Одна карточка и одно уведомление на
  отправителя в сутки UTC; каждый отказ в журнале
  (`channel_allowlist.access_requested`).
- Экран доски «Кто может писать ботам» (Settings → Channel allowlist,
  `/company/settings/channel-allowlist`, EN+RU): выбор режима, список
  допущенных с областью и отзывом/возвратом, форма добавления. API
  `/api/myrmidon/channel-allowlist` (GET/POST/PATCH, только доска, с
  аудитом).
- Права пишущего, кнопки одобрить/отказать на карточке и пометка каждого
  сообщения в аудите приходят в частях B–D задачи OPE-4949.

## settings-en

| `MYRMIDON_CHANNEL_ACCESS_MODE` | CA-A | `sponsor` | Who may write to the bots in the general channel layer. `allowlist`: an unlinked sender is served only when the board's channel allowlist admits them by channel identity (a board account is optional); everyone else gets one refusal line and the owner/admin gets an access-request card (once per sender per UTC day). Linked board members keep the vendor path either way | `sponsor` — the vendor guest-sponsorship path unchanged, byte for byte; an unreadable value falls back to `sponsor`, never to `allowlist`. Also settable live per message without a restart from the stored channel settings (`channelSettings.channel.channelAccessMode`, the screen or `PATCH /api/myrmidon/channel-settings`); the environment value pins over the stored one |
