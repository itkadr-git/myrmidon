## changelog-en

### The real git leaves PATH in the bot image (1.6.5 BOT-DISK-H, part H1c)

- In the development image the Debian `git` moves to
  `/opt/paperclip/libexec/git` (a `dpkg-divert`, so a package upgrade does not
  bring it back) and `/usr/bin/git` becomes a symlink to the git wrapper, like
  `/usr/local/bin/git`: a bare `git` in any terminal PATH answers through the
  wrapper. The wrapper's default real git is the libexec path
  (`MYRMIDON_GIT_REAL` still overrides it).
- `myr-ws` (`/opt/paperclip/bin` and `/usr/local/bin/myr-ws`) and `botd` are
  installed from the new build-context directory `docker/bot-runtime/bot-disk/`
  when present; the image still builds without them.
- The entrypoint starts `botd` instead of `bot-clone-hygiene`; an image without
  `botd` keeps the old reporter.

## changelog-ru

### Настоящий git уходит из PATH в образе ботов (1.6.5 BOT-DISK-H, часть H1c)

- В образе разработки Debian-овский `git` переезжает в
  `/opt/paperclip/libexec/git` (через `dpkg-divert`, обновление пакета его не
  вернёт), а `/usr/bin/git` становится симлинком на обёртку git — как и
  `/usr/local/bin/git`: голый `git` при любом PATH терминала отвечает через
  обёртку. Настоящий git по умолчанию у обёртки — путь в libexec
  (`MYRMIDON_GIT_REAL` по-прежнему его переопределяет).
- `myr-ws` (`/opt/paperclip/bin` и `/usr/local/bin/myr-ws`) и `botd`
  ставятся из нового каталога контекста сборки `docker/bot-runtime/bot-disk/`,
  если файлы там есть; без них образ всё равно собирается.
- Entrypoint запускает `botd` вместо `bot-clone-hygiene`; образ без `botd`
  оставляет прежний отчёт.
