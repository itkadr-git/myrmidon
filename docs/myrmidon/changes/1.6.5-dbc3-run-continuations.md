## changelog-en

### the execution continuation leaves `context_snapshot` (DB-CARE DBC-3)

- New table `heartbeat_run_continuations` (migration `0330_heartbeat_run_continuations`,
  one row per run, unique on `run_id`). The continuation envelope of a run is written
  there by `heartbeat.ts` instead of `heartbeat_runs.context_snapshot`; the row also
  carries `envelope_chars` for the DB audit and `wake_links` (run id, origin comment
  ids, source run id, interaction id) that reference the wake payload instead of
  copying it a second time. `heartbeat_runs.context_snapshot` stops carrying the task
  history, so the average snapshot size drops from the 31 KB the 08.10 audit measured.
- Readers (`execution-continuation.ts`, `run-continuation-snapshot.ts`,
  `native-completion-feedback.ts`, the interaction origin lookups) read the envelope
  from the new table and fall back to the legacy `context_snapshot` copy, so runs
  written before this change resume unchanged and a failed continuation write degrades
  to the old behaviour instead of stopping the run.
- `limitExecutionContinuationHistory` now also caps the message list by characters
  (`MYRMIDON_CONTINUATION_MESSAGE_CHARS`, default 32 000, 0 disables it). Bodies of the
  oldest messages that carry no direction become references (`bodyOmitted`): the id and
  freshness stay, the text lives in the task thread. Direction always survives — the
  original request, the latest request and the triggering comments keep their bodies,
  and a pinned body that alone exceeds the per-body budget
  (`MYRMIDON_CONTINUATION_MESSAGE_BODY_CHARS`, default 8 000) is shortened with an
  explicit marker instead of being dropped. The resume delta treats a reference as
  already delivered, and the cut is deterministic, so a capped message never comes back
  as new.
- `completedActions` of the envelope no longer collects tool receipts from every run the
  task ever had: only the previous context run (or the handoff source run) contributes,
  which is what made the envelope grow with the age of the task.

## changelog-ru

### executionContinuation уходит из `context_snapshot` (DB-CARE DBC-3)

- Новая таблица `heartbeat_run_continuations` (миграция
  `0330_heartbeat_run_continuations`, одна строка на прогон, уникальность по
  `run_id`). Конверт продолжения прогона пишет туда `heartbeat.ts`, а не
  `heartbeat_runs.context_snapshot`; в строке лежат `envelope_chars` для аудита БД и
  `wake_links` (идентификаторы прогона, исходных комментариев, прогона-источника,
  взаимодействия) — ссылки на wake-payload вместо второй его копии.
  `heartbeat_runs.context_snapshot` перестаёт носить историю задачи, поэтому средний
  размер снимка падает с 31 КБ, которые показал аудит 08.10.
- Читатели (`execution-continuation.ts`, `run-continuation-snapshot.ts`,
  `native-completion-feedback.ts`, поиск исходных комментариев взаимодействий) берут
  конверт из новой таблицы и откатываются на старую копию в `context_snapshot`:
  прогоны, записанные до этого изменения, возобновляются как раньше, а неудачная
  запись конверта деградирует к прежнему поведению вместо остановки прогона.
- `limitExecutionContinuationHistory` теперь ограничивает список сообщений ещё и по
  символам (`MYRMIDON_CONTINUATION_MESSAGE_CHARS`, по умолчанию 32 000, 0 отключает).
  Тела самых старых сообщений, не несущих указаний, становятся ссылками
  (`bodyOmitted`): идентификатор и свежесть остаются, текст живёт в ветке задачи.
  Указания выживают всегда — исходная заявка, последняя заявка и комментарии-поводы
  сохраняют тела, а тело закреплённого сообщения, которое одно превышает потолок на
  сообщение (`MYRMIDON_CONTINUATION_MESSAGE_BODY_CHARS`, по умолчанию 8 000),
  укорачивается с явной пометкой вместо удаления. Дельта возобновления считает ссылку
  уже доставленной, а обрезка детерминирована — сокращённое сообщение не вернётся как
  новое.
- `completedActions` конверта больше не собирает отчёты инструментов со всех прогонов
  задачи: вклад даёт только предыдущий контекстный прогон (или прогон-источник при
  передаче задачи), а именно их накопление и раздувало конверт с возрастом задачи.
