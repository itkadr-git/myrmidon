## changelog-en

### Host GC frees omp runner task copies of tasks under review when idle, clean and pushed (1.6.9)

- An engineer's task often waits in `in_review`, `blocked` or `backlog` for hours, and the closed-task rule never matches it. An omp runner keeps a full copy of 0.7-0.9 GB of every such task under `<runner>/workspace/`. On 16.11 one engineer held 24 copies (15 GB), new ones appeared every 5-10 minutes, and the bots volume lost about 7 GB in an hour. The host GC now gives the folder of a task in `in_review`, `blocked` or `backlog` the verdict it gives a closed task: removal when every git repository inside is clean, pushed (checked against the server) and free of stashes and alternates, otherwise archive first and removal after the archive verifies. The folder is judged only when all of this holds: no run is live on the task (`executionRunId`, `checkoutRunId`); nothing outside `.git` changed for 30 minutes (the folder, its top-level entries, those of `repo/`, and the HEAD and reflog of the git directory); the board answers. It does not wait for the clone TTL. `todo` and `in_progress` are never touched. Just before the removal the board is asked again and the folder must still be idle (`runner-task-folder-skipped` with the reason otherwise).
- A worktree folder whose `.git` file names a path inside the runner container (`gitdir: /workspace/...`) is now mapped to the runner's host `workspace` directory. Its state is checked for real (clean, pushed, stash, alternates) with the mapped git directory, for closed tasks and tasks under review alike. A worktree whose run copy is already gone has no readable git state and goes to the archive first, as before. The journal records `idleOpenStatus` for removals and archives made under the new rule.

## changelog-ru

### Уборка хоста освобождает копии задач исполнителя omp на ревью, когда они простаивают, чисты и запушены (1.6.9)

- Задача инженера часто часами стоит в `in_review`, `blocked` или `backlog`, и правило закрытых задач её не берёт. Исполнитель omp хранит в `<runner>/workspace/` полную копию (0,7-0,9 ГБ) каждой такой задачи. 16.11 один инженер держал 24 копии (15 ГБ), новые появлялись раз в 5-10 минут, том ботов терял около 7 ГБ в час. Теперь уборка хоста выносит для папки задачи в `in_review`, `blocked` или `backlog` тот же вердикт, что для закрытой: удаление, если каждый git-репозиторий внутри чист, запушен (проверка по серверу) и без стешей и alternates, иначе сначала архив, удаление после проверки архива. Папку судят, только если выполнено всё: на задаче нет живого прогона (`executionRunId`, `checkoutRunId`); вне `.git` ничего не менялось 30 минут (папка, её верхний уровень, верхний уровень `repo/`, HEAD и reflog git-каталога); доска отвечает. Срока жизни клона уборка не ждёт. `todo` и `in_progress` не трогаются никогда. Прямо перед удалением доску спрашивают ещё раз, папка должна по-прежнему простаивать (иначе запись `runner-task-folder-skipped` с причиной).
- Папка-worktree, чей файл `.git` указывает на путь внутри контейнера исполнителя (`gitdir: /workspace/...`), теперь сопоставляется с хостовым каталогом `workspace` исполнителя. Состояние проверяется по-настоящему (чистота, запушенность, стеш, alternates) по сопоставленному git-каталогу, для закрытых задач и задач на ревью. Worktree, чья копия прогона уже удалена, не имеет читаемого git-состояния и, как раньше, сначала уходит в архив. В журнале удаления и архивы по новому правилу несут поле `idleOpenStatus`.
