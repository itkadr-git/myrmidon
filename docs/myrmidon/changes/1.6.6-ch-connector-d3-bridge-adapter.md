## changelog-en

### CONNECTORS D3: the last third of the Telegram bridge touch points goes through the connector adapter (1.6.6)

- The bridge seam `server/src/myrmidon/channel-connectors/bridge/` now also
  serves the last third of the call map (OPE-6629, points 53-77): the Telegram
  helper modules the core reaches (upload projection, ephemeral callbacks, media
  intake, rich intake), the DM command menus and menu locale, and the notify
  track (jobs entry, proactivity sweep, the two instance-settings preservation
  keys). The core no longer imports any of these bridge modules directly.
- Every legacy module that lost its last core importer now carries a
  deprecation note: with the bridge flag off the module is still the code that
  runs (fail-open), but new importers must go through the seam, and deleting
  the direct path is the follow-up step after the channel connector ships. The
  code itself is not removed in this change.
- Two contract values stay bound to the legacy module even when a connector
  serves the theme, because stored data carries them: the private-action notice
  text `TELEGRAM_PRIVATE_ACTION_UNAVAILABLE` (already-written rows compare
  against it) and the canonical command list `TELEGRAM_DM_COMMANDS` (its copy
  hashes into the menu-registration version).
- Point 70 of the map — the `packages/shared` re-export of the telegramNotify
  settings contract — intentionally stays out of the seam: it is a data
  contract (types and validators the board UI reads too), not a bridge call a
  connector can serve.
- Nothing changes on the running board: no connector is registered yet, the
  switch is off, and the flag-off behavior is byte for byte the previous code.

## changelog-ru

### CONNECTORS D3: последняя треть точек касания моста Telegram-канала идёт через адаптер коннектора (1.6.6)

- Шов `server/src/myrmidon/channel-connectors/bridge/` закрывает теперь и
  последнюю треть карты вызовов (OPE-6629, точки 53-77): telegram-хелперы ядра
  (проекция вложений для отправки, эфемерные колбэки, медиам-приём, rich-приём),
  меню команд лички и локаль меню, и трек уведомлений (вход jobs, proactivity
  sweep, оба ключа сохранности instance-settings). Ядро больше не импортирует
  эти модули моста напрямую.
- Каждый легаси-модуль, у которого пропал последний импортер из ядра, получил
  deprecation-заметку: при выключенном флаге модуль по-прежнему исполняется
  (fail-open), но новые импортеры обязаны идти через шов, а удаление прямого
  пути — следующий шаг после поставки коннектора канала. Код в этой change не
  удаляется.
- Два контрактных значения остаются привязаны к легаси-модулю даже когда коннектор
  отдаёт тему, потому что их носит хранимые данные: текст уведомления
  `TELEGRAM_PRIVATE_ACTION_UNAVAILABLE` (с ним сравнивают уже записанные строки)
  и канонический список команд `TELEGRAM_DM_COMMANDS` (его копирай входит в хэш
  версии регистрации меню).
- Точка 70 карты — re-export контракта настроек telegramNotify из
  `packages/shared` — намеренно остаётся вне шва: это контракт данных (типы и
  валидаторы, которые читает и борд-UI), а не вызов моста, который коннектор
  мог бы отдавать.
- На боевой доске не меняется ничего: коннектор не зарегистрирован, выключатель
  выключен, поведение при выключенном флаге — байт-в-байт прежний код.

## settings-en-new

### 1.6.6 — CH-CONNECTOR D: bridge themes through the channel connector (batches 1+3)

The switch itself is unchanged from batch 1
(`MYRMIDON_CHANNEL_CONNECTOR_BRIDGE`, see
1.6.6-ch-connector-d1-bridge-adapter.md). Batch 3 extends the set of themes the
switch can move to a registered channel connector: the Telegram helper modules
(upload projection, ephemeral callbacks, media intake, rich intake), the DM
command menu and menu locale, and the notify track (jobs entry, proactivity
sweep, settings-preservation keys). With the switch off every theme is the
bridge module itself; with it on a connector serves the themes it declares and
the rest stays with the bridge module (fail-open). Points 53-77 of the OPE-6629
map join points 1-49 and 55-63 of batch 1; the shared data contract of point 70
stays out of the seam by design.

| Variable | Function | Default | What it does | How to disable / special |
|---|---|---|---|---|
| `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE` | CH-CONNECTOR D | unset (off) | Same switch as batch 1; batch 3 adds the themes listed above to what a registered connector may serve. Read per call, no restart needed | Unset or any value other than `1`/`true`/`yes`/`on`: every theme is the bridge module itself and the board behaves byte for byte as before |

## settings-ru-new

### 1.6.6 — CH-CONNECTOR D: темы моста через коннектор канала (партии 1+3)

Сам выключатель не меняется с партии 1 (`MYRMIDON_CHANNEL_CONNECTOR_BRIDGE`,
см. 1.6.6-ch-connector-d1-bridge-adapter.md). Партия 3 расширяет набор тем,
которые выключатель может передать зарегистрированному коннектору: telegram-
хелперы (проекция вложений для отправки, эфемерные колбэки, медиам-приём,
rich-приём), меню команд лички и локаль меню, трек уведомлений (вход jobs,
proactivity sweep, ключи сохранности настроек). Выключатель выключен — каждая
тема это сам модуль моста; включён — темы, объявленные коннектором, отдаёт
коннектор, остальное остаётся у модуля моста (fail-open). Точки 53-77 карты
OPE-6629 добавляются к точкам 1-49 и 55-63 партии 1; контракт данных точки 70
остаётся вне шва намеренно.

| Переменная | Функция | По умолчанию | Что делает | Как выключить / особое |
|---|---|---|---|---|
| `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE` | CH-CONNECTOR D | не задан (выключен) | Тот же выключатель, что в партии 1; партия 3 добавляет в то, что может отдаваться коннектору, темы выше. Читается на каждом вызове, перезапуск не нужен | Не задан или любое значение кроме `1`/`true`/`yes`/`on`: каждая тема — сам модуль моста, доска ведёт себя байт-в-байт как раньше |
