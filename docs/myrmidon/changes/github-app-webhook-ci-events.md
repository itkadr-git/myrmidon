## changelog-en

### CI and pull-request events from our own GitHub App reach the board (GITHUB-APP-WEBHOOK)

- New public receiver `POST /api/myrmidon/github-app/webhook`. The call is authenticated by GitHub's `X-Hub-Signature-256` (HMAC-SHA256 over the exact body, constant-time compare) against the webhook secret of the App entry named by `X-GitHub-Hook-Installation-Target-ID`; unknown App id answers `204`, a bad or missing signature `401`, an accepted delivery `202` with `{ companies, processed, duplicate, ignored }`.
- The delivery goes through the same event service as the connector events (`processForCompany` with no bindings): check_run / check_suite / workflow_run update the CI state of the pull request and return the task to its executor on a failed head, pull_request keeps the merge and conflict returns. Companies are picked by App id and `allowedRepos`; a delivery id is processed once per company; deliveries without a repository are ignored.
- New App-entry field `webhookSecretId` (company secret, server-owned) and `POST /api/myrmidon/companies/:companyId/github-shared-identity/apps/:entryId/webhook-sync` with `{ webhookUrl }`: creates the secret once, sets the App's webhook with the App JWT and answers the `{ url, contentType }` GitHub reports. A board save that omits `webhookSecretId` keeps the stored one.

## changelog-ru

### События CI и PR от собственного GitHub App доходят до доски (GITHUB-APP-WEBHOOK)

- Новый публичный приёмник `POST /api/myrmidon/github-app/webhook`. Вызов проверяется по заголовку GitHub `X-Hub-Signature-256` (HMAC-SHA256 по точному телу, сравнение за постоянное время) секретом вебхука той записи приложения, которую называет `X-GitHub-Hook-Installation-Target-ID`; неизвестный id приложения отвечает `204`, неверная или отсутствующая подпись — `401`, принятая доставка — `202` с `{ companies, processed, duplicate, ignored }`.
- Доставка идёт через тот же сервис событий, что и события коннектора (`processForCompany` без привязок): check_run / check_suite / workflow_run обновляют состояние CI у PR и возвращают задачу исполнителю при падении головного коммита, pull_request сохраняет возвраты по слиянию и конфликту. Компании выбираются по id приложения и `allowedRepos`; id доставки обрабатывается один раз на компанию; доставки без репозитория игнорируются.
- Новое поле записи приложения `webhookSecretId` (секрет компании, принадлежит серверу) и `POST /api/myrmidon/companies/:companyId/github-shared-identity/apps/:entryId/webhook-sync` с `{ webhookUrl }`: один раз создаёт секрет, задаёт вебхук приложения его JWT и отвечает `{ url, contentType }`, как их сообщает GitHub. Сохранение на доске без `webhookSecretId` оставляет прежний.
