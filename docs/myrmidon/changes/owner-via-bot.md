## changelog-en

### Owner decisions arrive as a message from the bot, not as a card (1.6.5-OWNER-VIA-BOT)

- New owner-delivery mode `via_bot`, now the default (`instance_settings.general[ownerDelivery]`, `GET/PATCH /api/myrmidon/owner-delivery`). In this mode the owner's Telegram DM receives NO card with buttons. `owner_decisions_only` and `all` keep their previous behaviour for instances that store them.
- When an agent creates a human-only question or confirmation for the task owner, the author is woken on that task with the open decision in its prompt and must explain it to the owner in one plain message: what to decide, why, each option with its consequence, a recommendation.
- New agent tool `myrmidonMessageOwner` (`POST /api/myrmidon/owner-message`) writes that message into the owner's standing Telegram DM conversation from a run on any task. Only the author of an open owner decision may use it; one message per question; several open questions must be covered by one summary message (`409 summary_required`).
- The owner's text answer reaches the agent as a normal DM turn marked as a reply to the open interaction. The new tool `myrmidonResolveInteractionByOwnerReply` (`POST /api/myrmidon/owner-message/resolve`) closes the interaction as the OWNER (the ordinary accept / reject / respond route runs with the owner as the acting user) and only when the owner's own comment in that chat, written after the bound message and received from Telegram, is named. Tool-action, secret and connection confirmations are not closable this way.
- The Paperclip skill documents both tools (`references/owner-dialogue.md`); the owner-delivery settings screen offers the new mode.

## changelog-ru

### Решения владельца приходят сообщением от бота, а не карточкой (1.6.5-OWNER-VIA-BOT)

- Новый режим owner-доставки `via_bot`, теперь по умолчанию (`instance_settings.general[ownerDelivery]`, `GET/PATCH /api/myrmidon/owner-delivery`). В нём в ЛС владельца в Telegram НЕ приходит карточка с кнопками. `owner_decisions_only` и `all` ведут себя как раньше у экземпляров, где они сохранены.
- Когда агент создаёт human-only вопрос или подтверждение для владельца задачи, автор будится на этой задаче с открытым решением в промпте и обязан одним обычным сообщением объяснить его владельцу: что решить, зачем, каждый вариант с последствием, рекомендация.
- Новый инструмент агента `myrmidonMessageOwner` (`POST /api/myrmidon/owner-message`) пишет это сообщение в постоянный диалог владельца в Telegram из прогона по любой задаче. Пользоваться им может только автор открытого решения владельца; одно сообщение на вопрос; несколько открытых вопросов обязаны войти в одну сводку (`409 summary_required`).
- Текстовый ответ владельца доходит до агента обычным ходом ЛС с пометкой «ответ на открытое interaction». Новый инструмент `myrmidonResolveInteractionByOwnerReply` (`POST /api/myrmidon/owner-message/resolve`) закрывает interaction от имени ВЛАДЕЛЬЦА (обычный маршрут accept / reject / respond выполняется с владельцем как действующим пользователем) и только если назван собственный комментарий владельца в этом чате, написанный после привязанного сообщения и пришедший из Telegram. Подтверждения инструмента, секрета и подключения так не закрываются.
- Навык Paperclip описывает оба инструмента (`references/owner-dialogue.md`); экран настроек owner-доставки предлагает новый режим.
