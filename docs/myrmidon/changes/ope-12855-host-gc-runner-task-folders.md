## changelog-en

### Host GC removes task folders of closed runner issues (OPE-12855)

- An omp runner keeps one task folder per board issue it ever checked out: the clone folder `<runner>/workspace/OPE-<n>/` and worktree folders (`OPE-<n>-wt`, `wt-ope<n>`) whose `.git` file points into a run directory that is deleted when the run ends. Nothing removed them; on 11.11 four runners held 41.5 GB of folders of long-closed issues and the bots volume stood at 91%. The host GC now removes a folder when the issue is `done` or `cancelled`, the folder is older than the clone TTL (24 h) and every git repository inside is clean, fully pushed, stash- and alternates-free. Dirty or unpushed folders — and folders whose git state cannot be proven from the host, such as a worktree with a dead gitdir — are archived to `<runner root>/.gc-archive/` first and removed only after the archive verifies. Folders of issues in any other status are kept, and an unreachable board keeps the folder (fail-closed). The pass shares the gate of the OPE-12722 pass: it runs only when a runner root is configured (`--runner-root` / `HOST_GC_RUNNER_ROOTS`).

- The runner agents' npm/npx caches (`<runner>/home/.npm/{_cacache,_npx}`) are pruned by the same host GC pass under the same runner-root gate: age is the newest mtime in the cache tree (a cache an npm/npx call is still writing stays fresh), default TTL 4 h (`--npm-cache-ttl` / `MYRMIDON_HOST_GC_NPM_CACHE_TTL_HOURS`, refused below 1 h). Symlinked cache directories are skipped and every removal is guarded against the runner root; removals are journaled `runner-npm-cache-*` and counted as `runnerNpmCachesRemoved`.

## changelog-ru

### Уборка хоста удаляет папки задач закрытых задач исполнителей (OPE-12855)

- Исполнитель omp хранит папку задачи по каждой задаче доски, которую когда-либо брал в работу: папку клона `<runner>/workspace/OPE-<n>/` и папки-worktree (`OPE-<n>-wt`, `wt-ope<n>`), чей файл `.git` указывает на каталог прогона, удаляемый после его завершения. Ничто их не убирало: 11.11 четыре исполнителя держали 41,5 ГБ папок давно закрытых задач, и том ботов стоял на 91%. Теперь уборка хоста удаляет папку, когда задача в статусе `done` или `cancelled`, папка старше TTL клона (24 ч), и каждый git-репозиторий внутри чист, полностью запушен, без стеша и alternates. Грязные и незапушенные папки — а также папки, чьё git-состояние нельзя доказать с хоста (например, worktree с мёртвым gitdir) — сначала архивируются в `<runner root>/.gc-archive/` и удаляются только после проверки архива. Папки задач в других статусах остаются, недоступная доска оставляет папку на месте (fail-closed). Проход делит предохранитель прохода OPE-12722: выполняется только при заданном корне исполнителей (`--runner-root` / `HOST_GC_RUNNER_ROOTS`).
- npm/npx-кэши исполнителей (`<runner>/home/.npm/{_cacache,_npx}`) убирает тот же проход host GC под тем же гейтом runner-root: возраст — по самому свежему mtime в дереве кэша (кэш, который npm/npx ещё пишет, остаётся свежим), TTL по умолчанию 4 ч (`--npm-cache-ttl` / `MYRMIDON_HOST_GC_NPM_CACHE_TTL_HOURS`, ниже 1 ч запрещён). Symlink-каталоги кэша пропускаются, каждое удаление guarded от runner root; удаления пишутся в журнал как `runner-npm-cache-*` и считаются в `runnerNpmCachesRemoved`.
