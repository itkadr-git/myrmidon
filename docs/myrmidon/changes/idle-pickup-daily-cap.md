## changelog-en

### Idle pickup no longer wakes an agent over its daily cap on every tick (IDLE-PICKUP-DAILY-CAP, OPE-11947)

- The per-day heartbeat cap gate (`heartbeat.daily_run_limit`, `heartbeat.daily_cost_limit`) does not hold a wake: it writes a `skipped` row to `agent_wakeup_requests` and returns nothing. Idle pickup offered every ready `todo`/`in_progress` task of an agent on every pass and relied on that gate, so an agent that had used up its `maxDailyRuns` collected one rejected wake per task per pass until midnight UTC: 4 179 rows in 6 hours on the production board (adm-infra 3 277, adm 815, adm-observability 86), 13 591 in 3 days. No run and no tokens were spent, but the table, the feed and the attention-card query filled up.
- Idle pickup now asks the cap gate's own verdict once per agent per pass (the same `getHeartbeatDailyCapBlock` over the agent's own policy, so the run count and the failed-before-model exclusion are not counted a second time). The first attempt of the day still reaches the gate and leaves its one receipt row, which is what the «agent exhausted its daily run limit» attention card is built from. From then on the agent is skipped before any per-task lookup and without a write: at most one row per agent per cap per day. A changed limit counts as a new cap and leaves its own receipt. When the cap lookup fails, the pass behaves as before and the gate decides.
- The pass result gains `dailyCapSkipped` (agents left alone because of a cap, once per agent per pass).

## changelog-ru

### Idle pickup больше не будит агента над дневным лимитом на каждом тике (IDLE-PICKUP-DAILY-CAP, OPE-11947)

- Гейт дневного лимита heartbeat (`heartbeat.daily_run_limit`, `heartbeat.daily_cost_limit`) не держит побудку в очереди: он пишет строку `skipped` в `agent_wakeup_requests` и ничего не возвращает. Idle pickup на каждом проходе предлагал агенту каждую его готовую задачу `todo`/`in_progress` и полагался на этот гейт, поэтому агент, исчерпавший `maxDailyRuns`, получал по отклонённой побудке на каждую задачу на каждом проходе до полуночи UTC: 4 179 строк за 6 часов на боевой доске (adm-infra 3 277, adm 815, adm-observability 86), 13 591 за 3 дня. Прогонов и токенов это не тратило, но засоряло таблицу, ленту и запрос карточек внимания.
- Теперь idle pickup один раз на агента за проход спрашивает вердикт самого гейта лимита (тот же `getHeartbeatDailyCapBlock` по политике агента, поэтому подсчёт прогонов и исключение failed-before-model второй раз не считаются). Первая попытка за сутки всё же доходит до гейта и оставляет свою единственную строку: из неё строится карточка внимания «агент исчерпал дневной лимит прогонов». Дальше агент пропускается до всех запросов по задачам и без записи: не больше одной строки на агента на лимит в сутки. Изменённый лимит считается новым и оставляет свою строку. Если вердикт получить не удалось, проход работает как раньше, решает гейт.
- В результат прохода добавлен счётчик `dailyCapSkipped` (агенты, оставленные в покое из-за лимита, один раз на агента за проход).
