## changelog-en

### The board no longer wakes reviewers and engineers while the CI of the pull request head is unfinished or unreadable (EMPTY-WAKES-CI-UNREADY)

- On the 1.6.9-rc.12 board on 16.11 (17:10–19:07) the reviewers (`adm-dev-review-*`) made 505 successful runs and gave a verdict in only 149. The others found "GitHub limit, CI unavailable" (239), "the CI of the head is not ready" (64), or hit HTTP 400 on a monitor (28). The wake reasons were: `execution_review_requested` 203, `ci_completed` 179, `idle_pickup` 66, `execution_review_participant_recovery` 48. The engineers (`adm-dev-eng-*`) made 326 runs and pushed in 55: 97 runs waited for the CI of their own PR and 27 met the GitHub limit. `runPriority.inProgressIdleWakeMinutes=5` woke an `in_progress` task every 5 minutes even while the CI of its PR was running. When idle pickup could not read the CI of the review head, it logged "waking as before" and woke the reviewer.
- One check now stands in `enqueueWakeupInner`, the point every automatic wake passes (`server/src/myrmidon/wake-ci-unready-gate.ts`). Reviewer: `idle_pickup`, `execution_review_participant_recovery` and `execution_review_requested` create no wake and no run while the CI of the current head is pending, or cannot be read. Under a GitHub rate limit the reviewer comes back after the reset plus 60 s; the sources ask again by themselves (the idle pickup sweep, the review CI wait monitor). Engineer: `in_progress_no_run`, `issue_continuation_needed` and `idle_pickup` create no wake while the PR of an `in_progress` task waits for CI. This is the same sign as the load discount of the swarm (`ciWaitingPullRequestIssueIds`): an open PR, CI queued or in progress, and the CI record belongs to the current head. The check reads the stored state of the board and makes no GitHub call.
- Not changed: the `ci_completed` wake (it says the CI of the head is final) and a manual wake of a person always pass; a critical task is still reviewed in parallel with CI; a head with finished CI, red or green, passes the check. The switch `MYRMIDON_WAKE_CI_UNREADY_GATE_ENABLED` turns the check off when it is set to `off`.
- `reviewCiDefersIdlePickup` now defers the wake when the CI read fails, instead of waking "as before".
- A monitor with `monitor.kind = "ci"` is accepted as a synonym of `external_service`. The board stores `external_service` and, if the caller gave no `serviceName`, sets `github-ci`. A refusal with a list of values would change the answer of the route (400 to 422) and the agents would still need a second call; the synonym changes nothing for the readers of the stored monitor and removes the failed call.

## changelog-ru

### Доска больше не будит ревьюеров и инженеров, пока CI головы PR не завершён или не читается (EMPTY-WAKES-CI-UNREADY)

- На доске 1.6.9-rc.12 16.11 (17:10–19:07) ревьюеры (`adm-dev-review-*`) сделали 505 успешных прогонов и вынесли вердикт только в 149. Остальные застали «лимит GitHub, CI недоступен» (239), «CI головы ещё не готов» (64) или HTTP 400 на создании монитора (28). Причины побудки: `execution_review_requested` 203, `ci_completed` 179, `idle_pickup` 66, `execution_review_participant_recovery` 48. Инженеры (`adm-dev-eng-*`) сделали 326 прогонов, пуш — в 55: 97 прогонов ждали CI своего PR, 27 упёрлись в лимит GitHub. `runPriority.inProgressIdleWakeMinutes=5` будил задачу `in_progress` каждые 5 минут, даже пока шёл CI её PR. Когда idle pickup не мог прочитать CI головы на ревью, он писал в лог «waking as before» и будил ревьюера.
- Теперь одна проверка стоит в `enqueueWakeupInner`, через который проходит любая автоматическая побудка (`server/src/myrmidon/wake-ci-unready-gate.ts`). Ревьюер: `idle_pickup`, `execution_review_participant_recovery` и `execution_review_requested` не создают ни побудки, ни прогона, пока CI текущей головы идёт или не читается. При лимите GitHub ревьюер возвращается после сброса плюс 60 с; источники спрашивают снова сами (проход idle pickup, монитор «Review CI wait»). Инженер: `in_progress_no_run`, `issue_continuation_needed` и `idle_pickup` не создают побудку, пока PR задачи `in_progress` ждёт CI. Признак тот же, что у скидки нагрузки роя (`ciWaitingPullRequestIssueIds`): открытый PR, CI в очереди или идёт, запись CI относится к текущей голове. Проверка читает сохранённое состояние доски и в GitHub не ходит.
- Без изменений: побудка `ci_completed` (она говорит, что CI головы завершён) и ручная побудка человека проходят всегда; критичная задача по-прежнему идёт на ревью параллельно с CI; голова с завершённым CI, красным или зелёным, проверку проходит. Переключатель `MYRMIDON_WAKE_CI_UNREADY_GATE_ENABLED` со значением `off` выключает проверку.
- `reviewCiDefersIdlePickup` теперь откладывает побудку, если чтение CI не удалось, а не будит «как раньше».
- Монитор с `monitor.kind = "ci"` принимается как синоним `external_service`. Доска хранит `external_service` и, если вызывающий не дал `serviceName`, ставит `github-ci`. Отказ со списком значений менял бы ответ маршрута (400 на 422), а агенту всё равно нужен был бы второй вызов; синоним ничего не меняет для читателей сохранённого монитора и убирает сам неудачный вызов.
