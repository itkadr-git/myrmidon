## changelog-en

### Fair-queue controls in the run settings (1.6.5 RUN-FAIRNESS, UI)

- Both run settings panels (Instance → General «Run limits», Settings →
  «Runs & queue») now edit the single-agent start share,
  `maxPerAgentStartSharePercent` (1..100 or off, default 15): the most starts
  one agent may take in a 10-minute window before its new runs wait for the
  other agents' turns, so a hot agent can no longer occupy the queue while
  the global ceiling is full.
- Both panels show the queue snapshot from `GET /api/myrmidon/runtime-limits`:
  runs in flight against the concurrency ceiling, how many runs wait, and
  since when the oldest one waits (with its agent).
- The «Runs & queue» screen names why the head of the queue still waits —
  the run's `contextSnapshot.waitReason` (ceiling full, start ramp, memory
  floors, host CPU, the fair share, the agent's own concurrency limit), in
  both locales. See [SETTINGS.md](../SETTINGS.md).

## changelog-ru

### Управление справедливой очередью в настройках прогонов (1.6.5 RUN-FAIRNESS, UI)

- Обе панели настроек прогонов (Instance → General «Run limits», Настройки →
  «Прогоны и очередь») теперь редактируют долю стартов одного агента,
  `maxPerAgentStartSharePercent` (1..100 или выкл, по умолчанию 15): самую
  большую долю стартов за 10-минутное окно, сверх которой новые прогоны
  агента ждут очереди остальных — один активный агент больше не занимает всю
  очередь при занятом глобальном потолке.
- Обе панели показывают снимок очереди из `GET /api/myrmidon/runtime-limits`:
  сколько прогонов в работе против потолка, сколько ждут и с какого времени
  ждёт самый старый (с его агентом).
- Экран «Прогоны и очередь» называет, почему головной прогон очереди ещё
  ждёт — `contextSnapshot.waitReason` прогона (потолок занят, плавный старт,
  пороги памяти, CPU хоста, справедливая доля, личный лимит агента) на обоих
  языках. См. [SETTINGS.ru.md](../SETTINGS.ru.md).

## settings-en

| `MYRMIDON_MAX_PER_AGENT_START_SHARE_PERCENT` | 1.6.5 RUN-FAIRNESS | `15` | Single-agent start share of run admission: the most starts one agent may take in a 10-minute window, in percent of all starts. Past its share the agent's new runs stay `queued` (`waitReason: agent_fair_share`) until the other agents have had their turns, so a hot agent cannot occupy the queue while the global ceiling is full. Editable on the fly like the other run limits (Instance → General «Run limits», Settings → «Runs & queue», `PATCH /api/myrmidon/runtime-limits`); a row saved before 1.6.5 lacks the key and takes the default | `0`, `off` or `100` — the share limit is off. Unset, empty or unreadable — the default 15 |
