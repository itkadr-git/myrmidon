## changelog-en

### Three hot queries get bounded and indexed (OPE-4131)

- `getWorkspaceSandboxReport` scanned every run of a company (170 371 rows);
  it now reads the newest 500 with a bounded index scan.
- `queryLiveContinuations` filtered on `lower(error_code)` — non-indexable —
  and returned whole rows; it now matches a value list and selects two columns.

## changelog-ru

### Горячие запросы доски без чтения строки целиком + индекс company/issue миграцией (OPE-4131 часть B, закрывает OPE-4106)

- `getConversationOwnershipBlocker`
  (`server/src/services/conversation-continuation.ts`) теперь читает только
  колонки, которые проверяет и возвращает (`id`, `agent_id`, `process_pid`,
  `process_group_id`, `process_started_at`), вместо полной строки
  `heartbeat_runs`. Полный select протаскивал многокилобайтные
  `result_json` / `runner_profile_json` / `context_snapshot` через
  исполнитель примерно 10 раз на прогон; одно планирование занимало 74 мс на
  бою.
- Миграция `0302_heartbeat_runs_company_issue_coalesce_created_index.sql`
  закрепляет выраженческий индекс
  `heartbeat_runs_company_issue_coalesce_created_idx` по
  `(company_id, coalesce(native_issue_id::text, context_snapshot->>'issueId'), created_at desc, id desc)`.
  Оператор поставил этот индекс вручную на бою (OPE-4106); миграция делает
  его частью управляемой схемы. `IF NOT EXISTS` сохраняет ручной индекс и
  делает повторный прогон холостым.
- Новый тест миграции
  `packages/db/src/heartbeat-runs-company-issue-coalesce-index.myrmidon.test.ts`:
  вся цепочка применяется, EXPLAIN использует индекс для предиката блокера,
  повторный прогон операторов — no-op.
- Строка DIVERGENCE: `OPE-4131-B`.
