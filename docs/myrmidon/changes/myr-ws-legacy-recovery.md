## changelog-en

### `myr-ws open` safely recovers standalone legacy clones (PR #1427)

- `myr-ws open <KEY> <REPO>` can adopt a legacy standalone Git clone at the task path after verifying that it is a real standalone copy, has a recognizable GitHub origin, and matches the requested repository. An unrelated directory, linked worktree, or repository mismatch is refused without being adopted.
- The original clone is always moved to `<path>.legacy-<KEY>` and retained there, whether or not it is clean; `myr-ws open` refuses if that path already exists. If the copy has a `HEAD` and uncommitted changes, the command first preserves its current commit at `refs/myr-ws/recovery/<KEY>` inside the copy and saves tracked and untracked working-tree changes in a Git stash named `myr-ws recovery <KEY>`; a clean copy gets neither. A copy with no `HEAD` (no initial commit) cannot be stashed, so `myr-ws open` fails with "could not preserve legacy working tree" and leaves the original copy untouched. When the copy had a `HEAD`, the JSON result always reports `recoveryRef` as `refs/heads/myr-ws/recovery/<KEY>`, but that branch in the base repository is created only if the copy's commit differs from the new worktree's `HEAD`, so the field may name a branch that does not exist.
- If preserving the worktree fails or cannot be verified, `myr-ws open` stops and leaves the original copy in place. If creating the replacement worktree fails, it restores the original clone path. Running `myr-ws open` again reuses the registered managed worktree.
- An unregistered linked worktree already at the task path is adopted into the registry and reused; this supports recovery after registry loss without converting the worktree.

## changelog-ru

### `myr-ws open` безопасно восстанавливает старые самостоятельные Git-копии (PR #1427)

- `myr-ws open <KEY> <REPO>` может принять старую самостоятельную Git-копию в каталоге задачи после проверки, что это отдельная копия репозитория, у неё есть распознаваемый GitHub origin и он совпадает с запрошенным репозиторием. Посторонний каталог, связанный worktree или копия другого репозитория не принимаются.
- Исходная копия всегда переносится в `<path>.legacy-<KEY>` и остаётся там, чистая она или нет; если такой путь уже есть, `myr-ws open` отказывается. Если у копии есть `HEAD` и незакоммиченные изменения, команда сначала сохраняет её текущий коммит в ссылке `refs/myr-ws/recovery/<KEY>` внутри копии, а отслеживаемые и неотслеживаемые изменения рабочего дерева — в Git stash с именем `myr-ws recovery <KEY>`; у чистой копии нет ни ссылки, ни stash. Копию без `HEAD` (без начального коммита) сохранить через stash нельзя: `myr-ws open` завершается ошибкой «could not preserve legacy working tree» и не трогает исходную копию. Если у копии был `HEAD`, в JSON-поле `recoveryRef` всегда возвращается `refs/heads/myr-ws/recovery/<KEY>`, но сама ветка в базовом репозитории создаётся, только если коммит копии отличается от `HEAD` нового worktree, поэтому поле может указывать на несуществующую ветку.
- Если сохранить изменения не удалось или их сохранение не прошло проверку, `myr-ws open` останавливается, не перемещая исходную копию. Если создать заменяющий worktree не удалось, команда возвращает исходную копию на прежний путь. Повторный `myr-ws open` использует уже зарегистрированный управляемый worktree.
- Если по пути задачи уже есть связанный worktree, отсутствующий в реестре, команда добавляет его в реестр и использует повторно. Это позволяет восстановиться после потери реестра без конвертации worktree.
