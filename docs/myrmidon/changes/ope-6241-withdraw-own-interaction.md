## divergence

| OPE-6241-WITHDRAW-OWN-INTERACTION | Отзыв агентом СВОЕЙ pending-карточки interaction (`POST /api/issues/{id}/interactions/{interactionId}/withdraw`) больше не требует совпадения `run.responsibleUserId` с `actor.onBehalfOfUserId`: `assertAgentInteractionRunAttribution` получил опцию `allowResponsibleUserMismatch`, которую включает только маршрут withdraw и только когда вызывающий — создатель карточки или исполнитель тикета. Прочие проверки атрибуции (ран существует, та же компания, тот же agentId) и содержательная авторизация (403 постороннему агенту, гейт исполнителя) неизменны; accept/reject/respond и human_only-резолв работают в старом строгом режиме | Вендор: `server/src/routes/issues.ts` (метки `myrmidon(OPE-6241)` в `assertAgentInteractionRunAttribution` и `assertIssueThreadInteractionWithdrawalAllowed`), тест-сторож в вендорском `server/src/__tests__/issue-thread-interaction-routes.test.ts` | Автоматизационные прогоны несут `responsibleUserId` сервисной учётной записи, а ключи агентов выписаны на человека, поэтому агент-создатель (и исполнитель тикета) не мог отозвать собственную pending-карточку: 422 `interaction_run_attribution_required` | `server/src/__tests__/issue-thread-interaction-routes.test.ts` (тесты «allows the creator agent to withdraw from an automation run with a service responsible user», «allows the assignee agent …», «rejects withdrawal by an unrelated agent …», «still rejects accept from an automation run …») | Когда вендор сам перестанет требовать совпадение responsible-user для отзыва собственной карточки: удалить опцию `allowResponsibleUserMismatch` и перенос вычисления isCreator/isAssignee по меткам `myrmidon(OPE-6241)` | (этот PR) |
