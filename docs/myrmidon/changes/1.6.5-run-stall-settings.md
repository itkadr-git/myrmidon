## changelog-en

### Run stall detection settings without a restart (RUN-STALL-SETTINGS)

- The progress-based run liveness sweep (RUN-STALL) is configured from the UI:
  `GET /api/myrmidon/run-stall` reports the effective values — the master
  switch, the silence threshold, the sweep interval and the scan page size —
  together with where each value came from (`settings` for the stored
  document, `env` for the deployment environment, `default` for the built-in
  fallback); `PATCH /api/myrmidon/run-stall` (instance admin only) writes
  `instance_settings.general.runStall`, records the change in the activity log
  for every company (`instance.run_stall.updated`, old and new values) and
  applies the values to the live sweep, so the very next pass works with the
  new threshold and interval. No restart — a restart drops every run in
  flight.
- The environment keeps its role on an instance that never saved the settings:
  unset `MYRMIDON_RUN_STALL_*` are the built-in defaults, and the values the
  deployment sets are read with the sweep's own semantics (an unrecognized
  switch value keeps the fix on). A stored value wins over the environment;
  out-of-range writes are refused with 400 (threshold 60 s – 24 h, interval
  15 s – 24 h, page size 1 – 200).
- Instance → General carries a «Run stall detection» section with the four
  values, each labelled with its source.
- The sweep itself does not change: only where it reads its settings from.

## changelog-ru

### Настройки сторожа зависших прогонов без перезапуска (RUN-STALL-SETTINGS)

- Сторож живости прогонов по прогрессу (RUN-STALL) настраивается из
  интерфейса: `GET /api/myrmidon/run-stall` отдаёт действующие значения —
  выключатель, порог тишины, интервал прохода и размер страницы скана — вместе
  с источником каждого (`settings` — сохранённый документ, `env` — окружение
  развёртывания, `default` — встроенное умолчание); `PATCH
  /api/myrmidon/run-stall` (только администратор инстанса) пишет
  `instance_settings.general.runStall`, записывает изменение в журнал
  активности по каждой компании (`instance.run_stall.updated`, старые и новые
  значения) и применяет значения к живому проходу: следующий же проход работает
  с новым порогом и интервалом. Без перезапуска — перезапуск обрывает идущие
  прогоны.
- Окружение сохраняет свою роль на инстансе, который настройки не сохранял:
  незаданные `MYRMIDON_RUN_STALL_*` — встроенные умолчания, а выставленные
  значения читаются с семантикой самого сторожа (нераспознанное значение
  выключателя оставляет исправление включённым). Сохранённое значение важнее
  окружения; выход за границы отклоняется с 400 (порог 60 с – 24 ч, интервал
  15 с – 24 ч, размер страницы 1 – 200).
- На странице Instance → General появилась секция «Run stall detection» с
  четырьмя значениями, каждое подписано своим источником.
- Сам сторож не меняется: меняется только то, откуда он читает настройки.
