| `MYRMIDON_RUN_STALL_ENABLED` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `1` (on) | Master switch of progress-based run liveness: off — a run whose own recorded progress stopped advancing is left running until the hard run timeout (vendor behavior). Since 1.6.5 the switch is managed in the team-liveness settings (`runStallEnabled` at `/api/myrmidon/team-liveness`, Instance → General → Team liveness): the sweep obeys that value on every pass, the "Run stall detection" section of the settings page shows it read-only, and this variable no longer decides a running instance | `0`/`false`/`off`/`no` — disable (vendor behavior). Unset or unrecognized — enabled: a typo does not silently extinguish the fix. Applies to an instance that never saved the team-liveness settings; the stored settings value wins over the environment |
| `MYRMIDON_RUN_STALL_THRESHOLD_SEC` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `1200` (20 min) | How long a running run may go without recorded progress (any appended run event, output flush, or useful action) before the sweep interrupts it as `run_stalled`: the task goes back to `todo` and its assignee is woken, so parts of the team-liveness work pick it up. Never a duration limit: a run working for hours with fresh progress is left alone. Since 1.6.5 the threshold is managed in the team-liveness settings (`runStallThresholdSec` at `/api/myrmidon/team-liveness`, Instance → General → Team liveness); the "Run stall detection" section shows it read-only | From 60 to 86400; values outside the range, non-numeric or fractional — the default. Applies to an instance that never saved the team-liveness settings; the stored settings value wins over the environment |
| `MYRMIDON_RUN_STALL_CHECK_INTERVAL_SEC` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `60` | Minimum spacing between two scan passes of the stall sweep; the scheduler queue itself ticks more often. Since 1.6.5 the effective value lives in the instance settings (`instance_settings.general.runStall.checkIntervalSec`) once saved and changes on the fly — Instance → General → "Run stall detection" or `GET`/`PATCH /api/myrmidon/run-stall`, instance-admin only for writes, the very next pass works with the new value, no restart | Values below 15 or non-numeric or fractional — the default (60). The interrupt path itself is not rate limited by this. On an instance that never saved the settings this variable is the default; the stored settings value wins over the environment. `PATCH` naming `enabled` or `thresholdSec` is refused with 409 `run_stall_managed_by_team_liveness` — those two belong to team-liveness |
| `MYRMIDON_RUN_STALL_PAGE_SIZE` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `50` | How many running runs one scan pass inspects at most, stalest progress first: the pass stays a bounded read of the runs table. Since 1.6.5 the effective value lives in the instance settings (`instance_settings.general.runStall.pageSize`) once saved and changes on the fly — Instance → General → "Run stall detection" or `GET`/`PATCH /api/myrmidon/run-stall`, no restart | From 1 to 200; values outside the range or non-numeric — the default. On an instance that never saved the settings this variable is the default; the stored settings value wins over the environment |

| `MYRMIDON_RUN_STALL_ENABLED` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `1` (вкл) | Выключатель живости прогона по прогрессу: выключено — прогон, у которого записанный прогресс перестал двигаться, живёт до жёсткого таймаута прогона (поведение вендора). С 1.6.5 выключатель управляется настройками team-liveness (`runStallEnabled` на `/api/myrmidon/team-liveness`, Instance → General → Team liveness): сторож подчиняется этому значению на каждом проходе, секция «Run stall detection» на странице настроек показывает его только для чтения, а эта переменная работающий инстанс больше не решает | `0`/`false`/`off`/`no` — выключить (поведение вендора). Не задано или нераспознанное значение — включено: опечатка не гасит починку молча. Действует на инстансе, который ни разу не сохранял настройки team-liveness; сохранённое значение важнее окружения |
| `MYRMIDON_RUN_STALL_THRESHOLD_SEC` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `1200` (20 мин) | Сколько идущий прогон может не записывать прогресс (любое событие прогона, вывод, полезное действие), прежде чем подметальщик прервёт его как `run_stalled`: задача возвращается в `todo`, исполнитель будится, работу подхватывают части TEAM-LIVENESS. Это не предел длительности: прогон, работающий часами со свежим прогрессом, не трогается. С 1.6.5 порог управляется настройками team-liveness (`runStallThresholdSec` на `/api/myrmidon/team-liveness`, Instance → General → Team liveness); секция «Run stall detection» показывает его только для чтения | От 60 до 86400; вне диапазона, не число или дробное — умолчание. Действует на инстансе, который ни разу не сохранял настройки team-liveness; сохранённое значение важнее окружения |
| `MYRMIDON_RUN_STALL_CHECK_INTERVAL_SEC` | RUN-STALL, 1.6.5 RUN-STALL-SETTINGS | `60` | Минимальный интервал между двумя проходами скана подметальщика; сама очередь планировщика тикает чаще. С 1.6.5 действующее значение после первого сохранения живёт в настройках инстанса (`instance_settings.general.runStall.pageSize`) и меняется на лету — Instance → General → секция «Run stall detection» или `GET`/`PATCH /api/myrmidon/run-stall`, без перезапуска | От 1 до 200; вне диапазона или не число — умолчание.
