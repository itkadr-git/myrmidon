OPE-8289 — Done gate for linked pull requests

An issue with one or more pull_request work products may transition to done only
when every active linked PR is verified merged. Open, draft, closed-unmerged,
invalid-reference, and provider-unavailable states block with the stable
issue_done_pull_request_gate conflict and the relevant PR URL. A closed PR can
be treated as delivered only when metadata.replacementPullRequestUrl contains a
valid GitHub pull request URL whose provider state is verified merged. A freeform
comment or the old PR's closed state is not evidence of delivery.

The issue service resolves provider state before the status transaction, then
compares the work-product snapshot before applying the transition. If a product
changes during that interval, retry completion. Callers that supply an external
transaction cannot safely make provider calls; these callers fail closed unless
stored work-product status already proves merged. This allows recovery by
refreshing the work-product state through the existing PR synchronization path,
then retrying completion. Cancellation remains unchanged.

Post-deploy audit query (same scope before and after rollout):

```sql
WITH open_prs AS (
  SELECT DISTINCT
    COALESCE(wp.metadata->>'repo', wp.url) AS pr_key,
    (wp.metadata->>'number') AS pr_number
  FROM issue_work_products wp
  WHERE wp.type = 'pull_request'
    AND wp.status IN ('open', 'draft', 'ready_for_review', 'approved', 'changes_requested')
),
affected AS (
  SELECT p.pr_key, p.pr_number
  FROM open_prs p
  WHERE EXISTS (
    SELECT 1
    FROM issue_work_products wp
    JOIN issues i ON i.id = wp.issue_id AND i.company_id = wp.company_id
    WHERE wp.type = 'pull_request'
      AND COALESCE(wp.metadata->>'repo', wp.url) = p.pr_key
      AND wp.metadata->>'number' IS NOT DISTINCT FROM p.pr_number
      AND i.status IN ('done', 'cancelled')
  )
)
SELECT pr_key, pr_number FROM affected ORDER BY pr_key, pr_number;
```

Run the identical query before and after rollout; it reports distinct PR
identities, not issue/product rows. Historical counts are not a current baseline.
