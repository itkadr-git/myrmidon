# OPE-10076: DEVFLOW behavior-level integration tests for PR approval and pipeline liveness

## Summary

This change adds comprehensive behavior-level integration tests covering the complete DEVFLOW lifecycle in `server/src/__tests__/devflow-lifecycle.integration.test.ts`.

## Requirements Covered

1. **Formal board review decision APPROVE results in GitHub PR approval / review-approved marker and enters auto-merge without host scripts**:
   - `propagateReviewApprovalToPullRequest` tags the linked PR with `review-approved` and submits an approving GitHub review (`event: "APPROVE"`).
   - Work product metadata is updated (`reviewApprovedAt`, `lastApprovedHeadSha`).
   - Audit trail activity `myrmidon.pr_approval.propagated` is recorded.
   - Current-head guard validates that PR head has not moved past the reviewed commit.
   - Enters auto-merge natively without host-side scripts (`label-board-approved.py`).

2. **Non-approval / REQUEST CHANGES does not mark approved**:
   - Outgoing review decisions with non-approval outcomes (`changes_requested`, `request_changes`, `refuse`, `return`, `rejected`, or rework/return comment markers) skip propagation (`action: "skipped"`, `reason: "non_approval"`).
   - No GitHub `review-approved` label or PR review is submitted.
   - Activity log records skipped propagation.
   - No false `staleMarker` alert is emitted for non-approval reviews.

3. **Duplicate decisions / events are safe and idempotent**:
   - Repeated review approval decisions and reconciliation sweeps detect `already_labeled` PRs and safely no-op (`action: "noop"`, `reason: "already_labeled"`).
   - Duplicate PR webhook events for `review-approved` preserve existing marker state.

4. **Stale/missing marker, stalled merge, and stalled router each emit a liveness alert**:
   - `staleMarkerSince` detects missing or stale `review-approved` markers after an APPROVE verdict and emits alert signal (`metric: "staleMarkerMs"`) when duration exceeds threshold.
   - `stalledMergeSince` detects open PRs with approvals that remain unmerged beyond threshold and emits alert signal (`metric: "stalledMergeMs"`).
   - `stalledRouterSince` detects unrouted review issues in `in_review` without a reviewer beyond threshold and emits alert signal (`metric: "stalledRouterMs"`).

5. **Recovery clears each alert**:
   - Applying the `review-approved` marker on current head or merging/closing the PR clears the stale marker alert (`staleMarkerSince` returns `null`).
   - Merging or closing the PR clears the stalled merge alert (`stalledMergeSince` returns `null`).
   - Assigning a reviewer or transitioning the issue out of `in_review` clears the stalled router alert (`stalledRouterSince` returns `null`).

6. **End-to-End Simulation**:
   - Complete multi-phase lifecycle test exercising review routing -> request changes -> rework -> approve -> native propagation -> auto-merge -> recovery.
