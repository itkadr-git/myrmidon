## changelog-en

### MODEL-PROVIDERS-POOLS-WEB: model channels, the ChatGPT and Antigravity pools, the fallback order and the agent key lists work from the board web UI

- The "Model providers" screen called `/model-providers/providers/...`, a path the server never had, so every call answered 404 (the list, the model list, the channels, the key rotation and the removal). The client now calls the paths the server mounts: `/model-providers` and `/model-providers/:id/...`. The change log of the screen no longer adds a second `/api` prefix, and the LiteLLM channel rows of both server spellings fill the same table columns.
- The `antigravity-pool` and `google-ai-pool` provider types are registered when the plugins `myrmidon.antigravity` and `myrmidon.google-ai` are ready, as `chatgpt-pool` is. Both support channels. `antigravity-pool` brings the four model groups `antigravity/gemini-3.8-flash-high`, `antigravity/gemini-3.8-flash-medium`, `antigravity/gemini-3.8-flash-low` and `antigravity/gemini-3.5-flash-lite`; the model id is the LiteLLM group name. `google-ai-pool` has no default models. A connector that declares no models no longer gets the ChatGPT models. The pool service address has no default for these two types: enter it in the base URL field.
- A pool lives on its own LiteLLM deployments. For `chatgpt-pool`, `antigravity-pool` and `google-ai-pool` the board sends no `/model/new`, `/model/update` or `/model/delete` when a model is enabled or disabled, when the key is rotated, when the provider is removed, or at the startup reconciliation. The board still shows or hides the pool models, and the fallback order (`GET` and `PUT .../litellm/fallbacks`) and the agent key lists stay board settings. The LiteLLM provider prefix of the pool types is now `openai`.
- Removing a provider that is not a pool deletes only its own gateway deployments, found by deployment id and by the provider's own `api_base`. Before this change a removal deleted every database deployment of each removed model group, which also removed the deployments of other providers and of the pool routers.
- The agent key allowlist pass read no enabled model (the joined rows were keyed by the SQL table names), so it never changed a key. It reads the registry now. To keep it from rewriting the model lists of every restricted key on its own, the startup check and the provider-change hooks run it as a dry run: they count the keys that would change, log the model names that would be added or removed, and send nothing. Applying is an explicit owner or admin action: `POST /api/myrmidon/companies/:companyId/litellm/keys/allowlist-sync` answers the dry-run report, and `?apply=true` applies it.

## changelog-ru

### MODEL-PROVIDERS-POOLS-WEB: каналы моделей, пулы ChatGPT и Antigravity, порядок резервов и ключи агентов задаются с доски через веб-интерфейс

- Экран «Model providers» ходил на `/model-providers/providers/...` — такого маршрута на сервере никогда не было, поэтому любой вызов (список, список моделей, каналы, ротация ключа, удаление) отвечал 404. Клиент теперь вызывает те пути, которые монтирует сервер: `/model-providers` и `/model-providers/:id/...`. Журнал изменений экрана больше не добавляет второй префикс `/api`, а строки каналов LiteLLM в обоих написаниях сервера заполняют одни и те же колонки таблицы.
- Типы провайдеров `antigravity-pool` и `google-ai-pool` регистрируются, когда готовы плагины `myrmidon.antigravity` и `myrmidon.google-ai`, как и `chatgpt-pool`. Оба поддерживают каналы. У `antigravity-pool` четыре группы моделей `antigravity/gemini-3.8-flash-high`, `antigravity/gemini-3.8-flash-medium`, `antigravity/gemini-3.8-flash-low` и `antigravity/gemini-3.5-flash-lite`; идентификатор модели — это имя группы LiteLLM. У `google-ai-pool` моделей по умолчанию нет. Коннектор, который не объявил моделей, больше не получает модели ChatGPT. Адреса сервиса пула у этих двух типов по умолчанию нет: его вводят в поле «Base URL».
- Пул живёт на собственных развёртываниях LiteLLM. Для `chatgpt-pool`, `antigravity-pool` и `google-ai-pool` доска не шлёт `/model/new`, `/model/update` и `/model/delete` — ни при включении и выключении модели, ни при ротации ключа, ни при удалении провайдера, ни при стартовой сверке. Доска по-прежнему показывает или скрывает модели пула, а порядок резервов (`GET` и `PUT .../litellm/fallbacks`) и списки моделей ключей агентов остаются настройками доски. Префикс провайдера LiteLLM для типов-пулов теперь `openai`.
- Удаление провайдера, не являющегося пулом, снимает только его собственные развёртывания в шлюзе: по идентификатору развёртывания и по `api_base` самого провайдера. Раньше удалялись все хранящиеся в базе развёртывания каждой группы, и вместе с ними пропадали развёртывания других провайдеров и роутеров пулов.
- Проход по спискам моделей ключей агентов не видел ни одной включённой модели (строки join приходили под SQL-именами таблиц) и поэтому никогда не менял ключи. Теперь он читает реестр. Чтобы он не переписывал списки моделей у всех ограниченных ключей сам, проверка на старте и хуки смены провайдера запускают его как холостой прогон: считают ключи, которые изменились бы, пишут в лог имена моделей, которые добавились бы или убрались, и ничего не отправляют. Применение — явное действие владельца или администратора: `POST /api/myrmidon/companies/:companyId/litellm/keys/allowlist-sync` отвечает отчётом холостого прогона, а `?apply=true` применяет его.
