## settings-en-replace

<!-- section: Track 4 — chats and skills -->

| — | X9c (X9d documentation row) | — (no variable) | In a bridged Telegram chat, a matching `@<alias>` mention routes to that same-company agent's standing Agent Chat conversation; the reply returns in-thread with the agent display-name prefix, and the first turn includes recent chat context. Without an explicit ID, the first resolvable `@`-mention anywhere in the message routes it; only a matching token at the beginning is removed from the message body. `/agents`, `/to <alias>`, and `/who` are implemented commands; `/to` stores the selected choice shown by `/who` and `/agents`, but it is not an inbound routing fallback, so a mention is required to address another agent in ordinary messages. X9d remains an open requirement for separate runtime work; this row documents only current X9c behavior. No new variable: this behavior rides the X8b bridge; see `guides/telegram-alias-addressing.md` | Off with the bridge: unset `MYRMIDON_TELEGRAM_DM_CONVERSATIONS` — vendor path without resolution, prefix, or commands. Unresolvable mentions go to the endpoint's assigned agent; unlinked senders are refused before resolution; in group topics only bot-addressed messages resolve. X9a/X9b/X9c in DIVERGENCE.md  Explicit `agent://UUID` takes precedence over names; invalid, foreign, unavailable or multiple IDs are refused without fallback. |

| — | X9c (строка документации X9d) | — (без переменной) | В мостовом Telegram-чате подходящее упоминание `@<алиас>` направляется в постоянную переписку Agent Chat агента той же компании; ответ возвращается в тред с префиксом отображаемого имени, а первый ход включает недавний контекст чата. При отсутствии явного ID первое распознанное `@`-упоминание в любом месте маршрутизирует сообщение; из тела удаляется только совпавший токен в начале. Команды `/agents`, `/to <алиас>` и `/who` реализованы; `/to` сохраняет выбор, который показывают `/who` и `/agents`, но не служит запасным адресатом входящей маршрутизации, поэтому для обращения к другому агенту в обычном сообщении нужно упоминание. X9d остаётся открытым требованием для отдельной runtime-работы; эта строка описывает только текущее поведение X9c. Новых переменных нет: поведение работает поверх моста X8b; см. `guides/telegram-alias-addressing.ru.md` | При выключенном мосте: не задана `MYRMIDON_TELEGRAM_DM_CONVERSATIONS` — путь вендора без резолва, префикса и команд. Нераспознанное упоминание направляется назначенному на эндпоинт агенту; непривязанный отправитель получает отказ до резолва; в топиках групп резолвятся только сообщения, адресованные боту.
