## changelog-en

### CONNECTORS G: the bridge returns to the direct path when the adapter does not answer (1.6.6)

- The seam of the bridge now wraps every symbol a channel connector serves with
  the fallback chain
  (`server/src/myrmidon/channel-connectors/bridge/fallback.ts`). The adapter
  answers — the core gets its value and the bridge module does not run (no double
  delivery). The adapter throws, rejects or runs out of time — one warn line, one
  `myrmidon_adapter_fallback_total{reason="error"|"timeout"}` sample, and the
  bridge module answers exactly once, so the Telegram bridge keeps working while
  the connector is down.
- With the switch off (the default) the seam hands the bridge module itself over:
  the adapter is not touched and the board behaves byte for byte as before.
- New setting `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE_TIMEOUT_MS` (default 15000 ms)
  bounds one adapter call; a value that is not a positive number keeps the
  default. The counter is part of the board's `/metrics` scrape.

## settings-en-new

### 1.6.6 — CH-CONNECTOR G: the bridge fallback chain of the channel connector

The seam of the bridge wraps every symbol a channel connector serves with the
fallback chain of design OPE-6985 (part G of OPE-4956): the adapter answers — its
value is served; the adapter throws, rejects or runs out of time — the call is
logged, counted in `myrmidon_adapter_fallback_total{reason}` and answered by the
bridge module exactly once. With the switch off none of this runs.

| Variable | Function | Default | What it does | How to disable / special |
|---|---|---|---|---|
| `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE_TIMEOUT_MS` | CH-CONNECTOR G | `15000` | Bound of one adapter call of the bridge seam, ms. A call that did not answer inside the bound is counted `reason="timeout"` and answered by the bridge module. Read per call, so the value in force follows the setting | Any value that is not a positive number (blank, `0`, `-5`, garbage) keeps the default. Set it generously: the bound exists so the bridge cannot hang on a dead adapter, not to police slow work |

## settings-ru-new

### 1.6.6 — CH-CONNECTOR G: fallback-цепочка моста коннектора канала

Шов моста оборачивает каждый символ, который отдаёт коннектор канала,
fallback-цепочкой из решения OPE-6985 (часть G задачи OPE-4956): адаптер
ответил — отдаётся его значение; адаптер бросил исключение, отклонил промис или
не уложился во время — вызов пишется в лог, считается в
`myrmidon_adapter_fallback_total{reason}` и ровно один раз отвечается модулем
моста. При выключенном выключателе ничего из этого не работает.

| Переменная | Функция | По умолчанию | Что делает | Как выключить / особое |
|---|---|---|---|---|
| `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE_TIMEOUT_MS` | CH-CONNECTOR G | `15000` | Предел одного вызова адаптера шва, мс. Вызов, не ответивший в предел, считается с причиной `reason="timeout"` и отвечается модулем моста. Читается на каждом вызове, поэтому действует значение на момент вызова | Любое значение, не являющееся положительным числом (пусто, `0`, `-5`, мусор), оставляет умолчание. Предел ставят с запасом: он нужен, чтобы мост не завис на мёртвом адаптере, а не чтобы ограничивать медленную работу |
