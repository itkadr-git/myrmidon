# Контейнеры ботов: дополнительные тома только для чтения

Драйвер даёт контейнеру бота ровно три тома: `/data/hermes`, `/workspace` и
`/scratch`. Всё, что нужно боту сверх этого — общие исходники, шаблоны, общие
инструменты, — раньше раскладывалось копиями в `/workspace/shared` каждого бота,
и при обновлении исходников их приходилось раздавать заново.

Эта возможность позволяет карточке смонтировать разрешённый оператором каталог
хоста в контейнер дополнительным томом **только для чтения**. Бот видит файлы
там, где они лежат на хосте; ничего не копируется, а писать в них бот не может.

Английская версия: [bot-extra-mounts.md](bot-extra-mounts.md).

## Настройка инстанса: `MYRMIDON_BOT_MOUNT_SOURCES`

Белый список каталогов хоста, которые карточка может смонтировать. Список
абсолютных путей через запятую:

```
MYRMIDON_BOT_MOUNT_SOURCES=/srv/shared/sources,/srv/shared/tools
```

* Не задано или пусто — **ни один дополнительный том не разрешён** (fail-closed).
* Карточка может назвать каталог только из этого списка и только целиком —
  правила префикса нет: `/srv/shared` не разрешает `/srv/shared/sources`.
* Значение читается один раз при запуске сервера (`startBotContainers`, W2a).
  Изменение действует после перезапуска сервера доски; бот, у которого набор
  томов после этого расходится с карточкой, пересоздаётся: список bind — часть
  шаблона контейнера.

## Настройка карточки: `adapterConfig.container.extraMounts`

```jsonc
{
  "container": {
    "enabled": true,
    "image": "ghcr.io/example/runtime@sha256:…",
    "memoryMb": 2048,
    "cpus": 1,
    "pidsLimit": 512,
    "extraMounts": [
      { "source": "/srv/shared/sources", "path": "/srv/shared/sources", "readOnly": true }
    ]
  }
}
```

* `source` — абсолютный каталог хоста; обязан быть в `MYRMIDON_BOT_MOUNT_SOURCES`.
* `path` — абсолютная точка монтирования внутри контейнера.
* `readOnly` — необязательное, по умолчанию `true`. `false` отклоняется: общий
  каталог writable не монтируется.
* Нет `extraMounts` — у бота остаются только три фиксированных тома.

Драйвер строит bind как `хост:контейнер:ro` и дописывает его после трёх
фиксированных. Помощники, которые готовят тома и укладывают профиль,
дополнительного тома не получают — они трогают только три тома бота.

## Точка монтирования внутри собственного тома бота (1.6.5-BOT-DISK-H, класс J)

Раньше `path` отклонялся в любом месте внутри `/data/hermes`. Теперь он
разрешён под тремя поддеревьями собственного тома бота — `.hermes/shared`,
`media` и `work` — и только там (класс J проекта эпика: карточка даёт боту
каталог, до которого он иначе не дотянулся бы, по привычному ему пути).

Такой том драйвер привязывает по **настоящему** пути этого поддерева внутри
единого монтирования бота, а не по пути из карточки: `/bot/hermes/media/site`
для бота с единым монтированием (`/bot`), `/bot-scope/<botKey>/hermes/media/site`
для участника общей области изоляции и `/data/hermes/media/site` для образа с
контрактом `1`. Путь из карточки — это путь, по которому читает бот, поэтому
собственная ссылка `/data/hermes` из точки входа работает в любом случае.

Всё остальное под `/data/hermes` — `bin`, `lazy-packages`, `lsp`, остаток
`.hermes` — по-прежнему отклоняется, поэтому карточка не может ни подменить
общую среду (см. ниже), ни писать в неё; дополнительные тома в любом случае
только для чтения.

## Общая среда ботов (1.6.5-BOT-DISK-H, класс C)

Когда настройка экземпляра `general.botDisk.sharedBotRuntimePath` называет
каталог хоста, драйвер добавляет три привязки на чтение его подкаталогов
`bin`, `lazy-packages` и `lsp` поверх собственных путей среды бота — те же три
пути и в той же форме настоящего пути, что выше, так что одна копия на хосте
заменяет копию на каждого бота (5–7 ГиБ на копию). Настройки экземпляра и шаг
оператора — в
[SETTINGS.ru.md](SETTINGS.ru.md#161--bot-disk-b-общий-кэш-пакетов-для-контейнеров-ботов).

## Что отклоняется и почему

| Правило | Причина |
|---|---|
| источника нет в `MYRMIDON_BOT_MOUNT_SOURCES` | карточка не должна дотянуться до каталога хоста, который оператор не назвал |
| источник относительный, содержит `..`, `//`, заканчивается на `/`, содержит обратный слэш, управляющий символ, или это `/` | два написания одного каталога сравнивались бы как разные, а `/` отдал бы весь хост |
| `readOnly` равен `false` | дополнительные тома по построению только для чтения |
| `path` относительный, небезопасный, или это `/workspace`, `/scratch`, `/tmp`, сам `/data/hermes` либо путь внутри них | нельзя затенять собственные тома драйвера и tmpfs образа — три поддерева данных владельца внутри `/data/hermes` это исключение выше |
| один и тот же `path` указан дважды | Docker отказал бы в создании и так |

Отклонённый том — ошибка прохода сверки (видна в журнале активности): контейнер
с ним не создаётся, существующий контейнер не трогается. Сообщение называет
поле, но никогда — секрет.

## dockergate

На бою доска говорит с демоном Docker через [dockergate](dockergate.md), который
пересобирает каждое тело создания из своей конфигурации и сравнивает байты. Там
изменилось два места:

* в конфигурации появился `mountSources` — тот же список каталогов хоста,
  заведённый и на стороне dockergate, — и `botRuntimeRoot`, каталог хоста общей
  среды ботов;
* тело создания бота может теперь нести после фиксированного bind только
  чтение: пары кэша, пары среды (`<botRuntimeRoot>/{bin,lazy-packages,lsp}` по
  настоящему пути внутри единого монтирования бота, только для чтения) и
  разрешённый том класса J по его настоящему пути. Всё остальное отклоняется
  кодом
  `mount_source_not_allowed` (источник не заведён либо bind на запись, не
  являющийся парой кэша) или `binds_mismatch` (занятая точка, повтор точки, не
  та точка для пары, не тот порядок).

Формы помощников по-прежнему требуют ровно три bind.

## Что проверить ревьюеру

* `buildBinds` дописывает `…:ro` для разрешённого тома и бросает исключение для
  неразрешённого (тесты сервера).
* `buildBinds` дописывает три привязки среды по настоящему пути внутри единого
  монтирования бота (единое монтирование, общая область, контракт `1`) и
  возвращает только фиксированную привязку, когда настройка экземпляра не
  задана; проверка занятых путей пропускает три поддерева данных владельца и
  ничего больше.
* dockergate принимает пары среды только под `botRuntimeRoot` и только по этому
  настоящему пути — другой корень, другой подкаталог, другая точка
  монтирования или `rw` отклоняются — и принимает том класса J по его
  настоящему пути, отклоняя поддеревья среды (тесты `policy`).
* `docker-driver` кладёт дополнительный том в `HostConfig.Binds`, а
  `containerTemplateDrifted` сообщает о расхождении при смене списка bind
  (правка карточки пересоздаёт бота).
* dockergate принимает разрешённый read-only bind от начала до конца и
  отклоняет источник вне `mountSources` до обращения к демону.

## Чего в этой правке нет

* Записываемого дополнительного тома (общий каталог, в который пишут несколько
  ботов, требует отдельного проекта: владелец, блокировки, одновременная
  запись).
* Значений `extraMounts` по умолчанию для проекта (направления): настройка
  живёт в карточке агента, а не в проекте.
* Поля интерфейса для `extraMounts` в разделе «Container» карточки — значение
  пока вводится в `adapterConfig`.
* Монтирования отдельного файла (поддерживаются только каталоги) и монтирования
  несуществующего на хосте каталога (Docker создал бы его как root, 0755).
