# Аудит базы доски 1.6.5 (db-audit)

Правило владельца 08.10.2026 (`doc/RELEASE-CHECKLIST.md`, раздел «Database audit (required
before every final tag)», коммит 33a653ad1): финальный тег (без суффикса `-rc`) выходит
только с принятым аудитом базы; отчёт лежит по адресу
`docs/myrmidon/releases/<версия>-db-audit.md` — то есть здесь. `-rc`-кандидаты аудита не
требуют. 1.6.5 — кандидат, поэтому гейт `scripts/myrmidon/release/db-audit-gate.sh` в этом
релизе работает в режиме **предупреждения**: находки печатаются, релиз не блокируется.
Финальный тег 1.6.5 ставится, когда «после» (§5) измерено на бою и файл обновлён.

Первый ручной снимок — аудит OPE-4270 (документ `db-audit` на доске, issue
`b0b82f79-3317-4ad2-b818-5ac6b9955177`). Начиная с 1.6.5 числа собирает сама доска:
модуль `server/src/myrmidon/datastore-care/` раз в час пишет снимок в `datastore_snapshots`
и по кнопке — отчёт аудита в `datastore_audit_reports` (свой срок хранения 90 дней), а
`GET /api/myrmidon/audit-reports/<id>/export` отдаёт отчёт в markdown.
Этот файл обновляется из такого отчёта (или ручного замера того же часа).

  было: ниже — числа снимка, каждое со ссылкой на источник.
- Дополнительные замеры, которых в ручном снимке нет (снимает оператор):

## 6. Срез «после»: как подтверждается

Приёмка по правилу — «после» снимается на живой базе и показывает улучшение аудированных
запросов. Шаги:

1. Выкатить релиз (индексы 0302/0306 и, в поезде 1.6.5, 0310 — таблицы модуля).
2. Снять отчёт из функции доски — он и есть срез того часа:

   ```sh
   curl -sS -H "Authorization: Bearer $PAPERCLIP_API_KEY" \
     "$PAPERCLIP_API_URL/api/myrmidon/audit-reports/<id>/export" > db-audit-export.md
   ```

3. Сверить с ручным `psql` в тот же час (расхождение ≤ 1 %):

   ```sql
   SELECT pg_size_pretty(pg_database_size(current_database()));
   SELECT pg_size_pretty(pg_total_relation_size('heartbeat_runs'));
   ```

4. Прогнать гейт: `bash scripts/myrmidon/release/db-audit-gate.sh --report report.json --mode warn`
   (1.6.5; со следующего релиза — `--mode block --strict`).
5. Снять `EXPLAIN (ANALYZE, BUFFERS)` для queryid 5993294684042321117 и повторить срез
   топ-25 запросов; расхождения убрать из §2–§4, «после» внести сюда же.

С 1.6.5 снимки идут сами каждые 24 часа (24 снимка/сутки) с сроком 90 дней, так что
повторные окна наблюдений для шагов 2–5 собираются без ручной работы.

## 7. Открытые вопросы

- `scripts/myrmidon/deploy/db-tuning.sql` (чек-лист называет его местом для параметров
  аудита) в репозитории отсутствует — его заводит тот, кто ведёт параметры (DBC-2/DBC-3);
  до этого параметры из §5 применяет оператор вручную по этому файлу.
- «После» на боевой базе снимает оператор/владелец на выкаченном релизе — это единственный
  оставшийся шаг перед финальным тегом 1.6.5.
- Удаление 730 неиспользуемых индексов и партиционирование — отдельные задачи, в
  DBC-1…DBC-4 не входят.
