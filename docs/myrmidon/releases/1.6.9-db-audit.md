# Аудит базы доски 1.6.9 (db-audit)

Правило владельца 08.10.2026: финальный тег, без суффикса `-rc`, выходит только с принятым аудитом базы. Отчёт лежит в `docs/myrmidon/releases/<версия>-db-audit.md`, то есть здесь. Гейт — `scripts/myrmidon/release/db-audit-gate.sh`.

## 1. Происхождение

- Автоотчёт модуля datastore-care (DBC-4): `POST /api/myrmidon/datastores/board/audit-reports` и экспорт `GET /api/myrmidon/audit-reports/45108c8d-d21e-44db-a95e-97188e0f4bf3/export`. Сформирован 2026-11-13T12:16:33Z на бою 1.6.9-rc.1 (коммит `88481a0193`), запрос — вручную (`manual`), перед финальным тегом.
- База: PostgreSQL 18.6, объём 27.7 GiB (в аудите 1.6.8 — 27.6 GiB).
- Снимок только на чтение. Мутаций при подготовке файла не было.

## 2. Вердикт гейта

`db-audit-gate.sh --mode warn`: норма 12, внимание 7, нарушение 0, нет данных 0. Отчёту 0 часов. Режим предупреждения (правило 1.6.5): выпуск не блокируется.

По сравнению с 1.6.8 (там было норма 11, внимание 8): критерий `growth-24h` теперь в норме, +0.22 % (3.9 MiB за 1.5 ч). Критерий `dead-tuples` по-прежнему с предупреждением, но по другой таблице: в 1.6.8 это была `execution_workspaces` (16.4 %), теперь `issue_claims` (11.7 %, 13961 мёртвых строк).

## 3. Рост базы

Причина роста базы, найденная в аудите 1.6.8 (запись аудита секретов в `secret_access_events` при сверке слотов шлюза), устранена в 1.6.8 (OPE-12890). С тех пор размер базы 27.6 → 27.7 GiB.

Поток записей в `secret_access_events` после выката 1.6.9-rc.1 (проверка после выката, 13.11 19:58 по Иркутску, UTC+8): 412 строк за час и 41 за 10 минут.

Место в файлах таблицы само не вернётся (в отчёте `secret_access_events` — 6.2 GiB, 12 847 728 живых строк); возврат места и сроки хранения — OPE-12979.

## 4. Предупреждения

| Критерий | Значение | Порог | Что делаем |
|---|---|---|---|
| db-size | 27.7 GiB | ≤ 8.0 GiB | причина роста устранена в 1.6.8 (раздел 3); возврат места и сроки хранения — OPE-12979 |
| cache-hit | 94.856 % | ≥ 99 % | следствие размера базы; вместе с ним — OPE-12979 |
| unused-indexes | 656 из 1208 (54.3 %), 410 MiB | ≤ 20 %, ≤ 512 МиБ | объём в пороге (в 1.6.8 — 658 из 1208, 410 MiB); удаление миграцией продолжается — OPE-12580 |
| dead-tuples | issue_claims: 11.7 % (13961) | ≤ 10 % | тот же класс, что в 1.6.8 (настройка autovacuum по таблице), идёт в OPE-12979 |
| autovacuum-vacuum / analyze | 0.2 / 0.1 | ≤ 0.05 | настройки базы — через предложение и окно обслуживания, OPE-12979 |
| work-mem | 32.0 MiB | ≤ 16 МиБ | пересмотреть значение сервера или порог критерия — OPE-12979 |

Ни одно предупреждение выпуск не блокирует: гейт в режиме предупреждения, правило 1.6.5.

## 5. Замечания к самому автоотчёту

- Единицы `work_mem` показаны верно: 32.0 MiB (в отчёте 32768 kB).
- Критерий `pgvector-indexed` показывает «1 из 1».
- Критерий `backup-freshness` учитывает внешнее покрытие (`vm-pbs`, ночной снимок ВМ) и даёт «норма».

## 6. Вывод

Нарушений нет, предупреждения выпуск не блокируют (гейт в режиме предупреждения). Рост базы из-за записи аудита секретов устранён в 1.6.8, поток после выката 1.6.9-rc.1 — 412 строк за час. Принятие аудита и разрешение финального тега `myr-v1.6.9` — за владельцем.
