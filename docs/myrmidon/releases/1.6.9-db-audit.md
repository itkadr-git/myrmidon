# Аудит базы доски 1.6.9 (db-audit)

Правило владельца 08.10.2026: финальный тег, без суффикса `-rc`, выходит только с принятым аудитом базы. Отчёт лежит в `docs/myrmidon/releases/<версия>-db-audit.md`, то есть здесь. Гейт — `scripts/myrmidon/release/db-audit-gate.sh`.

## 1. Происхождение

- Автоотчёт модуля datastore-care (DBC-4): `POST /api/myrmidon/datastores/board/audit-reports` и экспорт `GET /api/myrmidon/audit-reports/f8577d89-cb59-4473-8c7c-f5039dd6e81a/export`. Сформирован 2026-11-14T14:22:41Z на бою 1.6.9-rc.5 (тег `myr-v1.6.9-rc.5`, коммит `723cb0ba8`), сразу после 2 часов работы кандидата под нагрузкой. Запрос — вручную (`manual`), перед финальным тегом.
- База: PostgreSQL 18.6, объём 27.9 GiB (на rc.1 13.11 — 27.7 GiB, в аудите 1.6.8 — 27.6 GiB).
- Снимок только на чтение. Мутаций при подготовке файла не было.

## 2. Вердикт гейта

`db-audit-gate.sh --mode warn`: норма 12, внимание 7, нарушение 0, нет данных 0. Отчёту 0 часов. Режим предупреждения (правило 1.6.5): выпуск не блокируется.

По сравнению с аудитом на rc.1 счёт тот же (норма 12, внимание 7). Критерий `dead-tuples` по-прежнему с предупреждением, теперь по таблице `connection_event_deliveries`: 15.8 %, 11 827 мёртвых строк. На rc.1 это была `issue_claims`, 11.7 %. `growth-24h` в норме: +1.94 % на коротком окне 0.4 ч (9.5 MiB).

## 3. Рост базы

Причина роста базы, найденная в аудите 1.6.8 (запись аудита секретов в `secret_access_events` при сверке слотов шлюза), устранена в 1.6.8 (OPE-12890). С тех пор размер 27.6 → 27.9 GiB за двое суток.

Поток записей в `secret_access_events` на rc.5 (14.11 22:23 по Иркутску, UTC+8): 1894 строки за час, 401 — за 10 минут. На rc.1 было 412 за час, то есть поток вырос примерно в 4,6 раза. Это около 45 тыс. строк в сутки при 12,8 млн строк в таблице, так что на размер базы заметно не влияет. Рост потока — в OPE-12979 вместе с возвратом места.

Место в файлах таблицы само не вернётся (в отчёте `secret_access_events` — 6.3 GiB, 12 848 905 живых строк); возврат места и сроки хранения — OPE-12979.
