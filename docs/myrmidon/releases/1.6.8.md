# Release 1.6.8 — operator notes

> Russian version: [1.6.8.ru.md](1.6.8.ru.md)

This page is for the operator upgrading a board to 1.6.8: what changed, what is on by default, and what needs a switch or a host step. The changelog section
([../CHANGELOG.md](../CHANGELOG.md), "1.6.8") has 99 entries; here are the ones that change what the operator sees or does, each traced to its entry
(task number in brackets) and the linked guides. The full deploy procedure is [../deploy.md](../deploy.md); every setting named below is listed with defaults in
[../SETTINGS.md](../SETTINGS.md). The database audit report of this release is
[1.6.8-db-audit.md](https://github.com/itkadr-git/myrmidon/blob/myr-v1.6.8/docs/myrmidon/releases/1.6.8-db-audit.md).

## Operator actions at the update

Do these in addition to the usual deploy. Each one is explained in the sections below.

1. **Roll the components out together.** The board, dockergate, fleetd and the bot images are deployed from one tag, together
   ([../deploy.md](../deploy.md), "Deploy the board and the release components together"). Two orderings in this release depend on it:
   dockergate goes together with or before the board (the shared pnpm store, OPE-12869); the new fleetd binary goes before the configuration that uses
   `writableMountRoots`.
2. **Shared pnpm store (OPE-12869).** Create `<packageCacheRoot>/pnpm-store` owned by `10001:10001` on the bots' filesystem, and deploy
   dockergate together with or before the board (details below).
3. **omp SSH runner `tmp` volume (OPE-12966).** Create `tmp/` with mode `1777` next to `workspace/`, `home/` and `hostkeys/` before the first start. A running
   runner needs the volume added to its compose file and a recreate.
4. **Host GC runner root (OPE-12966, OPE-12722, OPE-12903).** The new host GC passes for the omp runners (the runner `tmp`, run copies, task folders of closed
   issues) run only when a runner root is configured (`--runner-root` or `HOST_GC_RUNNER_ROOTS`).
5. **dockergate `inspectOnlyImages` and the stack registry (OPE-12922).** List the exact image refs the stack registry may inspect in `inspectOnlyImages`
   (applied on `SIGHUP`); set `MYRMIDON_STACK_IMAGE_<NAME>` for each such component and point `MYRMIDON_STACK_DOCKER_SOCKET` at the dockergate socket.
6. **Bots of agents that left the bot runtime (OPE-12654).** The board now decommissions them by itself every 10 minutes; the host GC pass removes their data
   directories. Check the `bot_decommission_held` / `bot-data-held-unpushed` lines for bots that are held.
7. **Bot resource ceilings (OPE-12337).** A card with memory, CPU or pids above the dockergate ceiling is refused at save time with 422: raise
   `bots[].maxMemoryMb` in dockergate `config.json` and reload dockergate (`SIGHUP`).
8. **Read-only dockergate config (OPE-12383).** Ceiling updates are written to the file named by `limitsOverrideFile`; without a writable one the update is
   refused with `config_read_only` (403).
9. **fleetd on a remote site.** An extra writable mount needs `writableMountRoots`; the container template of the board host
   reaches an existing container at its next recreate.
10. **Renamed variables (OPE-12652).** Check your own env files and unit files for `PAPERCLIP_OMP_PROVIDERS` / `PAPERCLIP_OMP_COMMAND` and the other renamed
    names; the old names work for one release as deprecated aliases.
11. **Agent keys that write company behaviour settings (OPE-12699).** An agent key needs an explicit `users:manage_permissions` grant for the company.
12. **Deleting agents (OPE-12475).** An agent with recorded cost events cannot be deleted (409 `agent_has_cost_events`); terminate it.
13. **GitHub App webhook (GITHUB-APP-WEBHOOK, OPE-12868).** To receive CI and pull-request events from the shared GitHub App, register the webhook through
    `webhook-sync`; keep **Active** on in the App's webhook settings on GitHub.
14. **Bot images.** Running bot containers keep the old runtime (for example the old `skill_view` resolver, OPE-12719) until they are recreated by the rollout.

## What changes at the deploy

- **Deploy lock (OPE-12335).** `deploy.sh` takes an exclusive `flock` at the start. If the lock is held it exits at once with code 42 and prints the holder's
  PID, start time and version, or waits when `MYRMIDON_DEPLOY_LOCK_WAIT_SEC` is above 0 (default 0). The lock file is `MYRMIDON_DEPLOY_LOCK_FILE` (default
  `$STATE_DIR/deploy.lock` or `/var/lib/myrmidon/deploy/deploy.lock`). `--dry-run` only warns when the lock is held.
- **Image cleanup after a deploy (OPE-12664).** A successful product deploy removes unused `myrmidon*` and `agent-runtime*` images from the deploy host
  (a container in any state keeps its image). It does not run when the deploy fails; a cleanup failure is logged and does not change the deploy result.
- **Host disk signal (OPE-12664, OPE-12958).** The signal measures the root filesystem and `/srv/myrmidon-xfs`: a warning above 85%, a critical signal above
  90% with the largest consumers. The `host.disk_threshold_exceeded` line is now written per company (before, the write failed on every sweep).
- **Compose-set anchor (OPE-7010).** After the board health check the deploy compares the live compose file set with the `board-mount-set` block of the
  anchor file and, when they differ, rewrites the block and commits it. Optional: `MYRMIDON_COMPOSE_SET_ANCHOR_FILE`, `MYRMIDON_COMPOSE_SET_ANCHOR_GIT`,
  `MYRMIDON_COMPOSE_SET_LABEL_SOURCE`; an empty anchor-file setting skips it, and a malformed anchor is a warning that never fails a healthy deploy.
- **Post-deploy bot smoke (OPE-12609, OPE-12716).** `bot-apply-smoke.sh` no longer reports idle-stopped bots as crashed (the health mark counts only for a
  container that is not exited, dead or created), counts an `OOMKilled` only when it falls inside the deploy window, and verifies bots pinned to another host
  by their own gateway `/health`. A single OOM of a container the rollout did not touch is a `WARNING`; two or more untouched OOMs, or any OOM of a container
  the rollout recreated, still fail the deploy.
- **dockergate (OPE-12959, OPE-12922, OPE-12654, OPE-12383).** `inspectOnlyImages` (read-only image inspect for exact refs, applied on `SIGHUP`); route A22
  `DELETE containers/myrmidon-bot-<K>?force=true&v=true&myrmidon-decommission=true` for a stopped main container; `limitsOverrideFile` for the mutable per-bot
  limits (fresh installs point it at `/run/myrmidon-dockergate-state/limits.json`); the expected refusal to drop a quota entry while the data directory exists is
  now the informational event `disk_project_still_has_directory`, not an error. See [../dockergate.md](../dockergate.md).
- **Shared pnpm store (OPE-12869).** OPE-12720, in the same section, had moved the store into each bot's tree; OPE-12869 replaces it, and the steps below follow
  OPE-12869. The store is one directory for all bots: `<sharedPackageCachePath>/pnpm-store` bound read-write at `/cache/pnpm-store` (the sixth pair of the
  package cache mounts). The cache root must be on the same XFS filesystem as the bot volumes (outside `MYRMIDON_BOT_VOLUME_ROOT`, for example
  `/srv/myrmidon-xfs/package-cache`), because pnpm imports `node_modules` by reflink and a reflink works within one filesystem; the board cannot see the host
  filesystems, so this is an operator requirement, and the bot image's start-time reflink self-check (`hardlink-check.json`) reports a store on another
  filesystem. Steps: create `<packageCacheRoot>/pnpm-store` owned by `10001:10001`; deploy dockergate together with or before the board (the old dockergate
  refuses the bind with `mount_source_not_allowed`); then the board. In an existing clone the first `pnpm install` purges `node_modules` and reinstalls from the
  shared store; the bot image's pnpm wrapper passes `--config.confirm-modules-purge=false` so this works without a TTY. The per-bot `workspace/.pnpm-store`
  directories are unused afterwards and can be removed. Acceptance check: compare `df` of the bot partition before and after a fresh `pnpm install` in a new
  clone (`du -xs node_modules` counts a linked file in full and is not a check).
- **Lead role in shared caches (OPE-12384).** `general.botDisk.sharedCacheRoles` now includes `lead`; the lead bots are recreated with the shared cache mounts at
  the next reconcile pass. `sharedBotRuntimePath` shares only `bin` read-only (OPE-12493; dockergate `BotRuntimeMounts` accepts only `bin`).

## omp SSH runner

- **Own container (OMP-SSH-RUNNER, OPE-12633).** New image `agent-runtime-omp-ssh` (Bun, omp, pnpm, the GitHub CLI, a C toolchain, key-only sshd on port 2222).
  An `omp_local` agent is attached to a board SSH environment that points at one runner container per agent (template `docker/agent-runtime/omp-ssh/compose.yml`;
  default limits 4 GB, 1 CPU, 1024 processes). The procedure is the "OMP SSH Runner" section of `docker/agent-runtime/README.md`.
- **Data on the data disk (OPE-12664, OPE-12966).** The template keeps workspace, home and host key under `OMP_RUNNER_DATA_DIR` as bind volumes, and binds
  `${OMP_RUNNER_DATA_DIR}/tmp` at `/tmp` (create it with mode `1777` before the first start).
- **Shared package cache (OPE-12722).** Optional `OMP_RUNNER_CACHE_DIR` (default `${OMP_RUNNER_DATA_DIR}/cache`, private to the runner); to share the board's
  cache set it to `general.botDisk.sharedPackageCachePath`. It binds `<dir>/git` at `/cache/git` (read-only, owned by the board's user, created before the first
  start) and `<dir>/pnpm-omp` at `/cache/pnpm` (read-write, owned by uid 1000). The runner has its own `pnpm-omp` directory because `<dir>/pnpm` belongs to the
  bots (uid 10001). Acceptance measure: a `df` delta of the data disk, not `du`.
- **Run copies (OPE-12633, OPE-12664, OPE-12727).** The run's directory `<remote workspace>/.paperclip-runtime/runs/<runId>` is removed at every end of the run
  (also when the restore fails or the upload fails before the run starts); copies older than four hours are pruned when the next run starts (before: two days).
  The board's `/tmp/paperclip-ssh-sync-back-*` staging copies are removed after a restore and those older than four hours with the next restore.
- **Workspace sync (OMP-GIT-ONLY-SYNC).** `workspaceSync: "git_checkout"` transfers only the Git bundle and checkout; the default `full` is unchanged and a
  non-Git workspace falls back to `full`.
- **Sandbox (OMP-HARDEN).** `omp_local` supports `filesystemScope: "workspace"` (Bubblewrap), `networkScope: "deny" | "allowlist"` with `networkAllowlist`,
  `filesystemExtraPaths`, `filesystemSandboxCommand` (default `bwrap`); new `omp_local` agents default to the `workspace` scope; editing these keys needs an
  instance admin. Bubblewrap that cannot create a Linux user namespace fails the launch before the agent starts.
- **Host GC (OPE-12966, OPE-12722, OPE-12903).** `scripts/myrmidon/host-gc/host-clone-cache-gc.mjs` removes top-level entries of `<runner root>/<runner>/tmp`
  untouched for 24 hours (`--runner-tmp-ttl`, at least 3), run copies older than 4 hours (`--run-copy-ttl`, at least 3) and task folders of done or cancelled
  issues (a folder whose Git state cannot be proven clean and pushed is archived first). All three run only when a runner root is configured (`--runner-root` or
  `HOST_GC_RUNNER_ROOTS`); the repository's systemd unit sets the variable. A host that runs the script through its own wrapper must configure the root itself,
  and a wrapper that calls the script once per bot root should pass `--runner-root` on one invocation only, otherwise the pass repeats per bot.
- **Bridge poll (OPE-12727).** On the SSH transport one poll blocks remotely up to five seconds; `MYRMIDON_BRIDGE_QUEUE_POLL_IDLE_MS` tunes it (`0` restores the
  old per-poll behaviour).
- **Other fixes.** An SSH or tar transfer stream that closes early no longer crashes the board (SSH-STDIN-EPIPE); the restore merge no longer walks the whole
  target under the lock, and the lock wait is 10 minutes (OPE-12793).

## Bots and bot containers

- **Decommissioning (OPE-12654).** An agent whose card moved from `hermes_gateway` to another adapter, or that was terminated, used to drop out of every bot
  listing and left its container and data directory. The reconcile sweep now finds such bots every 10 minutes and stops and deletes the container with its
  leftovers. A bot is held (log line `bot_decommission_held`) while its agent has a running heartbeat run, while its clone-hygiene report shows unpushed work, or
  when it is running without a usable report. dockergate does not remove `<volumeRoot>/<K>`; it logs `bot_data_left_for_host_gc`, and the host GC pass removes the
  directory 24 hours after its last change, only when no `myrmidon-bot-<key>` container of any state remains, the board lists no `hermes_gateway` card for the
  agent, no run of the agent is `running` and no worktree under the directory holds unpushed work (otherwise `bot-data-held-unpushed`); an unreachable docker
  daemon or board keeps the directories. Terminating or deleting an agent goes through the same route; a bot on a fleetd site still goes through the site's
  cleanup (OPE-12323: fail-closed, the terminate or delete answers an error and keeps the agent record if the cleanup fails).
- **Resources (OPE-12337).** `GET /api/myrmidon/agents/:id/bot-container/status` and the agent card show the running container's actual limits next to the card's
  and warn on divergence.
- **Idle stop on fleetd (OPE-12663).** fleetd gets `POST /v1/bots/<key>/stopIdle` and the `idle-stopped.json` mark; IDLE-STOP now works for bots on a fleetd
  host. Non-hermes agents skip the bot container check on a transient retry (OPE-12269).
- **Quotas in botd (OPE-12110, BOT-DISK).** `hermes/.npm/_npx`: entries older than 24 hours go, the rest is kept within 512 MiB
  (`MYRMIDON_BOTD_NPM_NPX_QUOTA_BYTES`); `hermes/.cache/cargo-target`: 2 GiB (`MYRMIDON_BOTD_CARGO_TARGET_QUOTA_BYTES`); `hermes/.npm/_cacache`: 512 MiB.
  A quota can stay exceeded for one pass (nothing written in the last 15 minutes is touched).
- **Runtime fixes (bot image rollout).** `gh` 2.103.3 in every bot image (OPE-10494); patched aiohttp 3.14.5, httpx2 2.12.0, certifi 2026.10.19, and the build
  fails below them (OPE-12760); `skill_view` resolves `paperclip-managed:<slug>` (OPE-12719); a failed idempotency-store write is rolled back so a bot recovers
  after a full disk (OPE-12759); the repeated tool failure limit counts only the same call failing again (OPE-12796); botd git-base repack works on partial
  clones (OPE-12263).
- **fleetd on a remote site.** A safe marker read (no symlink, FIFO, directory or file over 64 KiB); the board host's container template (`/tmp` tmpfs, init,
  `on-failure` restart, `MemorySwap` = `Memory`); a spec with `cpus` below 0.01, a `gatewayPort` outside 1024-65535 or a foreign `boardExtraHost` is refused
  with `spec_invalid`; new key `writableMountRoots` (default empty); the memory leak is fixed (OPE-12923).

## Behavior that changes without a switch

- **Review (OPE-12683, OPE-12780, OPE-12859, OPE-10084).** A review or approval participant must be an agent of the task's own group (`swarmQueueEligible` not
  `false`), else 422 `invalid_review_participant`; with no eligible reviewer nothing is moved and the `no_reviewer` card is raised. The review pool includes
  `lead`; the least loaded participant is chosen and pending stages waiting longer than `rebalanceAfterMinutes` move to an idle pool member. When the recorded
  verdict already covers the current pull request head, the reviewer is not woken while CI is pending.
- **Run guard (OPE-12577, OPE-12796, OPE-12808).** The manager's wake after a final run guard stop passes the execution hold; a run interrupted by the stall
  sweep keeps its credentials for `MYRMIDON_RUN_STALL_GRACE_SEC` (default 600).
- **Run leases and masking (OPE-12578, OPE-12579, OPE-12557).** A passed controller lease is checked against the database before a run is cancelled; secret
  masking of long unbroken lines is bounded; advisory-lock transactions no longer take a second pool connection and at most two locked conversation deliveries
  run at once per process.
- **Retries (OPE-12286, OPE-9497).** Provider stub replies are detected as `provider_garbage` and retried with a pause (`MYRMIDON_PROVIDER_GARBAGE_RETRY_MAX_ATTEMPTS`,
  default 3; `MYRMIDON_PROVIDER_GARBAGE_RETRY_DELAY_MS`, default 300000 ms); deployment cooldown and HTTP 429 delay the retry instead of waking at once
  ([../guides/deployment-cooldown-retries.md](../guides/deployment-cooldown-retries.md)).
- **Task cards.** The server refuses an incomplete card with 422 `task_card_not_ready` in `enforce` mode (a warning in the log during the 3-day grace period or with
  `MYRMIDON_TASK_CARD_GATE_MODE=warning`); paths in «МЕСТО ПРАВКИ» that are absent on the default branch give `EDIT_TARGET_NOT_FOUND` (422 in `enforce`), and a
  network error or missing GitHub connection only warns (`EDIT_TARGET_UNVERIFIED`).
- **Agents (OPE-12475, OPE-12699, OPE-12675, OPE-12270).** Deleting an agent with cost events: 409 `agent_has_cost_events`; remaining references: 409
  `agent_referenced`. Company behaviour-settings writes by an agent key need `users:manage_permissions`. `tokens-trace` routes check company access first. A value
  containing `***REDACTED***` is refused on write (422).
- **Lists and wakes (OPE-12210, OPE-12197, OPE-12846, OPE-9590, OPE-12725, OPE-12204).** `GET /api/companies/:id/heartbeat-runs` defaults to `limit` 200 (max 1000)
  with a `before` cursor and `X-Next-Cursor`; the private-task wake reason is `heartbeat.private_issue_suppressed`; ready tasks of a caste with no staffed agent
  go to the default role; a running watchdog task does not count as live work of its own task; stuck `triggered` issue monitors are swept (a timeout wakes the
  assignee with `issue_monitor_timeout`); a queued run keeps its scheduled retry when the environment lease is released.
- **GitHub reads (OPE-12397, OPE-12446, OPE-12537, OPE-12890).** The board caches pull request and CI reads and sends nothing while the shared rate limit is
  exhausted (`MYRMIDON_GITHUB_OBJECT_CACHE_TTL_SEC` 120, `MYRMIDON_GITHUB_OBJECT_TERMINAL_TTL_SEC` 1800, `MYRMIDON_REVIEW_CI_PULL_CACHE_TTL_SEC` 60,
  `MYRMIDON_REVIEW_CI_COMPLETE_CACHE_TTL_SEC` 600; `0` turns a cache off); the review-return loop paces by `sweepIntervalSec` (default 300, range 60–3600, Review
  Rework panel; `MYRMIDON_REVIEW_REWORK_SWEEP_INTERVAL_SEC` overrides it); installation tokens are cached 50 minutes and the per-run credentials fuse is
  `MYRMIDON_GITHUB_CREDENTIALS_FUSE_PER_MINUTE` (default 60). Fewer secret resolutions write far fewer `secret_access_events` rows (OPE-12890, OPE-12537); see the
  [database audit](https://github.com/itkadr-git/myrmidon/blob/myr-v1.6.8/docs/myrmidon/releases/1.6.8-db-audit.md) for the table size and the follow-up in OPE-12979.
- **Main CI.** Pushes to `main` no longer cancel the running main run (one running and one pending run).

## Signals and screens

- **Attention (OPE-12709, OPE-12868).** `role_model_down` (a whole role has no working model channel: at least 5 finished runs in 30 minutes, none succeeded, at
  least 5 model refusals) and `provider_no_credits` (a no-credits marker in a run error, one card per channel), both critical, both delivered through the board
  errors Telegram channel at most once per hour; the agent list and card show «model unavailable since HH:MM» (`roleModelDownSince`). The critical card
  `github_app_webhook_disabled` appears when `webhook-sync` gets 404 from GitHub (Active is off) and clears after a later successful sync.
- **Instance → General.** The "Workspace hygiene" panel (OPE-6249): `workspaceQuotaMb` and `totalQuotaMb`, saved without a restart. The Review Rework panel edits
  `sweepIntervalSec`. 
- **Stack registry (OPE-12141, OPE-12718, OPE-12922, 1.7-STACK-UPDATES-B, OPE-12044, OPE-12957).** The scheduled check reads running versions from
  `MYRMIDON_STACK_HTTP_HINDSIGHT`, `MYRMIDON_STACK_HTTP_LITELLM`, `MYRMIDON_STACK_HTTP_LANGFUSE`; a GitHub 403 is retried once and otherwise marked stale; a
  `stack_update` card lives while the component is behind; a backlog draft (`todo`, `originKind stack_update`, deduplicated per component) is created when a
  component lags by `MYRMIDON_STACK_BACKLOG_LAG_RELEASES` (default 2) releases or carries a critical security note; advisories come from OSV.dev
  (`MYRMIDON_STACK_OSV_API_BASE`); the release reconciliation reads `MYRMIDON_VENDOR_GITHUB_REPO`, `MYRMIDON_GITHUB_API_BASE`, `MYRMIDON_VENDOR_TAG`,
  `MYRMIDON_RELEASE_RECONCILIATION_INTERVAL_SEC`, `MYRMIDON_RELEASE_TASK_COMPANY_ID`; `POST /api/myrmidon/stack/refresh` and `/check` run on the main board
  process. See [../stack-updates.md](../stack-updates.md).
- **GitHub App events (GITHUB-APP-WEBHOOK).** `POST /api/myrmidon/github-app/webhook` takes check_run, check_suite, workflow_run and pull_request deliveries
  (verified by `X-Hub-Signature-256`); the App entry gets `webhookSecretId`, and `POST /api/myrmidon/companies/:companyId/github-shared-identity/apps/:entryId/webhook-sync`
  with `{ webhookUrl }` creates the secret once and sets the App's webhook.
- **Model Providers screen (OPE-12361, OPE-10775).** The screen and the fallback editor are fully translated and show real pool counters. Codex / ChatGPT pool accounts: Codex / ChatGPT pool accounts: OAuth from the board UI, plans (`Plus`, `Pro`, `K-12`), 5-hour and 7-day quota windows, rotation
  that removes banned and exhausted accounts, and attention signals for them.
- **Corpus (OPE-12058, OPE-12372).** A failed document is parsed again with the «Reparse» button; embedding calls are retried once.
- **Datastore care audit (OPE-12248).** `MYRMIDON_DATASTORE_CARE_BACKUP_EXTERNAL` (a coverage label) makes `backup-freshness` report the external
  coverage and skip the local backup directory; `work_mem` units and the pgvector `relkind` filter are corrected.
- **Other.** Hindsight plugin request timeout 60 s, `requestTimeoutMs` (OPE-8150); an informational docs reminder comment on pull requests that change the
  API or schema without a change fragment; `MYRMIDON_*` names for the variables Myrmidon introduced (OPE-12652; `scripts/myrmidon/ci/paperclip-names-ratchet.mjs`
  guards new `PAPERCLIP_*` names).
