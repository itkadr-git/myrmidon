# Выпуск 1.6.6 — заметки для оператора

> English version: [1.6.6.md](1.6.6.md)

Страница для оператора, который обновляет доску до 1.6.6: что изменилось, что включено по умолчанию и что требует переключателя или шага на хосте. В разделе «1.6.6» журнала изменений
([../CHANGELOG.ru.md](../CHANGELOG.ru.md)) около трёхсот записей; здесь собраны те, что меняют то, что оператор видит или делает, каждая со ссылкой на свою запись и руководства.
Полная процедура выката — [../deploy.ru.md](../deploy.ru.md); каждая названная ниже настройка с умолчаниями перечислена в [../SETTINGS.ru.md](../SETTINGS.ru.md).

## Что меняется при выкате

- **Предпроверка диска.** `deploy_disk_precheck` добавляет к требуемому свободному месту размер в реестре каждого образа релиза, которого нет на хосте, до первого pull и до окна обслуживания и отказывает, если выкат не помещается (кандидаты на очистку печатаются; отказ и тогда, когда размер образа не удалось узнать из реестра, а `--dry-run` лишь предупреждает). Запас под предварительную копию базы — `MYRMIDON_DEPLOY_DB_DUMP_RESERVE_GB` (по умолчанию 5); он действует на полные выкаты, объявляющие `MYRMIDON_DEPLOY_IMAGE_REFS`, а `bot-image-rollout.sh` и `rollout-component.sh` сохраняют обычный порог `MYRMIDON_DEPLOY_MIN_FREE_GB`. Одноразовая копия базы ограничивается по скорости на устройстве данных Docker (`MYRMIDON_PREDEPLOY_IO_DEVICE`, `MYRMIDON_PREDEPLOY_IO_RATE`; PREDEPLOY-IO).
- **Очистка образов.** Шаг очистки считал своё окно по образам, которыми не пользуется ни один контейнер, и потому оставлял по два вытесненных поколения каждого образа бота поверх запущенного. Теперь он оставляет текущий релиз плюс `MYRMIDON_DEPLOY_IMAGE_KEEP` предыдущих.
- **Установщик.** Установщик одной командой вносит имена и глобальные адреса IPv4 машины в список допустимых адресов доски (`MYRMIDON_ALLOWED_HOSTNAMES`; `MYRMIDON_ALLOWED_HOSTS` через запятую заменяет найденный список), отказывает процессору ниже базового уровня x86-64-v2 до любых действий на машине, подключает службу dockergate, поднимает базу из образа pgvector и включает расширение до старта доски (версия не `0.8.7` — установка завершается ошибкой).
- **Публикация релиза.** Раздел заметок длиннее лимита GitHub в 125000 символов публикуется списком заголовков записей со ссылкой на полный журнал; бюджет ожидания CI тега — 80 минут; нарезка релиза падает, если в журнале нет раздела `## X.Y.Z`.
- **Раскатка образов ботов.** Лимиты памяти, процессора и числа процессов бота доходят до запущенного контейнера живым обновлением без перезапуска; изменения навыков доходят до запущенного контейнера без перезапуска; раскатка ждёт завершения прерванного прогона (запас опроса слива — 120 с).
- **База данных.** 61 миграция (`0389` … `0462`). `0401_wakeup_key_partial_unique_indexes` сначала чинит дубли ключей побудок `pause_resume:` и повтора застрявших задач (ключ остаётся у самой содержательной побудки с прогоном, идущая работа не отменяется). `0462_pull_request_work_product_url_backfill` заполняет `url` / `external_id` рабочих продуктов pull request из их метаданных. `0404_install_identity` хранит идентификатор установки (см. «Лицензирование»).

## Поведение, которое меняется без переключателя

- **Простаивающие контейнеры останавливаются (IDLE-STOP, OPE-7898).** Контейнер бота без активного прогона 30 минут (`MYRMIDON_IDLE_STOP_AFTER_SEC`, по умолчанию 1800, минимум 60) останавливается; перед стартом принятого прогона доска поднимает его и ждёт до 7 минут (`MYRMIDON_IDLE_START_HEALTH_TIMEOUT_MS`, по умолчанию 420000), пока он станет здоровым, иначе прогон отменяется с ошибкой в журнале. Режимы по каждому боту «По требованию» и «Всегда включён» есть в карточке агента и в списке ботов в настройках экземпляра. Пока в настройках экземпляра ничего не сохранено, выключатель следует `MYRMIDON_IDLE_STOP_ENABLED` (любое значение, кроме `false`, `0`, `no`, `off`, оставляет функцию включённой).
- **Автовозобновление при «контейнер не поднят».** Сторож сначала запускает контейнер бота (четыре попытки с интервалом 15 минут, затем одна критическая карточка тревоги), затем возобновляет агента как обычно.
- **Саморегистрация закрыта по умолчанию** (`MYRMIDON_AUTH_DISABLE_SIGN_UP`, по умолчанию `true`).
- **Для `blocked` нужна причина.** Переход в `blocked` отклоняется (422 `blocked_requires_reason`), если у задачи нет открытого блокера, `blockerMetadata.blockReason` или `unblockDescriptor` с владельцем и действием. Блокер в статусе `cancelled` теперь везде считается разрешённым, как `done`. Когда закрывается последний открытый блокер и зависимую задачу больше ничто не держит, она возвращается в `todo`.
- **Задачи с кодом — только инженерам.** Создание или переназначение задачи с кодом (метка `needs-engineer`, каста инженеров, нужна живая рабочая копия) на агента с ролью не `engineer` отвечает 422 `issue_requires_engineer`; людей по-прежнему можно назначать.
- **Ворота «готово».** Задача со связанными рабочими продуктами pull request не может перейти в `done`, пока каждый связанный pull request не проверен как влитый (конфликт `issue_done_pull_request_gate`; закрытый pull request принимается, только если `metadata.replacementPullRequestUrl` называет допустимую замену).
- **Охраняемая передача.** `PATCH /api/issues/{id}` принимает необязательные `expectedAssigneeAgentId` и `expectedStatusVersion`; когда заданы оба и исполнитель меняется, обновление выполняется как сравнение с подстановкой (compare-and-set).
- **Защита прогона.** Остановка по лимиту вызовов у прогона, который что-то изменил, продолжается в следующем прогоне со своим потолком (`runtimeConfig.heartbeat.runGuardContinuation.maxAttempts`, по умолчанию 6, не больше 20); окончательная остановка защитой будит руководителя исполнителя (`run_guard_stop_needs_input`). Пределы по умолчанию для остановок по чтению: 100 / 5 для ролей `engineer`, `reviewer`, `lead`, `architect` и 40 / 3 для остальных; прогон, остановленный по `no_progress_exploration`, один раз продолжается. Автоповтор упавшего прогона — одна политика: сбой классифицируется как `transient`, `permanent` или `unknown`; временный сбой повторяется с экспоненциальной задержкой до предела попыток, постоянный — никогда, неклассифицированный сохраняет единственную попытку.
- **Дневной лимит прогонов.** Прогон из очереди, отклонённый по `heartbeat.daily_run_limit`, откладывается до конца дневного окна (плюс до 5 минут джиттера), а не отменяется; нулевой лимит, дневной лимит стоимости и ручная побудка пользователя по-прежнему отменяют.
- **Маршрутизация ревью.** Доска сама (`boardMerge.enabled`, по умолчанию `true`; базовые ветки по умолчанию `["main"]`) вливает одобренный pull request, когда его голова зелёная и вливаемая (squash, через общую идентичность GitHub App), не больше `boardMerge.maxMergesPerPass` за проход; вливание привязано к одобренной голове, а обязательная проверка `CI result` на ней должна быть `success`. Возврат ревью на той же голове или только по инфраструктурным проверкам больше не будит исполнителя; исчерпанная серия побудок ревью эскалируется один раз и снова взводится через 6 часов.
- **Побудки.** Побудка-продолжение несёт сводку, а не историю задачи три раза; побудки-продолжения идут только по задачам, по которым есть что делать, с настоящим пределом попыток; агент больше не будит сам себя собственным PATCH или учётом комментария; устаревшая доставка больше не стартует ход (охрана побудок проверяет ещё и версию задачи).
- **Список задач.** `GET /api/companies/:companyId/issues` учитывает `page` (`offset = (page - 1) * limit`); `page=0` или нечисловое значение дают 400.

## Рантайм ботов (приходит с раскаткой образов ботов)

- **Сжатие `state.db`.** `state.db` бота проходит VACUUM, когда свободно больше 25% страниц и прошло `sessions.min_vacuum_interval_days` (30) дней; он ждёт тихого момента и места, а временная копия идёт в `$HERMES_HOME/.sqlite-tmp` на томе бота, а не в tmpfs. Проверка — строка лога шлюза `state.db VACUUM: … MB -> … MB`.
- **Входные токены.** Рантайм сохраняет кэш промптов провайдера (ничего не переписывает в середине сессии и ограничивает новое); запросы несут стабильный ключ разговора, чтобы кэш пула мог срабатывать; списки инструментов по ролям убирают неиспользуемые схемы; ядро навыка Myrmidon компактно, детали по требованию. `context_economy.stale_wakes` (переписывание вытесненных сообщений побудок) по умолчанию выключено.
- **Слоты шлюза.** Доска освобождает слот шлюза у каждого прогона, который завершает, а прогоны шлюза переживают перезапуск доски (результат остаётся видимым). Потеря связи со шлюзом моделей больше не переводит прогон на резервную модель.
- **Инструменты.** `execute_code` получает `PAPERCLIP_API_KEY` / `PAPERCLIP_API_URL` через `terminal.env_passthrough` (профиль меняется, поэтому контейнеры ботов пересоздаются окном обслуживания). Боты также читают ключ и адрес доски как `MYRMIDON_API_KEY` / `MYRMIDON_API_URL` (`PAPERCLIP_*` остаются синонимами).

## Необязательные возможности (выключены по умолчанию или требуют настройки)

- **Корпус знаний и модуль знаний (KNOWLEDGE-2.0, CORPUS-2.0).** Корпус выключен (`MYRMIDON_CORPUS_ENABLED` = 0); все маршруты корпуса отвечают 503 `corpus_disabled`, пока его не включат. Нужны pgvector (выше), адрес парсера (`MYRMIDON_CORPUS_PARSER_BASE_URL`) и эмбеддер; поиск гибридный (полнотекстовый плюс векторный, HNSW с итеративным сканированием); документы можно добавлять по адресу с периодом обновления; боты ищут через MCP-инструменты `corpus_*`; `corpus_search` возвращает названия документов, ранжирует глобально по наборам и принимает имена наборов. Модуль знаний добавляет REST и MCP под одними правами, правила, дистиллятор, ночную выгрузку в Git, ворота evals и экраны в текущем интерфейсе.
- **Процессы доски (BOARD-PROCESSES).** Доска может работать как процессы `api` плюс `worker`; состав — настройка экземпляра `general.processes`, а отсутствующий ключ означает `{ api: 1, worker: 0 }`, то есть нынешний единый процесс. Готовность — `GET /internal/ready` у каждого процесса и сводный `/healthz`.
- **Удалённые площадки исполнения (REMOTE-SITES).** Площадки регистрируются через API доски и управляются на экране флота; дорожка `site-monitor` (проверки здоровья, автоматический слив и переключение) и дорожка `site-scheduler` (переезд ботов между площадками) выключены, пока не заданы `MYRMIDON_SITE_HEALTH=1` / `MYRMIDON_SITE_SCHEDULER=1`; у fleetd появляется слушатель с взаимным TLS для API площадки.
- **Лицензирование.** Идентификатор установки хранится в базе доски (`myrmidon_install_identity`) и больше не меняется; это `MYR_LICENSE_INSTANCE_ID`, если он задан, иначе прежняя формула, поэтому уже выданные лицензии остаются действительными. Экран «Настройки → Экземпляр → Лицензии» показывает идентификатор, строку запроса, состояние лицензии каждого закрытого модуля и форму установки; установка сама забирает подписанный список отзыва лицензий выпускающей стороны.
- **Мониторинг.** Вебхук тревог для Zabbix и Alertmanager (тревога становится задачей роли-владельца с шагами ранбука и закрывается при восстановлении); данные дашборда флота из VictoriaMetrics и Zabbix; метрики `myrmidon_auth_401_burst_*` (`MYRMIDON_AUTH_401_BURST_THRESHOLD`, по умолчанию 20, `…_WINDOW_SEC`, по умолчанию 60); потери по OOM классифицируются как `resource.oom`; датчики простоя инженеров и разблокированных задач; датчики фазы живых прогонов со сторожем переподключения.
- **Экраны настроек.** Экземпляр → Возможности (реестр возможностей форка с живым здоровьем), жизненный цикл диска ботов, приоритет прогонов, сигнал резервной модели, гигиена рабочих копий, окна ленты внимания, значок политики исполнения, типизированные настройки адаптера и экран «Браузеры» редактируются в интерфейсе. Меню `/model` бота — дерево групп, которое правит владелец (MODEL-MENU).
- **Деньги и квоты.** Квоты токенов проекта (суточные / недельные, отказ при постановке в очередь); учёт использования ключей и аккаунтов провайдеров с предупреждением до исчерпания пакета или окна; жизненный цикл Codex OAuth для аккаунтов пула.
- **Секреты по ссылке.** Клиентские секреты OAuth инструментов и облачных коннекторов, учётные данные прикладных модулей и токен выгрузки телеметрии могут браться из ссылки на секрет.
- **Telegram и коннекторы каналов.** Контракт, реестр и хаб коннекторов канала и Telegram-коннектор по этому контракту приходят как флаг установки без переключения трафика; шов моста выключен, пока `MYRMIDON_CHANNEL_CONNECTOR_BRIDGE` не задана, и тогда доска ведёт себя байт в байт как раньше.
- **Миграция из Paperclip.** `myrmidon:migrate` принимает релизы Paperclip `v2026.916.1`, `v2026.1001.0`, `v2026.1005.0` и `v2026.1012.0` (пробный запуск печатает опись и ничего не пишет).
- **Склейка комментариев.** `MYRMIDON_WAKE_BATCH_WINDOW_MS` (выключено, рекомендуется 10000) заставляет комментарии одной задачи в пределах окна запускать один прогон.
