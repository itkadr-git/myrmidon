# Выпуск 1.6.8 — заметки для оператора

> English version: [1.6.8.md](1.6.8.md)

Страница для оператора, который обновляет доску до 1.6.8: что изменилось, что включено по умолчанию и что требует переключателя или шага на хосте. В разделе «1.6.8» журнала изменений
([../CHANGELOG.ru.md](../CHANGELOG.ru.md)) 99 записей; здесь собраны те, что меняют то, что оператор видит или делает, каждая со ссылкой на свою запись (номер задачи в скобках) и руководства.
Полная процедура выката — [../deploy.ru.md](../deploy.ru.md); переменные окружения доски, названные ниже, перечислены с умолчаниями в [../SETTINGS.ru.md](../SETTINGS.ru.md); других ключей (конфигурация dockergate, fleetd, `OMP_RUNNER_*`, `HOST_GC_RUNNER_ROOTS`) там нет, ссылки на их документы — в последнем разделе.
Отчёт об аудите базы этого выпуска —
[1.6.8-db-audit.md](https://github.com/itkadr-git/myrmidon/blob/myr-v1.6.8/docs/myrmidon/releases/1.6.8-db-audit.md).

## Что оператору сделать при обновлении

Эти шаги — сверх обычного выката. Каждый подробно описан в разделах ниже.

1. **Выкатывать компоненты вместе.** Доска, dockergate, fleetd и образы ботов выкатываются вместе из одного тега
   ([../deploy.ru.md](../deploy.ru.md), «Выкат доски и компонентов релиза вместе»). От этого зависят два порядка в этом выпуске:
   dockergate — вместе с доской или раньше неё (общее хранилище pnpm, OPE-12869); новый бинарник fleetd — раньше конфигурации, которая использует
   `writableMountRoots`.
2. **Общее хранилище pnpm (OPE-12869).** Создайте `<packageCacheRoot>/pnpm-store` с владельцем `10001:10001` на файловой системе ботов и выкатите
   dockergate вместе с доской или раньше неё (подробности ниже).
3. **Том `tmp` у SSH-исполнителя omp (OPE-12966).** Создайте `tmp/` с режимом `1777` рядом с `workspace/`, `home/` и `hostkeys/` до первого запуска.
   Работающему исполнителю нужно добавить том в compose-файл и пересоздать контейнер. При общем кэше пакетов исполнителей (`OMP_RUNNER_CACHE_DIR`, OPE-12722) до первого запуска создайте также `<dir>/git`.
4. **Корень исполнителей для уборки хоста (OPE-12966, OPE-12722, OPE-12903).** Новые проходы уборки хоста для исполнителей omp (их `tmp`, копии прогонов,
   папки задач закрытых задач) работают только при заданном корне исполнителей (`--runner-root` или `HOST_GC_RUNNER_ROOTS`).
5. **`inspectOnlyImages` у dockergate и реестр стека (OPE-12922).** Перечислите в `inspectOnlyImages` точные ссылки образов, которые реестру стека разрешено
   осматривать (применяется по `SIGHUP`); для каждого такого компонента задайте `MYRMIDON_STACK_IMAGE_<NAME>`, а `MYRMIDON_STACK_DOCKER_SOCKET` направьте на
   сокет dockergate.
6. **Боты агентов, ушедших из среды ботов (OPE-12654).** Доска теперь сама выводит их из эксплуатации раз в 10 минут; каталоги их данных удаляет проход
   уборки хоста. Для задержанных ботов смотрите строки `bot_decommission_held` и `bot-data-held-unpushed`.
7. **Потолки ресурсов бота (OPE-12337).** Карточка с памятью, CPU или pids выше потолка dockergate отклоняется при сохранении (422): поднимите
   `bots[].maxMemoryMb` в `config.json` dockergate и перечитайте конфиг (`SIGHUP`).
8. **Конфиг dockergate только для чтения (OPE-12383).** Обновления потолков пишутся в файл из `limitsOverrideFile`; без записываемого файла обновление
   отклоняется с `config_read_only` (403).
9. **fleetd на удалённой площадке.** Дополнительному монтированию на запись нужен `writableMountRoots`; шаблон контейнера хоста доски доходит до уже
   существующего контейнера при его следующем пересоздании.
10. **Переименованные переменные (OPE-12652).** Проверьте свои env-файлы и unit-файлы на `PAPERCLIP_OMP_PROVIDERS` / `PAPERCLIP_OMP_COMMAND` и другие
    переименованные имена; старые имена работают один выпуск как устаревшие синонимы.
11. **Агентские ключи, пишущие настройки поведения компании (OPE-12699).** Агентскому ключу нужен явный грант `users:manage_permissions` на компанию.
12. **Удаление агентов (OPE-12475).** Агента с записанными событиями расходов удалить нельзя (409 `agent_has_cost_events`): завершите его.
13. **Вебхук GitHub App (GITHUB-APP-WEBHOOK, OPE-12868).** Чтобы получать события CI и pull request от общего GitHub App, зарегистрируйте вебхук через
    `webhook-sync`; в настройках вебхука App на GitHub флажок **Active** должен быть включён.
14. **Образы ботов.** Работающие контейнеры ботов сохраняют старый рантайм (например, старый разрешатель `skill_view`, OPE-12719), пока раскатка их не
    пересоздаст.

## Что меняется при выкате

- **Замок выката (OPE-12335).** `deploy.sh` в начале берёт исключительный `flock`. Если замок занят, скрипт сразу завершается с кодом 42 и печатает PID,
  время старта и версию держателя, либо ждёт, когда `MYRMIDON_DEPLOY_LOCK_WAIT_SEC` больше 0 (по умолчанию 0). Файл замка — `MYRMIDON_DEPLOY_LOCK_FILE`
  (по умолчанию `$STATE_DIR/deploy.lock` или `/var/lib/myrmidon/deploy/deploy.lock`). `--dry-run` только предупреждает, что замок занят.
- **Удаление образов после выката (OPE-12664).** Успешный выкат продукта удаляет с хоста выката неиспользуемые образы `myrmidon*` и `agent-runtime*`
  (контейнер в любом состоянии сохраняет свой образ). При неудачном выкате удаление не запускается; сбой удаления пишется в журнал и не меняет результат выката.
- **Сигнал о диске хоста (OPE-12664, OPE-12958).** Сигнал меряет корневую файловую систему и `/srv/myrmidon-xfs`: предупреждение выше 85%, критический
  сигнал выше 90% с перечнем самых больших потребителей. Строка `host.disk_threshold_exceeded` теперь пишется по каждой компании (раньше запись падала при
  каждом проходе).
- **Якорь набора compose-файлов (OPE-7010).** После проверки здоровья доски выкат сравнивает живой набор compose-файлов с блоком `board-mount-set` файла-якоря
  и при расхождении переписывает блок и коммитит его. Необязательно: `MYRMIDON_COMPOSE_SET_ANCHOR_FILE`, `MYRMIDON_COMPOSE_SET_ANCHOR_GIT`,
  `MYRMIDON_COMPOSE_SET_LABEL_SOURCE`; пустое значение файла-якоря пропускает шаг, а некорректный якорь — предупреждение, которое не роняет здоровый выкат.
- **Проверка ботов после выката (smoke) (OPE-12609, OPE-12716).** `bot-apply-smoke.sh` больше не считает остановленных по простою ботов упавшими (метка здоровья учитывается
  только для контейнера не в состоянии exited, dead или created), считает `OOMKilled` только внутри окна выката и проверяет ботов, закреплённых за другим
  хостом, по их собственному `/health` шлюза. Одиночный OOM контейнера, которого раскатка не трогала, — `WARNING`; два и больше OOM нетронутых контейнеров или
  любой OOM контейнера, пересозданного раскаткой, по-прежнему проваливают выкат.
- **dockergate (OPE-12959, OPE-12922, OPE-12654, OPE-12383).** `inspectOnlyImages` (осмотр образа только на чтение для точных ссылок, применяется по `SIGHUP`);
  маршрут A22 `DELETE containers/myrmidon-bot-<K>?force=true&v=true&myrmidon-decommission=true` для остановленного основного контейнера; `limitsOverrideFile`
  для изменяемых лимитов бота (свежие установки направляют его на `/run/myrmidon-dockergate-state/limits.json`); штатный отказ удалить запись квоты, пока
  существует каталог данных, теперь информационное событие `disk_project_still_has_directory`, а не ошибка. См. [../dockergate.ru.md](../dockergate.ru.md).
- **Общее хранилище pnpm (OPE-12869).** OPE-12720 в этом же разделе переносило хранилище в дерево каждого бота; OPE-12869 это заменяет, и шаги ниже —
  по OPE-12869. Хранилище одно на всех ботов: `<sharedPackageCachePath>/pnpm-store`, привязанный на запись как `/cache/pnpm-store` (шестая пара монтирований
  кэша пакетов). Корень кэша должен лежать на той же файловой системе XFS, что и тома ботов (вне `MYRMIDON_BOT_VOLUME_ROOT`, например
  `/srv/myrmidon-xfs/package-cache`): pnpm импортирует `node_modules` через reflink, а reflink работает в пределах одной файловой системы. Доска не видит
  файловые системы хоста, поэтому это требование к оператору; самопроверка reflink при старте образа бота (`hardlink-check.json`) сообщает о хранилище на
  другой файловой системе. Шаги: создать `<packageCacheRoot>/pnpm-store` с владельцем `10001:10001`; выкатить dockergate вместе с доской или раньше неё
  (старый dockergate отклоняет привязку с `mount_source_not_allowed`); затем доску. В существующем клоне первый `pnpm install` удаляет `node_modules` и
  ставит заново из общего хранилища; обёртка pnpm в образе бота передаёт `--config.confirm-modules-purge=false`, поэтому это работает без TTY. Каталоги
  `workspace/.pnpm-store` у ботов после этого не используются и их можно удалить. Приёмка: сравнить `df` раздела ботов до и после свежего `pnpm install` в
  новом клоне (`du -xs node_modules` считает связанный файл целиком и проверкой не является).
- **Роль lead в общих кэшах (OPE-12384).** `general.botDisk.sharedCacheRoles` теперь включает `lead`; боты-лиды пересоздаются с общими монтированиями кэшей на
  следующем проходе сверки. `sharedBotRuntimePath` отдаёт на чтение только `bin` (OPE-12493; `BotRuntimeMounts` в dockergate принимает только `bin`).

## SSH-исполнитель omp

- **Свой контейнер (OMP-SSH-RUNNER, OPE-12633).** Новый образ `agent-runtime-omp-ssh` (Bun, omp, pnpm, GitHub CLI, набор для сборки на C, sshd только по ключам
  на порту 2222). Агент `omp_local` привязывается к SSH-окружению доски, которое указывает на один контейнер-исполнитель на агента (шаблон
  `docker/agent-runtime/omp-ssh/compose.yml`; лимиты по умолчанию 4 ГБ, 1 CPU, 1024 процесса). Процедура — раздел «Исполнитель omp по SSH» в
  `docker/agent-runtime/README.ru.md`.
- **Данные на диске данных (OPE-12664, OPE-12966).** Шаблон хранит рабочую папку, домашний каталог и ключ хоста в `OMP_RUNNER_DATA_DIR` (тома-привязки) и
  привязывает `${OMP_RUNNER_DATA_DIR}/tmp` к `/tmp` (создайте его с режимом `1777` до первого запуска).
- **Общий кэш пакетов (OPE-12722).** Необязательный `OMP_RUNNER_CACHE_DIR` (по умолчанию `${OMP_RUNNER_DATA_DIR}/cache`, кэш только этого исполнителя); чтобы
  использовать кэш доски, задайте `general.botDisk.sharedPackageCachePath`. Он привязывает `<dir>/git` к `/cache/git` (только чтение, владелец — пользователь
  доски, создаётся до первого запуска) и `<dir>/pnpm-omp` к `/cache/pnpm` (на запись, владелец uid 1000). У исполнителей свой каталог `pnpm-omp`, потому что
  `<dir>/pnpm` принадлежит ботам (uid 10001). Критерий приёмки — разница `df` диска данных, а не `du`.
- **Копии прогонов (OPE-12633, OPE-12664, OPE-12727).** Каталог прогона `<удалённая рабочая папка>/.paperclip-runtime/runs/<runId>` удаляется при любом
  завершении прогона (и когда возврат не удался, и когда загрузка упала до старта); копии старше четырёх часов удаляются при старте следующего прогона (раньше —
  двое суток). Копии `/tmp/paperclip-ssh-sync-back-*` на доске удаляются после возврата, а старше четырёх часов — при следующем возврате.
- **Синхронизация рабочей папки (OMP-GIT-ONLY-SYNC).** `workspaceSync: "git_checkout"` передаёт только Git-бандл и checkout; значение `full` по умолчанию не
  меняется, а рабочая папка без Git возвращается к `full`.
- **Песочница (OMP-HARDEN).** `omp_local` поддерживает `filesystemScope: "workspace"` (Bubblewrap), `networkScope: "deny" | "allowlist"` с `networkAllowlist`,
  `filesystemExtraPaths`, `filesystemSandboxCommand` (по умолчанию `bwrap`); новые агенты `omp_local` по умолчанию получают область `workspace`; менять эти
  ключи может только администратор инстанса. Bubblewrap, не сумевший создать пространство имён пользователей Linux, обрывает запуск до старта агента.
- **Уборка хоста (OPE-12966, OPE-12722, OPE-12903).** `scripts/myrmidon/host-gc/host-clone-cache-gc.mjs` удаляет записи верхнего уровня в
  `<корень исполнителей>/<исполнитель>/tmp`, не менявшиеся 24 часа (`--runner-tmp-ttl`, не меньше 3), копии прогонов старше 4 часов (`--run-copy-ttl`, не
  меньше 3) и папки задач закрытых или отменённых задач (папка, чьё состояние Git нельзя доказать как чистое и отправленное, сначала архивируется). Все три
  прохода работают только при заданном корне исполнителей (`--runner-root` или `HOST_GC_RUNNER_ROOTS`); systemd-юнит репозитория задаёт переменную. Хост,
  запускающий скрипт через свою обёртку, должен задать корень сам, а обёртка, вызывающая скрипт по разу на корень бота, должна передавать `--runner-root` в
  одном вызове, иначе проход повторяется на каждого бота.
- **Опрос моста (OPE-12727).** На SSH-транспорте один опрос блокируется удалённо до пяти секунд; настраивается `MYRMIDON_BRIDGE_QUEUE_POLL_IDLE_MS` (`0`
  возвращает прежнее поведение с опросом на каждый запрос).
- **Прочие исправления.** Поток SSH- или tar-передачи, закрывшийся раньше времени, больше не роняет доску (SSH-STDIN-EPIPE); слияние при возврате больше не обходит
  всю цель под замком, а ожидание замка — 10 минут (OPE-12793).

## Боты и контейнеры ботов

- **Вывод из эксплуатации (OPE-12654).** Агент, чья карточка перешла с `hermes_gateway` на другой адаптер, или завершённый агент раньше выпадал из всех
  списков ботов и оставлял контейнер и каталог данных. Сверка теперь находит таких ботов раз в 10 минут, останавливает и удаляет контейнер вместе с остатками.
  Бот не удаляется, а удерживается (строка журнала `bot_decommission_held`), пока у его агента идёт прогон, пока отчёт о чистоте клонов показывает неотправленную работу или
  пока бот работает без пригодного отчёта. dockergate не удаляет `<volumeRoot>/<K>`: он пишет `bot_data_left_for_host_gc`, а каталог через 24 часа после
  последнего изменения удаляет проход уборки хоста — только если не осталось ни одного контейнера `myrmidon-bot-<key>` в любом состоянии, доска не показывает
  карточку `hermes_gateway` агента, ни один прогон агента не `running` и ни в одном рабочем дереве каталога нет неотправленной работы (иначе
  `bot-data-held-unpushed`); недоступный docker-демон или доска оставляют каталоги на месте. Завершение или удаление агента идёт тем же маршрутом; бот на
  площадке fleetd по-прежнему проходит через очистку площадки (OPE-12323: fail-closed — если очистка не удалась, завершение или удаление отвечает ошибкой и
  оставляет запись агента).
- **Ресурсы (OPE-12337).** `GET /api/myrmidon/agents/:id/bot-container/status` и карточка агента показывают фактические лимиты работающего контейнера рядом с
  лимитами карточки и предупреждают о расхождении.
- **Остановка по простою на fleetd (OPE-12663).** У fleetd появились `POST /v1/bots/<key>/stopIdle` и метка `idle-stopped.json`; IDLE-STOP теперь работает для
  ботов на хосте fleetd. Агенты с другим адаптером, не hermes, пропускают проверку контейнера бота при повторе после временного сбоя (OPE-12269).
- **Квоты в botd (OPE-12110, BOT-DISK).** `hermes/.npm/_npx`: записи старше 24 часов удаляются, остальное держится в пределах 512 МиБ
  (`MYRMIDON_BOTD_NPM_NPX_QUOTA_BYTES`); `hermes/.cache/cargo-target`: 2 ГиБ (`MYRMIDON_BOTD_CARGO_TARGET_QUOTA_BYTES`); `hermes/.npm/_cacache`: 512 МиБ.
  Квота может быть превышена на один проход (то, что записано за последние 15 минут, не трогается).
- **Исправления рантайма (с раскаткой образов ботов).** `gh` 2.103.3 в каждом образе бота (OPE-10494); исправленные aiohttp 3.14.5, httpx2 2.12.0 и certifi
  2026.10.19, сборка падает при версии ниже (OPE-12760); `skill_view` разрешает `paperclip-managed:<slug>` (OPE-12719); неудавшаяся запись в хранилище
  идемпотентности откатывается, поэтому бот восстанавливается после заполнения диска (OPE-12759); лимит повторов ошибок инструмента считает только тот же
  вызов, упавший снова (OPE-12796); переупаковка git-base в botd работает на частичных клонах (OPE-12263).
- **fleetd на удалённой площадке.** Безопасное чтение маркера (не символическая ссылка, не FIFO, не каталог, не файл больше 64 КиБ); шаблон контейнера хоста
  доски (`/tmp` в tmpfs, init, политика перезапуска `on-failure`, `MemorySwap` равен `Memory`); спецификация с `cpus` меньше 0,01, `gatewayPort` вне 1024–65535
  или чужим `boardExtraHost` отклоняется с `spec_invalid`; новый ключ `writableMountRoots` (по умолчанию пусто); утечка памяти устранена (OPE-12923).

## Поведение, которое меняется без переключателя

- **Ревью (OPE-12683, OPE-12780, OPE-12859, OPE-10084).** Участник ревью или одобрения должен быть агентом своей группы задачи (`swarmQueueEligible` не `false`),
  иначе 422 `invalid_review_participant`; если подходящего ревьюера нет, ничего не переносится и поднимается карточка `no_reviewer`. В пул ревью входит `lead`;
  выбирается наименее загруженный участник, а ожидающие дольше `rebalanceAfterMinutes` стадии переходят к свободному участнику пула. Если записанный вердикт уже
  относится к последнему коммиту (head) pull request, ревьюер не будится, пока идёт CI.
- **Защита прогона (OPE-12577, OPE-12796, OPE-12808).** Побудка руководителя после окончательной остановки защитой проходит через удержание выполнения;
  прогон, прерванный сторожем зависания, сохраняет учётные данные на `MYRMIDON_RUN_STALL_GRACE_SEC` (по умолчанию 600).
- **Аренды прогонов и маскирование (OPE-12578, OPE-12579, OPE-12557).** Переданная аренда (lease) контроллера сверяется с базой, прежде чем прогон отменяется;
  маскирование секретов на длинных сплошных строках ограничено; транзакции с advisory-замком больше не берут второе соединение из пула, а доставок
  разговоров под замком на процесс идёт не больше двух одновременно.
- **Повторы (OPE-12286, OPE-9497).** Ответы-заглушки провайдера определяются как `provider_garbage` и повторяются с паузой
  (`MYRMIDON_PROVIDER_GARBAGE_RETRY_MAX_ATTEMPTS`, по умолчанию 3; `MYRMIDON_PROVIDER_GARBAGE_RETRY_DELAY_MS`, по умолчанию 300000 мс); deployment cooldown и
  HTTP 429 откладывают повтор вместо немедленной побудки ([../guides/deployment-cooldown-retries.ru.md](../guides/deployment-cooldown-retries.ru.md)).
- **Карточки задач.** Сервер отклоняет неполную карточку с 422 `task_card_not_ready` в режиме `enforce` (предупреждение в журнале в течение льготных 3 дней или
  при `MYRMIDON_TASK_CARD_GATE_MODE=warning`); пути из «МЕСТО ПРАВКИ», которых нет в ветке по умолчанию, дают `EDIT_TARGET_NOT_FOUND` (422 в `enforce`), а
  сетевая ошибка или отсутствие подключения к GitHub лишь предупреждают (`EDIT_TARGET_UNVERIFIED`).
- **Агенты (OPE-12475, OPE-12699, OPE-12675, OPE-12270).** Удаление агента с событиями расходов: 409 `agent_has_cost_events`; оставшиеся ссылки: 409
  `agent_referenced`. Запись настроек поведения компании агентским ключом требует `users:manage_permissions`. Маршруты `tokens-trace` сначала проверяют доступ к
  компании. Значение, содержащее `***REDACTED***`, при записи отклоняется (422).
- **Списки и побудки (OPE-12210, OPE-12197, OPE-12846, OPE-9590, OPE-12725, OPE-12204).** `GET /api/companies/:id/heartbeat-runs` по умолчанию отдаёт `limit` 200
  (максимум 1000) с курсором `before` и `X-Next-Cursor`; причина побудки для приватной задачи — `heartbeat.private_issue_suppressed`; готовые задачи касты без
  агентов уходят на роль по умолчанию; работающая задача-сторож не считается живой работой своей же задачи; застрявшие мониторы задач в состоянии `triggered`
  подчищаются (по таймауту агент будится с `issue_monitor_timeout`); прогон в очереди сохраняет запланированный повтор при освобождении аренды окружения.
- **Чтения GitHub (OPE-12397, OPE-12446, OPE-12537, OPE-12890).** Доска кэширует чтения pull request и CI и ничего не отправляет, пока общий лимит запросов
  исчерпан (`MYRMIDON_GITHUB_OBJECT_CACHE_TTL_SEC` 120, `MYRMIDON_GITHUB_OBJECT_TERMINAL_TTL_SEC` 1800, `MYRMIDON_REVIEW_CI_PULL_CACHE_TTL_SEC` 60,
  `MYRMIDON_REVIEW_CI_COMPLETE_CACHE_TTL_SEC` 600; `0` выключает кэш); цикл возвратов ревью идёт с темпом `sweepIntervalSec` (по умолчанию 300, диапазон
  60–3600, панель Review Rework; `MYRMIDON_REVIEW_REWORK_SWEEP_INTERVAL_SEC` переопределяет); токены установки кэшируются на 50 минут, а предохранитель
  учётных данных на прогон — `MYRMIDON_GITHUB_CREDENTIALS_FUSE_PER_MINUTE` (по умолчанию 60). Меньше обращений к секретам — гораздо меньше строк в
  `secret_access_events` (OPE-12890, OPE-12537); по отчёту об
  [аудите базы](https://github.com/itkadr-git/myrmidon/blob/myr-v1.6.8/docs/myrmidon/releases/1.6.8-db-audit.md), размер таблицы известен, а возврат места и сроки хранения — в OPE-12979.
- **CI на main.** Пуши в `main` больше не отменяют идущий прогон main (один идущий и один ожидающий прогон).

## Сигналы и экраны

- **Внимание (OPE-12709, OPE-12868).** `role_model_down` (у целой роли нет рабочего канала модели: не меньше 5 завершённых прогонов за 30 минут, ни одного
  успешного, не меньше 5 отказов модели) и `provider_no_credits` (в ошибке прогона маркер «нет кредитов», одна карточка на канал) — обе critical, обе доставляются
  через Telegram-канал ошибок доски не чаще раза в час; в списке агентов и в карточке показывается «модель недоступна с ЧЧ:ММ» (`roleModelDownSince`).
  Critical-карточка `github_app_webhook_disabled` появляется, когда `webhook-sync` получает от GitHub 404 (Active выключен), и пропадает после следующей
  успешной синхронизации.
- **Настройки → Общие.** Панель «Чистота рабочих пространств» (OPE-6249): `workspaceQuotaMb` и `totalQuotaMb`, сохраняются без перезапуска. Панель Review
  Rework правит `sweepIntervalSec`.
- **Экран «Провайдеры моделей» (OPE-12361, OPE-10775).** Экран и редактор резервов полностью переведены на русский и показывают настоящие счётчики пулов.
  Аккаунты пула Codex / ChatGPT: OAuth из интерфейса доски, типы аккаунтов (`Plus`, `Pro`, `K-12`), окна квоты 5 часов и 7 дней, ротация, которая убирает
  заблокированные и исчерпанные аккаунты, и сигналы внимания по ним.
- **Реестр стека (OPE-12141, OPE-12718, OPE-12922, 1.7-STACK-UPDATES-B, OPE-12044, OPE-12957).** Плановая проверка читает работающие версии из
  `MYRMIDON_STACK_HTTP_HINDSIGHT`, `MYRMIDON_STACK_HTTP_LITELLM`, `MYRMIDON_STACK_HTTP_LANGFUSE`; GitHub 403 повторяется один раз, иначе данные помечаются
  устаревшими; карточка `stack_update` живёт, пока компонент отстаёт; черновик в бэклоге (`todo`, `originKind stack_update`, без дублей по компоненту)
  создаётся, когда компонент отстаёт на `MYRMIDON_STACK_BACKLOG_LAG_RELEASES` (по умолчанию 2) выпусков или имеет критическую пометку безопасности;
  уязвимости берутся из OSV.dev (`MYRMIDON_STACK_OSV_API_BASE`); сверка релизов читает `MYRMIDON_VENDOR_GITHUB_REPO`, `MYRMIDON_GITHUB_API_BASE`,
  `MYRMIDON_VENDOR_TAG`, `MYRMIDON_RELEASE_RECONCILIATION_INTERVAL_SEC`, `MYRMIDON_RELEASE_TASK_COMPANY_ID`; `POST /api/myrmidon/stack/refresh` и `/check`
  выполняются в главном процессе доски. См. [../stack-updates.ru.md](../stack-updates.ru.md).
- **События GitHub App (GITHUB-APP-WEBHOOK).** `POST /api/myrmidon/github-app/webhook` принимает доставки check_run, check_suite, workflow_run и pull_request
  (проверяются по `X-Hub-Signature-256`); у записи App появляется `webhookSecretId`, а `POST /api/myrmidon/companies/:companyId/github-shared-identity/apps/:entryId/webhook-sync`
  с `{ webhookUrl }` один раз создаёт секрет и задаёт вебхук App.
- **Корпус (OPE-12058, OPE-12372).** Неудавшийся документ разбирается заново кнопкой «Разобрать заново»; запросы эмбеддингов повторяются один раз.
- **Аудит datastore-care (OPE-12248).** `MYRMIDON_DATASTORE_CARE_BACKUP_EXTERNAL` (метка внешнего покрытия) заставляет `backup-freshness` показывать внешнее
  покрытие и не сканировать локальный каталог копий; единицы `work_mem` и фильтр `relkind` для pgvector исправлены.
- **Прочее.** Таймаут запросов плагина Hindsight 60 с, `requestTimeoutMs` (OPE-8150); один информационный комментарий-подсказка на pull request, который меняет
  API или схему без фрагмента изменений; имена `MYRMIDON_*` для переменных, введённых Myrmidon (OPE-12652; `scripts/myrmidon/ci/paperclip-names-ratchet.mjs`
  следит за новыми именами `PAPERCLIP_*`).
