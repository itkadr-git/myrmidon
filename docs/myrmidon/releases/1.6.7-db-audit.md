# Аудит базы доски 1.6.7 (db-audit)

Правило владельца 08.10.2026: финальный тег, без суффикса `-rc`, выходит только с принятым аудитом базы. Отчёт лежит в `docs/myrmidon/releases/<версия>-db-audit.md`, то есть здесь. Гейт — `scripts/myrmidon/release/db-audit-gate.sh`.

## 1. Происхождение

- Автоотчёт модуля datastore-care (DBC-4): `POST /api/myrmidon/datastores/board/audit-reports` и экспорт `GET /api/myrmidon/audit-reports/780dbca9-5bb2-4f38-bee8-563ef9dcc326/export`. Сформирован 2026-11-08T12:52:08Z на бою 1.6.7-rc.11 (коммит `bfcc219873`), запустил оператор вручную перед финальным тегом.
- База: PostgreSQL 18, объём 22.4 GiB (за сутки до 1.6.6 — 21.9 GiB).
- Снимок только на чтение. Мутаций при подготовке файла не было.

## 2. Вердикт гейта

`db-audit-gate.sh --report <отчёт> --mode warn`: норма 11, внимание 7, нарушение 1, нет данных 0. Отчёту 0 часов. Режим предупреждения (правило 1.6.5): выпуск не блокируется.

## 3. Нарушение `backup-freshness` — разобрано, бэкап есть

Критерий ищет дампы в каталоге бэкапов экземпляра доски (`/paperclip/instances/default/data/backups`). Каталога нет намеренно: локальные дампы данных vm-core не делаем (решение владельца 29.10), резервная копия — ночной снимок ВМ.

Факт: последний снимок ВМ vm-core (VM 100) в хранилище PBS (`pbs-backup`, датастор `fleet`) — **2026-11-07T21:30:07Z**, за 15 ч 22 мин до аудита. Это укладывается в порог 24 ч.

Модуль бэкап уровня ВМ не видит — та же причина, что в 1.6.6; научить критерий видеть его — OPE-12234.

## 4. Предупреждения

| Критерий | Значение | Порог | Что делаем |
|---|---|---|---|
| db-size | 22.4 GiB | ≤ 8.0 GiB | сроки хранения журналов (activity_log, secret_access_events, heartbeat_run_events) — OPE-12234 |
| cache-hit | 95.9 % | ≥ 99 % | вместе с размером базы и параметрами памяти сервера — OPE-12234 |
| unused-indexes | 667 из 1208, 628 MiB | ≤ 20 %, ≤ 512 МиБ | разобрать список крупнейших (крупнейший `activity_log_company_responsible_user_created_idx`), удалять только с замером — OPE-12234 |
| dead-tuples | execution_workspaces: 15.6 % | ≤ 10 % | autovacuum по таблице — OPE-12234; отдельно `corpus_chunks` ~17 % мёртвых строк без VACUUM с 05.11 — OPE-12372 |
| autovacuum-vacuum / analyze | 0.2 / 0.1 | ≤ 0.05 | настройки базы — в той же задаче, через предложение и окно |
| pgvector-indexed | 1 из 2 | все | отчёт называет без индекса `corpus_chunks_embedding_hnsw_idx.embedding` (имя индекса вместо таблицы — похоже на ошибку критерия; HNSW-индекс по `corpus_chunks.embedding` существует) — OPE-12234 |

Ни одно предупреждение выпуск не блокирует: гейт в режиме предупреждения, правило 1.6.5.

## 5. Замечания к самому автоотчёту

- Единицы `work_mem` и `effective_cache_size` в таблице критериев по-прежнему пересчитаны неверно (`work_mem` показан как 32.0 KiB при серверных 32768 kB = 32 MiB) — OPE-12234.
- Критерий `backup-freshness` не видит бэкап уровня ВМ — OPE-12234.
