# Спецификация санкционированного датасета 50 сообщений ADM и версий baseline / current

**Задача**: OPE-9777 (разблокировка OPE-9264)  
**Проект**: 1.6.6 ADM-CONN (OPE-9247 / OPE-9244)  
**Политика безопасности**: OPE-1524 (гигиена секретов, исключение самовольного доступа к журналам сессий)

## 1. Версии baseline и current: проверенная provenance и незаполненные входы

Экстрактор и этот документ не доказывают состояние хуков ADM на хосте. Нельзя подставлять оценки размеров вместо измеренных байтов. Перед бенчмарком уполномоченный оператор должен зафиксировать SHA-256 и размеры реально загружаемых `CLAUDE.md`, `MEMORY.md`, файлов читаемой памяти, конфигурацию и коммит хуков `SessionStart`/`UserPromptSubmit` на хосте. Эти данные на момент PR не предоставлены; baseline по хосту остаётся непроверенным.

Репозиторные якоря (не доказательство установленной версии): контракт знаний `590eda445453807b041ce48f8975e5fb90b0e162`; current-кандидат хуков `45fed223f752d48bfdd26ac339d9e59ecbf7496b` (PR #1951), кэша `f3e0528ee1f99fd20ed5a70b67479d336123e501` (PR #1958), записи `db80305dbf0a9a1027ef9a5ef281b3790ec38cb0` (PR #1959), миграции `da227b41df4fc07bfa7cfa6ef0fa95a7b6cf28ec` (PR #1963). PR #1951 не находится в `origin/main` на момент проверки: указанный код — кандидат, не deployed current. Оператор бенчмарка обязан записать SHA каждой реально используемой ревизии.

В документации PR #1951 для кандидата указаны лимиты 12 KiB на `SessionStart` и 2 KiB на `UserPromptSubmit`; это ограничения, а не полученные замеры. Измерение расхода baseline/current в OPE-9264 нельзя принимать до получения подлинных входов и фиксации их версий.

- **Окончание окна (end UTC)**: `2026-10-27T00:00:00Z` (исключительно)

## 3. Воспроизводимое правило выборки и обезличивания

Политика **OPE-1524** категорически запрещает инженерам несанкционированное чтение сырых журналов сессий и утечку секретов. Выборка формируется по детерминированному алгоритму:

1. **Источник сообщений**:
   - Журналы сессий Claude Code оператора ADM на хосте (расположение: `~/.claude/projects/` или `~/.openclaw/`).
2. **Фильтрация входящих сообщений**:
   - Отбираются только сообщения инициатора/пользователя (`role: "user"` или `type: "user"`).
   - Исключаются: системные инъекции, ответы ассистента, результаты выполнения команд и инструментов (`tool_result`), пустые строки и шум.
3. **Обезличивание и удаление секретов (санитизация)**:
   - Обязательный прогон через сканер секретов `gitleaks stdin --no-banner --redact=100`; при отсутствии сканера или ошибке сканирования экспорт прекращается.
   - Обязательная регулярная замена чувствительных данных:
     - Ключи доски: `pcp_[A-Za-z0-9_-]+` $\to$ `[REDACTED_PCP_TOKEN]`;
     - Токены GitHub: `gh[pousr]_[A-Za-z0-9_]+` $\to$ `[REDACTED_GH_TOKEN]`;
     - Заголовки авторизации: `Bearer ...` $\to$ `Bearer [REDACTED_BEARER]`;
     - Приватные ключи: `-----BEGIN ... PRIVATE KEY-----` $\to$ `[REDACTED_PRIVATE_KEY]`;
     - Секретные параметры: `(api_key|token|secret|password)=...` $\to$ `[REDACTED_SECRET]`.
4. **Дедупликация и сортировка**:
   - Удаление идентичных сообщений (нормализация по пробелам).
   - Хронологическая сортировка по `timestamp_utc` (при совпадении меток — детерминированная сортировка по тексту).
5. **Равномерная выборка ровно 50 сообщений**:
   - Пусть общее число уникальных сообщений в окне равно $N$.
   - Если $N = 50$, берутся все 50; при $N > 50$ используется равномерный шаг $s = N / 50$, выбираются элементы с индексами $k = floor(i * s)$ для $i = 0..49$.
   - Если $N < 50$: экспорт прекращается с ошибкой; оператор должен получить дополнительные санкционированные сообщения за то же окно, без подстановки или дублирования.
6. **Выходной формат (`adm-50-messages.json`)**:
   ```json
   [
     {
       "id": 1,
       "timestamp_utc": "2026-10-20T10:15:30.000Z",
       "text": "Текст входящего запроса без секретов",
       "scrubbed": true
     },
     ...
     {
       "id": 50,
       "timestamp_utc": "2026-10-26T22:45:10.000Z",
       "text": "Текст входящего запроса без секретов",
       "scrubbed": true
     }
   ]
   ```

## 4. Скрипт экстрактора

Для автономного запуска оператором ADM на хосте реализован скрипт:
`scripts/myrmidon/adm-connector/extract-adm-dataset.mjs`

### Команда запуска:
```bash
node scripts/myrmidon/adm-connector/extract-adm-dataset.mjs \
  --input-dir ~/.claude/projects \
  --output adm-50-messages.json \
  --start 2026-10-20T00:00:00Z \
  --end 2026-10-27T00:00:00Z \
  --target-count 50
```

Скрипт покрыт автоматическими тестами:
`scripts/myrmidon/adm-connector/extract-adm-dataset.test.mjs` (прогон: `node --test scripts/myrmidon/adm-connector/extract-adm-dataset.test.mjs`).

## 5. Передача на offline-замер OPE-9264

Датасет реальных сообщений пока не поставлен. Ранее приложенный `adm-sample-50.json` имел синтетическое происхождение и отозван; не использовать его в замере и удалить старое вложение/work product после проверки владельцем доски. Самостоятельное чтение журналов инженером запрещено OPE-1524. Только уполномоченный оператор может запустить экстрактор на исходных сессиях, проверить отсутствие секретов и передать обезличенный экспорт по согласованному каналу. Внешние метаданные provenance (источник, оператор, SHA-256 экспорта, время, границы, правило отбора и число допустимых сообщений до выборки) фиксируются отдельно, не в каждой записи датасета. До этого результата OPE-9264 остаётся заблокированной по данным; числовое сравнение baseline/current не заявляется.
