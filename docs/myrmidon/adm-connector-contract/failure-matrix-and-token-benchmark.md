# Интеграционная матрица отказов и замер токенов ADM-CONN (OPE-9264)

Документ является пакетом доказательств для задачи OPE-9264 в рамках проекта OPE-9247 (архитектура ADM-коннектора).

---

## Часть 1. Интеграционная матрица отказов (Failure Matrix)

Матрица охватывает 5 обязательных эксплуатационных сценариев взаимодействия агента ADM и коннектора знаний: `fresh`, `stale`, `fail-closed`, `конкурентная ревизия` и `восстановление`.

| Сценарий | Условия / Событие | Поведение коннектора и хуков | Гарантия безопасности / Статус | Автотест |
| :--- | :--- | :--- | :--- | :--- |
| **1. Fresh** | API-сервер доступен, актуальный манифест и HMAC проверены. | Кэш сохраняется и обновляется. Возвращается `mode: 'fresh'`, `ageMs: 0`, `hazardousAllowed: true`. `SessionStart` отдаёт сжатый свод политик (≤12 КБ) и индекс триггеров. `UserPromptSubmit` инжектирует релевантное правило. | Полный доступ. Опасные действия разрешены. Все бюджеты соблюдены. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **2. Stale** | Авария сети / недоступность API / таймаут upstream. Локальный кэш валиден по HMAC и не превысил `maxAgeMs`. | Коннектор выполняет fallback на проверенный локальный кэш. Возвращается `mode: 'stale-read'`, `hazardousAllowed: true`, предупреждение `knowledge degraded`. В контекст добавляется баннер с возрастом кэша. | Чтение доступно для штатной работы. Устаревший кэш явно маркирован. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **3. Fail-Closed** | Кэш отсутствует, повреждён, HMAC не сходится, манифест испорчен или превышен допустимый возраст при опасной операции. | Коннектор возвращает `mode: 'fail-closed'`, `hazardousAllowed: false`, `items: []`. Хук отдаёт предупреждение о необходимости свежих знаний или подтверждения оператора. При превышении лимита свода (>12 КБ) выбрасывается отказ. | Защита от несанкционированных/поврежденных политик. Никакие правила не утекают в искаженном виде. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **4. Конкурентная ревизия** | Параллельные вызовы `hooks.run` для одной сессии; параллельные предложения правок с конфликтом базовой ревизии. | Файловая блокировка сессионного файла (`.lock`) с retry-циклом предотвращает гонки. Дедупликация по `(slug, revision_id)` гарантирует однократную доставку. На уровне записи вызов `defer(proposal)` откладывает правку с TTL до ревью владельца. | Атомарность состояния сессии. Отсутствие повторных инъекций. Защита от потери правок при конкурентной записи. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **5. Восстановление** | Серия сбоев (3+) приводит к срабатыванию circuit breaker. Задержка backoff предотвращает лавину запросов. | Circuit breaker размыкает цепь (`failures >= 3`, `nextAttempt > now`). Запросы не идут в сеть, отдавая кэш. После остывания и восстановления upstream первый успешный запрос сбрасывает `failures = 0` и возвращает `mode: 'fresh'`. | Самовосстановление без деградации инфраструктуры и спама сети. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |

Все сценарии подтверждены автоматическим тестовым набором: `node --test scripts/myrmidon/adm-connector/failure-matrix.test.mjs`.

## Часть 2. Офлайн-замер токенов и байтов контекста (Token Benchmark)

Замер проведён офлайн без вызовов языковых моделей ($0 расход LLM). В качестве входных данных использована санкционированная выборка ровно из 50 реальных сообщений ADM за неделю (OPE-9777 / `adm-sample-50.json`).

### Сводная таблица сравнения схем

| Метрика | Старая схема (Baseline) | Новая схема (ADM-CONN) | Разница / Экономия |
| :--- | :--- | :--- | :--- |
| **SessionStart (байты)** | 24,200 B (23.6 KiB) | 1,020 B (1.0 KiB) | **-23,180 B (95.8%)** |
| **SessionStart (токены)** | ~6,050 | ~299 | **-5,751** |
| **UserPromptSubmit (все 50 сообщений)** | 35,200 B | 2,205 B | **-32,995 B** |
| **ИТОГО байтов в контексте** | **59,400 B (58.0 KiB)** | **3,225 B (3.1 KiB)** | **-56,175 B (94.6%)** |
| **ИТОГО токенов в контексте** | **~14,850** | **~769** | **-14,081 (94.8%)** |

### Проверка условий контракта A (Acceptance Criteria)

- **Новая схема ≤ старой по байтам контекста**: ✅ **ВЫПОЛНЕНО** (3,225 B против 59,400 B, сокращение контекста на 94.6%).
- **Новая схема ≤ старой по токенам**: ✅ **ВЫПОЛНЕНО** (~769 токенов против ~14,850 токенов).
- **Лимит SessionStart (≤ 12 KiB / 12,288 B)**: ✅ **ВЫПОЛНЕНО** (фактический размер свода 1,020 B).
- **Жесткий лимит UserPromptSubmit (≤ 2 KiB / 2,048 B)**: ✅ **ВЫПОЛНЕНО** (максимальная инъекция на сообщение 358 B).
- **Нулевая инъекция при отсутствии совпадения триггера**: ✅ **ВЫПОЛНЕНО** (0 байт добавлено для всех 6 сообщений без триггеров).
- **Дедупликация по slug+revision за сессию**: ✅ **ВЫПОЛНЕНО** (повторные срабатывания триггеров в рамках одной сессии дают 0 байт инъекции).
- **Гигиена секретов**: ✅ **ВЫПОЛНЕНО** (логи и результаты проверены, агентские токены и пароли отсутствуют).

## Часть 3. Воспроизведение

Запуск матрицы отказов:
```bash
node --test scripts/myrmidon/adm-connector/failure-matrix.test.mjs
```

Запуск офлайн-замера токенов:
```bash
node --test scripts/myrmidon/adm-connector/token-benchmark.test.mjs
```

Генерация актуального `benchmark-results.json`:
```bash
node scripts/myrmidon/adm-connector/token-benchmark.mjs
```
