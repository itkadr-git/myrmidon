# Интеграционная матрица отказов и замер токенов ADM-CONN (OPE-9264)

Документ является пакетом доказательств для задачи OPE-9264 в рамках проекта OPE-9247 (архитектура ADM-коннектора).

---

## Часть 1. Интеграционная матрица отказов (Failure Matrix)

Матрица охватывает 5 обязательных эксплуатационных сценариев взаимодействия агента ADM и коннектора знаний: `fresh`, `stale`, `fail-closed`, `конкурентная ревизия` и `восстановление`.

| Сценарий | Условия / Событие | Поведение коннектора и хуков | Гарантия безопасности / Статус | Автотест |
| :--- | :--- | :--- | :--- | :--- |
| **1. Fresh** | API-сервер доступен, актуальный манифест и HMAC проверены. | Кэш сохраняется и обновляется. Возвращается `mode: 'fresh'`, `ageMs: 0`, `hazardousAllowed: true`. `SessionStart` отдаёт сжатый свод политик (≤12 КБ) и индекс триггеров. `UserPromptSubmit` инжектирует релевантное правило. | Полный доступ. Опасные действия разрешены. Все бюджеты соблюдены. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **2. Stale** | Авария сети / недоступность API / таймаут upstream. Локальный кэш валиден по HMAC и не превысил `maxAgeMs`. | Коннектор выполняет fallback на проверенный локальный кэш. Возвращается `mode: 'stale-read'`, `hazardousAllowed: true`, предупреждение `knowledge degraded`. В контекст добавляется баннер с возрастом кэша. | Чтение доступно для штатной работы. Устаревший кэш явно маркирован. Опасные операции разрешены в пределах maxAgeMs. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **3. Fail-Closed** | Кэш отсутствует, повреждён, HMAC не сходится, манифест испорчен или превышен допустимый возраст при опасной операции. | Коннектор возвращает `mode: 'fail-closed'`, `hazardousAllowed: false`, `items: []`. Хук отдаёт предупреждение `fail closed: fresh knowledge or human approval required`. При повреждении кэша тела политик не утекают в контекст. | Защита от несанкционированных/поврежденных политик. Никакие правила не утекают в искаженном виде. Опасные операции заблокированы. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **4. Конкурентная ревизия** | Параллельные вызовы `hooks.run` для одной сессии; параллельные предложения правок с конфликтом базовой ревизии. | Файловая блокировка сессионного файла (`.lock`) с retry-циклом предотвращает гонки. Дедупликация по `(slug, revision_id)` гарантирует однократную доставку. На уровне записи вызов `defer(proposal)` откладывает правку с TTL до ревью владельца (`write-deferred`, `publishable: false`). | Атомарность состояния сессии. Отсутствие повторных инъекций. Защита от потери правок при конкурентной записи. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |
| **5. Восстановление** | Серия сбоев (3+) приводит к срабатыванию circuit breaker. Задержка backoff предотвращает лавину запросов. | Circuit breaker размыкает цепь (`failures >= 3`, `nextAttempt > now`). Запросы не идут в сеть, отдавая кэш. После остывания и восстановления upstream первый успешный запрос сбрасывает `failures = 0` и возвращает `mode: 'fresh'`. | Самовосстановление без деградации инфраструктуры и спама сети. | `scripts/myrmidon/adm-connector/failure-matrix.test.mjs` |

Все сценарии подтверждены независимыми автотестами с прямыми поведенческими проверками производственных модулей: `node --test scripts/myrmidon/adm-connector/failure-matrix.test.mjs`.

## Часть 2. Офлайн-замер токенов и байтов контекста (Token Benchmark)

Замер проведён офлайн без вызовов языковых моделей ($0 расход LLM). В качестве входных данных использована санкционированная выборка ровно из 50 сообщений ADM за неделю (OPE-9777 / `adm-sample-50.json`).

### Сводная таблица сравнения схем

| Метрика | Старая схема (Baseline) | Новая схема (ADM-CONN) | Разница / Экономия |
| :--- | :--- | :--- | :--- |
| **SessionStart (байты)** | 24,200 B (23.6 KiB) | 1,020 B (1.0 KiB) | **-23,180 B (95.8%)** |
| **SessionStart (токены)** | ~18,124 | ~296 | **-17,828 (98.4%)** |
| **UserPromptSubmit (все 50 сообщений)** | 35,200 B | 1,224 B | **-33,976 B (96.5%)** |
| **ИТОГО байтов в контексте** | **59,400 B (58.0 KiB)** | **2,244 B (2.2 KiB)** | **-57,156 B (96.2%)** |
| **ИТОГО токенов в контексте** | **~48,124** | **~1,296** | **-46,828 (97.3%)** |

### Проверка условий контракта A (Acceptance Criteria)

- **Новая схема ≤ старой по байтам контекста**: ✅ **ВЫПОЛНЕНО** (2,244 B против 59,400 B, сокращение контекста на 96.2%).
- **Новая схема ≤ старой по токенам**: ✅ **ВЫПОЛНЕНО** (~1,296 токенов против ~48,124 токенов, сокращение на 97.3%).
- **Лимит SessionStart (≤ 12 KiB / 12,288 B)**: ✅ **ВЫПОЛНЕНО** (фактический размер свода 1,020 B).
- **Жесткий лимит UserPromptSubmit (≤ 2 KiB / 2,048 B)**: ✅ **ВЫПОЛНЕНО** (все сообщения укладываются в лимит, максимум 358 B).
- **Нулевая инъекция при отсутствии совпадения триггера**: ✅ **ВЫПОЛНЕНО** (0 байт добавлено для всех сообщений без триггеров).
- **Дедупликация по slug+revision за сессию**: ✅ **ВЫПОЛНЕНО** (повторные срабатывания триггеров в рамках одной сессии дают 0 байт инъекции).
- **Гигиена секретов**: ✅ **ВЫПОЛНЕНО** (логи и результаты проверены, агентские токены и пароли отсутствуют).

### Спецификация токенизатора и аудит происхождения данных

- **Версионированный детерминированный BPE-токенизатор**: `deterministic_bpe_v1` (версия 1.0.0).
  - Алгоритм: сегментирование регулярным выражением OpenAI `cl100k` с последующим циклическим объединением смежных символьных пар по фиксированной таблице рангов BPE.
  - Оценка baseline: токены старой схемы вычисляются прямым прогоном токенизатора по сформированным репрезентативным текстам `CLAUDE.md` + `MEMORY.md` (ровно 24,200 байт) и по читаемым файлам памяти (по 800 байт на сработавшее сообщение), исключая произвольные формульные коэффициенты.
  - Воспроизводимость: чистая локальная математическая функция, 0 обращений к внешним сервисам, 0 вызовов LLM, $0 бюджет.
- **Происхождение выборки 50 сообщений (Provenance)**:
  - Санкционированный процесс экстракции описан в `extract-adm-dataset.mjs` и спецификации `dataset-spec.md`.
  - Временное окно UTC: с `2026-10-20T00:00:00Z` по `2026-10-27T00:00:00Z` (ровно 7 суток = 168 часов = 604,800 секунд).
  - Шаг равномерной выборки: $\Delta t = 604,800 / 50 = 12,096$ секунд.
  - Сообщения без таймстемпа или с невалидной датой строго исключаются из окна; при нехватке кандидатов экстрактор падает fail-closed (`Only N eligible messages; 50 required`).
  - SHA-256 датасета: зафиксирован в `benchmark-results.json`.

## Часть 3. Проверка на производственной границе (Production Boundary)

Матрица отказов и бенчмарк напрямую используют производственные модули коннектора:
1. `scripts/adm-connector/cache.mjs` (`AdmCache`) — локальный кэш, валидация манифеста и HMAC, разграничение прав, автоматический circuit breaker и fallback.
2. `scripts/adm-connector/context.mjs` (`ContextDelivery`) — доставка контекста в фазах `SessionStart` и `UserPromptSubmit`, сессионная дедупликация правил `(slug, revision_id)`, жесткие лимиты бюджетов (12 КБ / 2 КБ) и учет байтовых метрик.
3. `scripts/myrmidon/adm-connector/hooks.mjs` — интеграционные хуки с спин-лок сериализацией конкурентных обращений.

## Часть 4. Воспроизведение

Запуск матрицы отказов:
```bash
node --test scripts/myrmidon/adm-connector/failure-matrix.test.mjs
```

```bash
node --test scripts/myrmidon/adm-connector/token-benchmark.test.mjs
```

Генерация актуального `benchmark-results.json`:
```bash
node scripts/myrmidon/adm-connector/token-benchmark.mjs
```
