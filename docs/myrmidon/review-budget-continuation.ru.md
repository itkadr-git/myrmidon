# Отложенное ревью из-за бюджета и пауза продолжений

Здесь описано предлагаемое поведение PR #4598; оно не появится в работающей системе до слияния PR и выката оператором образа, собранного CI.

Если участник текущего ревью не может вынести решение из-за исчерпания общего бюджета чтения CI, решение по-прежнему отклоняется. Уже сработавший монитор `Review CI wait` откладывается на 61 минуту и помечается как отложенный из-за бюджета; это консервативная задержка, а не измеренное время сброса. Новая голова PR снимает именно эту отсрочку; сроки других мониторов не меняются. Для последующего решения обычно нужны свежие свидетельства CI для точной головы; ограниченное исключение только для возврата описано ниже. Лимит бюджета и запрет перехода при неизвестном CI не меняются.

## Допуск решения ревью (PR #4608)

Следующее поведение появится после слияния и выката PR #4608. APPROVE требует свежего успешного CI точной головы. REQUEST CHANGES обычно читает CI заново; только при исчерпании общего бюджета GitHub допускается недавний авторитетный завершённый снимок SUCCESS или FAILURE той же компании, PR и сохранённой головы. Отсутствующий, незавершённый, устаревший, инвалидированный или несовпадающий снимок не допускает решение. Проверки прав и происхождения сохраняются. Снимок может отставать от недоставленного webhook, поэтому не разрешает APPROVE.

При возврате по снимку в активности обновления задачи записываются `reviewCiAudit.source` (`budget_exhausted_cached_success` или `budget_exhausted_cached_failure`) и `headSha`. При отказе из-за бюджета выдерживайте паузу не менее 61 минуты, не повторяйте немедленно; при диагностике различайте резервирования бюджета и реальные вызовы транспорта. Реализация: `server/src/myrmidon/review-stage-recovery/github-ci.ts`, `server/src/routes/issues.ts`.

## Пауза продолжений

После трёх успешных продолжений без внешнего ввода дальнейшие продолжения откладываются на час от последнего продолжения, вместо перевода задачи в `blocked`. Новый внешний ввод сбрасывает счётчик. Сверка восстановления возвращает старые искусственные блокировки continuation cap в `in_progress` только у задач агента без нерешённых блокирующих задач, ожидающего взаимодействия и активного действия восстановления. Настоящие блокировки она не снимает.

При расследовании оператору следует различать резервирование единиц бюджета и фактические вызовы транспорта. Сообщённые в инциденте 2000 резервирований и ноль вызовов транспорта в отклонённой попытке не определяют потребителей всего окна. Атрибуция на бою и выкат требуют подтверждения оператора; этот PR не меняет боевое состояние.
