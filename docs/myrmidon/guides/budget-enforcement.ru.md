# Исполнение лимитов расхода: сигнал, мягкая пауза или жёсткий отказ (1.7 BUDGET-CONFIG B)

> Английская версия: [budget-enforcement.md](budget-enforcement.md)

Бюджетная политика, пересёкшая свой жёсткий порог, раньше имела ровно одно
поведение: пауза скоупа, отмена идущей работы, ожидание владельца. Режим
исполнения превращает это единственное поведение в выбор — что делает
пересечённый лимит, пока его инцидент открыт:

| Режим | По умолчанию | Что происходит при пересечении лимита |
|---|---|---|
| `signal_only` | **да — по умолчанию, пока владелец не выключит** | Инцидент создаётся, владелец получает сигнал (системное уведомление в треде открытых задач скоупа и карточка бюджета в инбоксе решений). Скоуп НЕ ставится на паузу, прогоны НЕ отменяются, новые прогоны стартуют: лимиты только сигналят. |
| `soft` | нет | Скоуп ставится на паузу, владелец получает карточку «поднять бюджет или оставить на паузе» (Costs → Budgets, инбокс решений и треды прерванных задач). Поднятие бюджета через карточку снимает паузу, отложенная работа возобновляется. |
| `hard` | нет | Новые прогоны пересёкшего лимит скоупа отказываются до старта, с бюджетной причиной (та же проверка допуска, что всегда была у вендора, — теперь только в этом режиме). Идущая работа завершается. |

Режим — одно глобальное значение на весь инстанс: оно действует для всех
бюджетных политик всех компаний этого сервера (скоупы компания, агент и
проект одинаково). Настройка самих лимитов по уровням — работа BUDGET-CONFIG
A; эта страница — только о том, что происходит после пересечения.

## Где настраивается

Экран — **Instance → General → Budget enforcement** (рядом с лимитами
прогонов), API — `GET`/`PATCH /api/myrmidon/budget-enforcement` (GET — board,
PATCH — только instance-admin). Сохранение пишет
`instance_settings.general.budgetEnforcement` и действует со следующей
оценки бюджета — буквально со следующего события расхода или допуска прогона;
перезапуск не нужен. Источник действующего значения показан рядом с
переключателем:

- **Saved here** — сохранённая строка настроек (владелец выбрал на этом экране);
- **Forced by the server environment** — задан
  `MYRMIDON_BUDGET_ENFORCEMENT_MODE`, и ничего не сохранено: окружение —
  принудительное переопределение для инстанса, который никогда не делал
  выбор;
- **Default** — ничего не сохранено и не задано: `signal_only`.

Каждое изменение пишется в журнал (`instance.budget_enforcement.updated`,
по одной записи на компанию инстанса).

## Поведение режимов в деталях

### `signal_only` — лимиты только сигналят

Обе точки, где может сработать жёсткая остановка (новое событие расхода и
сохранение политики с экрана), по-прежнему создают hard-инцидент, мягкое
предупреждение и карточку бюджета в инбоксе решений — но пропускают паузу и
отмену прогонов. Прерванных тредов нет (ничего не прерывалось), поэтому
открытые задачи скоупа получают уведомление: «лимит расхода пересечён…
Ничего не остановлено: режим только сигнал, прогоны продолжаются, пока лимит
превышен» — один комментарий на (инцидент × задача), с дедупликацией,
best-effort. Карточка бюджета в инбоксе решений говорит «работа
продолжается: режим только сигнал» и несёт режим в метаданных.

Проверка допуска прогона в этом режиме не блокирует скоуп
«лимит-превышен-но-не-на-паузе»: прогон стартует точно так же, как без
лимита.

### `soft` — пауза и вопрос

Вендорский путь «пауза + отмена» работает без изменений (включая M3-сигнал
владельцу: треды прерванных задач получают отчёт «поднять бюджет или
оставить на паузе»). Новый прогон поставленного на паузу скоупа
отказывается: «…приостановлен, потому что достигнут жёсткий лимит бюджета».
Поднятие бюджета через карточку инцидента (`raise_budget_and_resume` — то же
действие, что на экране Costs и в карточке инбокса решений) снимает паузу и
инцидент, агент снова вызываем.

### `hard` — отказ

Скоуп ставится на паузу (как в soft), и дополнительно проверка «лимит
превышен» перед стартом нового прогона отказывает: «…не может стартовать,
потому что его жёсткий лимит бюджета всё ещё превышен» — даже если скоуп
сейчас не на паузе. Это режим, ближайший к поведению вендора до 1.7.

## Замечания

- Оба сигнала (уведомление этого режима и M3-отчёт об остановке) делят
  выключатель `MYRMIDON_BUDGET_SIGNAL_MODE=off`: с ним ни один не
  доставляется, инциденты и остановки при этом происходят.
- Смена режима не reconcil'ит уже открытые инциденты: инцидент, открытый в
  `signal_only`, остаётся открытым при переключении в `soft` — но следующая
  оценка (следующее событие расхода) применит новый режим, и всё ещё
  превышенный скоуп будет поставлен на паузу в этой точке. Открытые
  инциденты при смене режима закрывайте с экрана Costs.
- Вызовы `budgetService` без хука режима (маршруты, собирающие сервис «голым»)
  сохраняют вендорскую семантику «всегда останавливать»; подключённый путь —
  путь прогонов (сервис heartbeat).
