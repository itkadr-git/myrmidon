# Метрики knowledge-on-change (KNOWLEDGE-ON-CHANGE, 1.6.6)

> Английская версия: [knowledge-on-change-metrics.md](knowledge-on-change-metrics.md)

Метрики knowledge-on-change следят за соблюдением правила «вики перед
закрытием задачи, меняющей устройство системы» (навык `knowledge-on-change`,
родительская задача OPE-10225). Они читаются из базы доски
guarded-коллектором на `GET /metrics` и покрывают скользящее окно 7 дней.

## Два семейства

| Семейство | Тип | На какой вопрос отвечает |
|---|---|---|
| `myrmidon_knowledge_on_change_share` | gauge | Какая доля задач, закрытых за последние 7 дней и менявших систему (слитый PR), имеет ревизию вики, ссылающуюся на задачу |
| `myrmidon_knowledge_revision_delay_seconds` | summary (квантиль 0.5 / 0.95) | Сколько прошло от слияния PR до ревизии вики, ссылающейся на этот PR |

## Знаменатель: что считается системным изменением

Задача входит в знаменатель, когда выполняются все условия:

- `issues.status` равен `done` или `cancelled`;
- `issues.completed_at` попадает в 7-дневное окно;
- у задачи есть хотя бы одна строка `issue_work_products` с
  `type = 'pull_request'` и `status = 'merged'`.

Задача без слитого PR **не** является системным изменением и не входит
ни в знаменатель, ни в числитель, даже если у неё есть ревизия вики.

## Числитель: что считается покрытием

Системно изменённая задача покрыта, когда существует строка
`knowledge_sources` с `kind = 'task'` и `ref = issues.identifier` этой
задачи. Строка создаётся модулем знаний, когда ревизия ссылается на
задачу в разделе «Источники».

Доля = `покрытые / изменённые`. Когда за окно не закрыта ни одна
системно изменённая задача, gauge отдаёт HELP/TYPE без сэмплов (`null`) —
та же форма, что у сводки длительности прогонов при пустой выборке.

## Задержка: от слияния до ревизии

Для каждой строки `knowledge_sources` с `kind = 'pr'` коллектор
соединяет `knowledge_revisions` по `revision_id` и ищет время слияния
указанного PR среди слитых `issue_work_products`, сопоставляя по
`external_id` или `url`. Задержка:

```
knowledge_revisions.created_at - issue_work_products.updated_at
```

в секундах. Отрицательные, нечисловые и несопоставленные выборки
отбрасываются. Оба квантиля — линейно интерполированные перцентили по
оставшейся отсортированной выборке. Когда ни один PR не имеет ссылающейся
ревизии, summary отдаёт HELP/TYPE без сэмплов.

## Отказ

Оба семейства обёрнуты в существующий `guarded()`-коллектор: ошибка
чтения из БД не роняет скрейп, а только скрывает сэмплы этого семейства
и увеличивает `scrape_errors`. `METRIC_FAMILIES` перечисляет оба имени,
поэтому эндпоинт selfcheck на сломанной БД всё равно их называет.

Каждый сэмпл несёт существующую метку `role` (`api` | `worker` |
`all`); сравнивайте значения в пределах одного процесса.

## Как читать числа

- Доля близка к 1.0 — правило вики соблюдается. Доля падает — системные
  изменения закрываются без записи вики; найдите задачи SQL-запросом за
  метрикой и напомните владельцам.
- p50 задержки в часах — ревизии появляются в день слияния. p95,
  растущий до дней, — запись вики откладывается; проверьте, не стоит ли
  гейт (`MYRMIDON_KNOWLEDGE_GATE_MODE`) в `warning` вместо `enforce`.
