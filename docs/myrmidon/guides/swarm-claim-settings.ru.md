# Настройки очередей ролей (SWARM-CLAIM)

> English version: [swarm-claim-settings.md](swarm-claim-settings.md)

Пилот очередей задач по ролям управляется из интерфейса, без перезапуска
доски: кто берёт задачи из очереди, сколько живёт аренда, сколько задач может
держать один агент, как часто ходит сторож и обгоняет ли задача P0 очередь. С
1.6.1 каждое значение — настройка инстанса.

## Где живут настройки

Instance → General → **Role queues (SWARM-CLAIM)**. Экран пишет
`instance_settings.general.swarmClaim` через `GET`/`PATCH /api/myrmidon/swarm-claim`
(чтение — любой член board; запись — instance-admin). Сервер перечитывает
строку при каждом клейме, checkout, тике сторожа и чтении супервизора — ничего
не кешируется при старте, рестарт не нужен.

## Поля

| Поле | Что ограничивает | По умолчанию |
|---|---|---|
| Enable role queues | Главный выключатель всего пилота | выкл |
| Pilot roles | Какие роли клеймят. Через запятую (например `engineer`); пусто = все роли. Пилот на команде разработки — это ровно это поле с одной ролью | пусто |
| Pilot companies | Какие компании клеймят. Id через запятую; пусто = все компании | пусто |
| Lease TTL, seconds | Сколько живёт одна аренда без heartbeat; прогон продлевает её на каждом проходе checkout | `900` |
| Max active tasks per agent | Потолок живых клеймов на агента; пусто = без потолка | `3` |
| Sweep interval, seconds | Как часто ходит сторож истёкших аренд; читается на лету, стартовое значение — нижняя граница | `30` |
| P0 preempts the queue | Вкл — задача `critical` стоит первой в очереди. Выкл — строго от старых к новым | вкл |

## Откуда берётся каждое значение

Рядом с каждым полем показан его источник — «Saved here» (сохранено здесь),
«Environment override» (переопределение из окружения) или «Default» — и тот же
источник показывает экран надзора SWARM (маршрут /swarm-claim) для своих значений. Переменные
`MYRMIDON_SWARM_*` — **принудительные переопределения**: заданная в окружении
переменная перекрывает сохранённое значение только своего ключа (см.
[SETTINGS.ru.md](../SETTINGS.ru.md)). Снимите переменную, чтобы вернуть
управление интерфейсу.

## Проход побудки свободных агентов (idle wake)

У сторожа есть третий проход — **idle wake**; он идёт после освобождения
просроченных аренд и снятия зависших заявок. На каждом тике сторож перебирает
пары «роль с готовой очередью + свободные агенты этой роли» и будит
недостающее число агентов — каждая побудка привязана к верхней задаче очереди
(critical первым, когда включено вытеснение P0, иначе — самая старая). До
этого прохода роль с готовыми задачами, но без аренды на исходе могла
простаивать, пока кто-нибудь не разбудит её агента вручную.

Агент считается свободным, если у него нет живой заявки и живого прогона, он
не на паузе, не в ошибке и не достиг потолка активных задач. Сторож никогда не
будит роли вне пилотного набора и касты с `swarmEligible: false`; потолок
задач касты переопределяет глобальный для её агентов. У прохода два
ограничения:

- не больше `MYRMIDON_SWARM_IDLE_WAKE_BATCH` побудок на роль за проход (по
  умолчанию `5`, значение вне диапазона 1–25 подрезается) — массовый импорт
  задач не может разбудить весь парк одним залпом;
- каждая побудка идёт через обычный допуск (`enqueueWakeup`), поэтому пауза,
  режим обслуживания и пороги памяти и CPU хоста продолжают действовать — пока
  порог закрыт, проход никого не будит и пишет причину в журнал (не чаще одной
  строки за пять минут).

Побудки идут с причиной `swarm_claim_queue`; сама заявка записывается, когда
разбуженный прогон проходит checkout. Агент, которого разбудили с назначением,
но без заявки, может сам взять верхнюю задачу очереди своей роли через
`POST /api/myrmidon/companies/{companyId}/swarm-claim/claim` (запасной путь
самозахвата, описанный в агентском навыке).

Как следить: в сводке экрана надзора за роем (маршрут /swarm-claim) есть
счётчик **freeAgentsWithQueue** — свободные агенты роли с непустой очередью.
Здоровый пилот держит это число на нуле: если оно не падает, проход не может
будить (агенты на паузе, потолки исчерпаны, закрыт порог допуска) или не может
захватывать (гейт на стороне заявки) — и очередь ждёт оператора.

## Включение очередей на одну роль

Поток приёмки: включите *Enable role queues*, впишите `engineer` в *Pilot
roles* (и id компании в *Pilot companies*, когда компаний на инстансе
несколько), сохраните. В течение минуты свободный инженер возьмёт верхнюю
задачу очереди инженеров на своей следующей побудке — checkout запишет аренду,
завершающийся прогон освободит её и разбудит следующего инженера роли.

## Выключение

Выключение *Enable role queues* (или принудительное
`MYRMIDON_SWARM_CLAIM_ENABLED=0`) действует сразу: живые аренды освобождаются
синхронно — ответ сохранения сообщает, сколько (`releasedClaims`) — а сторож
повторит проход на своём тике с причиной освобождения `pilot_disabled`,
покрывая то, до чего синхронный проход не добрался. Прогоны, державшие
освобождённые аренды, завершаются сами; задачи возвращаются к вендорскому
поведению назначений.

## Журнал изменений

Каждое сохранение дописывает запись журнала — кто, что и когда, новее сверху —
она показана внизу секции и хранится в `general.swarmClaimJournal` (не больше
50 записей). То же изменение пишет строку `instance.swarm_claim.updated` в
журнал активности, который остаётся аудиторским следом.
