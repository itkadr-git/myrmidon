# Сервис воскрешения побудок

Сервис воскрешения побудок обрабатывает повторную обработку отбитых побудок агентов с причиной `execution_reconciliation_required`. Когда побудка агента отбивается во время сверки исполнения, система попытается воскресить её один раз после завершения сверки.

## Конфигурация

Дополнительная конфигурация не требуется. Сервис работает автоматически при завершении сверки исполнения.

## Поведение

- Отбитые побудки с причиной `execution_reconciliation_required` повторяются один раз после сверки
- Побудки с `evidence.automaticRecovery.replay="blocked"` не воскрешаются
- Каждая побудка ограничена одной попыткой воскрешения
- Попытки воскрешения отслеживаются через поле `resurrection_count` в базе данных

## Технические детали

- Воскрешение выполняется внутри адаптера Postgres диспетчера прогонов, в точке, где побудка получает статус `skipped` с причиной `execution_reconciliation_required`: в очередь ставится новая побудка с новым ключом идемпотентности и `resurrection_count + 1`
- Миграция базы данных добавляет столбец `resurrection_count` в таблицу `agent_wakeup_requests`
- `ResurrectionService` (`server/src/myrmidon/resurrection-service.ts`) — ручная и диагностическая точка входа поверх того же правила
