# AUTONOMY-MATRIX: Удержание действий для одобрения

Этот документ описывает функциональность, позволяющую матрице автономии удерживать действия, требующие одобрения, создавая карточки одобрения для проверки человеком перед выполнением.

## Обзор

Начиная с версии 1.6.2, система матрицы автономии поддерживает удержание действий, требующих одобрения. Когда агент пытается выполнить действие, которое имеет вердикт `approval_required` в матрице автономии, вместо немедленного выполнения система:

1. Создает карточку одобрения (с использованием существующего механизма запросов на выполнение инструментов)
2. Возвращает ответ 202, указывающий, что действие удержано
3. Сохраняет детали действия для последующего выполнения
4. Ожидает одобрения человеком перед выполнением первоначального действия

## Классы действий

Система поддерживает требования одобрения для следующих классов действий:

- `pause_wake_agents`: Приостановка, возобновление или пробуждение агентов
- Другие классы действий могут быть добавлены по мере необходимости

## Детали реализации

### Функция Gate

Функция `holdOrAssert` в шлюзе автономии обрабатывает рабочий процесс одобрения:

```typescript
async function holdOrAssert(
  req: Request, 
  actionClass: AutonomyActionClass, 
  descriptor: {
    route: string;
    method: string;
    params?: Record<string, unknown>;
    body?: Record<string, unknown>;
  }
): Promise<{ verdict: AutonomyVerdict; held?: boolean; approvalId?: string }>
```

### Изменения в API

Следующие конечные точки API теперь поддерживают рабочий процесс одобрения матрицы автономии:

- `POST /agents/:id/pause`
- `POST /agents/:id/resume` 
- `POST /agents/:id/wakeup`

Когда эти конечные точки сталкиваются с действием, требующим одобрения, они возвращают ответ `202 Accepted` со следующим телом:

```json
{
  "held": true,
  "approvalId": "unique-approval-id"
}
```

### Одобрение и выполнение

Удержанное действие записывается как `tool_action_request` вместе с `tool_invocation`
(`tool_name = autonomy_action_<class>`), а описатель для повтора —
`{ actionClass, route, method, params, body }` — хранится в
`tool_invocations.policy_explanation["myrmidon.autonomy"]` (`arguments_hash` остаётся
настоящим SHA-256 от него). Пока запрос не одобрен, маршрут не выполняется: обработчик
отвечает `202` и завершается.

При одобрении существующий конвейер ревью (`server/src/services/tool-action-review.ts`)
повторяет описатель от имени исходного актора и помечает обе строки
(`tool_action_requests.status` → `executed` / `failed`, `tool_invocations.status` →
`succeeded` / `failed`). Действие выполняется **ровно один раз**: запрос захватывается
условным `UPDATE ... WHERE status = 'approved'` (`approved` → `executing`), поэтому
повторное одобрение или повтор, не нашедший строку в статусе `approved`, ничего не
захватывает и ничего не делает. Отказ описатель не повторяет.

Карточка решается обычным входом одобрения запросов действий
(`POST /api/tool-gateway/action-requests/:id/approve`, только доска). Удержанное действие
автономии — не инструмент шлюза: у него нет соединения, каталожной записи и подписанных
аргументов, поэтому этот вход передаёт его в `decideHeldAutonomyAction`, а не в конвейер
инструментов, который отказался бы его проверить и отменил запрос. Та же ветка обслуживает
восстановительный обход шлюза: одобренное в момент падения процесса удержание повторяется
на следующем обходе, а не остаётся висеть. Отказ (`.../decline`) подписанных аргументов не
требовал и раньше и цель не трогает.

## Конфигурация

Матрицу автономии можно настроить через стандартный интерфейс редактирования матрицы. Установите вердикт для любого класса действий в `approval_required`, чтобы включить рабочий процесс одобрения для этого типа действия.
