# Проекция бюджетов LiteLLM (BUDGET-CONFIG C)

> Английская версия: [litellm-budget-projection.md](litellm-budget-projection.md)

Лимиты расхода принадлежат доске; LLM-шлюз (LiteLLM) их исполняет. Эта
функция проецирует каждый лимит, сохранённый на доске, в собственные бюджеты
шлюза — бюджеты ключей через `/key/update` и бюджеты тегов через
`/budget/update` — без перезапуска чего-либо, в течение минуты после
изменения. Одна точка изменения: лимит правится на доске (API настроек или
экран части D), никогда в двух местах.

## Где живут лимиты

На компанию, под `instance_settings.general.myrmidonBudgetProjectionCompanies[companyId]`
(тот же паттерн JSON без миграций, что у STT-оверрайдов). Документ:

| Поле | Значение | Умолчание |
|---|---|---|
| `enabled` | Главный выключатель проекции | выкл |
| `signalOnly` | Глобальный режим «только сигнал»: пока включён, каждый спроецированный бюджет мягкий — лимиты не останавливают работу, пока владелец его не выключит | вкл |
| `limits` | Строки лимитов: `{ level, scopeId, amountUsd, periodHours, mode }` | пусто |
| `sweepIntervalSec` | Интервал свипа компании, секунды | null (30 с) |

Уровни — иерархия эпика: `nest` (гнездо: компания/проект) → `caste` (каста) →
`foraging` (фуражировка) → `ticket` (задача). `mode` — выбор строки:
`block` (шлюз отказывает после лимита) или `soft` (доска сигнализирует и
ставит карточку владельцу). Глобальный переключатель `signalOnly`, пока
включён, переводит все строки в мягкий режим — умолчание эпика.

## API

```
GET   /api/myrmidon/companies/:companyId/litellm-budget-sync/settings
PUT   /api/myrmidon/companies/:companyId/litellm-budget-sync/settings   (только board)
GET   /api/myrmidon/companies/:companyId/litellm-budget-sync/status
POST  /api/myrmidon/companies/:companyId/litellm-budget-sync/re-sync    (только board)
```

Чтение требует доступа к компании; запись — board-актора. GET настроек
возвращает эффективный документ плюс `sweepIntervalSec` и
`sweepIntervalSource` — `"settings"`, `"env"` или `"default"` — чтобы
интерфейс показывал, откуда взялось каждое значение (контракт
SETTINGS-TO-UI). `MYRMIDON_LITELLM_BUDGET_SYNC_INTERVAL_SEC` — только
**принудительное** переопределение интервала; снимите переменную, чтобы
вернуть управление интерфейсу.

## Что пишет проекция

- **Бюджеты тегов**: каждая строка лимита становится одним бюджетом шлюза на
  стабильном теге `myrm-<уровень>-<скоуп>` (потолок скоупа на стороне шлюза).
- **Бюджеты ключей**: ключ шлюза каждого агента (ключ M2-B, адресованный по
  имени секрета в хранилище) несёт потолок касты агента — `agents.role` и
  есть ключ касты. Каста без строки лимита не трогает ключи своих агентов.

Пока `signalOnly` включён (умолчание), каждый бюджет пишется мягким: шлюз
сигнализирует, доска решает. Жёсткий блок-бюджет пишется только когда
владелец выключил глобальный переключатель И режим строки — `block`.

## Гарантия минуты

Проход свипа идёт на компанию с интервалом (умолчание 30 с — внутри окна
≤ 60 с; границы 10–3600 с) и на каждом тике перечитывает сохранённый
документ, поэтому сохранённый лимит не требует перезапуска. Цели проекции —
собственный runtime-API LiteLLM (`/key/update`, `/budget/update`): шлюз тоже
применяет бюджеты без перезапуска.

## Ручные правки в шлюзе сигнализируются, а не перезаписываются

Свип ведёт трёхстороннее сравнение: что говорит **доска**, что она в последний
раз **спроецировала** в шлюз и что шлюз содержит **сейчас**.

- Доска ≠ спроецировано → доска изменила лимит: проход записывает его и
  фиксирует новое спроецированное состояние.
- Доска = спроецировано ≠ шлюз → кто-то правил шлюз руками: это
  **расхождение**. Проход НЕ пишет. Он оставляет один системный
  комментарий-уведомление (тон warning) в самой свежей задаче `in_progress`
  компании, называя уехавшую цель, число доски и число шлюза; дедуп — по
  цели и UTC-дню через ключ в метаданных комментария. В комментарии сказано,
  как разрешить: пересохранить лимит на доске или запустить re-sync.

Санкционированный выход из расхождения — принудительный проход:
`POST …/litellm-budget-sync/re-sync` (только board) переписывает все цели из
лимитов доски и снимает расхождение.

## Требования оператора

Инстанс должен уже именовать контур шлюза (настройки M2-A/M2-B):
`MYRMIDON_LITELLM_BASE_URL` и `MYRMIDON_LITELLM_ADMIN_KEY_SECRET` — админ-ключ
единственный, кто может писать бюджеты; ключи агентов ими не управляют. Без
контура status и re-sync отвечают 503 `enabled: false`, свип — no-op.

## Журнал изменений

Каждое сохранение настроек пишет строку
`myrmidon.budget_projection.settings_saved` в журнале активности компании
(кто, что и когда). Расхождения дополнительно видны в треде задачи через
комментарий-сигнал.
