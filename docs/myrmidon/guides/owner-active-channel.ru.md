# Активный канал владельца: доклады следуют за владельцем между порталом и Telegram (1.7-ACTIVE-CHANNEL)

> English version: [owner-active-channel.md](owner-active-channel.md)

Владелец общается с доской двумя каналами: портал (интерфейс доски, вход по
сессии) и мост Telegram-лички (постоянный разговор X8b). Доклад — ответ
Полководца, ответ по плану, карточка вопроса или согласования агента — должен
приходить туда, где владелец сейчас, а не туда, что предполагал интерфейс.
До этой функции в футере рейки стоял литерал «Web · сейчас», а API статуса
не было вовсе.

Теперь доска отмечает последнюю активность владельца по каждому каналу и
направляет карточку доклада в активный на момент создания карточки канал.

## Как отмечается активность

Две точки отметки, одна небольшая таблица (`myrmidon_owner_activity`, строка
на пользователя доски и канал):

- **Портал (`web`)** — каждый запрос, аутентифицированный пользовательской
  сессией, помечает канал `web`. Запись дебаунсится (не чаще одной на
  пользователя в 30 с) и идёт без ожидания: неудачная отметка не ломает
  запрос и не блокирует его.
- **Telegram (`telegram`)** — входящее сообщение в мостовой Telegram-личке
  (путь X8b, связанный владелец) помечает канал `telegram`, тоже без
  ожидания, сразу после сохранения комментария.

Таблица хранит только id пользователя, название канала и метку времени — без
содержания сообщений.

## Что значит «активен»

Канал активен, пока его последняя отметка свежее **порога неактивности**
(умолчание — 120 минут). Активный канал — самая свежая отметка внутри
порога; при точном равенстве побеждает портал. Когда все отметки старше
порога — неактивен ни один канал.

Доставка карточек докладов (вопросы и согласования, которые агент создаёт на
задаче без собственного чат-биндинга) следует активному каналу:

- **активен в Telegram** — карточка уходит в постоянную Telegram-личку
  владельца с агентом-автором (путь U2);
- **активен в портале** — карточка остаётся на доске: владелец, который
  сегодня читает доску, читает карточку на доске, и тянуть доклад в Telegram
  во время работы в портале — движение в неверную сторону;
- **ни один канал не активен** — прежнее правило U2: побеждает Telegram,
  чтобы карточка всё равно дошла до пассивного владельца вне портала.

Собственные вендорские биндинги задачи всегда выигрывают: задача, которая
живёт в чужой тред-переписке, остаётся в ней — функция её не копирует.

## API

`GET /api/myrmidon/owner/active-channel` отвечает статусом вызывающего
пользователя доски:

```json
{
  "channel": "telegram",
  "lastActiveAt": { "web": "2026-10-05T09:55:00.000Z", "telegram": "2026-10-05T11:59:00.000Z" },
  "thresholdMin": 120,
  "thresholdSource": "default"
}
```

`channel` — `"web"`, `"telegram"` или `null`. `thresholdSource` говорит,
откуда взялось действующее значение порога: `settings` (сохранено в
настройках инстанса), `env` (принудительное переопределение окружением) или
`default`. Админ инстанса может спросить любого пользователя через `?userId=`;
обычный член доски читает только свой статус.

`PATCH /api/myrmidon/owner/active-channel` (админ инстанса) меняет порог:

```json
{ "thresholdMin": 30 }
```

Тело валидируется в целое 5–10080. Изменение пишет
`instance_settings.general.ownerActiveChannel`, записывает событие в журнал
активности каждой компании и сбрасывает короткий кэш читателей — следующее
решение о доставке уже использует новое значение. Без перезапуска.

## Порог в интерфейсе

Instance → General → панель «Активный канал владельца»: поле показывает
текущий порог, источник значения («Сохранено здесь» / «Принудительно из
окружения сервера» / «Умолчание»), активный канал владельца сейчас и кнопку
сохранения. Сохранение действует без перезапуска сервера.

`MYRMIDON_OWNER_ACTIVE_THRESHOLD_MIN` — только принудительное
переопределение: пока переменная задана, панель показывает
«Принудительно из окружения сервера», и поле неактивно. Уберите переменную,
чтобы вернуть управление сохранённому значению.

## Что показывает интерфейс

Футер рейки 2.0 и шапка телефона рисуют живой статус
(`useOwnerActiveChannel`, опрос раз в 30 с): «Активен · Веб»,
«Активен · Telegram» или «Давно не появлялся», когда ни один канал не внутри
порога. Прежние литералы («Web · сейчас», «Owner · Web») убраны.

  Postgres, критерии приёмки: сообщение владельца в Telegram делает
  активным Telegram, и карточка уходит туда; активность в портале оставляет
  карточку на доске; понижение порога через сервис меняет следующее решение
  без перезапуска.
- `server/src/__tests__/owner-telegram-delivery.myrmidon.test.ts` — прежний
  путь U2 без отметок активности ведёт себя байт в байт как раньше.

## Снятие

Удалите модуль `server/src/myrmidon/owner-active-channel/`, контракт shared
`packages/shared/src/myrmidon-owner-active-channel.ts`, файл схемы БД с
миграцией, панель и хук в `ui/` и куски с меткой
`myrmidon(1.7-ACTIVE-CHANNEL)` в файлах вендора; путь U2 можно вернуть в
`server/src/myrmidon/owner-delivery/`.
