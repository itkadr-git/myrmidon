# Умолчания списка задач для агентов (1.6.5 F-16, часть A)

Настройка инстанса `issuesListAgentDefaults` (хранится в
`instance_settings.general`, меняется без выката) задаёт, что получает
**агент-актор** (запрос с токеном агента) от эндпоинта списка задач
`GET /api/companies/{companyId}/issues`.

По умолчанию настройка **включена**: на инстансах, где её не трогали, ключ
отсутствует, а отсутствие означает «включено». Значение
`{ "enabled": false }` возвращает поведение до исправления байт-в-байт.

Зачем: на больших досках запрос списка без параметров отдавал агенту
1,5–4 МБ — он получал все `description`, даже когда ему нужно было просто
выбрать задачу. С включёнными умолчаниями тот же запрос отдаёт компактные
строки без `description` — примерно 3–4 КБ на строку вместо мегабайт; полное
тело выбранной задачи агент получает через детальный эндпоинт.

## Как переключить

В части A переключателя в интерфейсе нет (экран настроек придёт с частью B
— UI/nginx). Меняйте через API:

```
PATCH /api/instance/settings/general
{ "issuesListAgentDefaults": { "enabled": false } }
```

Настройку обработчик списка читает при каждом запросе
(`instanceSettingsService(db).getGeneral()`); перезапуск и выкат не нужны.

## Что меняется для агента-актора

Умолчания действуют только на запросы с токеном агента. Запросы доски
(человек, интерфейс) не затронуты — см. следующий раздел.

| Запрос агента | Ответ |
|---------------|-------|
| Без параметра `view` | ответ как при `view=compact` |
| Без `limit` | по умолчанию **200** строк |
| `limit` ≤ 500 | компактные строки, размер страницы равен `limit` |
| `limit` > 500 | **400** с подсказкой про пагинацию (вместо прежнего молчаливого ограничения) |
| `view=full&limit=N`, N ≤ 100 | полные строки с `description` |
| `view=full` без `limit` или `limit` > 100 | **400** с той же подсказкой |

В компактном ответе для агента поле `description` **не отдаётся**. Полное
тело выбранной задачи возвращает `GET /api/issues/{issueId}` — детальный
эндпоинт всегда отдаёт полную запись независимо от настройки.

Тексты ошибок (HTTP 400):

- лимит выше максимума для агента:
  `limit must be a positive integer up to 500 for agent actors; paginate
  with offset or afterId for larger windows`
- `view=full` без лимита или выше потолка полного вида:
  `view=full for agent actors requires an explicit limit up to 100; for
  larger windows paginate the default compact view with offset or afterId`

Пагинация: параметры `offset` / `afterId`; в ответе есть `nextOffset`,
когда строки ещё остались.

### Рекомендуемый порядок для агента

1. `GET /api/companies/{companyId}/issues` — до 200 компактных строк
   (заголовок, статус, приоритет, исполнитель, идентификаторы; без описания).
2. Выбранная задача — `GET /api/issues/{issueId}` за полным телом.
3. `view=full&limit=…` (≤ 100) — только когда описания действительно нужны
   сразу для многих задач.

## Доска: без изменений

Для запросов доски (человек, интерфейс) поведение — прежний контракт:
запрос без параметров получает полный ответ, `limit=1000` урезается до
максимума, как и раньше, а `view=full` для доски по-прежнему отвечает 400
(контракт совместимости UI). Вид `compact` существует для агентов и
скриптов, а не для веб-списка.

## Схема настройки

```json
"issuesListAgentDefaults": {
  "enabled": true
}
```

Схема также принимает `defaultLimit` / `maxLimit` / `fullViewMaxLimit`, но
сервер их пока не применяет — действующие значения зафиксированы:
200 / 500 / 100. Поддержка этих полей отложена до части B.

## ETag и кэширование

Условные запросы агента к списку продолжают работать. Ключ кэша списка
включает состояние настройки, поэтому тела с `description` и без него не
смешиваются при переключении (`304` обрабатывается по форме ответа).
