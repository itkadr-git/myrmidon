# Экран «Знания» (чтение, поиск, ревизии)

> Английская версия: [knowledge-screen.md](knowledge-screen.md)

Экран **«Знания»** доступен в оболочке UI 2.0, когда включена настройка
экземпляра `enableMyrmidonUi2`. Это поверхность чтения и проверки модуля
знаний компании; она не заменяет обычный путь авторства и утверждения.

## Как открыть

Выберите **Работа → Знания**. В этой же группе есть пункт **Работа →
Регламенты** — он открывает представление регламентов внутри автономии.

Экран читает компанию, выбранную в шапке доски. Человек без доступа к компании
получает обычный отказ доски; страницы и источники другой компании ему не
показываются.

## Чтение и поиск

- Дерево группирует страницы по пространству знаний и вкладывает страницу в
  путь, заданный её slug.
- Используйте поле поиска для полнотекстового поиска. Семантический поиск
  остаётся выбором интерфейса, но до включения семантического бэкенда использует
  доступную точку поиска знаний.
- Ссылки `[[slug]]`, `[[slug#anchor]]` и `[[slug|подпись]]` ведут на другую
  страницу. Ссылки внутри строчного кода и ограждённых блоков кода остаются
  обычным текстом.
- Панели источников и обратных ссылок ведут на задачи, решения, прогоны доски
  или внешний пул-реквест/URL, когда сохранённая ссылка разрешима. Неразрешимый
  источник остаётся видимым текстом, а не становится сломанной ссылкой.

## Ревизии и откат

Раздел **«Ревизии»** показывает append-only историю и построчно сравнивает две
ревизии. Восстановление прошлой ревизии создаёт новую — история не
перезаписывается.

Действие доступно только если его разрешает политика утверждения страницы.
Интерфейс называет необходимого утверждающего:

- **A** — действие несёт сам агент;
- **O** — действие несёт оператор или владелец.

Сервер остаётся источником истины. Отключённое действие, устаревшая страница
или неавторизованный актор получают отказ API и не меняют доставляемое знание.

## Регламенты

Регламенты сгруппированы по кастам. В каждой строке видны статус, число
ревизий и тот, кто должен её утвердить. Регламенты с человеческим
утверждением показывают действия утверждения и отката только при разрешающем
человеческое действие `approver_kind`; действие, закреплённое за агентом,
показывается как запрос, а не утверждается человеком от имени агента.
