# Онбординг сервера: предлагаемый жизненный цикл SSH-ключей

Здесь описано предложение из [PR #2824](https://github.com/itkadr-git/myrmidon/pull/2824), а не выпущенная или выкаченная возможность. PR открыт, а остальные части исполнителя парка проходят отдельную приёмку. Это описание не является инструкцией по развёртыванию.

## Идентичность хоста и доступ

Предлагаемый worker применяет trust on first use (TOFU): сохраняет первый принятый отпечаток SSH-ключа хоста до аутентификации и отклоняет изменённый отпечаток до отправки учётных данных, в том числе при повторном подключении. TOFU не подтверждает подлинность первого подключения: при необходимости сверяйте исходную идентичность хоста по доверенному каналу.

Приватный ключ доступа хранится в хранилище секретов доски. Worker устанавливает соответствующий публичный ключ и проверяет новое SSH-подключение только по ключу до возможного отключения парольной аутентификации. Если сохранение пароля не запрошено, доска удаляет начальный пароль только после успешного итогового отчёта о свежем входе и сверки текущего отпечатка и сохранённого ключа. Ошибка удаления фиксируется в аудите; удаление не гарантировано. Повторные или одновременные вызовы `addServer` используют отдельные секреты для каждой попытки, поэтому проигравший конфликт slug не меняет и не удаляет секреты зарегистрированного сервера.

Успех тестов не подтверждает выкат или приёмку всего исполнителя. До слияния и выката предложения откат этого изменения в бою не нужен.
