# Дебаты по кастам и кнопка «Обсудить» на задаче касты (1.7 DEBATE-ASYM B)

> English version: [debate-asym-castes.md](debate-asym-castes.md)

Часть A ([debate-asym.md](debate-asym.md)) настраивает движок дебатов один раз
на весь инстанс. Но касты делают разную работу: каста маркетинга спорит о
формулировке кампании, каста инженерии — о миграции, и бесплатные модели,
подходящие одной паре ролей, не обязательно подходят другой. Часть B даёт
**каждой касте свои настройки** и ставит запуск туда, где работу видно, — на
задачу этой касты в очереди ролей супервизора роя.

## Что можно настроить на касту

| Настройка | Смысл |
|---|---|
| **Вкл/выкл** | вообще могут ли для этой касты идти дебаты. Для касты без своей записи дебаты **включены** (конфигурация инстанса — уже осознанный выбор оператора, модели по умолчанию бесплатные); выключатель нужен, чтобы убрать касту из расхода — ту, чья работа не должна тратить вызовы шлюза, или ту, которую пилотируют позже |
| **Модели ролей** | генератор, критик и судья для этой касты. Правило разных семейств не меняется и проверяется на **итоговой** конфигурации: каста, переопределившая только критика, не может протащить судью того же семейства |
| **Инструкция на роль** | дополнительные указания каждой роли. Текст **дописывается к встроенному промпту полярности** и никогда его не заменяет: у критика остаются его адверсариальная полярность и штраф за пропущенную ошибку, у генератора — конструктивная, у судьи — место вне спора. Каста сужает, куда смотреть роли, но не меняет природу спора |
| **Круги** | 1..3, не больше (правило владельца) |
| **Потолок токенов** | общий потолок токенов одного дебата этой касты |

## Где это настраивается

Экран — **Инстанс → Общие → Асимметричные дебаты → Дебаты по кастам** (раздел
внутри панели дебатов, рядом с ролями уровня инстанса), API:

| Вызов | Тело / ответ |
|---|---|
| `GET /api/myrmidon/companies/:companyId/debates/castes/:casteKey/settings` | действующие значения, источник каждой части, сохранённая запись и настроен ли шлюз. Чтение — board |
| `PATCH` по тому же пути | `{ "settings": { enabled, generator, critic, judge, rounds, tokenCeiling, prompts } }` — или `{ "settings": null }`, чтобы снять запись и снова наследовать. **Только администратор инстанса** (запись ложится в значение настроек инстанса — то же правило, что у PATCH уровня инстанса); каждое сохранение пишется в журнал активности (`debate.caste_settings.saved`) |

Запись хранится **рядом с конфигурацией инстанса**, внутри того же значения
`instance_settings.general.debate`:

```jsonc
{
  "generator": { "model": "qwen-plus-free" },   // уровень инстанса (часть A)
  "critic":    { "model": "glm-4-flash-free" },
  "judge":     { "model": "deepseek-chat-free" },
  "rounds": 3,
  "tokenCeiling": 50000,
  "castes": {                                    // часть B, запись на касту
    "marketing": {
      "companyId": "…",                          // пишет сервер, не вызывающий
      "enabled": true,
      "critic": { "model": "glm-4-flash-free" },
      "rounds": 2,
      "tokenCeiling": 20000,
      "prompts": { "critic": "проверь юридические утверждения кампании" }
    }
  }
}
```

Два следствия, которые полезно знать:

- **Без миграции и без перезапуска.** Значение уже владеет конфигурацией
  движка и ключом сохранения (часть A держит его живым при записях вендора в
  `instance_settings`), и читается оно на каждом запуске/записи, а не кэшируется
  на старте, — сохранение действует на следующем дебате.
- **Запись привязана к своей компании.** Касты — строки компании; запись, у
  которой `companyId` не совпадает с разрешаемой кастой, инертна и отмечается
  как проигнорированная — она не применяется молча к одноимённой касте в другом
  месте.

## Прецедентность

Для касты: **запись касты** поверх **конфигурации инстанса** (сохранённая
строка → `MYRMIDON_DEBATE_CONFIG` → встроенное умолчание). Каждая подпись на
экране называет источник: *Set for this caste* / *Inherited from the instance
level (…)*; у выключателя своя подпись (*Set for this caste* / *On by default —
no per-caste switch saved yet*).

Ничего не деградирует молча. Кривая запись касты или итоговая конфигурация,
нарушившая правило разных семейств, отклоняются с точной причиной и ничего не
сохраняют; при запуске такая каста отклоняет дебат с `debate_config_rejected`
(422).

## Запуск дебатов из задачи

Кнопка **«Обсудить»** стоит в каждой строке **очереди задач касты** на
`/swarm-claim` (Надзор за роем → очереди ролей). Нажатие запускает один дебат по
этой задаче с кастой строки (`POST …/debates/issues/:issueId/run` с
`{ "casteKey": "<роль строки>" }`) и показывает результат прямо под кнопкой:

- вердикт судьи (первая строка),
- как дебат остановился (`agreement` / `rounds_exhausted` / `token_ceiling`) и почему,
- круги, токены к потолку и стоимость,
- касту, для которой шёл дебат, и какие роли спорили со своей инструкцией,
- имя документа результата, оставленного на задаче.

Полный транскрипт, роли и стоимость ложатся на задачу документом
`debate-result` (писатель из части A), а расход записывается cost-событиями
уровня задачи, так что BUDGET-CONFIG считает его как любую другую работу.

Отказы показываются, а не проглатываются:

| Ответ | Когда | Что видно на экране |
|---|---|---|
| `422 debate_caste_disabled` | выключатель касты снят | причина и подсказка, где выключатель (Инстанс → Общие → Асимметричные дебаты → Дебаты по кастам) |
| `422 debate_config_rejected` | итоговая конфигурация не может работать (правило семейств) | точная причина от сервера |
| `404 debate_caste_not_found` | роли строки нет в каталоге каст компании | сообщение сервера |
| `503` | шлюз (контур evals/дебатов) не настроен | проблема шлюза |
| `403 autonomy_*` | **агент**-вызывающий не допущен матрицей автономии | код forbidden/approval — дебат тратит вызовы шлюза, поэтому агент гейтится по классу `spend_above_threshold`; доска матрицу обходит |

Задача, **не привязанная к касте**, сохраняет поведение части A:
запуск без `casteKey` и без исполнителя использует конфигурацию уровня инстанса,
и документ результата ничего не говорит о касте. Кнопка всегда передаёт касту
той строки, в которой стоит.

## Пилот: каста маркетинга

1. Убедиться, что настроен сам движок: Инстанс → Общие → Асимметричные дебаты
   (или `PATCH /api/myrmidon/debate/settings`) — три модели ролей из трёх
   семейств, шлюз помечен как настроенный.
2. Выбрать касту **marketing** в «Дебаты по кастам», проверить, что выключатель
   включён, и сохранить модели, круги, потолок и — если касте нужно — свою
   инструкцию на роль (например: критику проверять юридические утверждения
   кампании, генератору держать ответ в рамках плана каналов). Значения до
   сохранения — действующие, с источником.
3. Открыть `/swarm-claim`, найти задачу маркетинга в очереди этой роли и нажать
   **«Обсудить»**. Результат появится под кнопкой; тот же запуск оставляет на
   задаче документ `debate-result`.
4. Следить за расходом: дебат пишет cost-события на задачу, и BUDGET-CONFIG
   видит его на уровне задачи как любую другую трату. Бесплатные модели стоят 0
   — токены всё равно считаются против потолка.

## Как снимать

Всё в части B — наше: `packages/shared/src/myrmidon-debate-castes.ts`, маршруты
и хранилище каст (`server/src/myrmidon/debates/{castes,routes,service}.ts`), два
экрана (`ui/src/components/myrmidon/CasteDebateSettingsPanel.tsx`,
`DebateTaskButton.tsx`), ключи форк-каталога `swarm.discuss*`. В вендоре правки
только помечены комментариями `myrmidon(1.7-DEBATE-ASYM-B)` (строка экспорта в
`packages/shared/src/index.ts`); см. `docs/myrmidon/DIVERGENCE.md`. Снятие части A
снимает и часть B: карта каст живёт внутри сохранённого значения части A, так
что удаление ключа `debate` и панели убирает оба уровня.
