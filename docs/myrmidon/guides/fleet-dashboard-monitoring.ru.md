# Данные дашборда флота: подключения VictoriaMetrics + Zabbix, API снимка, самопроверка (1.6.6 MONITORING C)

> English version: [fleet-dashboard-monitoring.md](fleet-dashboard-monitoring.md)

API данных дашборда флота (часть C трека MONITORING) отдаёт доске один
сводный снимок флота, на котором работает развёртывание: хосты, контейнеры
ботов, прокси LiteLLM и сборочный VPS. Показатели приходят из двух внешних
источников — VictoriaMetrics (PromQL node_exporter) и Zabbix (`host.get` /
`item.get`). Это руководство о том, как подключить источники, что отвечает
эндпоинт дашборда и как читать самопроверку. Сам экран флота — более
поздняя часть трека; здесь описан API, к которому обращаются экран и
операторские скрипты.

Оба источника — только на чтение, и это заложено в код: VM-клиент делает
только мгновенные (instant) PromQL-запросы (`/api/v1/query`), Zabbix-клиент
вызывает только `apiinfo.version`, `host.get` и `item.get`. Доска ничего не
записывает ни в одну из систем.

## Настройки подключений

Подключения настраиваются в настройках экземпляра доски (один документ на
компанию, тот же паттерн, что у настроек обслуживания и тревог); менять их
можно через API:

| Метод | Путь | Кто | Что делает |
|---|---|---|---|
| `GET` | `/api/myrmidon/monitoring` | пользователь доски | Читает настройки подключений компании (если у актора несколько компаний, передайте `?companyId=`) |
| `PATCH` | `/api/myrmidon/monitoring` | администратор экземпляра | Обновляет настройки; патч сливается аддитивно: поля, которых нет в запросе, сохраняют прежние значения |

Документ настроек:

| Поле | Умолчание | Что делает |
|---|---|---|
| `vmUrl` | не задано | Базовый URL VictoriaMetrics, например `http://vm:8428`. Не задано — источник VM отвечает `not_configured` |
| `vmTokenRef` | не задано | Ссылка на read-токен VM: `env:<NAME>` или `file:<PATH>` |
| `zabbixUrl` | не задано | Эндпоинт Zabbix API (URL `api_jsonrpc.php`). Не задано — источник Zabbix отвечает `not_configured` |
| `zabbixTokenRef` | не задано | Ссылка на read-токен Zabbix API: `env:<NAME>` или `file:<PATH>` |
| `vmJobSelector` | `node` | Значение метки job, по которой PromQL выбирает node_exporter флота (подставляется как `job=~"<value>"`) |
| `zabbixHostGroups` | `[]` | Группы хостов Zabbix, которые читает дашборд; пусто — все наблюдаемые хосты |
| `timeoutMs` | `10000` | Таймаут запроса к каждому источнику, 500–60000 мс |

Ссылки на токены, а не сами токены. В настройках хранится только
`env:<NAME>` (имя переменной окружения процесса сервера доски) или
`file:<PATH>` (файл, доступный доске, например Docker-секрет). Значение
разрешается заново на каждый запрос и живёт только в памяти: оно никогда не
сохраняется в настройках, не возвращается API и не попадает в логи. Если
ссылка разрешилась в пустое значение, это ошибка конфигурации. Источнику не
нужна авторизация — ссылку не задают, и источник опрашивается без токена.

Ненастроенный источник — не ошибка. Без `vmUrl` источник VM отвечает
`not_configured`, а дашборд по-прежнему отдаёт данные Zabbix — и наоборот.

## Снимок дашборда

`GET /api/myrmidon/monitoring/dashboard` (пользователь доски) отвечает одним
JSON-документом:

| Поле | Содержимое |
|---|---|
| `ok` | `true`, если ответили все настроенные источники |
| `generatedAt` | Момент снимка в формате ISO |
| `sources` | Статус каждого источника: `{name, ok, latency_ms, error}` для `victoriametrics` и `zabbix`; `error` — машинно-читаемый класс (`not_configured`, `http_502`, `timeout`, `request_failed`) без URL и деталей токена |
| `hosts` | Карточка каждого хоста флота: `name`, `origin` (`victoriametrics` / `zabbix` / `none`), `cpuPercent`, `memoryPercent`, `swapPercent`, `diskPercent`, `ageSec` (секунды с момента последнего замера), `runbookKey` |
| `containers` | Контейнеры ботов из cAdvisor (если они есть в VM): `name`, `cpuPercent`, `memoryBytes`, `state` |
| `litellm` | Сводка прокси LiteLLM, если VM её отдаёт: `ok`, `rps`, `latencyP95Sec`; иначе `null` |
| `vps` | Сводка сборочного VPS (хост с меткой build): `cpuPercent`, `memoryPercent`, `diskPercent`; иначе `null` |

Как объединяются данные двух источников:

- Показатели хостов берутся в первую очередь из VictoriaMetrics
  (node_exporter PromQL, выборка по `vmJobSelector`). Zabbix дополняет те
  хосты, которых VM не видит; хост, известный обоим источникам, сохраняет
  показатели VM (`origin: "victoriametrics"`).
- Отказавший источник не срывает ответ: дашборд отдаёт данные второго
  источника, а отказавший виден в `sources` с классом ошибки.
- Разделы контейнеров, LiteLLM и VPS собираются из VM по возможности: если
  такие запросы упали, карточки хостов остаются, а раздел пустеет.

`runbookKey` карточки хоста — ключ runbook'а восстановления, которым
пользуется действие «создать задачу с runbook» на экране флота: у
недоступного хоста — `host-unreachable` (его runbook лежит в
[runbooks/host-unreachable.md](../runbooks/host-unreachable.md)), у хоста с
загрузкой 90 % и выше по любому из CPU / память / swap / диск —
`host-saturation`, а у хоста с корневой файловой системой на 85 % и выше —
`host-disk-pressure`. У здорового хоста — `null`.

## Самопроверка

`GET /api/myrmidon/monitoring/dashboard/selfcheck` (пользователь доски)
проверяет каждый настроенный источник одним лёгким запросом — `up` у VM,
`apiinfo.version` у Zabbix — и отвечает:

```json
{
  "ok": true,
  "vm_ok": true,
  "zabbix_ok": true,
  "sources": [
    { "name": "victoriametrics", "ok": true, "latency_ms": 12, "error": null },
    { "name": "zabbix", "ok": true, "latency_ms": 44, "error": null }
  ]
}
```

Как читать ответ:

- Список `sources` всегда содержит оба источника, настроенный и
  ненастроенный, чтобы экран флота показал карточку статуса по каждому.
- `ok` равно `true`, только когда хотя бы один источник настроен и каждый
  настроенный ответил; ненастроенный источник (`not_configured`) на итог не
  влияет.
- В ответе нет секретов — только имена, флаги и задержки, поэтому его
  безопасно опрашивать из дашбордов и скриптов.
