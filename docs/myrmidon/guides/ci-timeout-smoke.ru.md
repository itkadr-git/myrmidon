# Ручная проверка таймаута CI

Инструкция предназначена для сопровождающих self-hosted исполнители GitHub Actions репозитория Myrmidon. Она проверяет настоящий таймаут job и последующую очистку исполнителя без изменений боевых jobs. Ручной workflow `.github/workflows/myrmidon-ci-timeout-smoke.yml` содержит одну job на `self-hosted`, `timeout-minutes: 1`, `sleep 99999` и `permissions: {}`. Слияние workflow не доказывает прохождение проверки таймаута или очистки.

## Перед запуском

1. Согласуйте с владельцем инфраструктуры исполнителей один запуск и read-only проверки хоста до и после него. Выберите окно CI. Штатным доступом подтвердите с владельцем, что подходящий исполнитель свободен; не прерывайте и не занимайте занятого исполнителя. Workflow использует общую метку `self-hosted`, поэтому проверка свободного исполнителя сама по себе не закрепляет конкретный хост.
2. Проверьте существующие запуски workflow и запись о согласовании. Если разрешённая проверка уже запускалась, изучите этот запуск вместо нового. Если состояние исполнителя или доступ к хосту не подтверждены, остановитесь и согласуйте действия; не угадывайте и не перебирайте учётные данные.
3. Запишите путь workflow, ref, фактический SHA коммита workflow, время предварительной проверки и выбранное окно. Получите согласие владельца ровно на один dispatch. Не запускайте workflow ради документации и не повторяйте запуск только для сбора доказательств.

## Запуск и сбор доказательств

1. Назначенный оператор один раз запускает workflow на согласованном ref и сразу записывает URL запуска. Не меняйте метки и маршрутизацию исполнителей или таймауты боевых jobs ради проверки.
2. Проверьте jobs запуска через GitHub Actions jobs API. Запишите ID и имя job, `conclusion`, `started_at`, `completed_at`, `runner_id` и `runner_name`, а также URL запуска и фактический head SHA. Критерий приёмки — `timed_out` именно у job: `failure` на уровне run, таймаут шага или один лишь `cancelled` не доказывают таймаут job.
3. По идентификатору исполнителя вместе с владельцем инфраструктуры определите фактический хост. На нём выполните адресную read-only проверку конкретной smoke job и запишите время и доказательства завершения её `sleep 99999` и связанного `Runner.Worker`. Не считайте процессы других jobs процессами проверки и не завершайте их. Один таймаут без доказательств с хоста не подтверждает очистку.
4. Запишите результаты таймаута и очистки в запись о согласовании. Если job попала на неожиданный или недоступный хост либо доказательства неполны, укажите, что результат не подтверждён, и привлеките владельца инфраструктуры; не запускайте повторно.

Для изучения существующего запуска без нового запуска выполните `gh api repos/itkadr-git/myrmidon/actions/runs/RUN_ID/jobs`, подставив записанный ID. Список существующих запусков доступен через `gh api repos/itkadr-git/myrmidon/actions/workflows/myrmidon-ci-timeout-smoke.yml/runs`.
