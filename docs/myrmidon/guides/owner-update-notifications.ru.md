# Уведомления владельцу о событиях обновления (TG-NOTIFY)

## Описание

В рамках функциональности **1.7 AUTO-UPDATE-SETTINGS** (OPE-8656) реализованы уведомления владельцу продукта в Telegram о ключевых событиях жизненного цикла автоматических обновлений.

Уведомления поддерживают следующие события:
- **Начало канарейки** (`canary_started`): запуск канареечного развёртывания новой версии (с указанием версии/хэша и параметров канарейки).
- **Успешный выкат** (`rollout_succeeded`): успешное завершение раскатки обновления на все инстансы.
- **Начало автоотката** (`rollback_started`): обнаружение проблем канарейки или развёртывания и запуск автоматического отката.
- **Завершение автоотката** (`rollback_completed`): успешный откат на стабильную версию с указанием точной причины сбоя.
- **Ожидание окна обслуживания** (`waiting_window`): информирование о том, что обновление ожидает наступления разрешённого сервисного окна.

## Настройки (`telegramNotify.updates`)

Настройки уведомлений об обновлениях входят в общий документ `telegramNotify` на уровне компании:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | `boolean` | `false` | Главный переключатель уведомлений об обновлениях. По умолчанию выключен. |
| `chatId` | `string \| null` | `null` | Идентификатор чата Telegram для прямой отправки (при отсутствии активного канала owner-delivery). |
| `topicId` | `string \| null` | `null` | Идентификатор темы форума (topic thread id) внутри супергруппы Telegram. |

### Чтение настроек без перезапуска

Настройки `telegramNotify.updates` сохраняются в хранилище инстанса (`instance_settings.general.myrmidonTelegramNotifySettings`) и считываются в момент возникновения события обновления. Перезапуск процессов доски или бота не требуется — изменения вступают в силу немедленно.

## Маршрутизация доставки

Доставка сообщений осуществляется по следующему алгоритму:
1. **Проверка активности**: если `updates.enabled === false`, отправка не производится, очередь не засоряется.
2. **Owner-delivery (приоритетный канал)**: проверяется наличие активного прямого канала связи с владельцем (Telegram DM через привязку пользователя или активную сессию). Если такой канал найден, уведомление направляется туда.
3. **Прямая отправка в Telegram (резервный канал)**: если активного owner-delivery нет, используется публикация в чат/топик, указанный в `updates.chatId` и `updates.topicId`, через существующую очередь исходящих сообщений (`chat_publications`).
4. Если ни один канал не настроен, сообщение не отправляется, в журнал пишется статус `no_destination_channel`.

## Управление через API

### Получение текущих настроек
```http
GET /api/myrmidon/telegram-notify
```
Ответ содержит секцию `updates`:
```json
{
  "settings": {
    "updates": {
      "enabled": false,
      "chatId": null,
      "topicId": null
    }
  }
}
```

### Включение уведомлений
```http
PATCH /api/myrmidon/telegram-notify
Content-Type: application/json

{
  "updates": {
    "enabled": true,
    "chatId": "-1001234567890",
    "topicId": "42"
  }
}
```
Каждое изменение параметров фиксируется в журнале изменений (`changelog`) документа `telegramNotify`.
