# Дедупликация событий и webhook-карточек взаимодействий

> Английская версия: [interaction-webhook-dedupe.md](interaction-webhook-dedupe.md)

При повторной доставке запросов от входящих webhook, чат-мостов или runtime-раннеров для создания карточек взаимодействий в треде задачи (`issue_thread_interactions`), повтор одного и того же исходного события не должен приводить к созданию дублирующих карточек.

Система обеспечивает идемпотентность через вычисление детерминированного ключа дедупликации на основе идентификатора события и проверку уникальности на уровне базы данных.

## Формирование ключа дедупликации

Если входящее событие не содержит явного ключа `idempotencyKey`, роутер формирует детерминированный ключ с помощью функции `buildInteractionDedupeKey`:

```typescript
import { buildInteractionDedupeKey } from "../interaction-router/dedupe-key.js";

const dedupeKey = buildInteractionDedupeKey({
  source: "runner",
  sourceEventId: event.sourceEventId,
  issueId: binding.issueId,
  routeType: "human_input",
});
```

Формат сформированного ключа: `interaction-route:<sha256>`, где хэш вычисляется от сериализованного массива `[source, sourceEventId, issueId, routeType]`.

## Приоритет и поведение при повторной доставке

1. **Приоритет явного ключа**: Если раннер или клиент явно передал непустой `idempotencyKey`, используется именно этот явный ключ с сохранением прежнего поведения.
2. **Подавление дублей**: Повторная доставка события с тем же `sourceEventId` возвращает существующую карточку без вставки новой записи в таблицу `issue_thread_interactions`.
3. **Разные события**: События с отличающимися `sourceEventId` получают независимые ключи и создают раздельные карточки взаимодействий.
