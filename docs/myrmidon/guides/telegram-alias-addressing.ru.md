# Мостовой Telegram-чат: адресация любого агента компании через @<alias>

> English version: [telegram-alias-addressing.md](telegram-alias-addressing.md)

Один мостовой Telegram-чат (личка бота, подключённая через
`MYRMIDON_TELEGRAM_DM_CONVERSATIONS`, или топик группы, где бот был
упомянут) может адресовать другого агента компании через подходящее
`@`-упоминание в обычном сообщении. Сообщение уходит в собственную
постоянную переписку этого агента, а ответ возвращается в тот же чат.
Алиас, упомянутый дальше по тексту, остаётся обычным текстом. `/to`
сохраняет выбранного адресата чата, которого показывают `/who` и `/agents`;
это не запасной адресат для входящей маршрутизации — чтобы обратиться к
другому агенту, обычное сообщение должно содержать подходящее `@`-упоминание.

```
@гип посчитай смету по разделу 3
```

Отдельная настройка не нужна: адресация едет поверх моста X8b. Пока
переменная не задана, путь вендора не меняется и этот гайд не применим.

## Куда уходит сообщение

- Ведущий `@`-токен, который резолвится в агента компании, маршрутизирует
  сообщение в **его собственную** постоянную переписку Agent Chat с той же
  Telegram-идентичностью. Токен дальше по тексту остаётся обычным текстом и
  не меняет адресата.
  `conversation_agent_id` — адресованный агент, `conversation_user_id`
  остаётся `telegram:<id пользователя доски>`. Переключение точечно:
  чат, обращавшийся к одному агенту, может обратиться к другому, а возврат
  к прежнему восстановит ту же переписку — история каждой переписки
  хранится в своей строке issues.
- Ответ адресованного агента публикуется **в тот же Telegram-тред**, из
  которого пришло сообщение, с префиксом отображаемого имени агента:
  `[ГИП] вот уточнённая смета…`.
- Первый ход адресованного агента цитирует недавние сообщения этого
  Telegram-чата, чтобы агент вошёл в разговор с контекстом. Глубина
  цитирования задаётся настройками кросс-канального цитирования
  (`MYRMIDON_CHAT_CROSS_CHANNEL_MESSAGES` и соседние).
- Ведущий `@<алиас>`-токен вырезается из тела хода — он уже сработал как
  маршрут. Упоминания дальше по тексту остаются обычным текстом и не
  меняют адресата.
- Сообщение без распознанного `@`-токена идёт назначенному на эндпоинт
  агенту ровно так же, как до этого изменения, даже если `/to` хранит
  другого адресата. Чтобы обратиться к другому агенту, добавьте подходящее
  `@`-упоминание.

## Что такое алиас и где он живёт

Алиас — короткий псевдоним, который выбирает оператор для агента. Алиасы
живут в JSON-карточке агента — массив строк `telegramAliases` в
`agents.metadata` (или `agents.adapter_config`):

```json
{ "telegramAliases": ["гип", "смета"] }
```

Порядок сопоставления при резолве упоминания:

1. точный алиас (без учёта регистра; при вложенности алиасов побеждает
   самый длинный, поэтому `@гип2` не резолвится как `@гип`),
2. имя агента,
3. должность агента.

Адресуемы только агенты **той же компании**, что и эндпоинт, — алиас
агента чужой компании никогда не резолвится.

## Кто может адресовать

Адресация следует гейту идентичности X8b: она применяется, только когда
отправитель в Telegram резолвится в связанного пользователя доски.
Непривязанный отправитель получает отказ моста раньше любого резолва. В
топиках групп сообщение резолвит адресата, только если оно адресовало
бота, — остальное отбрасывает вендорский `requireMention`-гейт.

## Команды

| Команда | Что делает |
|---|---|
| `/agents` | Список агентов компании с их алиасами |
| `/to <алиас>` | Сохраняет выбранного адресата чата, которого показывают `/who` и `/agents`; обычные сообщения без подходящего `@`-упоминания идут назначенному агенту эндпоинта. `/to` без аргумента сбрасывает сохранённый выбор. |
| `/who` | Показывает текущего адресата по умолчанию |

Неизвестный алиас в `/to` возвращает список валидных.

## Где записи

Сама адресация новых строк настроек не добавляет; поведение и его
отношение к вендорскому коду записаны в
[DIVERGENCE.md](../DIVERGENCE.md) (X9a, X9b), а настройки моста — в
[SETTINGS.md](../SETTINGS.md) (`MYRMIDON_TELEGRAM_DM_CONVERSATIONS`).
