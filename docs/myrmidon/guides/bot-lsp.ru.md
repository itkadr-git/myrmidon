# Настройка BOT-LSP

Это руководство объясняет, как настраивать параметры Language Server Protocol (LSP) для ботов в системе Myrmidon.

## Обзор

Функция BOT-LSP позволяет контролировать поведение языковых серверов в контейнерах ботов для оптимизации использования ресурсов. Это особенно важно для снижения потребления памяти процессами tsserver, которые могут накапливаться на хосте.

## Структура конфигурации

Настройки LSP могут быть настроены на двух уровнях:

1. **Стандарты экземпляра** - Применяются глобально ко всем ботам на экземпляре
2. **Переопределения для отдельных агентов** - Специфичные настройки для отдельных агентов, которые переопределяют стандарты экземпляра

### Доступные настройки

#### `enabled` (boolean)
- Контролирует, включена ли поддержка LSP для бота
- По умолчанию: `true`

#### `idleTimeout` (number)
- Время ожидания в секундах, после которого неиспользуемые языковые серверы отключаются
- По умолчанию: `600` (10 минут)
- Рекомендуется для разработки: `120` для экономии памяти

#### `excludeRoots` (string[])
- Шаблоны Glob для исключения из анализа языковым сервером
- Полезно для исключения монорепозиториев, которые проверяются отдельно
- Примеры: `['**/myrmidon/**', '/workspace/*/repo']`

#### `waitMode` (string)
- Режим ожидания для ответов языкового сервера ('sync' или 'async')
- По умолчанию: 'sync'

#### `servers` (Record<string, any>)
- Переопределения конфигурации для отдельных серверов
- Позволяет точно настраивать отдельные языковые серверы

## Примеры использования

### Конфигурация на уровне экземпляра (Разработка)

Для настройки всех ботов разработки с более короткими таймаутами и исключением путей монорепозиториев:

```typescript
{
  instanceDefaults: {
    lsp: {
      enabled: true,
      idleTimeout: 120,  // 2 минуты вместо 10
      excludeRoots: ['**/myrmidon/**', '/workspace/*/repo'],
      waitMode: 'sync'
    }
  }
}
```

### Переопределение на уровне агента

Для переопределения настроек для конкретного агента:

```typescript
{
  lsp: {
    enabled: false,      // Отключить LSP для этого агента
    idleTimeout: 60      // Таймаут 1 минута
  }
}
```

### Комбинирование настроек экземпляра и агента

Когда предоставлены как стандарты экземпляра, так и специфичные настройки агента, настройки агента имеют приоритет:

```typescript
// Стандарты экземпляра
{
  instanceDefaults: {
    lsp: {
      enabled: true,
      idleTimeout: 120,
      excludeRoots: ['**/myrmidon/**']
    }
  },
  // Переопределение агента
  lsp: {
    enabled: false,           // Переопределяет значение экземпляра
    excludeRoots: ['**/test/**']  // Переопределяет значение экземпляра
    // idleTimeout остается 120 из стандартов экземпляра
  }
}
```

### Конфигурация отдельных серверов

Тонкая настройка отдельных языковых серверов:

```typescript
{
  lsp: {
    servers: {
      tsserver: {
        memoryLimit: 1024,
        maxOldSpaceSize: 1024
      },
      eslint: {
        configFile: '.eslintrc.js'
      }
    }
  }
}
```

## Оптимизация памяти

Основная цель конфигурации BOT-LSP - снизить потребление памяти:

- Установите `idleTimeout` на меньшие значения (например, 120 секунд) для сред разработки
- Используйте `excludeRoots` для исключения монорепозиториев, которые проверяются отдельно через `devbuild`
- Рассмотрите возможность отключения LSP полностью для ботов, работающих с большими монорепозиториями

## Интеграция с devbuild

Для проектов монорепозиториев конфигурация LSP дополняет систему `devbuild`:

- Исключите пути монорепозиториев с помощью `excludeRoots`
- Пусть `devbuild` занимается проверкой типов и валидацией во время сборки
- Используйте более короткие значения `idleTimeout` для снижения потребления памяти во время разработки

## Особенности различий

Эта система конфигурации отличается от оригинальной конфигурации Hermes тем, что предоставляет специфичные для ботов элементы управления LSP, которые интегрируются с системой оркестровки контейнеров Myrmidon. Оригинальные настройки LSP Hermes обычно настраиваются в `hermes_cli/config_defaults.py`, в то время как эта система обеспечивает контроль на уровне контейнера через процесс компиляции профиля бота.
