# Особенность FORAGING-IDLE-GATE

## Обзор

Особенность FORAGING-IDLE-GATE гарантирует, что фуражировка (сбор знаний из утвержденных источников) происходит только тогда, когда в очереди роли нет задач и есть свободный агент. Это реализует правило продукта о том, что обучение (фуражировка) должно происходить только в простое, а рабочие задачи всегда имеют приоритет.

## Назначение

Цель этой особенности - предотвратить конкуренцию между фуражировками и обычными рабочими задачами за ресурсы агентов. Фуражировка будет выполняться только когда:

1. В очереди роли нет задач (задачи со статусом "todo" или "in_progress", назначенных на роль)
2. Есть хотя бы один свободный агент, доступный для роли

## Конфигурация

Особенность контролируется следующей переменной окружения:

- `MYRMIDON_FORAGING_IDLE_GATE_ENABLED`: Включает или отключает функциональность контроля простоя
  - По умолчанию: `1` (включено)
  - Установите в `0`, чтобы отключить контроль простоя и позволить фуражировку независимо от состояния очереди/агентов

Другие связанные параметры конфигурации:
- `MYRMIDON_FORAGING_ENABLED`: Управляет тем, включена ли фуражировка в целом
- `MYRMIDON_FORAGING_BUDGET_CENTS`: Устанавливает порог стоимости на проход
- `MYRMIDON_FORAGING_INTERVAL_SEC`: Устанавливает интервал сканирования в секундах

## Поведение

Когда контроль простоя включен:

1. Перед началом прохода фуражировки система проверяет каждую роль, у которой есть включенные источники фуражировки
2. Для каждой роли она проверяет:
   - Что в очереди роли нет задач
   - Что есть хотя бы один свободный агент, доступный для роли
3. Если одно из условий не выполнено, проход фуражировки пропускается для этой роли с причиной:
   - `queue_not_empty`: Когда в очереди роли есть задачи
   - `no_idle_agent`: Когда нет свободных агентов для роли
4. Если оба условия выполнены, фуражировка выполняется в обычном режиме

Когда контроль простоя отключен, фуражировка запускается по расписанию независимо от состояния очереди или агентов.

## Информация о результате

Результат сканирования фуражировки включает поле `skippedReason`, когда проход пропускается из-за контроля простоя:

- `queue_not_empty`: Фуражировка пропущена, потому что в очереди были задачи для роли
- `no_idle_agent`: Фуражировка пропущена, потому что не было свободных агентов для роли
- Отсутствует: Фуражировка выполнялась нормально

## Тестирование

Модульные тесты покрывают следующие сценарии:
1. Фуражировка работает нормально, когда контроль простоя отключен
2. Фуражировка пропускается, когда очередь не пуста и контроль простоя включен
3. Фуражировка пропускается, когда нет свободных агентов и контроль простоя включен
4. Фуражировка запускается, когда очередь пуста и свободный агент доступен
