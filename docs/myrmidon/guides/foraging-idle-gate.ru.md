# Гейт простоя фуражировки (myrmidon 1.6.3 FORAGING-IDLE-GATE)

## Что делает

Правило продукта: **обучение только в простое**. Перед тем как проход
фуражировки читает источники роли, проход проверяет, что роль простаивает:

- очередь роли пуста — это та же готовая очередь, которую читает
  пробуждение простаивающих агентов роя (задачи `todo` роли или без
  исполнителя, не заблокированные, не контейнеры с открытыми детьми, не в
  декомпозиции, без удержания);
- есть хотя бы один свободный агент роли — не на паузе и не в ошибке, без
  живого прогона и без живой аренды.

Занятая роль **пропускается в этом проходе**: её источники не читаются, а
результат прохода и журнал несут причину:

| причина            | смысл                                                        |
| ------------------ | ------------------------------------------------------------ |
| `queue_not_empty`  | в очереди роли есть готовые задачи в ожидании                 |
| `no_idle_agent`    | ни один агент роли не свободен (пауза, ошибка, прогон или аренда) |

Гейт действует **по роли внутри одного прохода**: занятая роль инженера
никогда не мешает sweep прочитать источники роли smm в том же проходе. Проход
никогда не обрывается из-за гейта.

## Переключатель

Гейт включён по умолчанию. Это значение страницы настроек —
`instance_settings.general.foragingIdleGate` — меняется через:

```
GET   /api/myrmidon/foraging/idle-gate     (чтение board; отвечает {enabled, source})
PATCH /api/myrmidon/foraging/idle-gate     (instance admin; тело {enabled: boolean})
```

Проход **перечитывает переключатель на каждом проходе**, поэтому изменение
на странице настроек действует на следующий проход без перезапуска сервера.
`GET` отвечает действующее значение и его источник:

- `settings` — сохранённое значение (`general.foragingIdleGate`);
- `env` — принудительное переопределение `MYRMIDON_FORAGING_IDLE_GATE_ENABLED`
  (для инстанса, где значение ни разу не сохраняли; `1/true/on/yes` = вкл,
  `0/false/off/no` = выкл, остальное читается как «не задано»);
- `default` — ничего не сохранено и в env пусто: включено.

Приоритет: сохранённое значение; затем env; затем встроенное значение. Нечитаемое
сохранённое значение считается отсутствующим, а ошибка чтения настроек
срабатывает «открыто» (гейт остаётся включённым) — временная ошибка БД не
может заблокировать фуражировку в состояние, которого никто не просил.

Другие связанные параметры (без изменений этой фичей):

- `MYRMIDON_FORAGING_ENABLED`: общее включение фуражировки
- `MYRMIDON_FORAGING_BUDGET_CENTS`: потолок стоимости на проход
- `MYRMIDON_FORAGING_INTERVAL_SEC`: интервал проходов в секундах

## Информация о результате

Результат прохода фуражировки содержит поле `skippedReason`, когда роль была
пропущена из-за гейта:

- `queue_not_empty`: у роли есть неназначенные задачи в очереди
- `no_idle_agent`: у роли нет свободного агента
- Отсутствует: у всех включённых источников роли простаивали (или гейт выключен)

## Экран настройки (UI-половина, OPE-4149)

На странице «Фуражировка» живут переключатель и история:

- Карточка **«Только в простое»**: переключатель пишет настройку через
  `PATCH /api/myrmidon/foraging/idle-gate` (нужны права администратора
  инстанса) и показывает действующее значение **вместе с источником** —
  «интерфейс», «переменная окружения» или «по умолчанию». Правило читается
  на каждом проходе, поэтому переключение действует со следующего прохода —
  перезапуск не нужен. Отказ записи (участник доски без прав администратора
  инстанса, временная ошибка) остаётся видимым в карточке, а не глотается.
- Карточка **«История проходов»**: последние проходы выбранной компании —
  когда прошёл, сколько источников прочитал, сколько находок дал и какие
  роли оставил без внимания с причиной (`queue_not_empty` / `no_idle_agent`).
  Проход, остановленный лимитом, так и написан.

```
GET /api/myrmidon/companies/:id/foraging/passes?limit=   (доступ к компании)
```

Журнал хранится в `instance_settings.general.foragingPassJournal` (сначала
новые, потолок — 50 записей на инстанс; проход одной компании никогда не
вытесняет историю другой). Каждый проход дописывает себя сам — включая
проход, который не смог получить список источников, — а неудачная запись в
журнал никогда не роняет проход. Читатель защитный: нечитаемая запись теряет
только себя, не всю историю. Журнал — это представление; след изменения
остаётся в журнале активности.

## Где живёт код

- `packages/shared/src/myrmidon-foraging-idle-gate.ts` — контракт резолвера
  (ключ, приоритет, источники), общий с сервером;
- `packages/shared/src/myrmidon-foraging-pass-journal.ts` — контракт журнала
  проходов (форма записи, чтение, дописывание с потолком), общий с экраном;
- `server/src/myrmidon/foraging/idle-gate-settings.ts` — сервис настроек
  (чтение/обновление/аудит) и чтение на каждом проходе;
- `server/src/myrmidon/foraging/idle-gate-routes.ts` — GET/PATCH роуты;
- `server/src/myrmidon/foraging/pass-journal.ts` — сервис журнала проходов
  (чтение/запись в общую строку настроек);
- `server/src/myrmidon/foraging/pass-routes.ts` — GET роут истории проходов;
- `server/src/myrmidon/foraging/service.ts` — гейт в `runPass`
  (`createDbForagingIdleCheck`: SQL проверки очереди и свободного агента) и
  запись прохода в журнал;
- `ui/src/pages/Foraging.tsx`, `ui/src/api/foraging.ts` — переключатель с
  источником значения и история проходов;
- тесты: `service.myrmidon.test.ts` (три критерия приёмки, фильтрация по
  роли, перечитывание без пересоздания сервиса),
  `idle-gate-settings.myrmidon.test.ts` (сервис настроек),
  `pass-journal.myrmidon.test.ts` (сервис журнала и проход, который сам
  записывается на каждом выходе), `pass-routes.myrmidon.test.ts` (доступ,
  предел), `packages/shared/src/myrmidon-foraging-idle-gate.test.ts`
  (резолвер), `packages/shared/src/myrmidon-foraging-pass-journal.myrmidon.test.ts`
  (читатель и дописывание с потолком), `ui/src/pages/Foraging.test.tsx`
  (переключатель, источник значения, причины в истории).
