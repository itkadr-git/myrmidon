# Самоорганизация: касты, гнёзда, феромоны

> English version: [swarm-self-organization.md](swarm-self-organization.md)

Как доска сама раздаёт неназначенные задачи свободным агентам. С версии 1.6.5
рой — это заявленная функция, а не пилот: один переключатель, и доска сама
сопоставляет каждую готовую задачу со свободным агентом подходящей касты.

## Как это работает одним абзацем

Задача без исполнителя стоит в очереди роя своей касты. Доска замечает
события (завершился прогон, снята пауза, создана или обновлена задача,
истекла аренда) и после каждого события проверяет: есть ли готовая задача и
свободный агент её касты. Если да — доска назначает задачу агенту и будит его
с этой задачей в руках. Никаких побудок «проснись и поищи работу» нет: каждый
автоматический прогон стартует только с конкретной задачей. Страховочный
проход на тике планировщика подхватывает то, что могло быть пропущено между
событиями.

## Три понятия

**Каста** — профессия агента (ключ роли: `engineer`, `reviewer`, `lead` и
т.д.). Справочник каст компании — **Настройки компании → Касты**: там можно
создавать свои касты, выключать касту из роя (переключатель «Участвует в
рое»), задавать свой потолок активных задач и выбирать касту по умолчанию
(радио «По умолчанию») — на неё попадают задачи, у которых каста не указана.

**Гнездо** — список проектов агента (карточка агента, поле «Гнёзда»). Пустой
список означает «все проекты». Задача из проекта попадает только к агентам, в
чьих гнёздах этот проект есть.

**Сила феромона** — число на задаче: чем оно больше, тем выше задача в
очереди роя. Если силу не задать, она ставится из приоритета по соответствию
из настроек (по умолчанию: critical 100, high 30, medium 10, low 1). Пока
задача ждёт, сила растёт — шаг накопления по умолчанию +1 за каждые 24 часа
ожидания, потолок +5. Неудачный прогон по задаче (failed/blocked/needs
follow-up/timed out), после которого задача не менялась, уменьшает силу на
штраф (по умолчанию −10 за каждый такой прогон подряд). Любое изменение
задачи (комментарий, правка, смена статуса) снимает штраф и остывание.
Задача с приоритетом critical при включённом вытеснении P0 идёт первой
независимо от силы.

## Как включить (одно действие)

**Instance → General → «Самоорганизация (рой)» → переключатель «Включено»**.

В 1.6.5 рой включён по умолчанию. Выключение действует сразу: живые аренды
отпускаются (ответ сохранения сообщает, сколько), исполнители с задач не
снимаются — назначения просто перестают делаться автоматически. Каждое
изменение пишется в журнал на той же панели (кто, что и когда).

## Как поставить задачу в рой

Три действия:

1. Создайте задачу **без исполнителя**.
2. Укажите **касту** (поле «Каста» в карточке задачи). Если не указать —
   сработает каста по умолчанию проекта, а без неё — каста по умолчанию
   компании.
3. При желании поправьте **силу феромона** (число) — по умолчанию она
   ставится из приоритета.

Дальше доска сама назначит задачу первому освободившемуся агенту касты из
гнезда проекта и разбудит его с этой задачей. Исполнителя руками ставить не
нужно — рой решает сам.

## Как проверить, что рой работает

1. Поставьте тестовую задачу в рой (без исполнителя, с кастой, у которой есть
   свободный агент).
2. Откройте экран **«Рой»** (`/swarm-claim`): задача должна быть в очереди
   своей касты с видимой эффективной силой; как только агент касты
   освободится, задача получит аренду и исполнителя, а агент — побудку
   `swarm_matched`.
3. Статусная строка панели «Самоорганизация (рой)» показывает живые цифры:
   сколько каст, сколько свободных агентов, сколько задач ждут, сколько
   сопоставлено за час и среднее ожидание. Проверку можно повторить запросом
   к базе: `SELECT count(*) FROM issues WHERE status='todo' AND
   assignee_agent_id IS NULL AND hidden_at IS NULL` — при наличии свободных
   агентов нужной касты очередь здорового роя стремится к нулю в пределах
   одного интервала страховочного прохода, без ручных назначений.

## Почему задача ждёт

Задача стоит в очереди и не назначается, если выполняется хотя бы одно из:

- **Нет свободного агента касты в гнезде проекта.** Все агенты касты заняты
  (у каждого живой прогон или достигнут потолок активных задач), на паузе или
  в ошибке, либо ни у кого из свободных агентов касты проект задачи не входит
  в гнёзда. На экране «Рой» видно по касте: очередь есть, свободных агентов —
  ноль.
- **Задача остывает.** Последний прогон по задаче завершился неудачно
  (failed/blocked/needs follow-up/timed out) и после него задача не менялась.
  Такая задача не сопоставляется в течение остывания: 30 минут после первого
  неудачного прогона, дальше удвоение за каждый следующий (60 мин, 120 мин …),
  потолок 24 часа. Остывание закрывает петлю «прогон → неудача → снова
  прогон». Любое изменение задачи (комментарий, правка) снимает остывание
  сразу. Список задач в остывании с причиной и временем следующего захода —
  на экране «Рой» (раздел «Остывание») и в `GET
  /api/myrmidon/companies/{companyId}/swarm/cooling`.
- **У задачи нет касты, а дефолтные не заданы.** Сначала смотрится каста
  задачи, потом каста по умолчанию проекта, потом каста по умолчанию компании
  (она есть всегда — встроенная `engineer`, пока владелец не назначил свою) —
  так что задача без касты в норме просто идёт в очередь касты по умолчанию.
- **Каста выключена из роя** (в справочнике каст снят флаг «Участвует в
  рое») — задачи такой касты не сопоставляются вовсе.
- **Рой выключен** переключателем или принудительно переменной
  `MYRMIDON_SWARM_CLAIM_ENABLED=0`.

Точные причины видны на панели «Самоорганизация (рой)» в предупреждениях:
«задачи без агентов касты: …», «задач в остывании: N», «прогонов без задачи
за сутки: N» (здоровое значение последнего — 0).

## Что удалено в 1.6.5

- **Пилот.** Поля «Pilot roles» / «Pilot companies» и переменные
  `MYRMIDON_SWARM_CLAIM_ENABLED_ROLES` / `MYRMIDON_SWARM_CLAIM_ENABLED_COMPANY_IDS`
  удалены — рой либо включён, либо выключен, без «пилотных» списков.
- **`MYRMIDON_SWARM_IDLE_WAKE_BATCH`.** Проход «разбудить пачку свободных
  агентов» убран: назначение делается по событиям, а не пакетными побудками.
- **Пилотный отчёт** супервизора и `MYRMIDON_SWARM_PILOT_BASELINE_DOC` —
  сравнение с базовой линией живёт на экране «Качество».

## Настройки

Все параметры — на панели **Instance → General → «Самоорганизация (рой)»**,
действуют без перезапуска. Полный справочник полей и переменных окружения —
в [SETTINGS.ru.md](../SETTINGS.ru.md), раздел «1.6.5 — Самоорганизация
(рой)».
