# Список допущенных каналов — кто может писать ботам

myrmidon(CA-A), релиз 1.6.6, трек 4. Решение владельца 06.10 (OPE-4949):
допуск пишущих в Telegram (и в любом будущем канале) — настройка на доске,
решаемая по идентичности канала; учётка доски необязательна. Английская
версия рядом (`channel-allowlist.md`).

## Что это

На доске ведётся список людей, которым можно писать ботам компании. Список
отделён от членства в компании: допущенному человеку учётка доски вообще не
нужна. Допуск привязан к идентичности канала — числовому id пользователя
Telegram — и дополнительно сверяется по @username (регистр и «@» не
важны). Каждая строка покрывает либо **все боты компании**, либо **один
конкретный бот-эндпоинт**; отозанная строка не допускает, но остаётся в
списке для аудита.

Режимы работы (Settings → Channel allowlist, или `PATCH
/api/myrmidon/channel-settings` с `channelAccessMode`):

- `sponsor` — вендорское значение по умолчанию: непривязанный отправитель
  обслуживается, если эндпоинт бота разрешает гостей-подопечных. Ничего не
  меняется относительно прежних релизов.
- `allowlist` — правило владельца: привязанные участники пишут как раньше,
  непривязанный человек пишет **только если список его допускает**, и
  поручительство гостей больше никого не допускает.

Режим читается на каждое сообщение — переключение действует без
перезапуска. `MYRMIDON_CHANNEL_ACCESS_MODE` закрепляет значение поверх
настройки доски.

## Чужак пишет

Его сообщение не исполняется:

1. отправитель получает одну строку без подробностей:
   «Доступ к этому боту не предоставлен. Запрос передан владельцу.»;
2. владельцу (или администратору, затем оператору) уходит карточка доски
   «Запрос доступа к боту от @user» с id канала и @username отправителя —
   ровно тем, что нужно для допуска;
3. в журнал пишется `channel_allowlist.access_requested`.

Одна карточка и одно уведомление на отправителя в сутки UTC: поток
сообщений от одного чужака стоит вам одного решения, а не сотни карточек.

## Допустить человека

Откройте **Settings → Channel allowlist** («Кто может писать ботам»):

- **Допустить человека**: выберите канал (telegram), вставьте id канала
  (из карточки запроса доступа или спросите у человека — это числовой id,
  который бот видит в каждом сообщении), при желании @username и область
  (все боты или один бот). Привязку к учётке доски можно добавить позже,
  когда она у человека появится, — допуск её не ждёт.
- **Отозвать** убирает допуск сразу (следующее сообщение уже отказ);
  строка остаётся в списке с меткой «отозван», пока её не вернут или не
  удалят.

Все действия на экране journalled (`channel_allowlist.created` /
`.updated` / `.revoked`), доступ только доске и в границах компании.

## Чего в этой части ещё нет

Части B–D OPE-4949 добавят: права пишущего (только вопросы / ставить задачи
/ утверждать карточки / управлять ботами), применяемые к каждому действию,
кнопки «одобрить с правами / отказать» на самой карточке запроса и полную
пометку каждого сообщения в аудите. До части B допущенный человек пишет с
теми же возможностями, какие вендор даёт обслуживаемому отправителю: список
решает *обслуживать ли*, а не *что можно*.
