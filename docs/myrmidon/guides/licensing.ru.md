# Лицензирование закрытых модулей

> English version: [licensing.md](licensing.md)

Закрытые модули-коннекторы (`google-ai`, `antigravity`, `chatgpt-pool`) работают
только с действующей лицензией. Лицензия — одна строка `MYR1.…` (файл
`license.key`), привязанная к идентификатору установки; один файл покрывает
все купленные модули. Получение и установка лицензии делаются на экране
**Настройки → Инстанс → Лицензии**. Экран и все маршруты `/api/licensing/*`
доступны только администратору инстанса.

## Как получить лицензию

1. Откройте **Лицензии**. Вверху — идентификатор установки (`myr-` и 20
   hex-символов `sha256(machine-id)` хоста).
2. В разделе **Запросить лицензию** уже отмечены закрытые модули, установленные
   в эту доску; добавьте или снимите нужные.
3. Нажмите **Скопировать запрос** и отправьте строку `MYRQ1.…` поставщику одним
   сообщением. Запрос не подписан и не секретен: в нём идентификатор установки,
   версия доски, модули и время.

## Как установить лицензию

1. Получите от поставщика файл `license.key` (или строку `MYR1.…`).
2. В разделе **Установить лицензию** вставьте строку или нажмите **Загрузить
   файл** и выберите `license.key`, затем **Сохранить лицензию**.
3. Доска проверяет лицензию тем же алгоритмом и тем же открытым ключом, что и
   модули. Лицензию для другой установки, просроченную, с неверной подписью или
   не лицензию вовсе она не сохраняет и объясняет причину; текущий файл при этом
   не меняется.
4. Сохранённая лицензия записывается в файл, который читают модули. Модули
   перечитывают его на каждой проверке — перезапуск не нужен.

В разделе **Состояние лицензии** для каждого модуля видно: «Действует до …»,
«Истекает …» (меньше 14 дней), «Истекла», «Не для этой установки», «Не входит в
лицензию», «Нет лицензии», «Подпись неверна». Это решение модуля по тому же
файлу и тем же правилам. Пока у установленного модуля нет действующей
лицензии, администратор видит баннер со ссылкой на экран.

## Где лежит лицензия (один файл на хост)

Модули на одном хосте живут по-разному, но читают один и тот же путь —
`MYR_LICENSE`, иначе файл `MYR_LICENSE_PATH`, по умолчанию
`/etc/myrmidon-license/license.key`:

| Где работает модуль | Как видит файл |
|---|---|
| процессы на хосте (`chatgpt-pool`, пул `google-ai`) | напрямую `/etc/myrmidon-license/license.key` |
| контейнеры модулей (мосты и MCP `google-ai`) | файл хоста, смонтированный только для чтения |
| адаптер `antigravity` — внутри контейнера доски | каталог хоста, смонтированный в доску |

Поэтому единственное место хранения — каталог хоста `/etc/myrmidon-license`, а
доска монтирует его **на запись** по тому же пути и получает
`MYR_LICENSE_PATH=/etc/myrmidon-license/license.key`. Экран пишет в этот файл, и
его видят все три вида модулей; второй копии ключа нет. Файл переписывается на
месте (тот же inode), поэтому контейнеры, смонтировавшие отдельный файл,
видят новую лицензию без пересоздания.

Установщик (`scripts/myrmidon/install/install.sh`) делает это сам: создаёт
каталог, отдаёт его пользователю доски (uid `1000`) и добавляет в `compose.yml`
сервиса `server`:

```yaml
    environment:
      MYR_LICENSE_PATH: "/etc/myrmidon-license/license.key"
    volumes:
      - ${MYRMIDON_LICENSE_DIR:-/etc/myrmidon-license}:/etc/myrmidon-license
      - /etc/machine-id:/etc/machine-id:ro
```

Для установки, собранной вручную, сделайте то же самое:

```sh
install -d -m 0755 -o 1000 -g 1000 /etc/myrmidon-license
# уже лежащий файл лицензии отдать доске:
chown 1000:1000 /etc/myrmidon-license/license.key && chmod 0644 /etc/myrmidon-license/license.key
```

и добавьте строки выше в compose доски. Монтирование отдельного файла
`license.key:...:ro` для доски не подходит: экран не сможет сохранить
лицензию. Если каталог не смонтирован, экран предупреждает об этом, а сохранение
отвечает понятной ошибкой с путём.

## Идентификатор установки

Идентификатор принадлежит доске и он ровно один. Он сохраняется в базе доски при
первом старте и дальше не меняется: ни от machine-id, ни от
`MYR_LICENSE_INSTANCE_ID`, ни при пересоздании контейнера. При первом старте это
`MYR_LICENSE_INSTANCE_ID`, если задан, иначе `myr-` + 20 hex от
`sha256(machine-id)` (формула прежних досок, поэтому уже выданные лицензии
остаются действительными), иначе `myr-` + 20 hex от случайного UUID. Экран
«Лицензии», `GET /api/licensing/install-id` и проверка лицензии берут его из
базы.

При старте доска записывает идентификатор в файл `instance-id` в каталоге
лицензии (`dirname(MYR_LICENSE_PATH)`, по умолчанию `/etc/myrmidon-license`;
атомарно, права 0644). Модули читают этот файл, поэтому каталог должен быть
смонтирован в доску на запись. Если запись невозможна, доска пишет
предупреждение и стартует, но модули идентификатор не узнают.

Лицензия, выданная для другой установки, показывается с обоими идентификаторами:
на какой она выдана и идентификатор этой доски.

## Если лицензия задана переменной

Если доске задан `MYR_LICENSE` (текст лицензии в окружении), он перекрывает
файл и для адаптера внутри доски. Экран тогда показывает состояние этой
лицензии, но сохранять файл не предлагает: уберите переменную, чтобы
пользоваться файлом.

## Смена ключа поставщика

Доска доверяет только открытым ключам, вшитым в сборку
(`server/src/myrmidon/licensing/trusted-keys.ts`), — тем же, что вшиты в модули.
Лицензия без поля `kid` проверяется каждым доверенным ключом; лицензия с `kid` —
только ключом с этим `kid`. Новый ключ добавляется в список со своим `kid`, старый
остаётся, пока действуют выпущенные им лицензии.

## Справка: API

| Маршрут | Что делает |
|---|---|
| `GET /api/licensing/install-id` | `{ installId, source }` |
| `GET /api/licensing/status[?modules=a,b]` | идентификатор, запрос `MYRQ1`, установленные модули, состояние лицензии по модулям, путь файла; текст лицензии не возвращается |
| `POST /api/licensing/license` `{ "value": "MYR1.…" }` | проверить и сохранить лицензию; `422` с кодом `license_<причина>`, `409` `license_path_unwritable` / `license_env_override` |

Выпуск лицензий — сторона поставщика, на этом экране его нет.
