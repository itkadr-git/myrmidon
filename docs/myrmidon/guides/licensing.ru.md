# Лицензирование закрытых модулей

> English version: [licensing.md](licensing.md)

Закрытые модули-коннекторы (`google-ai`, `antigravity`, `chatgpt-pool`) стартуют
только с действующей лицензией. Доска даёт владельцу установки две вещи:
идентификатор установки с запросом лицензии одной кнопкой и форму, которая
подписывает лицензию. Обе находятся в **Настройки → Инстанс → Общие →
Лицензирование** и видны только администратору инстанса (все маршруты
`/api/licensing/*` отвечают остальным 403).

## Идентификатор установки

Идентификатор — `myr-` и первые 20 hex-символов `sha256(machine-id)`
(`/etc/machine-id`, затем `/var/lib/dbus/machine-id`). Это тот же алгоритм, что
считают модули, поэтому лицензия, подписанная на идентификатор с экрана доски,
принимается модулями **только если доска и модули видят один и тот же
machine-id**. В контейнерах смонтируйте файл хоста только для чтения
(`/etc/machine-id:/etc/machine-id:ro`) либо задайте один и тот же
`MYR_LICENSE_INSTANCE_ID` доске и модулям. Если machine-id нет, идентификатор
один раз генерируется и кэшируется в `MYR_LICENSE_STATE_DIR` (по умолчанию
`~/.local/state/myrmidon-license`); экран при этом предупреждает, потому что у
новой установки будет новый идентификатор.

`GET /api/licensing/install-id` возвращает `{ "installId": "myr-…", "source": "machine-id" | "env" | "generated" }`.

## Запросить лицензию (сторона клиента)

1. Откройте раздел «Лицензирование», отметьте нужные модули.
2. Нажмите **Скопировать запрос лицензии**. Текст — одна строка
   `MYRQ1.<base64url(json)>` с полями `{v, instance_id, board, modules, ts}`.
3. Отправьте её владельцу любым мессенджером. Запрос не подписан: это удобство, а
   не аутентификация — личность клиента владелец проверяет сам.

## Выпустить лицензию (сторона владельца)

1. Настройте ключ подписи на сервере (ниже).
2. В разделе «Лицензирование» вставьте запрос в поле **Запрос лицензии от
   клиента** (идентификатор и модули подставятся) либо введите идентификатор
   вручную.
3. Отметьте модули, задайте срок в днях (или **Бессрочно**), впишите клиента в
   **Клиент / водяной знак**, нажмите **Выпустить лицензию**.
4. Скопируйте текст или скачайте `license.key` и положите туда, откуда модули на
   той установке читают лицензию.

Результат — формат лицензии модулей `MYR1.<payload>.<signature>`: канонический
JSON `{rev, instance_id, modules, features, expires, watermark}`, подписанный
Ed25519 по сырым байтам payload. В `features` всегда есть `core`. Каждый выпуск
пишется в журнал (кто, когда, идентификатор установки, модули, срок, водяной
знак — но не текст лицензии) и показывается в **Выпущенные лицензии**. Отзыв не
мгновенный: модули работают офлайн, лицензия заканчивается сроком или
непродлением.

## Настройки сервера

| Переменная | Назначение |
|---|---|
| `MYRMIDON_LICENSE_ISSUER_KEY_FILE` | Путь к **закрытому** ключу Ed25519 в PEM (PKCS#8), читаемому процессом доски. Не задан — форма сообщает, что ключ не настроен, выпуск отклоняется (409). Ключ читается при каждом выпуске, API его не возвращает и в логи не пишет. |
| `MYRMIDON_LICENSE_JOURNAL_FILE` | Журнал выпущенных лицензий (JSON lines). По умолчанию `<корень инстанса>/data/licensing/issued.jsonl`. Держите на постоянном томе. |
| `MYR_LICENSE_INSTANCE_ID` | Необязательное явное значение идентификатора; у доски и модулей должно совпадать. |
| `MYR_LICENSE_STATE_DIR` | Каталог кэша сгенерированного идентификатора, когда machine-id нет. |

Пару ключей генерируют один раз, закрытый ключ хранят вне репозитория, доске
дают файл только для чтения, а открытый ключ вшивают в сборку модулей:

```sh
openssl genpkey -algorithm ed25519 -out /path/to/issuer-ed25519.key.pem
openssl pkey -in /path/to/issuer-ed25519.key.pem -pubout
chmod 0400 /path/to/issuer-ed25519.key.pem
```

## Примечания

- `instance_id` в MYRQ1 — идентификатор модулей (`myr-…`), а не сырой sha256 hex:
  лицензия должна нести ровно ту строку, с которой модули сравнивают.
- Поле `py` запроса необязательное, доска его не формирует.
