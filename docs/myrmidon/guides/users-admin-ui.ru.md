# Экран управления пользователями компании (1.7 USERS-ADMIN-UI B)

> Английская версия: [users-admin-ui.md](users-admin-ui.md)

Экран **«Пользователи»** (`/company/settings/users`) — центральная панель управления пользователями для администраторов инстанса в Myrmidon. Так как публичная саморегистрация отключена, все учётные записи создаются и настраиваются непосредственно администраторами.

## Доступ и навигация

- **Навигация**: Боковая панель настроек компании → **Пользователи** (`/company/settings/users`).
- **Права доступа**: Пункт отображается только администраторам инстанса (`isInstanceAdmin`).
- **Прямой переход**: Пользователи без прав администратора при переходе по прямой ссылке получают ошибку HTTP 403: *«Для управления пользователями требуются права администратора инстанса»*.
- **Отличие от «Пользователи инстанса»**: Этот экран предназначен для интерактивного управления учётными записями, доступами и ролями на доске. Он отличается от глобального справочника `/company/settings/instance/users` ([instance-users.md](instance-users.md)), который выполняет только поиск пользователей по всем рабочим пространствам инстанса без возможности изменения.

## Создание пользователей

Форма **«Создать пользователя»** позволяет добавить нового участника:

1. **Имя пользователя (username)**: Уникальный логин для аутентификации и упоминаний через `@` (`username.trim()`).
2. **Отображаемое имя (name)**: Человекочитаемое имя, отображаемое в интерфейсе доски (`name.trim()`).
3. **Роль (role)**:
   - **Пользователь** (`member`): Базовые права участника рабочего пространства.
   - **Администратор** (`instance_admin`): Права администратора уровня инстанса.
4. **Временный пароль (необязательно)**:
   - Если указан: пользователь может сразу войти в систему с этим паролем.
   - Если оставлен пустым: Myrmidon генерирует безопасную одноразовую ссылку для первичной установки пароля (`passwordSetLink`).

### Одноразовая ссылка для установки пароля

При создании пользователя без пароля (а также при сбросе пароля):
- В верхней части экрана появляется информационный блок с ссылкой.
- Предупреждение: *«Скопируйте эту ссылку сейчас. Она показывается только один раз и здесь не сохраняется»*.
- Действия:
  - **Копировать ссылку**: Помещает URL ссылки в буфер обмена через общую утилиту работы с буфером.
  - **Скрыть**: Закрывает информационный блок.
- Перейдя по ссылке, пользователь самостоятельно задаёт постоянный пароль через публичный эндпоинт (`/myrmidon/users-admin-a/password-set`).

## Каталог пользователей и поиск

Блок **«Каталог пользователей»** отображает всех зарегистрированных пользователей доски:

- **Поиск**: Живая фильтрация в реальном времени по имени, логину или адресу электронной почты.
- **Счётчик**: Отображает количество найденных пользователей (`N пользователей`).
- **Сведения о пользователе**:
  - Отображаемое имя и логин `@username`.
  - Адрес электронной почты.
  - Бейджи статуса:
    - **Заблокирован** (красный бейдж): действие учётной записи приостановлено.
    - **Администратор** (основной бейдж): роль администратора инстанса (`instance_admin`).
    - **Пользователь** (основной бейдж): стандартный участник (`member`).

## Действия с учётной записью

Администратор может выполнять операции над каждым пользователем в каталоге:

- **Блокировка / Разблокировка**:
  - Переключает статус блокировки (`blocked`).
  - При блокировке немедленно закрываются все активные сессии пользователя и отзываются его API-ключи.
  - Фиксируются события аудита `instance.user.blocked` и `instance.user.unblocked`.
- **Сброс пароля**:
  - Деактивирует текущий пароль пользователя.
  - Генерирует новую одноразовую ссылку (`passwordSetLink`) и отображает её в верхнем информационном блоке для передачи пользователю.
  - Фиксируется событие аудита `instance.user.password_reset`.
- **Управление ролями**:
  - Переключение роли между пользователем (`member`) и администратором (`instance_admin`).
  - Защита от саморазжалования: администратор не может снять административные права с самого себя.
  - Защита последнего администратора: система запрещает снятие прав с единственного оставшегося администратора инстанса (HTTP 409 Conflict).
  - Фиксируется событие аудита `instance.user.role_changed`.

## Журнал аудита и бэкенд

Все мутирующие действия, совершённые на этом экране, записываются в журнал аудита инстанса. Подробности о REST API, дедупликации записей между компаниями и журналах аудита описаны в руководстве [users-admin-a.ru.md](users-admin-a.ru.md).
