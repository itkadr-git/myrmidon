# Рекомендации по бюджету промпта и глубокий разбор

> English version: [prompt-budget-advice.md](prompt-budget-advice.md)

Карточка агента отвечает на два вопроса о промпте последнего прогона: какая его
часть доминирует и что с ней делать. Статический советник считает конкретные
рекомендации по запросу из записанной разбивки токенов по частям, а кнопка
«Deep analysis» ставит задачу агенту-оптимизатору на дешёвой модели, который
черновиком правок инструкций отвечает комментарием к этой задаче. Ничего не
планируется по таймеру и ничего не меняется автоматически: рекомендации
считаются при открытии карточки, а глубокий проход запускается только по клику
оператора.

## Где живёт поверхность

Панель «Prompt budget advice» находится на вкладке обзора карточки агента,
сразу под карточкой «Latest run». Она читает только свои advice-ручки, поэтому
монтируется и работает сама по себе; панель не зависит от сигнала бюджета
промпта части порогов того же релиза.

## Что показывает панель

Панель — чистое представление тела рекомендаций. Её состояния:

- Во время загрузки: «Loading the prompt breakdown...».
- У агента ещё нет прогона с записанной разбивкой промпта: строка «No run of
  this agent has a recorded prompt breakdown yet.», а кнопка «Deep analysis»
  остаётся выключенной.
- Разбивка есть: строка заголовка «Last run <runId> · <total> tokens in the
  prompt», затем список по частям — крупнейшая часть первой, каждая строка
  показывает ключ части, её токены (короткая форма: `1.5k` для тысяч) и её долю
  (целые проценты остаются целыми, дробные — с одним знаком). Равенство токенов
  разрешается по ключу части, поэтому порядок стабилен между прогонами.
- Ни одна часть не пересекает порог предупреждения (или промпт меньше 2000
  токенов): «No part of the last prompt crosses the warning threshold.» — тело
  помечает это как `healthy: true`.
- Одна или несколько частей пересекают порог: карточка на каждую рекомендацию с
  бейджем серьёзности, заголовком правила, ключом части с её долей и токенами и
  конкретным действием. Серьёзность — **Warning** с доли 30 % промпта и
  **Critical** с 50 % (красный бейдж); обе серьёзности рисуют одинаковую
  карточку, отличается бейдж.

Панель запрашивает один раз при монтировании (`retry: false`, без опроса):
цифры — это последний записанный прогон, а не живой поток.

## Правила рекомендаций

Советник — чистая функция над разбивкой одного прогона
(`server/src/myrmidon/prompt-budget-advice/advice.ts`) — он не трогает базу и
не вызывает модель. Таблица правил сопоставляет доминирующую часть конкретному
действию; каждое правило сопоставляется с ключом части без учёта регистра,
первое подошедшее правило описывает часть, а последняя запись — запасная,
поэтому переименованная или новая часть всё равно получает общую рекомендацию.
Пороги — константы кода, а не настройки:

| Константа | Значение | Смысл |
|---|---|---|
| `PROMPT_BUDGET_ADVICE_SHARE_PCT` | `30` | Часть заслуживает рекомендации с этой доли промпта (проценты) |
| `PROMPT_BUDGET_ADVICE_CRIT_SHARE_PCT` | `50` | Часть такого размера — Critical, а не Warning (проценты) |
| `PROMPT_BUDGET_ADVICE_MIN_TOTAL_TOKENS` | `2000` | Ниже этой суммы промпт мал независимо от долей — рекомендаций нет вообще |

Таблица правил, в порядке сопоставления:

| Правило | Срабатывает на ключи частей вроде | Заголовок | Действие |
|---|---|---|---|
| `instructions` | `instruction`, `system`, `identity`, `contract`, `bundle`, `preamble`, `prompt-file`, `agent-card` | Instructions bundle | Вынести справочный материал из всегда включённого пакета инструкций в навыки, загружаемые по запросу; в пакете оставить только операционные правила. |
| `skills` | `skill`, `inject` | Skills and injections | Выключить навыки, которые этому агенту не нужны на каждом прогоне, или убрать их тела за загрузку по запросу. |
| `session-history` | `session`, `handoff`, `history`, `continuation`, `transcript`, `conversation` | Session history and handoff | Использовать сессионную стратегию уровня прогона вместо уровня задачи и сжимать handoff вместо переноса всей истории. |
| `tool-results` | `tool`, `result`, `output`, `attachment`, `artifact`, `file-content` | Tool results and attachments | Обрезать результаты инструментов и вложения до попадания в промпт: просить меньше вывода, резюмировать крупные данные, не держать файлы в контексте. |
| `wake-payload` | `wake-payload`, `payload`, `wake-json` | Wake payload JSON | Сократить wake-payload, который несёт побудка: меньше полей, без громоздкого встроенного JSON. |
| `task-markdown` | `task`, `issue-markdown`, `issue-description`, `issue-body`, `description` | Task markdown | Сократить markdown задачи, переносимый в промпт: ссылаться на документ вместо вставки целиком. |
| `wake-prompt` | `wake` | Wake prompt | Обрезать обвязку wake-промпта: повторяющийся шаблон вокруг собственно запроса. |
| `generic` | всё остальное | Dominant prompt part | Разобрать эту часть: это крупнейшая доля промпта; убрать то, что не нужно на каждом прогоне. |

## Откуда берётся разбивка

Советник читает недавние прогоны агента (не более 20, новые первыми по времени
завершения — `PROMPT_BUDGET_ADVICE_SCAN_LIMIT`) и берёт первый, в котором есть
пригодная цифра: записанная шлюзом разбивка по частям
(`usageJson.promptBreakdown` строки `heartbeat_runs`), либо — когда разбивки
нет — записанная сумма входных токенов без частей (прогон, не прошедший через
шлюз, всё равно даёт сумму, о которой можно предупредить). Новой таблицы и
миграции нет: разбивка живёт в существующей колонке
`heartbeat_runs.usage_json`. Агент совсем без пригодного прогона отвечает
`hasRun: false`.

## Кнопка «Deep analysis»

Статический совет дёшев и механичен; глубокий проход — настоящий прогон агента
на дешёвой модели. Кнопка — действие оператора: POST-маршрут требует доступа
доски к компании. Один клик ставит задачу на доске:

- Заголовок `Prompt budget deep analysis: <agent name>`, приоритет medium,
  статус `todo`, исполнитель — настроенный агент-оптимизатор.
- В описании — целевой агент (id, имя, модель с карточки — «not set on the
  card», если не задана), разбивка последнего прогона таблицей, уже выданные
  статически рекомендации и инструкции: назвать доминирующие части, подготовить
  ЧЕРНОВИК конкретных правок (что меняется, точный текст или настройка,
  ожидаемая экономия токенов) и опубликовать этот черновик одним комментарием
  к задаче. Ограничения задачи запрещают оптимизатору самому менять какую-либо
  конфигурацию — он только готовит черновик на проверку человеку, поэтому
  глубокий проход не может молча отредактировать другого агента.
- Задача несёт ключ дедупликации `prompt-budget-advice:<agentId>:<runId>` —
  одна задача глубокого разбора на целевого агента за прогон; повторный клик по
  тому же прогону не плодит дубликатов.

После постановки задачи панель показывает «Deep analysis task:» со ссылкой на
неё (`/issues/<identifier>`, с запасным вариантом — id задачи, пока
идентификатора нет). Пока POST в полёте, кнопка читается «Filing the task...»
и выключена.

Агент-оптимизатор — аддитивное поле `promptBudget.optimizerAgentId` области
общих настроек инстанса, которой владеет часть порогов того же релиза (см.
[../SETTINGS.ru.md](../SETTINGS.ru.md)); переменной окружения нет. Deep-POST
отказывает с 422 и понятным текстом, когда:

- агент-оптимизатор не настроен (поле отсутствует, пустое или не uuid);
- настроенный оптимизатор — сам анализируемый агент;
- настроенный оптимизатор не является агентом этой компании;
- у целевого агента нет записанного прогона с разбивкой промпта для анализа.

## API

| Маршрут | Доступ | Ответ |
|---|---|---|
| `GET /api/myrmidon/companies/:companyId/prompt-budget/agents/:agentId/advice` | участник компании | `{ agentId, agentName, model, hasRun, runId, total, parts, healthy, recommendations }` |
| `POST /api/myrmidon/companies/:companyId/prompt-budget/agents/:agentId/advice/deep` | доска | `201 { issueId, identifier, title }`; `422` с понятным текстом, когда оптимизатор отсутствует или непригоден; `404`, когда агент не из этой компании |

Оба пути сидят под префиксом prompt-budget того же релиза, но несут свой хвост
`/agents/:agentId/advice`, поэтому не задевают маршруты настроек и статуса
части порогов.

## Настройки

| Поле | Умолчание | Что делает |
|---|---|---|
| `promptBudget.optimizerAgentId` | нет | Агент, которому ставится задача глубокого разбора по кнопке «Deep analysis» — uuid другого агента той же компании; пустое, отсутствующее или не-uuid значение отвечает на deep-POST ошибкой 422. Переменной окружения нет |

Пороги (30 % / 50 % / 2000 токенов) — константы кода в
`server/src/myrmidon/prompt-budget-advice/advice.ts`, а не настройки — они
решают, когда рекомендацию стоит показывать, а не какова политика продукта.
