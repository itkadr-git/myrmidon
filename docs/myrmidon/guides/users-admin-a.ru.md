# Управление пользователями и журнал аудита (users-admin-a)

## Обзор

Модуль `users-admin-a` предоставляет функциональность администрирования пользователей и журнал аудита действий на уровне инстанса. Так как публичная саморегистрация отключена, администраторы инстанса создают и настраивают учётные записи пользователей напрямую.

Каждое административное действие фиксируется в журнале активности с указанием автора, целевого пользователя, времени и параметров действия.

## API Эндпоинты

### 1. Каталог пользователей и создание

- `GET /api/myrmidon/users-admin-a/users`
  - Доступно только администраторам инстанса (`instance_admin`).
  - Возвращает список всех пользователей: роли (`instance_admin` или `member`), статус блокировки, отображаемые имена и дату создания.

- `POST /api/myrmidon/users-admin-a/users`
  - Создание учётной записи пользователя.
  - Тело запроса: `{ username, name, password?, role? }`
  - Если пароль не указан, создаётся одноразовая ссылка для установки пароля (`passwordSetLink`).
  - Событие аудита: `instance.user.created`.

### 2. Изменение пользователей и управление доступом

- `PATCH /api/myrmidon/users-admin-a/users/:userId`
  - Обновление состояния пользователя.
  - Поля тела запроса (хотя бы одно обязательно):
    - `blocked`: boolean (блокировка или разблокировка; отзыв активных сессий и API-ключей).
    - `resetPassword`: boolean (сброс текущего пароля, генерация одноразового токена).
    - `role`: `"instance_admin" | "member"` (смена роли; саморазжалование и снятие последнего администратора отклоняются с кодом 409).
  - События аудита:
    - `instance.user.blocked` / `instance.user.unblocked`
    - `instance.user.password_reset`
    - `instance.user.role_changed` (сохраняются `previousRole` и `newRole`)

### 3. Установка пароля по токену

- `POST /api/myrmidon/users-admin-a/password-set`
  - Публичный эндпоинт для установки пароля пользователем по выданному одноразовому токену.
  - Тело запроса: `{ token, newPassword }`
  - Событие аудита: `instance.user.password_set`.

### 4. Журнал аудита

- `GET /api/myrmidon/users-admin-a/audit`
  - Доступно только администраторам инстанса.
  - Параметры запроса:
    - `userId`: Фильтр по идентификатору целевого пользователя (`entityId`).
    - `actorId`: Фильтр по автору действия (`actorId`).
    - `action`: Фильтр по названию действия (например, `instance.user.created`, `instance.user.role_changed`).
    - `limit`: Количество возвращаемых записей (от 1 до 200, по умолчанию 50).
  - Дедупликация: Автоматическая дедупликация fan-out записей между компаниями.
  - Обогащение: Дополнение записей именем и логином автора и цели.

## Пользовательский интерфейс

Интерфейс администрирования доступен по адресу `/company/settings/users` и разделён на две вкладки:

1. **Пользователи**:
   - Форма создания пользователей (с временным паролем или ссылкой).
   - Список пользователей с поиском по имени, логину и email.
   - Действия: Блокировка/разблокировка, смена роли (Сделать админом / Снять админа) и сброс пароля.
2. **Журнал аудита**:
   - Фильтрация по целевому пользователю, автору и типу действия.
   - Таблица с отображением времени события, бейджа действия, целевого пользователя, автора и деталей.
