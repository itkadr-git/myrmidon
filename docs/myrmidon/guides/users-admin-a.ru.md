# Пользователи под управлением администратора: создание, блокировка, сброс (1.7 USERS-ADMIN-UI A)

> English version: [users-admin-a.md](users-admin-a.md)

Администратор экземпляра может создавать пользователей доски напрямую — с
логином и паролем или с логином и одноразовой ссылкой, по которой пользователь
сам устанавливает пароль, — блокировать и разблокировать их и сбрасывать
забытый пароль. Это серверная половина функции (1.7 USERS-ADMIN-UI A); экраны доски
поставляются отдельно. Самостоятельная регистрация **выключена по умолчанию**
и включается только явной настройкой экземпляра.

## Кто может это делать

Каждый изменяющий маршрут требует актора-администратора экземпляра
(`assertInstanceAdmin` — то же правило, по которому живёт страница настроек
экземпляра). Список пользователей доступен всем пользователям доски. Сам
токен установки пароля — доказательство для пользователя, открывшего ссылку:
этот маршрут сессии не требует.

## API

Все маршруты живут под `/api/myrmidon/users-admin-a`:

| Маршрут | Метод | Кто | Что делает |
|---|---|---|---|
| `/users` | GET | доска | Пользователи с ролью, блокировкой, флагом синтетического адреса |
| `/users` | POST | админ экземпляра | Создать пользователя (ниже) |
| `/users/:id` | PATCH | админ экземпляра | `blocked`, `reason`, `resetPassword` |
| `/password-set` | POST | сам токен | Погасить одноразовую ссылку, установить новый пароль |
| `/self-sign-up` | GET | доска | Переключатель саморегистрации и его источник |
| `/self-sign-up` | PATCH | админ экземпляра | Переключить саморегистрацию |

### Создание пользователя

`POST /users` с `username` (3–30 символов: буквы, цифры, точка, подчёркивание),
необязательным `email`, необязательным `password` и `role` —
`instance_admin` или `member`:

- С `password` — аккаунт существует сразу; вход работает немедленно.
- Без `password` — ответ несёт одноразовую `passwordSetLink`
  (`/api/myrmidon/users-admin-a/password-set?token=…`, действует 24 часа).
  Пользователь открывает её, выбирает пароль — токен умирает.
- Без `email` — пользователь получает синтетический адрес
  `<username>@myr.local` (зарезервированное пространство имён, почта туда не
  пишет) и входит по логину через `POST /api/auth/sign-in/username`.
  Пользователи с настоящей почтой входят по почте как раньше.

Создание пишет таблицы Better Auth напрямую (`user`, `account` с издателем
`local:credential`, `instance_user_roles`) ровно в том виде, в котором их
пишет сам вендор, поэтому вход идёт по пути проверки Better Auth, а не по
параллельному.

### Блокировка

`PATCH /users/:id` с `{"blocked": true, "reason": "…"}` немедленно закрывает
все живые сессии пользователя (строки `session` удаляются), а страж входа
отказывает в новых сессиях с `403 USER_BLOCKED` — по почте, по логину, на
любом пути входа, который есть у Better Auth (проверка висит на
`session.create.before` database hook). Админ не может заблокировать сам
себя. Разблокировка — тот же вызов с `false`.

### Сброс пароля

`PATCH /users/:id` с `{"resetPassword": true}` отзывает все выданные
токены установки пароля пользователя и возвращает свежую одноразовую
`passwordSetLink`. Сброс не показывает и не устанавливает пароль сам; новый
пароль выбирает пользователь по ссылке.

### Журнал

Каждое изменение попадает в журнал активности (`instance.user.created`,
`instance.user.blocked`, `instance.user.unblocked`,
`instance.user.password_reset`, `instance.user.password_set`) с указанием,
кто, кого и с какими правами, режима пароля и причины блокировки.

## Переключатель саморегистрации

Саморегистрация (`POST /api/auth/sign-up/email`) **выключена по умолчанию**.
`GET /self-sign-up` возвращает действующее значение и его источник:

- `settings` — экземпляр включил её явно (маршрут PATCH пишет
  `instance_settings.general.authSelfSignUp`);
- `env` — принудительное переопределение `MYRMIDON_AUTH_SELF_SIGN_UP=true|false`
  побеждает сохранённое значение (опечатка в переменной не считается ни тем,
  ни другим — берётся следующий источник);
- `default` — ничего не задано: выключено.

Страж читает строку настроек при каждой попытке регистрации, так что
переключение действует без перезапуска; переменная окружения — только для
оператора, которому нужно принудительно зафиксировать значение.

## Где лежат данные

- Пользователи и учётные данные: существующие таблицы Better Auth (`user`,
  `account`, `session`), форма не менялась.
- Чёрный список блокировок:
  `instance_settings.general.myrmidonAuthBlockedUsers` — отображение id
  пользователя на `{blockedAt, blockedBy, reason}`, переживает любую запись
  `general` вендором.
- Токены установки пароля: новая таблица `user_password_set_tokens` (sha256
  сырого токена, кем и как выдан, история отзыва; само значение возвращается
  один раз и не хранится).
