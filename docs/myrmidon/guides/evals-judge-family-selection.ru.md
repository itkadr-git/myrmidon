# Эталонные оценки: судья из другого семейства моделей

Оценки эталонных задач выставляет модель-судья за LLM-шлюзом компании.
Исторически судья работал на модели из `MYRMIDON_EVALS_MODEL` (по умолчанию
`qwen-plus-free`), а большинство агентов парка тоже сидит на DashScope/Qwen —
судья оценивал «своих». С myrmidon 1.6.5 (OPE-4143, долг волны 1.6.2) судья
выбирается из семейства, отличного от семейства оцениваемого агента, если
список кандидатов это позволяет; совпадение семейств видно в результате.

## Как выбирается судья

1. Модель оцениваемого агента определяется на старте прогона из субъекта
   задачи (`subjectModelFor` в `service.ts`); никаких полей клиента или
   изменений схемы не требуется.
2. Список кандидатов-судей (по приоритету, первый — наивысший) резолвится на
   каждый прогон — перезапуск не нужен:
   - `MYRMIDON_EVALS_JUDGE_PRIORITY_MODELS` (env, принудительное переопределение), иначе
   - встроенный список бесплатных моделей по умолчанию, реально обслуживаемых
     гейтвеем:
     `qwen-plus-free, qwen-max-free, qwen-turbo-free`
     (`SERVED_FREE_GATEWAY_MODELS`; невалидированные id в списке по умолчанию
     запрещены).
3. `judgeCandidateOrder(agentModel, candidates, fallbackModel)` идёт по списку
   от головы и ставит первым первого кандидата, чьё семейство ≠ семейству
   агента. Семейства определяются расширяемой таблицей в
   `server/src/myrmidon/evals/model-family.ts` (`qwen`, `gpt`, `claude`,
   `glm`, `deepseek`, `kimi`, `gemini`, `llama`, `mistral`, `yi`, `phi`, `o1`,
   `o3`, …); новое семейство — одна строка в этой таблице. Сопоставление
   заякорено по токенам: подстрока засчитывается только в начале id или после
   `/ . _ -`, поэтому `deepyida` — не `yi`, `chaos`/`cosmos` — не `o3`,
   `mystique`/`dolphin` — не `phi`.
4. Если кандидатов другого семейства нет, прогон всё равно оценивается —
   первый кандидат судит, каждая задача в `eval_runs.scores` несёт
   `sameFamily: true`, в журнал сервера падает предупреждение с семейством
   агента, моделью агента и именем судьи.
5. Платная модель (без суффикса `-free`) не попадает в список по умолчанию и
   может судить, только если оператор явно вынес её в настройку. Если прогон
   не передал `agentModel`, судит настроенная `MYRMIDON_EVALS_MODEL`
   (отличать не от чего).
6. Ошибка гейтвея выбранного судьи (недоступен / HTTP-ошибка) больше не
   прерывает прогон: `createJudge` переходит к следующему кандидату, а когда
   вся цепочка приоритетных кандидатов исчерпана с ошибкой, последний шанс
   получает настроенная `MYRMIDON_EVALS_MODEL` (её оценки помечены
   `sameFamily: true`). Прогон падает, только если не сработала вся цепочка;
   тогда проброшена последняя ошибка.

## Где видна пометка

- В записи прогона: `scores.tasks[].sameFamily` (по каждой оценённой задаче).
- В журнале сервера: предупреждение о работе судьи того же семейства.
- Бейдж на доске (OPE-4150, дочерняя задача) рисует `sameFamily` из сохранённых скоров.

## Связанные настройки

См. таблицу `MYRMIDON_EVALS_*` в `docs/myrmidon/SETTINGS.ru.md`
(строка EVALS-JUDGE-FAMILY); английская версия — `docs/myrmidon/SETTINGS.md`.

## Тесты

`server/src/myrmidon/evals/judge.family-selection.myrmidon.test.ts` покрывает
критерии приёмки: список по умолчанию состоит только из реально обслуживаемых
гейтвеем моделей и не-qwen агенту даёт не-qwen судью; агенту на qwen
подбирается не-qwen судья; при коллизии семейств оценка всё равно есть,
пометка `sameFamily` стоит и падает предупреждение; ошибка гейтвея выбранного
судьи не прерывает прогон — следующий кандидат, затем настроенная модель с
пометкой `sameFamily`; платная модель не выбирается, пока оператор сам не
внесёт её в список; заякоренное по токенам сопоставление больше не срабатывает
на встроенные подстроки `yi`/`o1`/`o3`/`phi`.
