# Доля вендорного кода в репозитории

Правило релиза требует измерять долю файлов, унаследованных от вендорского
кода, на каждом релизе. До сих пор число бралось из ручного аудита
(~6,1 тыс. из ~6,8 тыс. файлов). `scripts/myrmidon/vendor-share.mjs` даёт его
одной командой и прямо из репозитория.

## Что считается унаследованным

Отслеживаемый файл считается унаследованным, когда выполнены **оба** условия:

1. его путь существовал в базовом вендорском коммите. Переименование
   учитывается штатным детектором git, поэтому файл, перенесённый через
   `git mv`, по-прежнему сопоставляется со старым путём;
2. доля совпадающих строк с базовой версией не ниже порога (по умолчанию
   50%). Доля — пересечение мультимножеств непустых строк, делённое на
   большую сторону: неизменённый файл даёт 100%, полный перезапись — 0%.

Остальное попадает в `new` (пути нет в базе), `modified` (переписан ниже
порога), `binary` или `excluded`. Список исключений — константа в скрипте:
lock-файлы (`package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `*.lock`,
`Cargo.lock`, …), артефакты сборки (`dist`, `build`, `out`, `coverage`,
`.next`, `__snapshots__`), сгенерированное (`*.min.js`, `*.map`, `*.snap`,
`*.generated.*`), файл базового коммита и реестр отличий.

## Использование

```bash
# короткая таблица Markdown (вывод по умолчанию)
node scripts/myrmidon/vendor-share.mjs

# машиночитаемый отчёт JSON
node scripts/myrmidon/vendor-share.mjs --json

# строже порог, другой базовый коммит или другой чекаут
node scripts/myrmidon/vendor-share.mjs --threshold 0.7
node scripts/myrmidon/vendor-share.mjs --base <sha>
node scripts/myrmidon/vendor-share.mjs --repo /path/to/checkout
```

| Опция | Значение |
| --- | --- |
| `--threshold`, `-t` | порог схожести, 0..1 (по умолчанию 0.5) |
| `--base` | базовый вендорский коммит или ссылка (по умолчанию из `scripts/myrmidon/vendor-base.txt`) |
| `--repo` | анализируемый репозиторий (по умолчанию текущий каталог) |
| `--json` | вывести JSON вместо таблицы Markdown |
| `--help`, `-h` | справка |

## Порог и источник его значения

Порог разрешается по порядку: флаг `--threshold`, затем переменная окружения
`MYRMIDON_VENDOR_SHARE_THRESHOLD` (принудительное переопределение), затем
встроенное значение `0.5`. Отчёт всегда называет источник
(`flag`, `env` или `default`), поэтому неожиданное число можно проследить до
породившего его значения. Переменная описана в [SETTINGS.md](../SETTINGS.md).

## Вывод

JSON: `summary` (`totalFiles`, `inherited`, `modified`, `newFiles`, `binary`,
`excluded`, `share`, `threshold`, `thresholdSource`, `baseCommit`,
`baseSource`), разбивки `byDirectory` и `byPackage` с долей по каждой, а также
пофайловый список (поле `basePath` — путь, с которым сопоставлено
переименование). Markdown: сводная таблица и по таблице на каталоги верхнего
уровня и на пакеты.

## Базовый вендорский коммит

Коммит записан в `scripts/myrmidon/vendor-base.txt` вместе с командой, которая
его находит: самый свежий релизный тег вендора, достижимый из `main`
(`git tag --merged main 'v20*' --sort=-v:refname | head -1` → `v2026.916.1` →
`d554c4789ed3…`). Наши релизы используют `myr-v*`, поэтому всё ниже этого тега —
вендорский код.

## Производительность

На текущем `main` скрипт измеряет ~9 тыс. отслеживаемых файлов за несколько
секунд — с большим запасом внутри двухминутного бюджета. Базовые версии
читаются ограниченными пачками через `git cat-file --batch` вместо процесса на
файл, а файлы с неизменившимся хешем блоба классифицируются вообще без чтения
содержимого.

## Проверка

`scripts/myrmidon/vendor-share.myrmidon.test.mjs` собирает маленький
искусственный репозиторий во временном каталоге — базовый коммит, затем
нетронутый файл, полностью переписанный файл, переименование через `git mv`,
новый файл и исключённый lock-файл — и проверяет каждую классификацию,
арифметику сводки и контракт CLI (форма JSON, вывод Markdown, источник порога).
CI запускает все `scripts/myrmidon/**/*.test.mjs` через `node --test`.

Ручная проверка:

```bash
node scripts/myrmidon/vendor-share.mjs
node --test scripts/myrmidon/vendor-share.myrmidon.test.mjs
```
