# Свои касты — справочник ролей агентов компании

> English version: [custom-castes.md](custom-castes.md)

У каждого агента на доске есть роль — строка в `agents.role`, которая
определяет, в какую очередь роя попадают его задачи и какие разрешения
применяются. До этой функции ролью могла быть только одна из двенадцати
встроенных. Свои касты заменяют этот жёсткий список справочником, которым
владеет каждая компания: она начинает с тех же двенадцати записей, а дальше
может заводить свои, переименовывать, настраивать поведение каждой и удалять
лишние.

Это руководство описывает сам справочник: где он живёт, из чего состоит
каста, как устроен API и что происходит с агентами и их задачами при
изменении касты.

## Где он живёт

- **В базе данных.** Справочник — таблица (`agent_castes`) в разрезе
  компании: у каждой компании свой набор каст, и при удалении компании её
  касты удаляются вместе с ней. Переменных окружения и настроек инстанса за
  этой функцией нет.
- **В интерфейсе.** В настройках компании справочник — это экран «Agent
  castes». Роль агенту по-прежнему назначают в его редакторе — разница лишь в
  том, что теперь роль — это ключ касты из справочника, поэтому только что
  созданную касту можно назначить сразу.
- **В API.** `GET/POST /api/myrmidon/companies/:companyId/castes`,
  `PATCH/DELETE /api/myrmidon/companies/:companyId/castes/:key`.

Справочник читается из базы при каждом запросе — кэша в процессе нет, и
перезапускать ничего не нужно. Каста, которую владелец доски создал,
изменил или удалил, видна гейту клейма роя и всем клиентам уже со следующего
вызова.

## Стартовый набор: двенадцать встроенных каст

При первом чтении справочника компании он заполняется двенадцатью встроенными
кастами — теми же ролями, что были в жёстком списке (`ceo`, `engineer` и
остальные десять), с английскими и русскими названиями, `swarmEligible: true`,
без своего потолка задач (`maxActiveTasks: null` — действует глобальный лимит
роя) и с цветом значка, детерминированно разложенным по палитре. Заполнение
идемпотентно: вставляются только те ключи, которых у компании ещё нет, поэтому
созданные или отредактированные вами записи оно не перезаписывает.

У встроенных каст стоит `builtIn: true`. В остальном они ведут себя как любая
другая каста, кроме того, что сам этот признак неизменяем (см. ниже).
Текущие роли существующих агентов не трогаются — заполнение не переписывает
`agents.role`.

## Из чего состоит каста

| Поле | Тип | Что это |
|---|---|---|
| `key` | строка | Стабильный идентификатор — латиница, цифры, дефисы и подчёркивания, 1–60 символов, в нижнем регистре. Именно эта строка стоит у агента в `agents.role`. После создания не меняется. |
| `nameEn` | строка | Английское название, обязательное, до 160 символов. |
| `nameRu` | строка или null | Русское название, до 160 символов. |
| `description` | строка или null | Свободное описание, до 2000 символов. |
| `color` | строка | Цвет значка из статусной палитры: `primary`, `muted`, `blue`, `amber`, `green`, `violet`, `red`, `gray`. По умолчанию `gray`. |
| `icon` | строка или null | Необязательный идентификатор иконки, до 64 символов. |
| `defaultModel` | строка или null | Модель по умолчанию для агента этой касты, до 512 символов. |
| `swarmEligible` | булево | Участвуют ли агенты этой касты в пуле клейма роя. По умолчанию `true`; надзорную касту вроде лида или дежурного ревьюера создают с `false`, чтобы рой никогда не отдавал ей задачу. |
| `maxActiveTasks` | целое или null | Свой потолок активных задач роя, 1–1000. Перекрывает глобальный `MYRMIDON_SWARM_MAX_ACTIVE_TASKS` только для агентов этой касты; `null` оставляет глобальный потолок. |
| `builtIn` | булево | Выставляется при заполнении справочника, через API не задаётся. Неизменяемо. |

Каждая каста в ответе также несёт метки времени `createdAt` и `updatedAt`.

## Контракт API

Все четыре маршрута — в разрезе компании: чужой компании отвечают 403, а
чтение открыто любому актору с доступом к компании (агенты компании читают
справочник). Изменения — создание, правка, удаление — только для доски.

| Маршрут | Доступ | Поведение |
|---|---|---|
| `GET /api/myrmidon/companies/:companyId/castes` | доступ к компании | Отвечает `{ castes: [...] }`. Первое чтение компании перед ответом заполняет двенадцать встроенных каст. |
| `POST /api/myrmidon/companies/:companyId/castes` | доска | Создаёт касту, отвечает `201` с созданной записью. `key`, который у компании уже есть, — `409`; ключ неправильной формы, отсутствующий `nameEn` или цвет вне палитры — `400`. |
| `PATCH /api/myrmidon/companies/:companyId/castes/:key` | доска | Обновляет изменяемые поля, отвечает `200` с обновлённой записью. Тело с `key` (с другим значением) или с `builtIn` — `400`: оба поля неизменяемы. Тело вообще без изменяемых полей — тоже `400`. Неизвестный ключ касты — `404`. |
| `DELETE /api/myrmidon/companies/:companyId/castes/:key` | доска | Удаляет касту, отвечает `204`. Про тело `reassignTo` — в разделе «Удаление касты» ниже. |

Тела ошибок рядом с сообщением несут машиночитаемый `code` — например
`caste_key_immutable`, `caste_builtin_immutable`, `caste_has_agents` или
`caste_reassign_target_missing`, — чтобы клиент мог отреагировать, не разбирая
текст.

## Удаление касты и перевод агентов

Касту, на которой нет агентов, удаляют безусловно: запись удаляется, ответ —
`204` (тело с `reassignTo` игнорируется).

Каста, на которой ещё стоят агенты, просто так исчезнуть не может:

- `DELETE` без тела отвечает `409` (`code` `caste_has_agents`, с числом
  затронутых агентов в `affected`) — справочник не оставляет агентов на роли,
  которой больше нет.
- `DELETE` с телом `{"reassignTo": "<key>"}` переводит всех агентов компании,
  у которых роль равна удаляемому ключу, на целевую касту и удаляет запись —
  одной транзакцией. Целевая каста должна существовать в той же компании и
  отличаться от удаляемого ключа, иначе ответ — `400`.

Очереди ролей роя строятся из `agents.role`, поэтому задачи переведённых
агентов автоматически следуют за ними в очередь новой касты — отдельной
перестройки очередей не происходит, и ничего не нужно перезапускать.

## Как справочник использует остальная система

- **Создание и правка агента** проверяют `role` по справочнику: назначить
  ключ, которого нет среди каст компании, нельзя — ответ `400`
  (`role_not_company_caste`). Сначала заведите касту, потом назначайте её. Для
  роли, которой нет во встроенной таблице названий, UI доски показывает сам
  ключ.
- **Гейт клейма роя** перед выдачей задачи смотрит на касту агента:
  `swarmEligible: false` отвечает на клейм `caste_excluded`, а кастовый
  `maxActiveTasks` ограничивает агентов этой касты независимо от глобального
  лимита. Роль без записи в справочнике ведёт себя в точности как до функции.
- **Намеренно без изменений:** матрица автономии разрешает ключ касты как
  строку роли без смены схемы, проверки встроенной касты `ceo` остались
  байт-в-байт прежними, а гранты по касте в cloud-connector не тронуты.

Каждое изменение пишет одну запись в журнал активности компании
(`caste_created`, `caste_updated`, `caste_removed` или
`caste_removed_reassigned` — последняя называет целевую касту и число
переведённых агентов).
