# Восстановление уведомления об остановке релиза

Уведомитель сохраняет метку репозитория `release-stop-lock-<event id>` после
успеха и ошибки. Это долговременное резервирование от дублей, а не временная
блокировка для обычной очистки. Ошибка `gh issue create` может означать, что
GitHub сохранил issue, но ответ потерялся. Список также может запаздывать;
таймаут ожидания резервирования намеренно завершает попытку с ошибкой.

Для сверки определите ID остановленного запуска и тег релиза по Actions и
логам уведомления. Найдите среди всех открытых и закрытых issue точное название
`release-stop: <tag> (<event id>)` и проверьте тело issue и ссылку на запуск.
Если issue найдена, сохраните метку: повтор устранит дубликат, когда запись
станет видна в списке. Не создавайте вторую issue и не удаляйте метку только
из-за пустого списка; повторите проверку после распространения и изучите логи.

Только убедившись, что issue не создана и уведомитель этого события уже не
работает, оператор может удалить осиротевшую метку
`release-stop-lock-<event id>` в репозитории и повторить уведомление. При
сомнении сохраните метку и эскалируйте ситуацию, чтобы не создать дубликат.
Метки накапливаются по событиям.

Источник: `scripts/myrmidon/release/release-stop-notify.sh`, OPE-13406, PR #3964.
