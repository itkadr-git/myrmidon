# Выбор модели и глубины рассуждений из Telegram-чата

> English version: [telegram-model-think.md](telegram-model-think.md)

В мостовой личке Telegram (руководство
[telegram-dm-status.ru.md](telegram-dm-status.ru.md), настройка
`MYRMIDON_TELEGRAM_DM_CONVERSATIONS`) работают две команды-переключателя:
они меняют, с какой моделью и с какой глубиной рассуждений отвечает агент
этого чата. Выбор действует на чат: он хранится в JSON-колонке
`assignee_adapter_overrides` переписки (`adapterConfig.model` /
`adapterConfig.effort`) и переопределяет карточку агента только для этой
переписки. Каждое изменение записывается в журнал активности как
`issue.updated`.

## `/model` — модель этого чата

- `/model` без аргумента показывает действующую модель и источник значения
  (`this chat`, `agent default` или `adapter default`), а затем
  пронумерованный список доступных вариантов.
- `/model <имя или номер>` выбирает модель: точное имя (в любом регистре),
  номер из списка (с 1) или однозначное окончание имени после `/`.
- `/model default` снимает переопределение чата — выбор снова решает
  карточка агента.

`/new <модель>` делает то же, что и `/model <модель>`, но сразу начинает
новую сессию; в отличие от `/model`, команда не ждёт окончания текущего
ответа — модель относится к сессии, которую `/new` сейчас откроет.

В списке не больше 30 моделей. Сначала идут модель карточки и её резервные,
ниже — остальные кандидаты. Значения-пустышки `default` и `auto` («пусть
решает адаптер») в список не попадают.

### Откуда берётся список (шлюзовые агенты)

Для шлюзового агента (`hermes_gateway`) варианты читаются из LLM-шлюза в
два яруса:

1. **Список, разрешённый ключу этого агента** — опрос `/v1/models` ключом
   самого агента: модели, которые этот агент вообще может запускать.
2. **Весь каталог шлюза**, который доска уже собирает (строки сбора
   расходов), — когда чтение по ключу недоступно: ключа на доске нет, шлюз
   не отвечает или у шлюза нет `/v1/models`. Такой список шире списка одного
   агента, поэтому ответ добавляет строку, что показан весь каталог.

Список сгруппирован по семейству провайдера (`dashscope-*`, `zai-*`,
`nous-*`), каждое семейство под своей строкой-заголовком; нумерация сквозная,
поэтому заголовок не сдвигает номера, которые вы вводите. Для остальных
адаптеров список даёт собственное обнаружение моделей адаптера (например,
`opencode_local` отвечает из `opencode models`).

## `/think` — глубина рассуждений

`/think` устроена так же, как `/model`: без аргумента показывает действующую
глубину и её источник; `<уровень или номер>` устанавливает её; `default`
снимает переопределение. Фиксированный список уровней: `none`, `minimal`,
`low`, `medium`, `high`, `xhigh`, `max`, `ultra`.

Для hermes-адаптеров (`hermes_gateway`, `hermes_local`) уровень сверяется с
политикой усилий модели, с которой ответит этот чат: GLM-модель принимает
только `low`, `high` и `max`. Уровень, который модель не принимает, не
записывается, а ответ называет допустимые. Проверяется модель чата, а если
её нет — модель карточки; когда модель неизвестна, выбор не ограничивается.

## Когда выбор вступает в силу (шлюзовые агенты)

Шлюзовый агент работает в bot-контейнере по скомпилированному профилю,
поэтому записанный выбор применяется к профилю сразу, без перезапуска: ответ
говорит, что изменение вступит в силу со следующего ответа.

- **Применить не удалось** — значение чата возвращается к прежнему, а ответ
  называет причину и сообщает, что прежнее значение восстановлено.
- **Bot-containers в этом процессе не подключены** (возможность выключена) —
  запись сохраняется, и это не ошибка: ответ говорит, что новый профиль пока
  не применён, и изменение вступит в силу при следующем применении профиля.

Для остальных адаптеров достаточно самого переопределения — адаптер читает
значение при следующем прогоне.

## Каким агентам доступны команды

`/model` работает с `hermes_gateway`, `hermes_local`, `claude_local`,
`codex_local`, `cursor`, `cursor_cloud`, `gemini_local`, `grok_local`,
`kimi_local`, `opencode_local`, `pi_local`; `/think` — с `hermes_gateway` и
`hermes_local`. Отказ для любого другого адаптера называет тип адаптера и
причину (адаптер не поддерживает смену из чата либо варианты для чата
прочитать не удалось) на языке пользователя чата.

Обе команды не пишут, пока для чата идёт ответ: приходит отказ об идущем
ответе, и выбор нужно повторить после него.
