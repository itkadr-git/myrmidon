# MCP-инструменты корпуса для ботов доски

Доска отдаёт корпус знаний компании ботам собственным MCP-эндпоинтом: бот ищет
и читает корпус модулем доски, а не фасадом RAGFlow.

- Эндпоинт: `POST /api/myrmidon/companies/:companyId/corpus/mcp`
- Форма: JSON-RPC по HTTP (`initialize`, `tools/list`, `tools/call`) — та же, что
  у эндпоинта OCR, на который бот уже настроен; версия протокола `2025-03-26`.
  Доступ — по компании из пути (`assertCompanyAccess`), как в остальном API с
  привязкой к компании.
- Инструменты: `corpus_search`, `corpus_get_document`, `corpus_list_datasets`,
  `corpus_list_documents`.

## Как включить

Инструменты появляются **вместе с модулем**: они следуют настройке
`instance_settings.general.corpus` (блок настроек части C), и настройка читается
на каждом вызове — включение и выключение корпуса действует со следующего вызова
бота, без перезапуска.

- Модуль выключен: `tools/list` возвращает пустой список, а `tools/call`, всё же
  назвавший инструмент корпуса, отвечает результатом с `isError` и кодом
  `corpus_disabled`. Бот, чья конфигурация старше переключателя, сообщает фразу, а
  не падает на недоступном эндпоинте.
- Модуль включён, данные не подключены: набор инструментов есть и отвечает
  `corpus_unavailable` — модуль включён, и это не выдаётся за «в корпусе пусто».
- Потолок берётся из настроек модуля: `top_k` (поиск) и `limit` (документы) выше
  настроенного максимума отклоняются, а не подрезаются.

## Инструменты

### `corpus_search`

Поиск чанков по смыслу. Аргументы: `query` (обязательный), `dataset` или
`dataset_ids` для сужения поиска, `top_k` (по умолчанию — из настроек, сверху
ограничен ими), `min_score` (псевдоним `similarity_threshold`) для отсечения
слабых попаданий. Ответ — список чанков, который сравнивает теневой прогон: текст
чанка, его score и документ-источник (id, имя, страница, ссылка).

### `corpus_get_document`

Чтение документа: метаданные, состояние разбора и — если не передано
`include_text: false` — текст, собранный из проиндексированных чанков. На вход
идёт id документа из результата поиска.

### `corpus_list_datasets`

Что вообще можно искать: датасеты компании с числом документов и чанков.
Аргументов нет.

### `corpus_list_documents`

Что лежит в датасете, с состоянием разбора каждого документа (`queued`,
`parsing`, `embedding`, `ready`, `failed`) — бот видит, готов ли документ к
поиску. Аргументы: `dataset`/`dataset_ids`, `offset` и `limit` (пропуск требует
`limit`).

## Ошибки

Любая неудача — результат инструмента со стабильным кодом, по которому бот может
действовать: `corpus_disabled`, `corpus_unavailable`, `invalid_tool_input`,
`dataset_not_found`, `document_not_found`, `query_failed`.

## Чего этот эндпоинт не делает

Он только читает. Загрузка, разбор и индексация документов — части A–C модуля
корпуса (их маршруты и их экран); замена фасада RAGFlow в конфигурации бота —
шаг части E и оператора. Прогон обоих путей на одних запросах (теневой режим) —
то, ради чего в `corpus_search` приняты совместимые с RAGFlow псевдонимы
аргументов: `dataset_ids` и `similarity_threshold` рядом с `dataset` и
`min_score`, чтобы одно тело запроса годилось обоим путям.
