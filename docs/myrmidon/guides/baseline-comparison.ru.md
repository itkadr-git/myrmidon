# Сравнение с базовой линией на экране Quality

Экран Quality (`/quality`) показывает шесть метрик доставки за окно — по
проектам и по ролям. С версии 1.6.5 под двумя таблицами метрик на странице
есть блок «Сравнение с закреплённым снимком»: то же окно рядом с закреплённым
снимком базовой линии компании, с дельтами по строкам.

Блок читает
`GET /api/myrmidon/companies/:companyId/baseline/compare?from&to`
(влито в 1.6.2, PR #484) с теми же `from`/`to`, что выбраны на странице, —
пресеты окна (7/14/30 дней) и поля произвольных дат управляют и таблицами
метрик, и сравнением.

## Что показывает блок

Для каждого проекта и каждой роли — строка из пяти метрик рядом:

| Колонка | Источник |
|---|---|
| Текущее окно | `current.byProject` / `current.byRole` ответа compare |
| Базовая линия | `baseline.byProject` / `baseline.byRole` (payload закреплённого снимка) |
| Дельта | считается на клиенте по двум строкам, сопоставленным по ключу |

Метрики в строке: задач завершено, время цикла (ср), время ревью (ср), доля
возвратов, стоимость задачи (ср). Дельта — абсолютное изменение плюс процент;
для доли возвратов — в процентных пунктах. Цвет показывает направление:
зелёный — стало лучше базовой линии, красный — хуже (время цикла, время
ревью, доля возвратов и стоимость — «меньше = лучше»; завершённые задачи —
«больше = лучше»).

Серверный блок `differences` в ответе compare несёт те же дельты по каждому
ключу: `differences.byProject[key]` и `differences.byRole[key]` содержат пары
`{ absolute, percentage }` по каждой метрике для всех групп, которые есть на
обеих сторонах сравнения (записи `reviewTimeP90` там нет — в контракте
BASELINE нет p90 времени ревью). Группа, существующая только на одной
стороне, записи не получает, и её строка показывает «—» вместо дельты —
блок сравнения выводит строки из `current.by*` и `baseline.by*`,
сопоставленных по ключу, поэтому отображение от серверного блока не зависит.
Проценты дельт считаются по каждому ключу отдельно, поэтому задача никогда
не считается дважды (один раз под своим проектом и ещё раз под своей ролью).
`percentage` равен `null`, когда базовое значение равно 0: изменение от нуля
реально, но осмысленного процента у него нет. Ключ проекта `null` попадает в
запись под ключом `""`.

## Отсутствие закреплённого снимка — не ошибка

Когда у компании нет закреплённого снимка, эндпоинт отвечает
`baseline: null`, и блок показывает нейтральное уведомление «нет базовой
линии» — таблицы метрик выше продолжают работать. Уведомление подсказывает
оператору, как закрепить снимок (`POST .../baseline/snapshots` с
`"pinned": true`, см. [baseline-snapshots-api.ru.md](baseline-snapshots-api.ru.md)).

Сбой запроса сравнения (сеть, 5xx) рисует собственное уведомление об ошибке
внутри блока; остальная страница Quality при этом не ломается.

## Файлы

- `ui/src/pages/BaselineCompareBlock.tsx` — компонент блока
  (`myrmidon(1.6.5-BASELINE-COMPARE-UI)`).
- `ui/src/pages/Quality.tsx`, `ui/src/pages/Quality.production.tsx` — импорт
  и подключение блока под таблицей по ролям (строки с меткой).
- `ui/src/i18n/myrmidon-locales/{en,ru}.json` — ключи `quality.compare.*`.
- `ui/src/pages/Quality.test.tsx` — тесты компонента: таблицы с дельтами,
  состояние «нет базовой линии» (не ошибка), изолированное состояние ошибки
  сравнения.
