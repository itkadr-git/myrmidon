# Контроль действия DELETE в матрице автономии

## Обзор

Начиная с версии 1.6.2, матрица автономии контролирует действие класса `delete` для различных точек DELETE. Агенты, чьи роли имеют значение `delete` равное `forbidden` в матрице автономии, будут получать ошибку 403 при попытке удалить ресурсы через конечные точки API.

## Затронутые конечные точки

Следующие конечные точки DELETE теперь проверяют матрицу автономии для класса действия `delete`:

| Конечная точка | Описание |
|----------------|----------|
| `DELETE /api/issues/:id` | Удалить задачу |
| `DELETE /api/issues/:id/comments/:commentId` | Удалить комментарий из задачи |
| `DELETE /api/attachments/:attachmentId` | Удалить вложение |
| `DELETE /api/issues/:id/inbox-archive` | Разархивировать элемент входящих |

## Конфигурация

Настройте разрешение на удаление в матрице автономии:

```json
{
  "rules": [
    {
      "role": "your-agent-role",
      "actionClass": "delete",
      "verdict": "allowed" // или "forbidden" или "approval_required"
    }
  ],
  "defaults": {
    "delete": "allowed"
  }
}
```

## Формат ответа

Когда агент пытается выполнить операцию DELETE, которая запрещена матрицей автономии, API возвращает:

```json
{
  "error": "This action is forbidden for this role by the autonomy matrix",
  "code": "autonomy_forbidden",
  "actionClass": "delete",
  "role": "agent-role-name"
}
```

## Поведение

- **Allowed**: Операция DELETE выполняется нормально
- **Forbidden**: Операция отклоняется с ответом 403
- **Approval Required**: В настоящее время обрабатывается как запрещенная (в будущем может быть реализован рабочий процесс одобрения)

## Доступ пользователей доски

Пользователи доски (вызывающие, не являющиеся агентами) не подчиняются ограничениям матрицы автономии и могут выполнять операции DELETE независимо от конфигурации матрицы.
