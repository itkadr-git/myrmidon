# API снимков базовой линии

Модуль BASELINE (1.6, часть A) считает шесть метрик доставки за окно на
`GET /api/myrmidon/companies/:companyId/baseline/metrics`. Три эндпоинта ниже
надстроены над ним: они считают тот же ответ, кладут его целиком в хранилище и
держат как точку отсчёта («как было»), с которой сравнивают последующие
измерения.

Хранимая строка — та, что пишет модуль: замороженный ответ метрик лежит в
`payload`, а строка отдаётся как есть (поля не переименовываются, отдельного
массива `metrics` нет). `from`/`to` запроса — это колонки `windowFrom`/`windowTo`.

## POST /api/myrmidon/companies/:companyId/baseline/snapshots

Считает метрики за окно из тела запроса и сохраняет ответ.

**Доступ:** только доска — `assertBoard` плюс проверка доступа к компании.
Ключ агента отклоняется с `403`; так же отклоняется член доски, не входящий в
компанию (маршруты чтения ниже пускают ключ агента той же компании).

**Тело** (`application/json`):

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `from` | строка ISO 8601 | да | Начало окна |
| `to` | строка ISO 8601 | да | Конец окна |
| `label` | строка | нет | Человекочитаемая метка; без неё сохраняется `null` |
| `pinned` | boolean | нет | Закрепить новый снимок как точку отсчёта компании; по умолчанию `false` |

**Ответ — `201 Created`**: сохранённая строка.

```json
{
  "id": "5b1f0dd2-1a1e-4a3f-9c31-6a0b0a44f001",
  "companyId": "11111111-1111-4111-8111-111111111111",
  "windowFrom": "2026-09-19T08:28:00.000Z",
  "windowTo": "2026-10-03T08:28:00.000Z",
  "generatedAt": "2026-10-04T10:00:00.000Z",
  "payload": {
    "window": { "from": "2026-09-19T08:28:00.000Z", "to": "2026-10-03T08:28:00.000Z" },
    "generatedAt": "2026-10-04T10:00:00.000Z",
    "source": { "statusLog": "activity_log", "costs": "none" },
    "byProject": [],
    "byRole": []
  },
  "label": "Базовая линия до пилота",
  "pinned": true
}
```

**Ошибки**

- `400 Bad Request` — нет `from` или `to`:
  `{"error":"Both 'from' and 'to' are required"}`.
- `403 Forbidden` — актор не доска или доска вне компании.

## GET /api/myrmidon/companies/:companyId/baseline/snapshots

**Доступ:** проверка доступа к компании (доска или ключ агента этой компании).

**Ответ — `200 OK`**: JSON-массив сохранённых строк в том порядке, в котором их
отдаёт база (маршрут порядок не задаёт).

```json
[
  {
    "id": "5b1f0dd2-1a1e-4a3f-9c31-6a0b0a44f001",
    "companyId": "11111111-1111-4111-8111-111111111111",
    "windowFrom": "2026-09-19T08:28:00.000Z",
    "windowTo": "2026-10-03T08:28:00.000Z",
    "generatedAt": "2026-10-04T10:00:00.000Z",
    "payload": { "window": {}, "generatedAt": "", "source": {}, "byProject": [], "byRole": [] },
    "label": "Базовая линия до пилота",
    "pinned": true
  }
]
```

## GET /api/myrmidon/companies/:companyId/baseline/snapshots/:snapshotId

**Доступ:** проверка доступа к компании.

**Ответ — `200 OK`**: одна сохранённая строка (та же форма, что выше).

**Ошибки** — `404 Not Found`, если у компании нет строки с таким id:
`{"error":"Snapshot not found"}`.

## Закрепление

- Создание снимка с `pinned: true` сначала снимает `pinned` у снимков компании,
  закреплённых сейчас, и только потом вставляет новую строку. Поэтому точка
  отсчёта у компании одна, а прежняя остаётся обычным незакреплённым снимком.
- `pinned: false` (умолчание) закреплённую строку не трогает.
- Инвариант держат эти два запроса, а не уникальный индекс: частичный индекс
  `baseline_metric_snapshots_company_pinned_idx` только ускоряет поиск и не
  запрещает вторую закреплённую строку при одновременной записи.

## Пример

```bash
curl -X POST \
  https://board.example.test/api/myrmidon/companies/11111111-1111-4111-8111-111111111111/baseline/snapshots \
  -H 'Authorization: Bearer <board-api-key>' \
  -H 'Content-Type: application/json' \
  -d '{
    "from": "2026-09-19T08:28:00.000Z",
    "to": "2026-10-03T08:28:00.000Z",
    "label": "Базовая линия до пилота",
    "pinned": true
  }'
```
