# Матрица автономии: класс действия `deploy`

Класс `deploy` матрицы автономии применяется на двух маршрутах, которые запускают выкат или
входят в обслуживание:

- `POST /api/myrmidon/deploy-jobs` запускает задание выката.
- `POST /api/myrmidon/maintenance` входит в окно обслуживания (или выходит из него).

Шлюз срабатывает первым, до проверки администратора экземпляра, и отвечает из сохранённой матрицы
по роли вызывающего:

| Вызывающий | Вердикт | Результат |
|---|---|---|
| агент | `forbidden` | 403, код `autonomy_forbidden` |
| агент | `approval_required` | 403, код `autonomy_approval_required` (у board-маршрута пока нет примитива удержания действия, поэтому вердикт отказывает, а не пропускает молча) |
| агент | `allowed` | проходит шлюз; маршруты остаются только для доски, поэтому ключ агента всё равно получает 403 «нужен доступ доски» |
| пользователь доски | любой | матрица не применяется; проверка администратора экземпляра остаётся |

## Умолчания

Заводское умолчание для `deploy` изменено с `allowed` на `approval_required`: агент без явного
разрешения не может запустить выкат. Если в сохранённой матрице `deploy` остался `allowed` и нет
явного правила для deploy — при чтении значение поднимается до `approval_required`. Чтобы разрешить
deploy для роли, добавьте правило в Company Settings, Autonomy, например:

```json
{ "role": "engineer", "actionClass": "deploy", "verdict": "allowed" }
```

## Слияние

Маршрутов слияния pull request в доске нет, поэтому у класса `merge` пока нет точки применения.
