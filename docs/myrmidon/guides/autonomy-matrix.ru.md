# Матрица автономии: точки исполнения

Матрица автономии отображает «роль × класс действия» в `allowed` /
`approval_required` / `forbidden`, а гейт (`server/src/myrmidon/autonomy/gate.ts`)
спрашивается в точке действия. Эта страница отвечает на вторую половину
вопроса: **где каждый класс действия действительно исполняется?**

Реестр (`server/src/myrmidon/autonomy/registry.ts`) держит ответ, а
`registry.myrmidon.test.ts` вычитывает каждый стык из исходников, поэтому
таблица ниже не может разойтись с кодом.

## Исполняется на этом дереве

| Класс действия | Точка исполнения | Файл-стык | Вызов гейта |
| --- | --- | --- | --- |
| `delete` | `DELETE /api/issues/:id` и пять соседних DELETE-маршрутов | `server/src/routes/issues.ts` | `assertAllowed(req, "delete")` |
| `change_instructions` | `PATCH /api/agents/:id/instructions-path`, `PATCH /api/agents/:id/instructions-bundle`, `DELETE /api/agents/:id/instructions-bundle/file` | `server/src/routes/agents.ts` | `decide(req, "change_instructions")` |
| `change_instructions` | `POST /api/agents/:id/instructions-revisions/:revisionId/rollback` | `server/src/myrmidon/agent-instructions-revisions/index.ts` | `decide(req, "change_instructions")` |

Вердикт `forbidden` отвечает 403 со стабильным кодом `autonomy_forbidden`;
вердикт `approval_required` на маршрутах без строки вызова отвечает 403
`autonomy_approval_required`, пока не появится держание действия. Вызывающий
не-агент (доска, админ инстанса) матрице не подчиняется, а отказанный запрос
никогда не выполняет работу маршрута.

## Как это проверяется

- `registry.myrmidon.test.ts` рядом с реестром вычитывает каждый стык из
  исходников: убери вызов гейта из подключённого маршрута — и набор краснеет.
- `gate-deny.myrmidon.test.ts` рядом с гейтом закрепляет отказную половину самого
  гейта — `forbidden` превращается в 403 `autonomy_forbidden`, `allowed` проходит,
  а вызывающий не-агент матрице не подчиняется.
- `server/src/routes/agents-autonomy-e2e.myrmidon.test.ts` — маршрутный сквозной
  случай: настоящий express-маршрут, настоящий гейт и настоящий документ матрицы
  (подменяется только фабрика, читающая БД, — на in-memory стор). Агент, чьи
  инструкции требуют запрещённого `change_instructions`, получает 403
  `autonomy_forbidden`, и бандл инструкций не переписывается — после отказа
  маршрут не выполняет свою работу.

## Классы объявлены, но на этом дереве не исполняются

Эти классы есть в контракте матрицы, но ни один маршрут-стык их здесь не
спрашивает, поэтому они лежат в `PENDING_ENFORCEMENT`, а не в реестре (тест
краснеет, если класс не попал ни туда, ни туда):

| Класс действия | Почему стыка ещё нет |
| --- | --- |
| `pause_wake_agents` | Пауза, снятие паузы и побудка на этом дереве не гейтятся; стык едет своей веткой автономии и переезжает в реестр при слиянии. |
| `merge` | Вердикт merge пока не спрашивается ни одним маршрутом; держание через шлюз инструментов — задокументированный следующий шаг. |
| `deploy` | Вердикт deploy пока не спрашивается ни одним маршрутом. |
| `external_message` | Вердикт external_message пока не спрашивается ни одним маршрутом. |

`other` и `spend_above_threshold` исключены (`REGISTRY_EXEMPT_CLASSES`): у
«прочего» нет своего стыка, а класс расходов принадлежит бюджетному стыку (1.7).

## Что гарантирует тест реестра

- Каждый класс матрицы либо исполняется на стыке, либо перечислен в
  `PENDING_ENFORCEMENT` с причиной — класс не может молча потерять свою точку.
- Точка исполнения остаётся в реестре, только пока её исходник вызывает
  `assertAllowed(req, "<класс>")` / `decide(req, "<класс>")`: убери вызов гейта
  из подключённого маршрута — и тест краснеет.
- Ни один список не называет класс вне `AUTONOMY_ACTION_CLASSES`, и списки
  никогда не пересекаются.
