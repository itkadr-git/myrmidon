# Настройка и проверка чат-эндпоинта

На странице деталей чат-эндпоинта показаны текущее состояние настройки и
безопасные для этого состояния действия.

## Завершение настройки для verifying

Если эндпоинт имеет статус `verifying` и `setup.step` равен `test`, на странице
деталей появляется прямое действие **Finish setup**. Оно использует существующий
маршрут `POST /api/chat-endpoints/:endpointId/test`. Новый маршрут завершения не
создаётся, а серверные проверки не обходятся.

Кнопка отключена на время запроса. После успешного завершения запрос деталей
инвалидируется, поэтому страница показывает новый статус эндпоинта и больше не
предлагает это действие.

Если сервер возвращает `409` с кодом `chat_test_round_trip_incomplete`,
эндпоинт остаётся в текущем состоянии. Страница сообщает оператору, что нужно
дождаться ответа агента на тестовый диалог. Доступный ранее путь **Finish setup**
в мастер настройки остаётся доступным, чтобы продолжить настройку или повторить
тест.

## Сигнал зависшего verifying

Если в ответе API есть `verifyingStale: true`, страница деталей показывает
нейтральный предупреждающий бейдж **Verifying over 24 hours with live traffic**.
Это сигнал внимания, а не ошибка: он не меняет состояние эндпоинта и не
останавливает трафик. Если сервер не устанавливает флаг, бейдж не показывается.

Сервер передаёт этот флаг в ответах для деталей и списка эндпоинтов. UI считает
поле необязательным, поэтому старые ответы остаются допустимыми.

## Доступность и состояния действия

Действие использует настоящую кнопку с видимой подписью. Во время мутации она
остаётся отключённой и показывает индикатор выполнения. Бейдж внимания использует
обычный нейтральный стиль, а не стиль ошибки или destructive-действия.
