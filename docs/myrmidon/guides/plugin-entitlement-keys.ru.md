# Ключи плагинов

myrmidon(PLUGIN-ENTITLEMENT C): ключи лицензирования на уровне экземпляра,
управляющие активацией плагинов. Плагин, в манифесте которого указано
`requiresEntitlement: true`, не активируется — не запускается worker, не
регистрируются слоты UI, плагин скрыт из меню и настроек — пока
администратор экземпляра не примет действующий ключ для его точного
идентификатора.

## Как это работает

1. Манифест плагина объявляет `requiresEntitlement: true`.
2. Загрузчик плагинов проверяет гейт при каждом проходе активации: он читает
   принятые ключи из `instance_settings.general.pluginEntitlementKeys` и
   ищет действующий (не истёкший) ключ с идентификатором манифеста.
3. Нет ключа → плагин пропускается (это не ошибка; повтор на следующем
   проходе). Есть ключ → плагин активируется как обычно.
4. Гейт перечитывает строку настроек при каждом проходе, поэтому приём или
   удаление ключа действует без перезапуска сервера.

## Интерфейс настроек

Блок «Ключи плагинов» на странице настроек экземпляра:

- пара полей (идентификатор плагина + ключ) и действие «Добавить ключ»;
- список принятых ключей — идентификатор плагина, срок действия, пометка
  «истёк»;
- удаление каждого ключа.

Строки — в каталоге локализации форка
(`ui/src/i18n/myrmidon-locales/{en,ru}.json`, пространство
`pluginEntitlement`); в русской локализации нет английских строк.

## API

Только администратор экземпляра (монтируется в `server/src/app.ts` под `/api`):

| Метод | Путь | Тело | Результат |
|---|---|---|---|
| GET | `/api/myrmidon/plugin-entitlement/keys` | — | принятые ключи `[{ pluginId, expiresAt, acceptedAt }]` — значения ключей не возвращаются никогда |
| POST | `/api/myrmidon/plugin-entitlement/keys` | `{ pluginId, key }` | 201 + обновлённый список (без значений ключей); повторный pluginId заменяет предыдущий ключ; неверный токен → 400 с понятным сообщением |
| DELETE | `/api/myrmidon/plugin-entitlement/keys/:pluginId` | — | обновлённый список (без значений ключей); удаление несуществующего id — без изменений |
| GET | `/api/myrmidon/plugin-entitlement/public-key` | — | `{ publicKey, source }` — открытый ключ проверки и источник значения (`settings`, `env` или `none`) |
| PUT | `/api/myrmidon/plugin-entitlement/public-key` | `{ publicKey }` | сохранение открытого ключа проверки в настройках экземпляра; `null` или пустая строка очищают значение |

Каждый ответ — проекция-представление (`toPluginEntitlementKeyViews`): в
хранилище лежат полные токены, но API их не возвращает, а сообщения об
ошибке 400 несут только причину отказа — без материала ключа.

## Формат ключа и проверка подписи (1.6.3, PLUGIN-ENTITLEMENT A)

Ключ включения плагина — токен, подписанный ed25519:

```
PEK1.<payload JSON в base64url>.<подпись в base64url>
```

- payload — `{ pluginId, instanceId, expiresAt }` (строгая схема; все поля
  обязательны, `expiresAt` — дата-время ISO: «бессрочно» в токене не
  выражается);
- подпись — ed25519 по ровно тому сегменту payload, что стоит между
  префиксом `PEK1.` и последней точкой;
- открытый ключ проверки (PEM, ed25519) — настройка экземпляра
  `instance_settings.general.pluginEntitlementPublicKey`; меняется в
  интерфейсе без перезапуска. `MYRMIDON_PLUGIN_ENTITLEMENT_PUBLIC_KEY` (PEM
  или base64 «сырого» 32-байтового ключа) — принудительное переопределение
  через env, действует только когда в настройках значения нет;
- `instanceId` — идентификатор экземпляра доски (`PAPERCLIP_INSTANCE_ID`,
  по умолчанию `default`): токен, выпущенный для другого экземпляра,
  отклоняется.

Проверка выполняется в двух местах:

1. **приём** — `POST .../keys` проверяет подпись, идентификатор плагина,
   идентификатор экземпляра и срок до сохранения ключа. Сохраняемый
   `expiresAt` берётся из подписанного payload, а не из тела запроса;
2. **активация** — гейт загрузчика перепроверяет каждый сохранённый ключ на
   каждом проходе активации (открытый ключ может смениться после приёма
   ключа), поэтому сохранённый ключ, подпись которого больше не сходится,
   не даёт права на плагин: один только срок — не вердикт.

Общий контракт (`packages/shared/src/myrmidon-plugin-entitlement.ts`)
содержит независимые от среды части: схему payload, парсер токена и
проекцию-представление. Сама проверка подписи (`verifyEntitlementToken`)
живёт на сервере в
`server/src/myrmidon/plugin-entitlement/validation.ts`.

Выпуск токенов (вне доски): сгенерируйте пару ключей ed25519, храните
закрытый ключ, а открытый выдайте экземплярам как их настройку. Подпись —
`node:crypto` `sign(null, payload, privateKey)` (чистый режим ed25519) по
сегменту payload в base64url.

## Контракт хранения

`packages/shared/src/myrmidon-plugin-entitlement.ts` — общий контракт:

- `pluginEntitlementKeySchema` — `{ pluginId, key, expiresAt: string|Date|null, acceptedAt }`, strict;
- `pluginEntitlementKeysSchema` — массив (максимум 100);
- `normalizePluginEntitlementKeys` — отсутствующая или битая строка нормализуется в `[]` (fail closed: повреждённые данные никогда не разблокируют плагин);
- `findActivePluginEntitlementKey` / `isPluginEntitlementKeyActive` — разрешение срока (null = бессрочно).

Ключи переживают любую вендорскую запись строки `general` через хелпер
`preservePluginEntitlementKeysGeneralKey` (тот же паттерн, что у остальных
myrmidon-ключей general).

## Проверка ключей

Криптографическая проверка сделана (1.6.3, PLUGIN-ENTITLEMENT A): см.
«Формат ключа и проверка подписи» выше. Верификатор — ed25519 поверх токена
PEK1; открытый ключ проверки — настройка экземпляра
`pluginEntitlementPublicKey` (запасной вариант через env
`MYRMIDON_PLUGIN_ENTITLEMENT_PUBLIC_KEY`, когда в настройках значения нет).

## Пример

`packages/plugins/examples/plugin-entitlement-test-example/` — минимальный
манифест с `requiresEntitlement: true`, чтобы гейт и интерфейс можно было
проверить без реального лицензионного плагина. В коде, тестах и документации
нет названий реальных плагинов — только этот фикстурный пример.

## Тесты

- `server/src/myrmidon/plugin-entitlement/plugin-entitlement.myrmidon.test.ts` — активность ключей (бессрочный, истёкший, точное совпадение id), нормализация fail-closed, решения гейта активации (с проверкой подписи: верная проходит; чужая подпись, истёкший, другой экземпляр, другой плагин — отклонены), семантика хранилища (замена при повторном приёме, удаление, preserve, чтение открытого ключа с запасным env), парсер токена, проекция-представление (значения ключей не покидают API), проверки входного ключа;
- `packages/shared/src/myrmidon-plugin-entitlement.myrmidon.test.ts` — формат токена (payload/подписанный сегмент, отказ на мусоре и на payload без обязательных полей), нормализация списка, активность ключа, проекция-представление, контракт ответа с открытым ключом;
- `ui/src/components/myrmidon/PluginEntitlementSettingsPanel.myrmidon.test.tsx` — список со сроком и пометкой, пустое состояние, приём через API, показ причины отказа сервера, отсутствие вызова API при пустом ключе, удаление через API, источник открытого ключа, сохранение открытого ключа через API;
- `packages/shared/src/validators/plugin.test.ts` — флаг манифеста опционален, аддитивен и строго типизирован.
