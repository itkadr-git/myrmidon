# Ключи плагинов

myrmidon(PLUGIN-ENTITLEMENT C): ключи лицензирования на уровне экземпляра,
управляющие активацией плагинов. Плагин, в манифесте которого указано
`requiresEntitlement: true`, не активируется — не запускается worker, не
регистрируются слоты UI, плагин скрыт из меню и настроек — пока
администратор экземпляра не примет действующий ключ для его точного
идентификатора.

## Как это работает

1. Манифест плагина объявляет `requiresEntitlement: true`.
2. Загрузчик плагинов проверяет гейт при каждом проходе активации: он читает
   принятые ключи из `instance_settings.general.pluginEntitlementKeys` и
   ищет действующий (не истёкший) ключ с идентификатором манифеста.
3. Нет ключа → плагин пропускается (это не ошибка; повтор на следующем
   проходе). Есть ключ → плагин активируется как обычно.
4. Гейт перечитывает строку настроек при каждом проходе, поэтому приём или
   удаление ключа действует без перезапуска сервера.

## Интерфейс настроек

Блок «Ключи плагинов» на странице настроек экземпляра:

- пара полей (идентификатор плагина + ключ) и действие «Добавить ключ»;
- список принятых ключей — идентификатор плагина, срок действия, пометка
  «истёк»;
- удаление каждого ключа.

Строки — в каталоге локализации форка
(`ui/src/i18n/myrmidon-locales/{en,ru}.json`, пространство
`pluginEntitlement`); в русской локализации нет английских строк.

## API

Только администратор экземпляра (монтируется в `server/src/app.ts` под `/api`):

| Метод | Путь | Тело | Результат |
|---|---|---|---|
| GET | `/api/myrmidon/plugin-entitlement/keys` | — | принятые ключи `[{ pluginId, key, expiresAt, acceptedAt }]` |
| POST | `/api/myrmidon/plugin-entitlement/keys` | `{ pluginId, key }` | 201 + обновлённый список; повторный pluginId заменяет предыдущий ключ; неверный ввод → 400 с понятным сообщением |
| DELETE | `/api/myrmidon/plugin-entitlement/keys/:pluginId` | — | обновлённый список; удаление несуществующего id — без изменений |

## Контракт хранения

`packages/shared/src/myrmidon-plugin-entitlement.ts` — общий контракт:

- `pluginEntitlementKeySchema` — `{ pluginId, key, expiresAt: string|Date|null, acceptedAt }`, strict;
- `pluginEntitlementKeysSchema` — массив (максимум 100);
- `normalizePluginEntitlementKeys` — отсутствующая или битая строка нормализуется в `[]` (fail closed: повреждённые данные никогда не разблокируют плагин);
- `findActivePluginEntitlementKey` / `isPluginEntitlementKeyActive` — разрешение срока (null = бессрочно).

Ключи переживают любую вендорскую запись строки `general` через хелпер
`preservePluginEntitlementKeysGeneralKey` (тот же паттерн, что у остальных
myrmidon-ключей general).

## Проверка ключей

Криптографическая проверка — зависимость ML1/ML2 (вне рамок этой части).
Пока её нет, принимается синтаксически корректный ключ для известного
идентификатора плагина; интерфейс и поток хранения финальны и проверяемы
независимо от верификатора.

## Пример

`packages/plugins/examples/plugin-entitlement-test-example/` — минимальный
манифест с `requiresEntitlement: true`, чтобы гейт и интерфейс можно было
проверить без реального лицензионного плагина. В коде, тестах и документации
нет названий реальных плагинов — только этот фикстурный пример.

## Тесты

- `server/src/myrmidon/plugin-entitlement/plugin-entitlement.myrmidon.test.ts` — активность ключей (бессрочный, истёкший, точное совпадение id), нормализация fail-closed, решения гейта активации, семантика хранилища (замена при повторном приёме, удаление, preserve), проверки входного ключа;
