# dockergate

> English version: [dockergate.md](dockergate.md)

Прокси перед сокетом Docker для драйвера контейнеров ботов доски (`server/src/myrmidon/bot-containers/`). Код: `tools/dockergate/` (Go, только стандартная библиотека), образ: `docker/dockergate/Dockerfile`, публикация: `.github/workflows/myrmidon-dockergate.yml` в `ghcr.io/itkadr-git/myrmidon-dockergate`.

## Зачем

Сервер доски работает под тем же uid, что и боты с терминалом. Доступ доски к сокету демона Docker равен root хоста для любого такого бота: контейнер с `Privileged`, с монтированием `/` и так далее создаётся одним вызовом. dockergate стоит между доской и демоном и пропускает только вызовы, которые делает драйвер, и только с телами, которые драйвер строит. Всё остальное запрещено (запрет по умолчанию). Сырой сокет демона доске не монтируется, доске отдаётся сокет dockergate (`MYRMIDON_BOT_DOCKER_SOCKET`, см. [SETTINGS.md](SETTINGS.md)).

Дополнительные read-only тома бота (общие каталоги) описаны в
[bot-extra-mounts.md](bot-extra-mounts.md); на стороне dockergate их разрешает
ключ `mountSources`. Единственное исключение на запись — общий кэш пакетов
([bot-disk-cache.ru.md](bot-disk-cache.ru.md)); его разрешает ключ `packageCacheRoot`; он же разрешает зеркала git доски
(`<packageCacheRoot>/git` → `/cache/git`), но только на чтение.

## Как решается

1. **Вызывающий.** Соединение принимается, только если его открыл закреплённый процесс доски (`SO_PEERCRED`, затем сверка процесса по `/proc`): первый потомок главного процесса контейнера доски с ожидаемым `argv`. Чужой вызывающий получает статический отказ или молчаливое закрытие; слот соединения он не занимает. Режим `caller.mode: uid` (только uid и gid) нужен для CI и отвергается проверкой конфигурации при боевом `volumeRoot`.
2. **Маршруты.** Сопоставляется сырой request-target, без раскодирования процентных escape-последовательностей; допускаются только литералы шаблона. Метод, версия API (только `v1.45`) и заголовки проверяются жёстко.
3. **Тела.** Тело создания контейнера разбирается строгой схемой (неизвестный ключ, дубликат ключа, `null`, дробное число и экранированная буква отклоняются), затем пересобирается канонически, и сравнивается побайтно с полученным. Пересборка идёт от значений из `bots[]`, а не из запроса. Tar-загрузки (`ustar`) проверяются побайтно и пересобираются так же: типы, uid/gid, режимы, пути, порядок, содержимое. Маркер `applied.json` внутри tar профиля — данные, которые пишет сама доска, поэтому его содержимое не пересобирается; проверяется форма (см. [Маркер применённого профиля](#маркер-применённого-профиля)).
4. **Согласованность бота.** `botKey` берётся из имени контейнера; метка, тома, сеть и скрипт помощника обязаны ему соответствовать. Дополнительные тома сверх трёх томов бота разрешены только как read-only binds, источник которых целиком назван в `mountSources`, а точка монтирования не занята, плюс общий кэш пакетов: binds на запись принимаются только как фиксированные пары `<packageCacheRoot>/{pnpm,go-mod,go-build,gradle}` → `/cache/{pnpm,go-mod,go-build,gradle}`; у помощника дополнительных томов нет. Пределы памяти, CPU и числа процессов не могут превышать записанные в `bots[]`.
5. **Состояние.** Перед вызовом dockergate сам смотрит контейнер и проверяет предусловия (метка бота, статус, наличие `.next`).
6. **Ответы урезаются** до полей, которые читает драйвер, с потолком размера. Ответ A2 несёт состояние, которое читает драйвер, и все поля, которые сравнивает его проверка дрейфа шаблона — `Config.Image` и `HostConfig` `Memory`, `NanoCpus`, `PidsLimit`, `NetworkMode`, `Binds`. Урезанное сравниваемое поле — не «ответ поменьше»: доска читает там ничего, считает контейнер другим и пересоздаёт его каждый проход (инцидент 01.10, `HostConfig.Binds`). Контрактный тест гейта сверяет ответ A2 со списком полей, который эмитит драйвер (`tools/dockergate/contract/emit-fixtures.ts`), так что потеря поля краснит CI.

## Маркер применённого профиля

Каждая загрузка профиля завершается маркером применённого профиля `applied.json`. Это объект ровно со строковыми ключами `restartHash` и `filesHash` и массивом строк `files`, плюс необязательное целое `maxConcurrentRuns` (1..50), которое доска записывает со времён CONCURRENCY-SYNC. Любой другой ключ, `maxConcurrentRuns` другого типа или вне этого диапазона и файл сверх потолка размера отклоняются с `tar_content` (в детали журнала — `applied_json` / `applied_keys` / `applied_size`). Доска старше CONCURRENCY-SYNC пишет маркер из трёх ключей; dockergate принимает обе формы, и маркер, записанный старой доской, применение профиля не блокирует.

## Конфигурация

Файл JSON. Неизвестный ключ на любом уровне и отсутствие обязательного не дают запуститься (`check-config` и `serve` выходят с кодом не 0).

| Ключ | Смысл |
|---|---|
| `listen` | абсолютный путь сокета dockergate |
| `upstream` | абсолютный путь сокета демона |
| `apiVersion` | только `1.45` |
| `caller` | обязательно. `container` (имя контейнера доски), `containerLabels`, `uid`, `gid`, `argv`, `maxStartDelayTicks`, `mode` (`container-main-process` по умолчанию, `uid` только для CI) |
| `volumeRoot` | каталог томов ботов на хосте; том бота `<root>/<botKey>/{hermes,workspace,scratch}`; раскладка контейнера бота — та, что объявляет контракт рантайма его образа: ОДНА привязка `<root>/<botKey>:/bot` (жёсткие ссылки не пересекают монтирования, BOT-DISK-D) или старая форма — те же три каталога, привязанные напрямую в `/data/hermes`, `/workspace` и `/scratch` в фиксированном порядке драйвера (образы с контрактом `1` без метки области, BOT-LAYOUT-V); контейнеры-помощники сохраняют три узкие привязки тех же каталогов; `/bot` и `/data` — зарезервированные пути контейнера |
| `mountSources` | каталоги хоста, которые бот может смонтировать дополнительно, только для чтения (пустой или отсутствующий список — ни одного). Каждый дополнительный bind в теле создания должен начинаться с одного из этих путей целиком, иметь суффикс `ro` и точку монтирования вне `/workspace`, `/scratch`, `/bot`, `/tmp` — три поддерева данных владельца внутри `/data/hermes` это единственное исключение, и они принимаются по настоящему пути внутри единого монтирования бота (1.6.5-BOT-DISK-H11, см. [bot-extra-mounts.ru.md](bot-extra-mounts.ru.md#точка-монтирования-внутри-собственного-тома-бота-165-bot-disk-h-класс-j)); иначе `mount_source_not_allowed` или `binds_mismatch`. Список применим и при `SIGHUP` |
| `botRuntimeRoot` | каталог хоста общей среды ботов (1.6.5-BOT-DISK-H11; настройка экземпляра доски `general.botDisk.sharedBotRuntimePath`, см. [bot-extra-mounts.ru.md](bot-extra-mounts.ru.md#общая-среда-ботов-165-bot-disk-h-класс-c)). Под ним, и только там, бот может смонтировать фиксированные подкаталоги `bin`, `lazy-packages` и `lsp` как привязки **на чтение** по настоящему пути внутри единого монтирования бота (`/bot/hermes/…`, `/bot-scope/<botKey>/hermes/…`, `/data/hermes/…`); другой корень, другой подкаталог, другая точка монтирования или `rw` — `mount_source_not_allowed`. Абсолютный каталог без `..`, `//` и завершающего `/`, вне `volumeRoot`, не пересекается с `scopeRoot` и `packageCacheRoot` и не является их родителем. Пустой или отсутствующий (по умолчанию) — ни одной привязки среды. Применим при `SIGHUP` |
| `packageCacheRoot` | каталог хоста с общим кэшем пакетов, тот же путь, что в настройке экземпляра доски (см. [bot-disk-cache.ru.md](bot-disk-cache.ru.md)). Под ним, и только там, бот может смонтировать на запись фиксированные подкаталоги `pnpm`, `go-mod`, `go-build`, `gradle` в `/cache/pnpm`, `/cache/go-mod`, `/cache/go-build`, `/cache/gradle`; любой другой bind на запись — `mount_source_not_allowed`. Подкаталог `git` принимается только как bind **на чтение** в `/cache/git` (голые зеркала git доски, 1.6.2-BOT-DISK-C); `git` с `rw` или в другой точке монтирования отклоняется так же. Абсолютный каталог без `..`, `//` и завершающего `/`, вне `volumeRoot`. Пустой или отсутствующий (по умолчанию) — ни одной привязки кэша. Применим при `SIGHUP` |
| `scopeRoot` | каталог хоста общих областей изоляции (BOT-DISK-F, см. [bot-disk-cache.ru.md](bot-disk-cache.ru.md#область-изоляции-кто-делит-диск)): по подкаталогу `<kind>-<id>` на экземпляр. Бот может смонтировать только экземпляр из своего `bots[].scopeInstances`. Абсолютный каталог без `..`, `//` и завершающего `/`, не `volumeRoot` и не его родитель, не пересекается с `packageCacheRoot`. Пустой или отсутствующий (по умолчанию) — `<volumeRoot>/.scopes` (ключ бота не может начинаться с `.`, поэтому коллизии с каталогом бота нет). Применим при `SIGHUP` |
| `network` | единственная сеть ботов |
| `images` | непустой список образов, только по дайджесту (`имя@sha256:...`), тег не допускается |
| `bots[]` | запись бота: `botKey`, `maxMemoryMb`, `maxCpus`, `maxPids` и необязательное `scopeInstances` — имена каталогов общих областей изоляции (`<kind>-<id>`, kind: `group`, `caste`, `subtree`, `project`, `catalog`, `company`), участником которых бот является и которые может монтировать. Пусто или нет — бот никогда не участник общей области |
| `limits` | лимиты и таймауты: размеры заголовка и тел, таймауты чтения и апстрима, число соединений и вызовов в полёте, общая частота, частота отказов на процесс, окна частоты по ботам (`createPerWindow`, `startPerWindow`, `restartPerWindow`, `stopPerWindow`, `putArchivePerWindow`, `rateWindowSec`). Пропущенный ключ берёт значение по умолчанию |
| `statsFile` | абсолютный путь файла счётчиков |

`SIGHUP` перечитывает файл; применяются только `bots`, `images`, `network`, `volumeRoot`, `mountSources`, `packageCacheRoot`, `botRuntimeRoot` и `scopeRoot`. Неверный файл или файл, меняющий что-либо ещё, отклоняется, работает прежняя конфигурация.

## Журнал и счётчики

Журнал (JSON, одна строка на решение) содержит маршрут, `botKey`, решение, код причины, и для отказа по полю тела: путь поля, длину значения и первые 12 символов sha256. Тел запросов и ответов, имён из tar, значений окружения, заголовков клиента и секретов в нём нет по построению. События без решения: `caller_decoy`, `reject_flood`, `caller_resolve_failed`, `caller_not_board_main`, `config_reload_failed`.

Коды причин: `caller_resolve_failed`, `caller_not_board_main`, `caller_pin_stale`, `target_form`, `method_not_allowed`, `api_version`, `route_not_allowed`, `header_forbidden`, `content_type`, `body_not_allowed`, `body_too_large`, `json_syntax`, `json_duplicate_key`, `json_unknown_key`, `json_type`, `json_value`, `json_not_canonical`, `bot_not_enrolled`, `image_not_allowed`, `image_contract`, `image_user`, `helper_image_mismatch`, `name_label_mismatch`, `binds_mismatch`, `mount_source_not_allowed`, `network_mismatch`, `limit_exceeds_enrollment`, `script_mismatch`, `nonce_invalid`, `tar_syntax`, `tar_type`, `tar_owner`, `tar_mode`, `tar_path`, `tar_nonce`, `tar_order`, `tar_content`, `tar_too_large`, `tar_not_canonical`, `foreign_container`, `state_precondition`, `volume_root_invariant`, `rate_limited`, `concurrency_limited`, `upstream_error`, `upstream_timeout`, `upstream_upgrade`, `response_too_large`, `marker_too_large`.

`statsFile` (JSON, переписывается атомарно) хранит только числа и имена: разрешения и отказы по маршрутам и причинам, `denyPeer`, `rejectDropped`, `resolveFailures`, `resolveDecoys`, ошибки апстрима, `markerTooLarge`, `rateLimited`, состояние закрепления, ответ демона на ping, гистограмму длительности по маршрутам. Значений из запросов и ответов демона в нём нет. Полезные сигналы для мониторинга: рост `denyPeer` или `resolveDecoys`, отказы кроме ожидаемых, `pinned: false`, устаревший `updatedAt`.

## Запись бота

1. Подготовить каталог тома бота `<volumeRoot>/<botKey>`: каталог принадлежит root и не
   записываем группой и прочими (проверка `CheckVolumeRoot` отклоняет режим с битами
   групповой/общей записи, то есть 0755 или строже); подкаталоги `hermes`, `workspace`,
   `scratch` — root или пользователь бота (uid 10001), тоже без групповой/общей записи.
   Содержимое не трогать. (uid 65532 — это пользователь самого контейнера dockergate,
   к владельцу тома он отношения не имеет.)
2. Добавить запись в `bots[]` (структурной правкой JSON, не регуляркой) с потолками памяти, CPU и числа процессов.
3. Если боту нужны дополнительные read-only тома, добавить их источники в `mountSources` (тоже структурной правкой); источник, не названный здесь, до демона не дойдёт. Если экземпляр использует общий кэш пакетов, задать `packageCacheRoot` тем же каталогом, что в настройке доски (тоже структурной правкой).
4. Проверить: `dockergate check-config --config <файл>`.
5. Отправить `SIGHUP` процессу dockergate.

## Участники общей области изоляции (BOT-DISK-F)

По умолчанию бот монтирует свой каталог (`<volumeRoot>/<botKey>:/bot`). Владелец может перевести
экземпляр области (группу, касту, поддерево подчинения, проект, команду каталога или всю
компанию) в режим *общий корень*; тогда его участники монтируют ОДИН каталог — экземпляра:
`<scopeRoot>/<instance>:/bot-scope`. В нём одно хранилище pnpm и подкаталог на участника
(`<botKey>/{hermes,workspace,scratch}`), поэтому жёсткая ссылка работает внутри бота и между
участниками. dockergate принимает ровно это, только для ботов, записанных на экземпляр, и ничего
шире:

- **Тело бота.** Помимо изолированного тела — тело с дополнительным ключом верхнего уровня
  `"Env":["MYRMIDON_BOT_SCOPE_SUBDIR=<botKey>"]` (единственный допустимый `Env`; любой другой остаётся
  `json_unknown_key`), tmpfs `{"/tmp":"","/data":"uid=10001,gid=10001,mode=0755,size=1m"}` (`/data`
  участника хранит только ссылки в его подкаталог, их делает entrypoint) и **одна** привязка
  `<scopeRoot>/<instance>:/bot-scope` без суффикса. Имя экземпляра читается из привязки и должно
  быть в `scopeInstances` бота; привязка пересобирается побайтно, поэтому соседний экземпляр,
  сам корень областей, имя с `..` или суффикс `:ro`/`:rw` — `mount_source_not_allowed` или
  `binds_mismatch`. Дополнительные монтирования карточки и привязки кэша — как раньше;
  `/bot-scope` и `/scope` — зарезервированные пути контейнера.
- **Помощники.** Три узкие привязки уходят внутрь подкаталога участника
  (`<scopeRoot>/<instance>/<botKey>/{hermes,workspace,scratch}`). Помощник подготовки участника
  дополнительно монтирует каталог экземпляра в `/scope` и запускает свой постоянный скрипт
  (`PrepareScriptShared`: тот же цикл плюс `scope`), который передаёт каталог экземпляра uid бота,
  чтобы контейнер мог создать в нём хранилище pnpm. Скрипт должен соответствовать раскладке
  привязок (иначе `script_mismatch`).
- **Инварианты хоста** (`CheckScopeDir`, при каждом create с экземпляром): `scopeRoot`, если есть, —
  каталог root, не ссылка, без записи группе и прочим; каталог экземпляра и подкаталог участника,
  если есть, — каталоги, не ссылки, владелец root или uid 10001, без записи группе и прочим;
  `hermes`, `workspace`, `scratch` в подкаталоге участника — как у изолированного бота. Нарушение —
  `volume_root_invariant` (`scope.root`, `scope.instance`, `scope.K`, `scope.<dir>`).
- **Маркер.** Маркер применённого профиля участника читается по
  `/bot-scope/<botKey>/hermes/.myrmidon/applied.json` (A3); принимается только путь с его ключом.

Чтобы записать участника: добавьте имя каталога экземпляра в `bots[].scopeInstances` (структурная
правка) и отправьте `SIGHUP` **до** того, как владелец применит смену области на доске; пока этого
нет, пересоздание бота отклоняется (`mount_source_not_allowed`). Имя каталога каждого агента видно
в настройках экземпляра, «Изоляция дисков». Эталонные данные (`contract/testdata/scope/`,
`scripts/prepare-shared.sh`) создаются тем же кодом драйвера, что и изолированные.

## Боты старой раскладки (BOT-LAYOUT-V, 1.6.5)

Форма привязок контейнера бота — та, что объявляет контракт рантайма его образа
(`myrmidon.bot-runtime.contract`; драйвер читает её из меток образа на A1), и
шлюз принимает ровно две формы, которые драйвер может выдать:

- **Один том** (контракт `2`, а также образы с контрактом `1` и меткой области):
  одна привязка `<volumeRoot>/<botKey>:/bot`, описанная выше.
- **Старая форма** (контракт `1` без метки области — образы, собранные под три
  отдельных тома, например 1.6.4): те же три каталога хоста, привязанные
  напрямую в `/data/hermes`, `/workspace` и `/scratch`; принимаются только в
  фиксированном порядке драйвера и только как первые три записи тела;
  дополнительные и кэш-привязки за ними не меняются. Другой порядок или
  неполный набор — `binds_mismatch`.

Бот старой раскладки никогда не привязывает экземпляр области (раскладка
области требует стартовых ссылок образа, которые делают только образы однотомной
раскладки). Его маркер и отчёт гигиены клонов лежат под `/data/hermes`, поэтому
A3 и A13 принимают и литеральные запросы архива
`path=%2Fdata%2Fhermes%2F.myrmidon%2Fapplied.json` и
`path=%2Fdata%2Fhermes%2F.myrmidon%2Fclone-hygiene.json` для собственного
контейнера бота — и ничего больше под этим путём.

## Выкат и откат

1. Образ берётся из `ghcr.io/itkadr-git/myrmidon-dockergate` строго по дайджесту; метка OCI `org.opencontainers.image.revision` сверяется с коммитом `main` или тега `myr-v*`.
2. Каталог сокета `/run/myrmidon-dockergate/` создаётся при загрузке (tmpfiles) и монтируется в контейнер доски; сырой сокет демона в него не монтируется.
3. dockergate запускается отдельным контейнером без привилегий: пользователь 65532, файловая система только для чтения, все capabilities сброшены, лимиты памяти и CPU заданы; доступ к сокету демона получает только он.
4. В окружении доски `MYRMIDON_BOT_DOCKER_SOCKET=/run/myrmidon-dockergate/engine.sock`, перезапуск доски (окно без пересборки ботов).
5. Приёмка: `check-config`, полный цикл драйвера (status, create, writeProfile, start, restart, recreate) на одном боте, в журнале нет отказов кроме ожидаемых.
6. Откат: вернуть прежнее значение `MYRMIDON_BOT_DOCKER_SOCKET`, перезапустить доску; dockergate остановить. Состояние контейнеров ботов при этом не меняется.

## Остаточные риски

- Процесс с uid доски, который через ptrace или `/proc/<pid>/mem` заставляет главный процесс доски сделать вызов, получает полномочия драйвера над записанными в `bots[]` ботами (не root хоста). Смягчение: `kernel.yama.ptrace_scope=1`; полностью: боты вне контейнера доски.
- Поток соединений от процесса с uid доски может задержать законный вызов до следующего прохода реконсиляции.
- Доверие к демону и образам: образ проверяется по дайджесту из `images` и метке контракта; сам образ dockergate не подписывается.
