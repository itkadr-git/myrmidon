# Телеметрия прогона

Сводный снимок `resultJson.runTelemetry` доступен в detail- и list-ответах heartbeat-прогонов. В нём записаны идентификаторы прогона, агента и задачи, источник/причина пробуждения, ревизия задачи на момент приёма пробуждения (`eventRevision`), родительский прогон/повтор, число вызовов модели, токены и категория результата. Промпты, ответы модели, сырые payload пробуждения, учётные данные и секреты не сохраняются.

## Атрибуция вызовов и стоимость

ID вызовов шлюза и ID запросов LiteLLM хранятся отдельно, не более 500 каждого типа; флаги усечения показывают, когда список неполный. Явный `model_call_count` шлюза важнее числа ID. Парсер шлюза принимает метаданные `call_ids` и `model_call_ids` как ID вызовов. Без явного счётчика оценка строится по метаданным шлюза и ограниченному числу строк вызовов в выводе. Токены суммируются из usage прогона.

Цены для API-эквивалентного расчёта настраиваются оператором в Instance → General → Model API pricing: USD за миллион входных, кэшированных входных и выходных токенов по модели. Начальные значения: `gpt-6-luna` — $0.10 / $0.01 / $0.50; `gpt-6.1-sol` — $2.00 / $0.10 / $10.00. Для модели без заданной цены стоимость помечается как неизвестная; spend пулов в LiteLLM не записывается.

## Результат и ревизия

Ревизия берётся из квитанции пробуждения и не восстанавливается по более позднему состоянию задачи. Исход определяется артефактами работы, зарегистрированными для этого прогона: артефакт, commit/push или другой work product. Без work product связанное с прогоном решение о статусе обозначается `status`; комментарий прогона к задаче — `comment_only`; иначе — `nothing`. Статусы и комментарии других прогонов не приписываются этому запуску.

## Сверка

Для проверки сопоставьте отдельные ID шлюза и LiteLLM с записями шлюза этого прогона, а затем отдельно сравните токены и spend платных каналов. При усечённом списке ID используйте явное число вызовов и флаги усечения; список ID в этом случае не является полной выборкой.
