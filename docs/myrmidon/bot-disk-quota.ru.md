# Квота диска на бота (1.6.1-BOT-DISK-C)

> English version: [bot-disk-quota.md](bot-disk-quota.md)

03.10 диск хоста заполнился до 100 %, и доска упала: десятки томов ботов (каждый
содержит клоны рабочих каталогов, дампы scratch и каталог hermes бота) ничем не
ограничивались. Эта функция даёт каждому боту квоту диска, чтобы разросшийся клон
одного бота больше не уложил весь хост.

## Что измеряется

Бот владеет одним каталогом на хосте, где крутятся его контейнеры:

```
<MYRMIDON_BOT_VOLUME_ROOT>/<botKey>/{hermes,workspace,scratch}
```

(`botKey` — id агента; раскладка — в [host-disk.ru.md](host-disk.ru.md).)
Полный размер этого каталога — использование бота. Измерение обходит дерево как
measure у workspace-hygiene: симлинки измеряются, но не обходятся, файлы на
жёстких ссылках (так общее хранилище pnpm импортирует пакеты) считаются один раз
на бота, а огромный или глубокий том останавливается на лимитах обхода
(200 000 записей, глубина 32, 5 с) — остановленный обход даёт нижнюю границу, а
не ошибку.

Когда сервер доски не на том хосте, где лежат тома ботов (хост fleetd),
`MYRMIDON_BOT_VOLUME_ROOT` там не виден и функция молчит: нет измерения,
карточек, отказов. Так же — при несохранённой квоте.

## Настройки

`general.botDiskQuota` в настройках экземпляра, без перезапуска из панели
«Per-bot disk quota» на странице общих настроек экземпляра или через API
(`PATCH /api/myrmidon/bot-disk-quota`, только администраторы экземпляра, аудит
`instance.bot_disk_quota.updated`):

| Поле | Смысл |
|---|---|
| `defaultQuotaMb` | квота каждому боту компании («умолчание касты») |
| `perCaste[]` | `{casteKey, quotaMb}`, совпадение по `agents.role` — вся каста с другой квотой |
| `perAgent[]` | `{agentKey, quotaMb}` — один бот, выше касты |
| карточка `container.diskQuotaMb` | переопределение на карточке агента; выше всего |

Применяется первое найденное значение (карточка → perAgent → perCaste → default).
Нет значения для бота — нет лимита для бота. Квота пересчитывается на каждой
проверке приёма рабочего каталога и на каждом измерении сметчика, поэтому
сохранение действует сразу: без перезапуска и переприменения карточек.

Неверное сохранённое значение читается как «выключено» (fail-closed) — сломанная
настройка не может ни заблокировать работу, ни поднять карточку.

## Сигналы и отказ

- Бот на ≥80% квоты (но не сверх неё) поднимает карточку внимания источника
  `bot_disk_quota` («Bot disk quota») в очереди внимания доски. В ней измеренное
  использование, лимит и процент — видать, что чинить, не открывая настройки.
- Бот сверх квоты поднимает ту же карточку с формулировкой «quota exceeded», и НОВЫЙ
  рабочий каталог для него отклоняется до создания каталога:
  `realizeExecutionWorkspace` прерывается с
  `BOT_DISK_QUOTA_EXCEEDED: <name> has used <used> MB of its <quota> MB disk
  quota, so a new workspace clone is refused. Remove unneeded worktrees, build
  outputs and caches under your volume, then retry.`
  Существующий рабочий каталог квота никогда не отказывает и не удаляет: бот
  продолжает работать в том, что уже есть, а карточка просит уборку — отказ
  только останавливает рост. Это же правило бережёт хост: бот не может клоняться
  в полный диск, а доска (она под квоту не входит) продолжает работать.

Карточка — сигнал, не тикет: пока бот на уровне или сверх него, каждый проход
сметчика (бот перемеряется не чаще раза в 10 минут) обновляет её — ключ
подавления — id бота, так повторный выпуск обновляет ту же карточку вместо
стопки. Когда использование падает ниже 80% — после уборки,
сбора черновиков или сниженной настройки — сметчик снимает сигнал, карточка
закрывается.

## Сметчик

Такт обслуживания (`server/src/index.ts`, одна строка: `scheduleBotDiskQuotaSweep()`)
измеряет за такт одну страницу ботов (по умолчанию 20, порядок — по последней
активности) и проходит по кругу всех ботов; курсор страницы сбрасывается после
последнего бота. Бота, измеренного меньше 10 минут назад, следующий такт не
перемеряет (его последний сигнал стоит), так что такт не обходит один каталог
дважды подряд. Упавший бот (нечитаемый том) идёт в `failed` сметчика и
пробуется снова в свой следующий ход; итоги такта пишутся в журнал.

Последний `lastSweep` отдаёт `GET /api/myrmidon/bot-disk-quota` и показывается
под панелью — оператор видит, что делает сметчик, не открывая журнал сервера.

## Чего квота НЕ делает

- Ничего не удаляет. Сбор брошенных черновиков — BOT-DISK-A (`general.botDisk`,
  сметчик idle-TTL); эта функция только считает и отказывает.
- Не ограничивает записи внутри уже рабочего каталога. Бот, уже сидящий в своём
  клоне, может писать пока хост терпит — квота не даёт следующему клону
  увеличить ту же ошибку.
- Не трогает ботов на хостах fleetd (доска их диск не видит; молчит).

## Код ошибки для бота

Стабильная строка: `BOT_DISK_QUOTA_EXCEEDED:` — тот же контракт, что у других
отказов приёма рабочего каталога (`WORKTREE_MISSING:` …). Бот может сверять по ней.
