# Кэширование политик в tool-gateway (OPE-4129)

## Обзор
tool-gateway принимает решение о доступе к инструментам по **снимку политик
на запрос**, а не перечитывает все таблицы политик на каждый инструмент в
`tools/list`.

На один `tools/list` (или вызов инструмента) шлюз загружает снимок,
отфильтрованный по компании, ровно один раз:

- `tool_profiles` — фильтр по `company_id`
- `tool_profile_bindings` — фильтр по `company_id`
- `tool_policies` — фильтр по `company_id`

Все решения по инструментам (`decideWithCachedData`) далее работают по этому
снимку в памяти: константное число запросов к `tool_*` на запрос, независимо
от количества инструментов.

## Кэш снимка и инвалидация
Короткоживущий кэш снимка в памяти (`policyCache` в
`server/src/services/tool-gateway.ts`) с ключом `{companyId}:{agentId}`.

Инвалидация — **по событию, а не по TTL**:

- Каждая мутация `tool_profiles` / `tool_profile_bindings` /
  `tool_policies` (CRUD профилей, записи, привязки, ask-first политики,
  привязки профилей MCP-шлюзов) после успешной записи вызывает
  `emitToolPolicyChanged()` из
  `server/src/services/tool-policy-cache-events.ts`.
- tool-gateway подписан через `onToolPolicyChanged()` и мгновенно сбрасывает
  все кэшированные снимки — изменение политики видно уже в следующем
  запросе.
- Оставшийся TTL 30 секунд — только страховка на межпроцессный случай:
  мутация в другом процессе доски не может вызвать событие в текущем
  процессе, поэтому остальные процессы сходятся в течение ≤ 30с. В
  однопроцессной выкатке изменения видны без задержки.

## Настройки
Новых настроек не появляется, кэш работает автоматически. Единственная
константа — страховочный TTL между процессами (`CACHE_TTL_MS = 30 * 1000` в
`tool-gateway.ts`).

## Производительность (замер 04.10.2026)

- До: `decide()` на каждый инструмент перечитывал таблицы `tool_*` целиком —
  ~870 тыс. запросов на таблицу за 11,7 ч (~5,4 млн всего); `POST
  /mcp/gateways` в среднем 18–26с на 12 шлюзов.
- После: ровно 3 запроса `tool_*` с фильтром по компании на `tools/list`
  (бюджет ≤ 5), независимо от числа инструментов. Регрессионный тест —
  `server/src/services/tool-gateway.perf.test.ts` (константное число
  запросов при 10/50/100 инструментах).

## Файлы

- `server/src/services/tool-gateway.ts` — `getCachedPolicyData`,
  `decideToolAccessWithCache`, кэш снимка + инвалидация по событию
- `server/src/services/tool-access-policy.ts` — `decideWithCachedData`
- `server/src/services/tool-policy-cache-events.ts` — шина событий
  (`emitToolPolicyChanged` / `onToolPolicyChanged`)
- `server/src/services/tool-access.ts` — точки мутаций эмитят событие
- `server/src/services/tool-gateway.perf.test.ts` — регрессионный тест

DIVERGENCE: снимок отфильтрован по компании и инвалидируется по событию;
устаревание между процессами ограничено страховочным TTL 30с вместо
минут TTL-кэша.
