# Оптимизация производительности прогонов (Heartbeat Runs)

## Обзор

Эта оптимизация решает проблемы производительности прогонов, за счет:

1. Устранения дублирования данных `executionContinuation`
2. Оптимизации запросов к базе данных для исключения ненужного выбора тяжелых JSON-колонок
3. Добавления индексов для ускорения частых запросов

## Изменения

### Оптимизация запросов к базе данных

#### Блокировка владения разговором (Conversation Ownership Blocker)
- Изменена функция `getConversationOwnershipBlocker()` для выбора только необходимых колонок вместо `SELECT *`
- Снижено потребление ресурсов за счет выбора конкретных полей: `id`, `agentId`, `processPid`, `processGroupId`, `status`, `createdAt`, `processStartedAt`

#### Список прогонов
- Добавлена опция `includeHeavyColumns` в функцию `list()`
- Когда `includeHeavyColumns` равен `false`, исключаются тяжелые JSON-колонки, такие как `resultJson`, детали `contextSnapshot`, и поля ошибок
- Сохранена обратная совместимость со значением по умолчанию `true`

#### Лента внимания
- Оптимизирована функция `listAttentionExhaustedRunsWithoutHeavyColumns()` для исключения тяжелых колонок
- Используется в ленте внимания для уменьшения размера полезной нагрузки и повышения производительности

### Миграции базы данных

#### Миграция 0296: Индексы производительности
- Добавлен индекс `heartbeat_runs_company_issue_coalesce_created_idx`
- Повышает производительность запросов с фильтрацией по ID компании, ID задачи и времени создания

#### Миграция 0297: Удаление дублирования executionContinuation
- Удаляет дублированное хранение поля `executionContinuation`
- Обеспечивает хранение поля только один раз внутри объекта `paperclipWake`

## Влияние на производительность

Эти оптимизации обеспечивают:
- Снижение размера таблицы `heartbeat_runs` за счет устранения дублирующихся данных
- Уменьшение времени выполнения запросов для обычных операций
- Снижение использования памяти при загрузке данных прогонов
- Более быструю загрузку ленты внимания
