# Heartbeat runs: хранение продолжения и измерения

В этом документе описаны хранение продолжения прогона и запросы для анализа `heartbeat_runs`. Приведённые ниже значения — исторические результаты аудита, а не гарантия для любой установки. Чтобы измерить текущее состояние, выполните read-only запросы из `heartbeat_runs_optimization.sql` на репрезентативной базе.

## Хранение продолжения

Конверт продолжения выполнения хранится в `heartbeat_run_continuations` — одна строка на прогон. Таблица содержит конверт, счётчик сериализованных символов, необязательные ссылки на данные побудки и индексы для уникального поиска по прогону, компании/агенту и компании/задаче. В сохраняемый `heartbeat_runs.context_snapshot` текущий конверт не попадает: при записи удаляется поле `executionContinuation` верхнего уровня, присутствующее в памяти. Payload побудки сохраняется без второй копии; при отправке адаптеру диспетчеризация добавляет конверт обратно.

Для строк, записанных до перехода на эту модель, читатели сохраняют совместимость с прежним значением `context_snapshot.executionContinuation`. Миграция `0330_heartbeat_run_continuations.sql` создала таблицу и её индексы. Миграция `0380_remove_execution_continuation_duplication.sql` очищает исторические дубликаты между полем верхнего уровня в снимке и вложенным `paperclipWake.executionContinuation`. Эта очистка касается старых данных снимка; она не переносит текущие конверты в таблицу продолжений или обратно.

## Стоимость запросов и измерения

SQL для измерений показывает размер снимков, размер таблицы и TOAST, данные о количестве и размере строк таблицы продолжений, а также выполняет `EXPLAIN (ANALYZE, BUFFERS)` для проекции, соответствующей списку прогонов. Текущая проекция списка сначала читает значения контекста из тонких колонок, а для исторических строк с `NULL` в этих колонках использует JSON-поля `context_snapshot`. Поэтому строки с заполненными тонкими колонками не требуют detoast снимка. SQL-запрос показывает форму с JSON-извлечением для иллюстрации резервного пути; это не полная текущая проекция списка. Проверка владения диалогом использует узкую проекцию шести необходимых значений, а не загружает целую строку прогона и её JSON-поля для каждого кандидата.

Индекс `heartbeat_runs_company_issue_coalesce_created_idx` поддерживает поиск по компании и задаче через `coalesce(native_issue_id::text, context_snapshot ->> 'issueId')` с сортировкой по убыванию времени создания и id. Проверяйте фактический план на репрезентативной базе: в зависимости от статистики и распределения данных PostgreSQL может выбрать другой план.

Тест хранения продолжений: `server/src/services/heartbeat-run-continuations.myrmidon.test.ts`. Из корня репозитория выполните:

```sh
pnpm --filter @myrmidon/server exec vitest run src/services/heartbeat-run-continuations.myrmidon.test.ts
```

SQL содержит только запросы `SELECT`, включая запрос `EXPLAIN ANALYZE`. Тем не менее измерения следует проводить на копии staging-базы или в согласованное окно обслуживания: `EXPLAIN ANALYZE` исполняет измеряемый `SELECT` и может расходовать ресурсы. Выполнение против живой базы здесь не заявляется.

## Исторические значения

В одном из прежних аудитов базы доски общий размер `heartbeat_runs` составлял около 1,1 ГБ, включая примерно 1,07 ГБ данных TOAST; дублирующие конверты оценивались примерно в 354 МБ. В отдельной выборке средний размер снимка составлял около 30,7 КБ в целом и 7,58 КБ для завершённых строк. Эти значения получены до появления отдельной таблицы продолжений и очистки исторических данных, поэтому не являются текущими показателями после миграций. Для актуальной исходной точки повторно выполните предоставленные запросы.

## Риски и интерпретация

- Для старых строк может по-прежнему требоваться резервное чтение из снимка, пока данные не доступны через новую таблицу; не удаляйте этот механизм совместимости без отдельной проверки.
- Историческая миграция очистки сохраняет копию верхнего уровня, если она есть, либо сначала переносит вложенное значение вверх, если верхнего значения нет, и затем удаляет вложенный дубликат. Точные условия записей смотрите в тексте миграции.
- Результаты измерений зависят от размера базы, статистики PostgreSQL и состояния кеша. Сравнивайте сопоставимые запуски и отдельно фиксируйте параметры окружения.
