# Установка

> English version: [Installation](Installation)

Одна команда превращает чистый сервер в работающую доску Myrmidon.
Скопируйте её на сервер и запустите — дальше установщик делает всё сам:

```sh
curl -fsSL https://github.com/itkadr-git/myrmidon/releases/download/myr-v1.6.5-rc.15/install.sh | sudo bash
```

Пока финальный выпуск 1.6.5 не вышел, команда ставит текущего кандидата —
установщик приложен к выпускам начиная с 1.6.5, поэтому постоянная ссылка
`releases/latest/download/install.sh` пока отдаёт 404 и заработает вместе с
финальным выпуском. Нужны только интернет на сервере и `curl` (на чистой
Ubuntu или Debian он ставится командой `sudo apt-get install -y curl`).

## Что установщик делает, шаг за шагом

1. **Проверяет машину** по [системным требованиям](System-requirements.ru) и
   простыми словами объясняет, чего не хватает, — и останавливается сразу,
   а не падает на середине.
2. **Ставит Docker** и плагин compose, если их ещё нет (из официального
   репозитория Docker).
3. **Находит выпуск, названный в команде** (пока это текущий кандидат, а
   после выхода 1.6.5 — последний стабильный выпуск), и скачивает ровно его
   файлы — те, что прошли проверки выпуска. Выпуск не меняется задним
   числом, поэтому завтрашняя установка той же версии будет совпадать с
   сегодняшней.
4. **Создаёт все секреты** (пароль базы данных и внутренние ключи доски) и
   пишет настройки в `/opt/myrmidon`. Руками заполнять ничего не нужно; файл
   с секретами читает только root.
5. **Скачивает образы программы и запускает службу**: базу данных, доску и
   компонент, который позже будет запускать агентов.
6. **Ждёт, пока доска ответит**, и печатает итог.

Весь запуск занимает несколько минут, бо́льшая часть времени уходит на шаг 5.
Установщик не задаёт вопросов; каталог установки, порт и адрес доски он
спросит, только если запустить его с флагом `--interactive`.

## Что вы увидите в конце

Итог примерно такой:

```
Myrmidon 1.6.6 установлен и отвечает.

  Адрес:              http://my-server:3100
  Первый администратор: откройте http://my-server:3100 , создайте учётную
                        запись — первый зарегистрировавшийся становится
                        администратором этого сервера.
  Файлы:              /opt/myrmidon
```

Откройте напечатанный адрес в браузере и создайте учётную запись: первый
зарегистрировавшийся становится администратором этого сервера. Дальше доска
готова к работе — добавьте модель и создайте первого агента в интерфейсе
(см. [Настройки в интерфейсе](Settings-in-the-interface.ru)).

## Если шаг упал

Установщик останавливается на упавшем шаге и объясняет причину простыми
словами — например, что памяти меньше нужной или порт занят. Исправьте то,
что он назвал, и запустите ту же команду ещё раз: повторный запуск безопасен,
установщик начинает с чистого состояния. Если не поднялась сама доска,
установщик тут же печатает последние строки её журнала.

## Полезные параметры

- `install.sh --version myr-vX.Y.Z` — поставить конкретный выпуск вместо
  последнего.
- `install.sh --dir /srv/myrmidon --port 8080` — другой каталог или порт
  (о них же спросит `--interactive`).
- `install.sh --lang ru` / `--lang en` — язык сообщений установщика; по
  умолчанию язык берётся из локали системы, а флаг его перекрывает.

Чтобы добавить параметр к однострочной команде, сначала скачайте скрипт:

```sh
curl -fsSL -O https://github.com/itkadr-git/myrmidon/releases/download/myr-v1.6.5-rc.15/install.sh
sudo bash install.sh --version myr-vX.Y.Z
```

## Обновление и удаление

- **Обновление:** запустите ту же однострочную команду ещё раз. Установщик
  сначала снимет копию базы данных, переключится на новый выпуск, проверит,
  что доска отвечает, и сам вернётся на прежний выпуск, если новый не
  поднялся. Подробнее: [Обновление и откат](Upgrading-and-rollback.ru).
- **Остановка и удаление:** `sudo bash install.sh --uninstall` остановит
  службу и сохранит данные; `--uninstall --purge` удалит также базу данных и
  каталог установки.

## Для опытных администраторов

Ручной выкат через `deploy.sh` вынесен на отдельную страницу:
[Ручной выкат](Manual-deployment.ru). Это поток с окном обслуживания — на нём
работает боевой сервер проекта. Для установки с нуля он не нужен.
