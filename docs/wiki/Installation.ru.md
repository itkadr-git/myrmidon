# Установка

> English version: [Installation](Installation)

Одна команда приводит чистый сервер к работающей доске Myrmidon. Скопируйте
её на сервер и запустите — дальше установщик делает всё сам:

```sh
curl -fsSL https://github.com/itkadr-git/myrmidon/releases/latest/download/install.sh | sudo bash
```

По этой ссылке всегда лежит установщик последнего выпуска. Из требований —
интернет на сервере и `curl` (на чистых Ubuntu и Debian он ставится командой
`sudo apt-get install -y curl`).

## Что установщик делает, шаг за шагом

1. **Проверяет машину** по [системным требованиям](System-requirements.ru) и
   человеческим языком говорит, чего не хватает, — и останавливается сразу,
   а не падает на середине.
2. **Ставит Docker** и плагин compose, если их ещё нет (из официального
   репозитория Docker).
3. **Находит последний выпуск** и скачивает строго его файлы — те самые, что
   прошли проверки выпуска. Выпуск не меняется задним числом, поэтому
   завтрашняя установка той же версии будет совпадать с сегодняшней.
4. **Создаёт все секреты** (пароль базы данных и внутренние ключи доски) и
   пишет настройки в `/opt/myrmidon`. Руками заполнять ничего не нужно; файл
   с секретами читает только root.
5. **Скачивает образы программы и запускает службу**: базу данных, доску и
   часть, которая позже будет запускать агентов.
6. **Ждёт, пока доска ответит**, и печатает итог.

Весь запуск занимает несколько минут, бо́льшая часть — шаг 5. Вопросов
установщик не задаёт; три из них (каталог установки, порт, адрес доски)
включаются флагом `--interactive`.

## Что вы увидите в конце

Итог примерно такой:

```
Myrmidon 1.6.6 установлен и отвечает.

  Адрес:              http://my-server:3100
  Первый администратор: откройте http://my-server:3100 , создайте учётную
                        запись — первый зарегистрировавшийся становится
                        администратором этого сервера.
  Файлы:              /opt/myrmidon
```

Откройте напечатанный адрес в браузере и создайте учётную запись — первый
зарегистрировавшийся на сервере становится его администратором. Дальше доска
готова к работе: добавьте модель и создайте первого агента в интерфейсе
(см. [Настройки в интерфейсе](Settings-in-the-interface.ru)).

## Если шаг упал

Установщик останавливается на упавшем шаге и пишет причину человеческим
языком — например, что памяти меньше нужного или порт занят. Исправьте то,
что он назвал, и запустите ту же команду ещё раз: повторный запуск безопасен,
установщик продолжит с чистого состояния. Если не поднялась сама доска,
последние строки её журнала будут напечатаны тут же.

## Полезные параметры

- `install.sh --version myr-vX.Y.Z` — поставить конкретный выпуск вместо
  последнего.
- `install.sh --dir /srv/myrmidon --port 8080` — другой каталог или порт
  (их же спрашивает `--interactive`).
- `install.sh --lang ru` / `--lang en` — язык сообщений установщика; по
  умолчанию он берётся из локали системы, параметр его перекрывает.

Чтобы передать параметры в однострочной форме, сначала скачайте скрипт:

```sh
curl -fsSL -O https://github.com/itkadr-git/myrmidon/releases/latest/download/install.sh
sudo bash install.sh --version myr-vX.Y.Z
```

## Обновление и удаление

- **Обновление:** запустите ту же однострочную команду ещё раз. Установщик
  сначала снимет копию базы данных, переключит выпуск, проверит, что доска
  отвечает, и сам вернётся на прежний выпуск, если новый не поднялся.
  Подробнее: [Обновление и откат](Upgrading-and-rollback.ru).
- **Остановка и удаление:** `sudo bash install.sh --uninstall` остановит
  службу и сохранит данные; `--uninstall --purge` удалит ещё и базу данных,
  и каталог установки.

## Для опытных администраторов

Ручной выкат через `deploy.sh` — поток с окном обслуживания, под которым
работает боевой сервер, — вынесен на отдельную страницу:
[Ручной выкат](Manual-deployment.ru). Для установки с нуля он не нужен.
