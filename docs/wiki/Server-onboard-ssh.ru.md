# Онбординг сервера: предлагаемый жизненный цикл SSH-ключей

В [PR #2824](https://github.com/itkadr-git/myrmidon/pull/2824) предложен SSH worker; PR не влит и не выкачен. Это не инструкция по развёртыванию, а остальные части исполнителя проходят отдельную приёмку.

Предлагаемый worker сохраняет первый принятый отпечаток ключа хоста до аутентификации и отклоняет изменённый отпечаток при повторном подключении. TOFU не подтверждает подлинность первого соединения самостоятельно. Приватный ключ доступа хранится в хранилище секретов доски; новый вход только по ключу проверяется до возможного отключения парольной аутентификации. Начальный пароль удаляется только после успешного проверенного отчёта, если его сохранение не запрошено. Ошибка удаления фиксируется в аудите. Каждая попытка `addServer` владеет отдельными секретами, в том числе при конфликте slug.

[Источник для оператора](https://github.com/itkadr-git/myrmidon/blob/main/docs/myrmidon/guides/server-onboard-ssh.ru.md) описывает доказательства и ограничения; [задание affected-tests](https://github.com/itkadr-git/myrmidon/actions/runs/44820491758/job/136580197745) использовало loopback SSH и PostgreSQL, а не боевые хосты.
