# Проверка брендинга перед релизом (только чтение)

> English version: [Brand-release-check](Brand-release-check)


Ручная проверка перед присвоением релизного тега. Не вносит изменений в систему, код и конфигурацию.

## 1. Проверка репозитория (CI)

```bash
node scripts/myrmidon/docs-branding-guard.mjs        # docs/ — без замечаний
node scripts/myrmidon/brand-release-audit.mjs        # корень + docs/ + package.json — режим отчёта
node scripts/myrmidon/brand-release-audit.mjs --gate # режим с ошибкой при обнаружении
node scripts/myrmidon/brand-release-audit.mjs --package-json-only --gate # проверка манифестов package.json
node --test scripts/myrmidon/brand-release-audit.test.mjs
```

Режим отчёта выводит точное количество и пути оставшихся упоминаний вне белого списка. Ненулевое число допустимо, если параллельный этап ребрендинга ещё не слит — зафиксируйте значение в отчёте релиза. Поля `repository`, `homepage` и `bugs` в манифестах `package.json` должны указывать на репозиторий `https://github.com/itkadr-git/myrmidon`.

## 2. Тексты пользовательского интерфейса (браузер, только чтение)

Откройте интерфейс доски и убедитесь, что во всех видимых пользователю строках используется имя Myrmidon:

- Заголовок вкладки браузера и заголовки страниц (включая навигационную цепочку).
- Экран «О системе»: название продукта и обязательная строка атрибуции `Based on Paperclip (MIT)` (удаление запрещено).
- Версия в боковой панели и её атрибут `aria-label`.
- Пустые состояния списков, тексты онбординга, уведомления об ошибках, диалог создания задачи.

Допускается поиск через DevTools (Elements → поиск `Paperclip` с учётом регистра). Разрешённые совпадения: строка атрибуции, имена пакетов, заголовки HTTP в сетевой документации.

## 3. Тексты ботов и журналов (только чтение)

- Проверьте активный статус прогона агента в личном сообщении владельцу: префикс продукта — Myrmidon. Устаревший текст «Paperclip needs a disposition before this issue can continue» поддерживается как легаси-алиас до версии 1.8; получение его от старого экземпляра ожидаемо, отправка новой сборкой является ошибкой.
- Ответы API `GET /api/…`: поля `message` и `details` в ошибках, сводки задач, описания агентов — без старого бренда. Служебные идентификаторы (`X-Paperclip-Run-Id`, переменные окружения `PAPERCLIP_*`, имена пакетов `@paperclipai/*`) сохраняются для совместимости.
- Журналы запущенного сервера: проверьте хвост лога на наличие старого бренда. Совпадения в обработчиках устаревших алиасов допустимы; в новых сообщениях — ошибка.

## 4. Что не является ошибкой

- Файлы `LICENSE`, `NOTICE`, уведомления сторонних библиотек (`ui/public/fonts/NOTICE.md`, `packages/adapters/hermes/LICENSE`): юридическая атрибуция сохраняется бессрочно.
- Строка атрибуции `Based on Paperclip (MIT)`.
- Машинные и протокольные идентификаторы до планового переименования: `@paperclipai/*`, `PAPERCLIP_*`, `X-Paperclip-*`, CLI `paperclipai`, путь `skills/paperclip/`, имена навыков и API, имена контейнеров и баз данных в примерах развёртывания.
- Внешние сервисы вендора.
- Исторические записи (CHANGELOG, треки изменений, старые строки реестра отличий DIVERGENCE).

## 5. Фиксация результатов

В отчёте релиза укажите: вывод проверочных скриптов (количество и пути), вручную проверенные контрольные точки, список оставшихся замечаний с указанием эпика-владельца.
