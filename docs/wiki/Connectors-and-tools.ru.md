# Коннекторы и инструменты

> English version: [Connectors-and-tools](Connectors-and-tools)

Агенты работают через инструменты: опасные и тяжёлые из них Myrmidon держит
вне контейнера бота — в отдельных службах и шлюзах под управлением доски, —
а каждому боту выдаёт ровно те, на которые тот имеет право.

## Мост браузера

Мост браузера позволяет боту компании действовать в браузере на ПК клиента:
открывать страницы, читать, нажимать, заполнять, скачивать, делать снимки
экрана и — по политике, заданной оператором, — участвовать в шаге подписания,
который человек завершает на этом ПК. На ПК клиента нет открытого порта:
расширение браузера само устанавливает соединение **наружу** со шлюзом
коннекторов доски. Панель коннекторов (Настройки компании → Коннекторы) —
отсюда оператор управляет сопряжением и отзывом устройств, белым списком
доменов, политикой подписания и журналом.

Раздел настроек «Браузеры» даёт владельцу наблюдать за живыми браузерами,
через которые боты входят на сайты, и управлять ими: открыть сессию экрана,
поддерживать её, закрыть, очистить данные сайта.

## Коннекторы MCP

Доска может подключить внешний сервер MCP, совместимый со стандартом, —
любой HTTP endpoint MCP, который компания эксплуатирует или которому
доверяет, — и передать его инструменты выбранным агентам без правки кода
форка. На собственном сервере MCP доски каждый инструмент публикуется под
именем `myrmidon*`; старые имена `paperclip*` продолжают работать как
устаревшие псевдонимы один выпуск, чтобы установленные системы не ломались.

Выданные внешним клиентам токены доступа к шлюзу находятся под постоянным
мониторингом: лента внимания заблаговременно (за 14 дней) выставляет карточки
оператору, рекомендуя ротацию для активных токенов и отзыв для истекших
неиспользованных токенов без раскрытия секретных хешей.

## Облачные хранилища и Microsoft 365

Облачный коннектор делает облачное хранилище полноценным модулем доски:
владелец с панели подключает один облачный аккаунт на провайдера и оттуда
же раздаёт агентам доступ к папкам. Токен OAuth живёт в секретнице
экземпляра как секрет компании — боты его не видят.

Служба cloud-files даёт ботам-контейнерам OneDrive и общий почтовый ящик
одного служебного аккаунта Microsoft — через шлюз инструментов доски.

## Медиа, офис и OCR

Образ бота не несёт ни ffmpeg, ни LibreOffice, ни poppler, ни Tesseract. Они
живут в отдельных службах, а бот получает один адрес MCP. OCR превращает
полученный ботом PDF — вложение письма, файл, скачанный через мост браузера,
документ в рабочей области — в текст, с которым бот может работать, и
добавляет структурную выжимку для тендерной документации.

## GitHub

Агенты разработки отправляют код через GitHub-брокер запуска: доска выдаёт
запуску учётные данные ровно на него. Компания может авторизовать GitHub
один раз на весь сервер своим собственным приложением GitHub App вместо
персональных OAuth-учёток.

Для защиты почасовых лимитов GitHub App токены кэшируются в оперативной
памяти брокера, объединяются параллельными запросами (single-flight), сохраняются
на диске во временном каталоге прогона (`PAPERCLIP_GITHUB_CREDENTIALS_CACHE_DIR`)
и защищаются предохранителем частоты запросов (`MYRMIDON_GITHUB_CREDENTIALS_FUSE_PER_MINUTE`, по умолчанию 60/мин).
См. [Руководство по кэшированию учетных данных GitHub](Github-credentials-cache.ru).

## Плагины и права доступа

Плагины работают как изолированные процессы с явно объявленными возможностями
(capabilities). При оркестрации задач возможность `issue.attachments.write`
позволяет фоновым процессам загружать ограниченные файлы (подтверждения, отчёты,
логи) без передачи прямых ключей администратора доски или доступа к БД.

Оболочка UI2 также показывает слоты боковой панели и launcher-элементы
установленных плагинов в рейке и мобильной навигации. UI-вклад страницы плагина
загружается при прямом открытии URL. См. [руководство по оболочке UI2](Ui2-shell.ru).
